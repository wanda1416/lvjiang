# 毕业率计算引擎 — leoq7 WASM 逆向分析

## 1. 概述

leoq7 网站（yysls.leoq7.com）提供了一套基于 WebAssembly 的毕业率计算引擎，由 Rust 编译为 WASM。用户输入 8 件装备数据后，引擎自动计算面板属性、DPS 和毕业率。本文档记录对该引擎的完整逆向分析结果，作为律匠项目本地实现毕业率计算的技术参考。

---

## 2. 计算引擎架构

### 2.1 整体流程

```
8 件装备数据 + 配置选项
    ↓
buildDiyRaw()  → 构建 Float64Array(184) DIY 输入
    ↓
yysls_calc_diy()  → WASM 计算面板
    ↓
panelFromArray()  → 解析面板属性（36 个面板行）
    ↓
面板后处理：applyClassPanelRules → applyRateOverflow
    ↓
collectBonuses()  → 收集装备/定音/心法 bonuses
    ↓
applyPanelBonuses()  → 将 bonuses 叠加到面板
    ↓
再次 applyRateOverflow()  → 属性上限裁剪
    ↓
buildClassRaw()  → 构建职业输入 Float64Array(38+)
    ↓
yysls_calc_class_outputs()  → WASM 计算 DPS / 毕业率
    ↓
输出：总伤害、DPS、毕业率
```

### 2.2 核心文件

| 文件 | 作用 |
|------|------|
| `yysls_calc.wasm` | Rust 编译的 WASM 计算引擎 |
| `generated-calc-metadata.js` | 元数据：字段映射、流派配置、默认值、满值表 |
| `generated-calc-strings.js` | WASM 字符串表（流派名、套装名等） |
| `excel-runtime.js` | JS 封装层：输入构建、面板解析、bonuses 处理 |

## 4. 定音处理 — 贷款定音机制

### 4.1 核心发现

**定音属性（外功穿透、指定武学技能增伤）不在 `statRows` 中，永远不会被加入 DIY 输入。** 定音始终通过 `collectBonuses` + `applyPanelBonuses` 单独处理。

### 4.2 普通模式 vs 贷款定音

| 模式 | 定音处理 |
|------|---------|
| 普通模式 | 定音值通过 `collectBonuses` 收集，外功穿透需除以 1.15 |
| 贷款定音 | 定音值从 `loanDingyinValue` 数组读取，同样除以 1.15 |

### 4.3 外功穿透公式（贷款定音）

```
面板外功穿透 = max(0, WASM面板外穿 - 58.4, 心法外穿加成) + 贷款外穿 / 1.15
```

- `58.4`：WASM 内部假设的 4 件定音外穿值（`fallbackDiyAssumedOuterPen`）
- 心法外穿加成：凝神章 = 5.1，征人归 = 5.1，等

**示例**：贷款外穿 67.2，凝神章
```
max(0, 0 - 58.4, 5.1) + 67.2/1.15 = 5.1 + 58.43 = 63.53 ≈ 63.5
```

### 4.4 增伤除以 1.15 规则

所有增伤类属性（外功穿透、指定武学技能增伤、对首领增伤等）在生效时需要除以 `damageBonusResistance = 1.15`。

```
生效值 = 显示值 / 1.15
```

**示例**：贷款定音增伤 36.8 → 36.8 / 1.15 = 32%

## 5. 面板解析（panelFromArray）

### 5.1 面板行映射（panelRows）

WASM 输出数组通过 `panelRows` 映射到面板属性：

| 索引 | 行号 | 属性 | 索引 | 行号 | 属性 |
|------|------|------|------|------|------|
| 0 | 4 | 最小外功攻击 | 1 | 5 | 最大外功攻击 |
| 2 | 6 | 精准率 | 3 | 7 | 会心率 |
| 4 | 8 | 直接会心率 | 5 | 9 | 会心伤害加成 |
| 6 | 10 | 会意率 | 7 | 11 | 直接会意率 |
| 8 | 12 | 会意伤害加成 | 9 | 13 | 最小鸣金攻击 |
| 10 | 14 | 最大鸣金攻击 | 16 | 26 | 外功穿透 |
| 17 | 28 | 鸣金穿透 | 18 | 29 | 鸣金伤害加成 |
| 26 | 36 | 指定武学增效 | 28 | 38 | 对首领单位增伤 |
| 29 | 39 | 全武学增效 | | | |

> 注意：`statRows`（DIY 输入行号）和 `panelRows`（面板输出行号）是**完全不同的映射**。

### 5.2 面板后处理

1. **applyClassPanelRules**：流派特殊规则（当前仅牵丝类有牵丝穿透/伤害加成规则）
2. **applyRateOverflow**：属性上限裁剪
   - 精准率 cap 100%
   - 会心率 cap 80%
   - 会意率 cap 40%
   - 溢出部分按 `seasonResistance = 2.15` 转换为白值
   - 组合上限：会意率 + 会心率 + 直接会心率 + 直接会意率 ≤ 100%

## 6. Bonuses 收集与面板叠加

### 6.1 collectBonuses

收集所有装备的主属性、副属性、定音属性（或贷款定音值），按属性类型汇总。

### 6.2 applyPanelBonuses 关键逻辑

| 属性 | 处理方式 |
|------|---------|
| 外功穿透 | `max(0, 面板值 - 58.4, 心法加成) + 贷款外穿/1.15` |
| 对首领增伤 / 全武学增效 | `displayDamageBonus(值, commonEffective=true)` → 不除 1.15 |
| 指定武学增效 | `displayDamageBonus(值, genericWeaponEffective=true)` → 不除 1.15 |
| 剑/枪武学增效 | `displayDamageBonus(值, weaponSpecificEffective=false)` → **除以 1.15** |
| 指定武学技能增伤 | `effectiveDamageBonus(值)` → **除以 1.15** |

> `damageBonusState` 标记了哪些属性已经是"生效值"（不需要再除 1.15），哪些是"显示值"（需要除 1.15）。

## 8. 毕业率计算

### 8.1 公式

```
毕业率 = DPS / baselineDps × 100%
```

- WASM 直接输出 `graduationRatio`（outputs[2]）
- 若 WASM 未输出，则用 `DPS / baselineDps` 手动计算

## 9. 验证结果（蔡元君 · 鸣金虹）

### 9.1 已验证匹配的属性

| 属性 | 网站值 | 计算值 | 状态 |
|------|--------|--------|------|
| 外功穿透 | 63.5 | 63.53 | ✅ |
| 剑武学增效 | 8% | 8.01% | ✅ |
| 全武学增效 | 8% | 8.02% | ✅ |
| 对首领增伤 | 8.3% | 8.33% | ✅ |
| 蓄力技增伤 | 32% | 32.00% | ✅ |

### 9.2 存在差异的属性

| 属性 | 网站值 | 计算值 | 差异 | 可能原因 |
|------|--------|--------|------|---------|
| 会意率 | 40% | 37.3% | -2.7% | 会意弓珏加成未生效 |
| 直接会意率 | 2.3% | 0% | -2.3% | 弓珏类型未影响 WASM 输出 |
| 鸣金穿透 | 36 | 30 | -6 | 最小鸣金攻击未达阈值 |
| 最大外功 | 5625 | 5362 | -263 | 缺少额外属性来源 |
| 最大鸣金 | 1350 | 1269 | -81 | 缺少额外属性来源 |

### 9.3 差异根因分析

1. **会意弓珏**：弓珏类型（`s2` 字段）可能影响 WASM 内部的会意率/直接会意率计算，但本地 WASM 调用未体现该效果
2. **套装加成**：用户可能选择了特定套装（默认"玉斗"），套装提供额外属性
3. **鸣金穿透阈值**：WASM 内部可能根据最小鸣金攻击判断穿透值（类似牵丝穿透规则：`最小攻击 >= 阈值 ? 高值 : 低值`）
4. **五维转换**：劲/势 → 攻击属性的转换比例可能受额外因素影响

## 10. 本地实现方案

### 10.1 方案 A：直接调用 WASM（推荐）

将 `yysls_calc.wasm` 打包到律匠项目中，通过 Node.js 或 Python（`wasmer`/`wasmtime`）直接调用。

**优点**：计算结果与网站完全一致
**缺点**：需要处理 WASM 运行时依赖

### 10.2 方案 B：纯 Python 复现

按照本文档的计算流程，用 Python 重新实现所有逻辑。

**优点**：无外部依赖
**缺点**：WASM 内部的五维转换等黑盒逻辑无法完全复现

### 10.3 方案 C：混合方案

- 面板计算：调用 WASM（精确）
- 面板后处理 + bonuses + 职业输入 + DPS 计算：Python 实现（已验证）
