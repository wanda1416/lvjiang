# 出装搭配与模拟计算器

## 实施范围

备战方案原“模拟装备”入口改为独立“模拟计算器”；“创建模拟装备”移至
删除筛选装备／批量复制装备左侧，继续只创建当前用户的单件模拟装备。

玩法页管理出装搭配，新建、编辑、复制和删除使用独立的
`yysls/game_config/builds.yaml`，不嵌入 playstyles，也不纳入整份游戏配置保存。
稳定 ID 与显示名称分离；每次保存重读文件，仅合并当前搭配，冲突则提示重载。

## 数据与状态

- 搭配保存玩法、PVE/PVP、装备等级、承音／普通数值口径、八件装备词条和套装、
  弓玦套装与等级、强制／最佳／推荐要求。总词条分布由八件装备派生。
- PVE 默认公共要求为首领增伤两条；其他要求由搭配编辑，不改变旧调律规则。
- 模拟器冻结打开时当前方案的基础属性、毕业率模型、用户及真实装备作为对照。
  写回仅保存搭配，不保存私人基础属性、最终面板、用户信息或真实装备指纹。
- 加载另一搭配不改变活动备战方案；修改未保存的草稿切换／关闭时必须确认。
- 弓玦归搭配定义所有；计算时使用不含弓玦的方案基础属性，再叠加目标弓玦。
  真实方案的弓玦不随模拟编辑改动。装备套装复用现有公共属性计算链。

## 分配与计算

总词条通过带容量的最小费用流分配到首词条和普通词条位置，复用游戏配置
候选与装备合法性校验：普通词条同名最多一次、属攻最多两条、神力最多一条。
首词条独立计算；本属在武器只展开无相、非武器展开玩法属性，外属保留具体名称
以免折叠不同外属后丢失多条共存能力。分配尽量保留参考装备原位置，不宣称 DPS 全局最优。

每次调整显示总数、要求满足情况、推荐八件分布、战斗属性与
毕业率。无法分配时清空过期结果；不写入非法组合。未满 40 条允许保存合法草稿，
强制要求未满足明确标记，不作为合格完整目标。属性计算复用 PlanScoringContext
和 LoadoutScorer，不复制毕业率公式。不接入自动调律运行流程。

左区以「装备词条」「词条约束」两个页签承载数量配置和原出装要求。右区不设页签和额外
标题，直接纵向展示八件装备表格及备战方案全屏模式的完整战斗属性面板；不能另拆页签或
第三分栏，只让用户从顶部毕业率数字猜测变化。
模拟器向该面板注入打开时冻结的流派、基础属性、世界等级和当前模拟装备，不读取随后发生
变化的外部方案状态。

战斗属性的增益卡片在全屏与半屏模式统一只展示「全奇术增伤」。旧装备携带的单体、群体
奇术增伤在装备属性聚合时折入全奇术增伤，不改写原装备；卡片须容纳最多四条不同的防具
定音技能且不能与固定属性重叠。

界面参考模拟器截图采用词条卡片、圆形减加按钮与满值说明，保持项目主题与按钮语义。
分配表逐列展示宫商角徵羽，武器后紧接环佩，保持攻具与防具套装分组；位置候选留在引擎内部。
