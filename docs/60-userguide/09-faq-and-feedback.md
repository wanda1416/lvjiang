# 9. 常见问题与反馈

先按 9.1-9.9 自查；确认是程序问题后，按 9.10-9.20 整理材料再提交，缺关键信息的反馈无法排查。

## 9.1 连接问题

| 现象 | 处理 |
|------|------|
| 「未找到可见窗口」 | 确认投屏窗口未最小化；重新点「扫描窗口」 |
| 扫描后「未匹配到关键字」 | 配置管理里的「窗口标题」与实际窗口标题不符，改关键字或手动下拉选择 |
| 「未找到 ADB 设备」 | 检查数据线、手机上是否弹出并允许了 USB 调试授权；无线模式确认同一局域网 |
| 日志提示“App 不可达或设备端执行通道未就绪，回退 adb shell input” | 不影响使用，只是点击改走 `adb shell input`。要用设备端执行：手机上安装律匠 app，系统设置 → 无障碍 → 开启「律匠自动操作」，确认 App 首页显示“辅助已开启”，再重新连接。连接成功后首页会显示“PC 已连接” |
| PC 连接后悬浮球消失 | 正常行为。PC 控制期间 App 自动隐藏悬浮球，避免它进入截图或与 PC 工作流并行操作；断开设备连接后自动恢复。PC 模式不要求悬浮窗权限 |
| 已启用「设备端执行」，截图仍显示 screencap 或 scrcpy | 这是正常行为。设备端执行只选择输入通道，截图始终服从独立的「安卓截图」设置 |
| 换了一台手机，所有识别/点击整体偏了一截（挖孔 / 黑边） | 游戏内容区位置和作者的机器不一样。手机上：游戏停在大厅 → 悬浮图标 → 「屏幕标定」→ 在参照图上点两个拉开距离的按钮，app 自动在本机画面里找到同一按钮并画出绿框 → 「保存画布」。错了点「恢复默认」 |
| 手机上「屏幕标定」提示没有参照图 | 该布局没随版本带参照截图。脚本作者在自己手机上停在大厅 → 屏幕标定 → 「重新截图」→ 「本机画面设为参照图」，把生成的 `layouts/<布局>/_reference.png` 与 `_reference.json` 提交进 `config/system` |
| 点击落点与截图位置差几个像素（极少数机型） | 截图网格与触摸网格不重合。PC 连好手机后执行 `python -m lvjiang.core.android.calib -s <序列号> probe --apply` 自动标定 |
| 「连接设备失败 / 无法获取设备分辨率」 | 重插数据线、手机端撤销后重新授权 USB 调试 |
| 「scrcpy 截图后端不可用」 | 程序已自动回退 screencap，可继续使用；想用视频流可重启程序重试 |
| 预览「截屏失败」 | 投屏窗口被关闭或设备掉线，重新扫描并定位/连接 |
| 「请先停止当前任务」 | 运行中不能重新扫描窗口/设备，先按 F10 停止 |
| 端游窗口点击无效 / 键盘无响应 | 先核对连接方案及权限：预置「端游」方案在 Windows 上要求管理员权限；自定义方案应与目标游戏进程的实际权限匹配。若游戏以管理员身份运行，请也以管理员身份启动律匠 |
| 启动时提示「当前布局画布区域尺寸不符合预定义要求」 | 画面形态与布局对不上——端游全屏要用「端游全屏」方案、窗口模式用「端游」，设备布局要求 20:9。提示里会给出当前画布尺寸、实际比例和允许误差，照着换方案即可；自定义布局可在场景管理「编辑」里改画布尺寸要求 |
| 「开始执行」变灰显示「方案不支持」 | 当前连接方式不在方案声明的模式里。最常见的是选了「端游」却去点「扫描设备」。切到匹配的方案（手游 = ADB，端游 / 端游全屏 / 手游投屏 = 窗口），或在方案设置里补勾模式 |
| 该选哪个方案 | 手机/模拟器走 ADB 选**手游**；PC 端游窗口选**端游**；投屏或模拟器窗口走窗口截图选**手游投屏**。见 [2.4 连接方案](02-main-interface.md#24-连接方案) |
| 图库 / 环境 / 布局三个下拉框点不动 | 正常。选中方案后这三项由方案锁定，想手动调就把方案切回 `- 自定义 -` |
| 预置方案改不了 / 删不掉 | 「手游」「端游」「端游全屏」「手游投屏」随安装包下发，本地改了下次升级也会被覆盖。需要别的组合请用「从当前组合新建」建自己的 |

## 9.2 识别问题

| 现象 | 处理 |
|------|------|
| 识别不准 / 点击位置偏移 | 先确认方案选对了——图库/环境/布局配错时坐标会整体偏移且不报错；再见[场景管理](03.02-scene-management.md)坐标校准，用「工具 → 图像识别」确认 OCR 结果 |
| OCR 全部未识别到 | 确认截图是否正常（预览区查看）；检查场景区域坐标是否偏移 |
| 装备词条解析失败 / 装备「状态异常」带「!」 | 程序在提示某个词条读错了，不是崩溃。按 [3.2 自助排查：装备词条解析失败](03.02-scene-management.md#自助排查装备词条解析失败) 用自己机器的截图跑「识别全部字段」，分清是区域框、截图质量还是 OCR 误读 |
| 面板网格校准失败 | 面板区域可能不在当前画面内，检查场景编辑器中面板定义 |

## 9.3 调律问题

| 现象 | 处理 |
|------|------|
| 调律没反应就结束 | 查看运行日志：常见为未选规则/部位/玩法，或材料不足触发了「结束全部调律」 |
| 装备被意外回收 | 查看[调律说明文档](04.06-running-tuning.md#465-调律说明文档)中的判定依据，定位是哪条处置规则生效 |
| 装备没进调律 | 检查扫描处理的进入门槛是否设太高；用「装备调律验证」手动测试判定 |
| 重置调律没生效 | 每件装备单次运行只重置一次（受重置冷却期约束） |
| 规则判定结果不对 | 先在「装备调律验证」对话框手动输入词条测试，确认规则逻辑 |
| 「跳过实际调律」开关忘关 | 到调律 Tab → 参数页取消勾选，状态会随会话持久化 |

## 9.4 批量任务问题

| 现象 | 处理 |
|------|------|
| 日志提示「暂无启用的单元」 | 到批量 Tab → 「单元」页勾选要执行的单元（原文：[批量] 暂无启用的单元，请到「单元」页勾选） |
| 「请至少勾选一个脚本」 | 到批量 Tab → 脚本页勾选要执行的脚本 |
| 条目准备失败跳过整行 | 检查条目准备工作流是否正确配置；查看运行日志中 `[批量]` 前缀的错误信息 |
| 脚本执行失败 | 查看运行日志定位具体脚本和异常信息；结果文件在 `config/session/output/` |
| 提示“用户未配置账号名/角色名/角色序号/账号尾号” | 到「用户管理」为该用户填写 `account`、`role`、`role_index`、`tail`，详见[四个属性的配置说明](03.04-batch-tasks.md#内置-prepare_itemwf-需要的四个属性) |
| 用户没有切换 | 确认批量配置选中了正确的内部用户，并检查该用户的 `account` 和 `tail` 属性；`tail` 应能匹配账号选择列表中的可见文字 |
| 进入了错误角色 | 检查该用户的 `role_index` 是否对应角色列表位置，`role` 是否为游戏内显示的角色名 |

## 9.5 装备数据与毕业率问题

| 现象 | 处理 |
|------|------|
| 扫描后装备面板没有数据 | 确认运行前选择了正确用户；分别运行“扫描备战装备”和“扫描全部装备” |
| 真实装备识别错误 | “养成”只记录转律、承音和数值提升，不能校正既定属性；请修正布局/OCR 后重扫，或先复制为模拟装备校正 |
| 模拟装备没有进入最优组合 | 未穿戴模拟装备当前不会自动进入候选；先穿到当前方案并关闭“排除模拟” |
| DPS/毕业率显示 `--` | 选择用户、流派、角色基础属性和毕业率方案，确认当前流派已导入方案 |
| 毕业率明显偏高 | 关闭满承音、满定音、满等级，核对基础属性是否由同一套装备反推 |
| 换装后毕业率不可信 | 重新核对角色基础属性、弓玦和毕业率方案，详见[5.4](05.04-base-attributes-and-graduation.md) |
| 最优组合提示某部位无候选 | 放宽装备页等级/词条筛选，检查流派主副武器类型和规则取消勾选项 |

## 9.6 其他

| 现象 | 处理 |
|------|------|
| 程序启动报错 | 确认 Python 版本 ≥ 3.10；确认已 `pip install -e ".[dev]"` |
| 插件未加载 | 启动命令需加 `-reg yysls` 参数加载燕云调律插件 |

## 9.7 工作流问题

| 现象 | 处理 |
|------|------|
| 日常下拉找不到某个工作流 | 「工具 → 脚本编辑 → 脚本配置」中检查该脚本是否勾选「暴露」 |
| 工作流执行卡住 | 点击「暂停」查看运行日志定位卡在哪一步；必要时 F10 停止 |
| 工作流参数不生效 | 确认已点「加载」按钮刷新参数面板；部分参数由专属页面管理（如调律） |
| 江湖号令识别不到任务 | 检查是否停在正确的活动页；用「工具 → 图像识别」确认 OCR 结果 |

## 9.8 常见误操作

| 误操作 | 后果 | 解决 |
|--------|------|------|
| 源码版启动时忘记加 `-reg yysls` | 没有燕云调律插件，左侧没有调律 Tab | 重启并加上参数；`dev.bat` / `dev.sh` 同样不默认加载，需要一起传 `-reg` |
| 布局选错 | 点击偏移、识别失败 | 顶部「当前布局」下拉切换，见 [1.4 布局适配](01-quick-start.md#14-运行前检查布局适配) |
| 游戏没停在正确页面就启动工作流 | 工作流第一步就失败 | 查看工作流清单中的「前置」要求，停在对应页面再启动 |
| 发行版 exe 被安全软件拦截 | 无法启动 | 将安装目录加入安全软件白名单，或重新安装时选「仅为当前用户」 |
| 预置「端游」方案拒绝启动 | Windows 上未满足方案声明的管理员权限要求 | 右键 `lvjiang.exe` → 「以管理员身份运行」，详见 [1.1 环境要求](01-quick-start.md#11-环境要求) |
| 调律 Tab「跳过实际调律」忘记关 | 只模拟不实际调律 | 调律 Tab → 参数页 → 取消勾选 |

## 9.9 术语速查

| 术语 | 含义 |
|------|------|
| **ADB** | Android Debug Bridge，安卓调试桥，用于电脑与手机通信的协议 |
| **USB 调试** | 手机开发者选项中的开关，允许电脑通过 ADB 控制手机 |
| **投屏** | 将手机画面实时显示到电脑窗口的技术 |
| **OCR** | 光学字符识别，从截图中读取文字的技术 |
| **布局** | 定义游戏界面各区域坐标的配置方案，不同分辨率可能需要不同布局 |
| **连接方案** | 图库 + 环境 + 布局 + 支持的连接方式的具名组合。内置手游 / 端游 / 端游全屏 / 手游投屏四个预置方案 |
| **场景** | 游戏的一个界面（如背包页、调律页），包含多个区域定义 |
| **工作流 / 脚本** | 自动化流程定义，描述「扫描 → 识别 → 决策 → 点击」的步骤序列 |
| **DSL** | 领域特定语言，律匠自研的 `.wf` 工作流语法 |
| **Profile** | 用户数据档案，记录角色的货币、进度、调律历史等信息 |
| **调律** | 游戏中的装备重铸机制，消耗材料随机刷新词条 |
| **定音** | 调律的一种特殊形式，锁定特定词条进行重铸 |
| **品阶** | 装备品质，如金、紫、蓝、绿 |
| **流派规则评级** | 对单件装备词条组合给出的顶级、优秀、一般、垃圾等结论 |
| **毕业率** | 当前完整战斗属性的 DPS 相对所选方案 100% 基准 DPS 的比例 |

## 9.10 反馈渠道

正式提交问题前，先完成 9.1-9.9 的自查。反馈入口和支持范围见
[README — 反馈与支持](../../README.md#-反馈与支持)（仅源码检出）。

本章说明哪些反馈会进入开发者排查、提交问题时必须提供哪些信息，以及哪些内容不属于项目支持范围。

> “受理”表示问题具备排查条件，并不代表已经确认是程序缺陷，也不代表承诺修复时间或发布日期。

| 反馈内容 | 推荐渠道 |
|----------|----------|
| 可复现的程序缺陷 | GitHub Issue |
| 功能建议、需求边界讨论 | GitHub Issue |
| 文档过时、步骤无法执行 | GitHub Issue |
| 使用交流、一般咨询 | 微信交流群 |
| 一对一教学、远程配置 | 不提供 |

GitHub Issue 是正式问题记录。交流群中的聊天不会自动进入开发者排查队列；如果讨论后确认可能是程序问题，仍需按本章要求整理并提交 Issue。

主窗口「帮助 → 反馈」打开一份精简版的本章内容（必备信息清单、受理范围、隐私遮盖提醒），
底部三个按钮分别是「扫码加群」「查看详细规范」（跳转本章）「提交 GitHub Issue」。

二维码不再随安装包预置。「扫码加群」优先读取
`config/session/feedback-qrcode.jpg`；没有缓存时在后台从站点下载。
「刷新二维码」重新获取最新图片，失败不会删除已有缓存；首次下载失败会提示
无法访问的 URL 和检查网络。缓存随客户端目录一起移动。
手机工作台的反馈联系页面也默认读取缓存，可点击「刷新二维码」获取最新图片；
刷新失败仍展示缓存并说明网络原因。

在线配置的官方基底身份位于 `config/session/baseline.json`。从旧版本升级应使用
完整 ZIP 或安装器，不要仅替换可执行文件：打包流程会提供新基底身份，安装器会
清理旧的 `config/system-baseline.json`。记录缺失或损坏时仍可运行当前磁盘配置，
但会跳过在线更新；请重新解压或安装完整应用，并保留自己的 local/session 数据。

提交前请先搜索已有 Issue，并查阅本文 9.1-9.9 的常见问题。同一个问题只提交一个 Issue，不要在多个渠道重复催促。

## 9.11 Bug 的受理条件

Bug 必须同时满足以下条件：

1. 问题发生在当前版本明确支持的系统、运行环境和功能中。
2. 使用官方发行包或未修改的源码能够复现；修改过源码、系统工作流或布局时必须主动说明。
3. 提供了明确的前置页面、复现步骤、预期结果和实际结果。
4. 提供了版本、环境、布局和输入链路等必要信息。
5. 提供了足以覆盖异常现场的连续日志；视觉或点击问题还应提供截图或录屏。

缺少关键信息的问题会被标记为“等待补充”，在信息补齐前不进入代码排查。能够受理不等于一定修复：最终还要判断是否为重复问题、配置错误、游戏更新、上游依赖或项目缺陷。

## 9.12 标题和问题摘要

标题应同时包含问题类型、运行环境、相关功能和具体异常。例如：

```text
[Bug][Android/安卓布局][扫描全部装备] 扫描防具后意外退出装备页
```

不要使用“不能用”“出错了”“有 Bug”等无法检索和区分问题的标题。

正文开头用一两句话说明：在什么环境运行什么功能，本来应该发生什么，实际发生了什么。

## 9.13 必须提供的环境信息

所有 Bug 都要提供：

- 律匠版本号。
- 发行版或源码版；源码版同时提供 `git rev-parse --short HEAD` 的结果。
- 电脑操作系统和版本。
- 游戏客户端版本、界面语言，以及是否调整过游戏 UI 缩放。
- 律匠中选择的运行环境：`android` 或 `desktop`。
- 当前布局名称，布局是否经过本地修改或屏幕标定。
- 是否修改过 `config/system/` 下的工作流、场景或布局。

Android、模拟器或 ADB 环境还要提供：

- 手机或模拟器名称及 Android 版本。
- 游戏画面分辨率和横屏/竖屏方向，例如 `2800×1260，横屏`。
- 连接方式：USB ADB、无线 ADB 或模拟器 ADB。
- 截图方式：静态截图 `screencap` 或视频流 `scrcpy`。
- 输入方式：`adb shell input` 或设备端执行。
- 日志是否提示截图或输入通道发生了自动回退。

Desktop 环境还要提供：

- 目标是端游窗口、手机投屏窗口还是模拟器窗口。
- 目标窗口分辨率、Windows 显示缩放比例和是否以管理员身份运行。
- 使用前台光标输入还是后台输入。

## 9.14 必须提供的复现过程

请按实际发生顺序描述：

1. 开始前游戏停留的页面，以及必须完成的前置操作。
2. 在律匠中选择的用户、布局和环境。
3. 执行的工作流或功能名称。
4. 使用的全部参数和相关开关。
5. 从开始到异常发生的每一步操作。
6. 实际结果和预期结果。
7. 每次必现、偶发，还是只发生过一次；如为偶发，请给出大致频率。
8. 最近一个确认正常的律匠版本或时间点，如果知道。

不要只提交最终错误弹窗。自动化问题往往由更早的页面识别、导航或配置选择导致，需要保留完整上下文。

## 9.15 日志、截图和其他证据

程序日志按日期位于：

```text
logs/lvjiang_日期.log              # 当天
logs/logs/年月/lvjiang_日期.log    # 最近 7 天内的更早日期，下次启动时归入；再早的会删除
```

崩溃现场位于：

```text
logs/crashes/
```

工作流结果通常位于：

```text
config/session/output/<用户>/YYYY-MM/DD/
```

普通问题至少提供从本次任务 `[开始]` 之前到异常发生之后的连续日志，不要只复制最后一行。

| 问题类型 | 还需提供 |
|----------|------------|
| 崩溃、闪退 | 完整 traceback、对应日期日志、`logs/crashes/` 中的现场文件 |
| OCR 或识别错误 | 未裁掉上下文的原始画面、OCR 实际结果、预期文字、布局和分辨率。提交前请先按 [3.2 自助排查：装备词条解析失败](03.02-scene-management.md#自助排查装备词条解析失败) 跑一次「识别全部字段」并附上输出 |
| 点击偏移或错误导航 | 异常发生前后的录屏、实际点击位置、预期位置和完整运行日志 |
| 工作流执行错误 | 工作流名称、全部参数、开始至结束日志、相关输出 JSON |
| 装备规则或计算错误 | 原始装备/属性、启用的规则和方案、实际结果、人工预期结果 |
| ADB 连接问题 | 连接方式、截图/输入方式、设备状态及相关 ADB 日志 |
| 性能问题 | 操作数量、至少三次耗时、电脑/设备配置及是否使用视频流截图 |

误点击、误回收、错误购买、数据损坏或自动化越过确认页面属于高风险问题。发现后应立即停止任务并保留现场，不要求为了复现再次承担损失风险。

## 9.16 隐私与脱敏

公开提交前请遮盖：

- 游戏账号、角色名和其他可识别身份的信息。
- ADB 设备序列号。
- 本机用户名及不相关的本地绝对路径。
- Token、Cookie、密钥、验证码等凭据。

脱敏时不要删除日志时间、日志级别、调用顺序、错误栈或关键参数。不要直接上传整个 `config/session/`：其中可能包含用户名称、装备数据和执行结果；`config/local/telemetry/` 同样不要打包上传。开发者确实需要某个配置或数据库时，会说明具体文件和脱敏要求。

以上是**你**提交反馈时需要遮盖的内容。反过来，**律匠自己**会上传哪些数据、如何关闭，见[隐私说明](../../PRIVACY.md)（仅源码检出）——两者遵循同一条边界。

## 9.17 功能建议与文档问题

功能建议不要求异常日志，但至少要说明：

- 真实使用场景和当前操作方式。
- 当前痛点及发生频率。
- 希望达到的结果。
- 不能改变的现有流程或兼容边界。
- 适用的环境、布局和用户范围。

只写“增加某功能”而没有使用场景的建议可以讨论，但不会直接进入开发计划。

文档问题请提供文档链接和章节、当前文字、实际操作结果以及建议修正内容。

## 9.18 不在受理范围的内容

以下内容不作为项目 Bug 排查：

- 一对一使用教学、远程协助安装配置或逐步陪同操作。
- 没有版本、环境、复现步骤和日志的笼统反馈。
- 未执行用户指南和常见问题中基础排查步骤的已知误操作。
- 已在当前版本修复、且无法在当前版本复现的问题。
- 第三方脚本、插件、非官方安装包或本地修改导致的问题，且无法在干净版本复现。
- 数据线、网络、ADB 未授权、游戏服务器或安全软件自身造成的问题。
- 当前文档或界面明确标记为“不支持”的功能；可以改为提交功能建议。
- 实验性/Beta 功能的稳定性保证；可以提交测试反馈，但不承诺按正式功能的优先级处理。
- 封号、游戏资产损失以及违反游戏用户协议造成的后果。
- 反作弊绕过、进程注入、读取游戏内存等需求。
- 商业使用、商业部署或商业授权请求。

如果 README、用户指南、版本说明和界面对同一功能的支持状态描述不一致，可以按“文档问题”提交，注明所有冲突位置。

## 9.20 源码环境：采集卡顿现场

：采集卡顿现场

在运行律匠的电脑上安装独立诊断依赖，并在复现前指定律匠进程 PID：

```powershell
python -m pip install psutil py-spy
python scripts/diagnostics/python_process.py --pid 1234 --duration 180
```

默认报告存入 `config/local/diagnostics/` 的独立时间目录，不需要在主仓库提交。
记录进程与线程 CPU、内存、子进程、系统负载和 Python 栈；Ctrl+C 可提前结束。
Windows 抓栈通常需要管理员权限，失败原因会记录在报告中；`--no-stack` 仅采集资源。
抓栈可能短暂暂停目标。报告移除了进程启动命令，但仍可能含本地路径，分享前检查隐私。
同时说明卡顿发生的时间和操作，便于与采样对齐。
