# v0.12.0 — 布局体系与工作流治理升级

## 律匠 v0.12.0

> **发布状态：正式发布。发布日期：2026-09-14。** 本文以 v0.11.2 正式版为基线。

本版本包含布局 schema、目录身份和工作流发现规则的不兼容升级。升级前请务必阅读
下面的迁移说明；尤其是自行标定过布局、保存过场景截图或编写过 `.wf` 的用户，不能
直接沿用旧目录结构。

### ⚠️ 不兼容变动与升级指引

#### 1. `layouts.yaml` 直接切换为 schema v2，不提供自动迁移

- **现象：** `layouts.yaml` 现在必须声明 `schema_version: 2`。布局使用稳定 key
  作为目录名和持久化身份，名称只负责界面展示。系统布局 key 为 `android`、
  `android_cast`、`desktop`；原“默认布局”显示为“安卓布局”，原“继承布局”显示为
  “投屏布局”。旧版 `config/local/layouts.yaml` 及其中文目录不会被新版自动识别。
- **原因：** 旧结构把可修改的显示名称同时当作目录名和配置引用，重命名会连带破坏
  布局、模板和截图路径。schema v2 将稳定身份与显示文案彻底分离。
- **如何调整：** 升级前备份 `config/local`，升级时删除旧
  `config/local/layouts.yaml`，不要整份覆盖回新版。需要保留旧标定时，将
  `layouts/默认布局/`、`templates/默认布局/` 手动复制到对应的 `android/` 目录，
  将“桌面布局”目录复制到 `desktop/`。自定义布局应先在新版界面中创建唯一 key 和
  唯一名称，再把旧场景 JSON、模板复制到新 key 目录。场景编辑器底图同样需要将
  `config/session/screenshots/默认布局/` 和“桌面布局”分别迁移到 `android/`、
  `desktop/`。 `android_cast` 继承 `android`，通常无需单独复制实体文件。迁移后
  重新选择一次连接方案。

#### 2. 自定义 WF 必须声明是否可以运行

- **现象：** 工作流改为递归扫描后，不再根据“顶层文件”或 `standalone/` 目录推断
  脚本用途。缺少运行属性的自定义 `.wf` 不会出现在日常任务或批量任务列表中。
- **原因：** 目录现在只负责组织文件；脚本能否独立运行、能否加入批量任务，统一由
  文件头元数据明确约束，避免把子过程误当任务启动。
- **如何调整：** 在自定义脚本开头连续的 `#%` 元数据区加入
  `#% runnable: true`；需要进入批量候选时再加入 `#% batchable: true`，后者也隐含
  可独立运行。可选 `id` 允许以 Unicode 字母开头，并继续使用 Unicode 字母、数字和
  下划线，例如中文 id 合法。本次不扫描或改写用户脚本，请自行逐个补充元数据。

#### 3. WF 的 `env` 同时约束展示和执行

- **现象：** 声明了 `#% env: [android]` 或 `#% env: [desktop]` 的脚本，只在匹配的
  当前目标环境中显示；环境不匹配时也无法从批量任务等入口绕过校验启动。参数自身
  声明 `env` 后，也只在对应环境展示。
- **原因：** 元数据环境必须与脚本中的 `check_env` 具有相同语义，避免用户看到并启动
  明知无法在当前输入后端执行的脚本或参数。
- **如何调整：** 检查自定义脚本的 `env` 是否覆盖实际运行目标。跨端脚本可声明
  `[android, desktop]` 或省略 `env`；仅平台专用的参数应单独声明参数级 `env`。

#### 4. 系统预置 WF 不再允许删除

- **现象：** 脚本编辑器不再允许删除系统随包提供的工作流，也不再用墓碑文件隐藏
  系统脚本。
- **原因：** 删除系统内容会造成升级后脚本缺失或引用断裂；停用、复制到本地修改和
  调整任务配置已经能够覆盖正常定制需求。
- **如何调整：** 无需某个系统脚本时，请在任务配置中取消使用；需要改造时复制为
  自定义脚本并修改引用。不要继续依赖旧墓碑屏蔽系统文件。

#### 5. 鸣金虹木桩脚本路径调整

- **现象：** 系统脚本从 `standalone/stake_mingjinhong.wf` 移至
  `stake/stake_mingjinhong.wf`。直接保存旧路径的外部配置将找不到原文件。
- **原因：** 木桩测伤脚本统一收拢到独立的 `stake/` 分类，并由元数据决定是否可运行。
- **如何调整：** 将自定义配置或脚本中的旧路径替换为
  `stake/stake_mingjinhong.wf`。没有直接引用该路径的用户无需操作。

### ✨ 新增功能

- `click` 在 Android 触摸、设备端手势和 PC 鼠标输入上统一支持 `hold`，可写
  `click [scene].[target] hold 1.4`；`hold` 与 `after wait` 按顺序累计执行。
- 控制场景新增跨端战斗与移动视图，统一切换武器、奇术、技能按键和移动方向；鸣金虹
  木桩脚本合并桌面/Android 版本，并按环境展示对应参数。
- 工作流参数支持 `env`，默认跨环境展示，声明后仅在对应目标环境出现。
- 在线配置可新增实验性远程 `.wf`。远程脚本强制标记 `[远程]`、只读且不能覆盖同路径
  系统脚本，运行页会显示红色来源与行为安全警告。
- 脚本编辑、录制和元数据配置合并为一个工作台；低精度录制会无损压缩连续键盘时间线，
  小键盘按键按独立键码记录，工具区域可持续缩放而不会突然消失。
- “扫描全部装备”新增“最少词条数”参数。默认 `0` 保持原行为；设置为 `1～5` 后，
  普通词条不足的装备仍参与去重，但不会写入装备库，定音不计入词条数。
- 批量生命周期收尾统一由 `finish_item.wf` 处理，可选择退出登录页或直接停止 Android
  应用；旧花蕊织收尾路径会在读取批量配置时自动迁移。

### 🔧 修复

- 场景截图发现已有图片尺寸不匹配时会先截取当前帧、再请求确认，避免错误覆盖正确布局，
  也不会因确认对话框错过需要保存的瞬间画面。
- 修复失效的活动布局导致场景编辑器首次打开时截图和场景定义为空的问题。
- 恢复批量配置“单用户执行时跳过生命周期工作流”选项，并修复批量配置类型门禁。
- 暂停和结束操作会立即显示“暂停中”或“结束中”，引擎到达响应点后再切换正式状态。
- 单个 WF 元数据解析失败时只记录错误并忽略该文件，不再拖垮整个脚本列表；编辑器在
  显著位置提示元数据错误，并在编辑器失焦后校验，避免逐字符解析卡顿。
- 修复 Windows 调律配置编辑会话重复转换 CRLF、导致保存后 YAML 每行多出一个空行。
- 调律规则“玩法设定”补齐副武器增伤词条列，主、副武器按同等地位展示。
- 会心小外更新通用条件：双最小属攻且带会心/精准判垃圾；双最小属攻但不带会心/精准
  判一般；单条最小属攻不再单独降档。
- 数据模型变动规则行高收紧，倍率输入取消不必要的上限。

### 📦 重构

- 布局持久化身份与显示名称分离；布局、模板和截图统一使用稳定 key。
- 工作流发现改为递归扫描和 front-matter 元数据驱动；脚本 id、运行属性、环境及参数
  约束由同一解析和校验链路处理。
- 系统预置布局的战斗、移动区域从游戏主页迁移到通用控制场景，减少跨布局重复定义。
- 批量登录页恢复过程收敛到公共子过程，花蕊织不再维护专用的重复启动/收尾脚本。
