# 图色函数 — 取色 / 色占比 / 亮段 / 色心方位 / 同色图标 / 多点找色

> Layer: L7（DSL 合同）· Stability: stable · 实现：`src/lvjiang/workflows/builtins/vision.py`
> → `src/lvjiang/core/recognizers/color_ops.py`（纯 numpy，可用截图文件离线回归）

游戏 UI 不在无障碍树里，"现在是哪个界面"只能靠画面判。OCR 慢且对图标无能为力，
这组函数用颜色统计做**毫秒级状态判定**，是 `scan`/`find` 之外的第三条感知通道。

## 公共约定

- **坐标入参**：`$ref = [scene].[region]`（RectCoordRef）、`[scene].[point]`（CircleCoordRef）或
  `find` 产出的 FoundRegion。点退化为零面积矩形；圆取外接正方形。函数实参不接受 `[scene].[region]`
  字面引用，先赋给变量。
- **颜色**：一律 RGB `"#rrggbb"`，与截图工具取色一致（内部帧是 BGR，不用管）。
- **距离/尺寸参数归一化**：`color_vec` 的环带半径、`find_icons` 的面积/bbox 门槛按**画布高**比例；
  `find_multi_color` 的偏移 `dx/dy` 按**画布宽**比例。按像素调出来的阈值换算：`px / 画布高`、`px / 画布宽`。
- **每次调用截一帧**并裁到布局画布；截图失败直接抛错（坐标全错，不能静默）。
- 这些是**内置函数**，写在 `eval` / `$x = …` / 条件表达式里，不是指令。

## 函数一览

| 函数 | 返回 | 用途 |
|------|------|------|
| `pixel($ref)` | `[r, g, b]` | 取中心点颜色 |
| `bright($ref)` | int 0–765 | 中心点亮度 r+g+b |
| `color_ratio($rect, "#rrggbb", tol)` | float 0–1 | 目标色 ± tol 的像素占比 |
| `color_ratio($rect, "#lo", "#hi")` | float 0–1 | 三通道各在 [lo, hi] 内的像素占比（非对称范围） |
| `bright_segs($rect, on_min, off_max)` | int | 沿区域中线数亮→暗跳变次数（页签栏有几段字） |
| `color_vec($rect, $center, c_lo, c_hi, margin [, channel, min_r, max_r, step])` | `{deg, count}` / null | 主导通道像素相对中心的合成方位角（小地图路线/朝向） |
| `find_icons($rect, channel, c_min, margin1 [, margin2, o_max, min_area, min_bbox, c_max])` | `[FoundRegion…]` | 同色连通块（位置不固定的图标），按面积降序，可 `click` |
| `find_multi_color($rect, "#anchor", [[dx, dy, "#c"], …] [, tol])` | FoundRegion / `""` | 按键精灵式多点找色 |

`channel`：`0`=red `1`=green `2`=blue，指哪一通道要**主导**（比另外两通道各高出 `margin`）。
对半透明叠加层（小地图路线、标记）比绝对 RGB 范围稳——底图混色时绝对值漂，
"绿远大于红蓝"这个关系不变。

## 状态判定写法

```
# 顶部 HUD 白字占比 ⇒ 在对局内
def in_match()
    $box = [hud].[status_text]
    return color_ratio($box, "#aaaaaa", "#ffffff") >= 0.03
end

# 主界面：右下绿色主按钮 + 底部页签 ≥ 4 段
def is_lobby()
    $btn = [lobby].[start_btn]
    $bar = [lobby].[tab_bar]
    return color_ratio($btn, "#008228", "#5affa0") >= 0.05 and bright_segs($bar, 300, 150) >= 4
end

# 结算页：绿「下一步」与主界面绿按钮同色，只能靠页签段数区分 ⇒ 派发顺序 lobby 先于 settle
def is_settle()
    $nxt = [settle].[next_btn]
    $bar = [lobby].[tab_bar]
    return not in_match() and color_ratio($nxt, "#00963c", "#78ffbe") >= 0.008 and bright_segs($bar, 300, 150) < 3
end
```

## 同色图标：位置不固定的地图标记

```
# 绿色主导 c_min=150 g-r≥35 g-b≥60 r,b≤190；minArea 120px²/minBbox 32px @1080p → 0.0101 / 0.0296
$map = [map].[canvas]
$icons = find_icons($map, 1, 150, 35, 60, 190, 0.0101, 0.0296)
if $icons is_empty
    log warn "未检测到目标图标"
    return -1
end
$first = $icons[0]
click $first
```

注意 spec 只在**对应界面**下有意义：主界面的绿色主按钮本身就是一大块绿主导色，同一
spec 会把它当图标命中。先判 `is_map_open()` 之类的界面状态，再 `find_icons`。

## 分辨率说明

`color_ratio` 是占比、`bright` 是单点 → 与分辨率无关（1080p 与 540p 实测数值一致）。
`bright_segs` 数的是亮暗跳变，缩放会合并细缝，段数略降（实测 21→18、10→7），阈值要留余量。
`find_icons` 的面积/bbox 门槛已按画布高归一化，跨分辨率可用。

## 与其他感知手段的分工

| 要回答的问题 | 用什么 |
|-------------|--------|
| 这块区域写着什么字 | `scan`（OCR） |
| 某段文字在画面哪里 | `find … by contains` |
| 某张小图在画面哪里 | `find … by image`（[04.3-find.md](04.3-find.md)） |
| 这块区域最像图库里哪一条 | `recognize`（ORB 分类） |
| 现在是哪个界面 / 按钮亮没亮 | 本页 `color_ratio` / `bright` / `bright_segs` |
| 同类图标都在哪 | 本页 `find_icons` |
| 小地图路线朝向 | 本页 `color_vec` |
