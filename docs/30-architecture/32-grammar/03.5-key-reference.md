# 按键名称与组合键速查

本文只说明 `press` 可以使用哪些物理键，以及组合键怎样书写。四种执行模式、
状态清理和等待子句见 [键盘输入](03.4-keyboard.md)。

## 组合键

使用 `+` 在一条指令中连接多个键：

```text
press "CTRL" + "C"
press "CTRL" + "SHIFT" + "S"
press "SHIFT" + "`"
```

执行时从左到右按下全部键，再从右到左释放。因此第三条在常见的美式键盘
布局下输入 `~`。同一个组合中不能重复写相同的物理键。

组合键同样支持其他模式：

```text
press "CTRL" + "A" hold 0.5
press "CTRL" + "SHIFT" down
press "CTRL" + "SHIFT" up
```

`up` 会先检查组合中的所有键都处于 DSL 按下状态，再逆序释放，避免只释放
一半后才报错。工作流异常或停止时，仍由按键状态注册表统一释放残留按键。

## 主键盘

| 类型 | 可用写法 |
|---|---|
| 字母 | `A`–`Z` |
| 顶部数字 | `0`–`9` |
| 功能键 | `F1`–`F12`；不支持 F13 以上 |
| 方向键 | `UP`、`DOWN`、`LEFT`、`RIGHT` |
| 编辑和导航 | `ESC`、`ENTER`、`SPACE`、`TAB`、`BACKSPACE`、`DELETE`、`INSERT`、`HOME`、`END`、`PAGEUP`、`PAGEDOWN` |
| 修饰键 | `SHIFT`、`CTRL`、`ALT`、`LSHIFT`、`RSHIFT`、`LCTRL`、`RCTRL`、`LALT`、`RALT` |
| 锁定及其他 | `CAPSLOCK`、`NUMLOCK`、`SCROLLLOCK`、`PRINTSCREEN`、`PAUSE` |

`SHIFT`、`CTRL`、`ALT` 默认指左侧按键。左右侧名称不会互相折叠。

## 标点物理键

标点键既可以写易读的物理键名，也可以直接写未按 Shift 时的字符：

| 键帽 | 物理键名 | 字符别名 |
|---|---|---|
| `` ` ~ `` | `GRAVE` | `` ` `` |
| `- _` | `MINUS` | `-` |
| `= +` | `EQUALS` | `=` |
| `[ {` | `LBRACKET` | `[` |
| `] }` | `RBRACKET` | `]` |
| `\ |` | `BACKSLASH` | `\` |
| `; :` | `SEMICOLON` | `;` |
| `' "` | `APOSTROPHE` | `'` |
| `, <` | `COMMA` | `,` |
| `. >` | `PERIOD` | `.` |
| `/ ?` | `SLASH` | `/` |
| ISO 附加键 | `OEM102` | 无 |

字符别名表示物理键，不会自动补 Shift。例如 ``press "`"`` 按下 Grave 键，
要得到 `~` 应写：

```text
press "SHIFT" + "`"
```

同理，`_`、`+`、`{`、`}`、`|`、`:`、`"`、`<`、`>`、`?` 都应使用
`SHIFT` 加对应的未换挡字符。最终产生哪个字符仍取决于操作系统当前键盘布局；
`press` 表达的是物理键，不是 Unicode 文本输入。

## 小键盘

| 类型 | 可用写法 |
|---|---|
| 数字 | `NUMPAD0`–`NUMPAD9`，兼容别名 `NUM0`–`NUM9` |
| 运算 | `NUMPAD_MULTIPLY`、`NUMPAD_ADD`、`NUMPAD_SUBTRACT`、`NUMPAD_DIVIDE` |
| 小数点 | `NUMPAD_DECIMAL` |
| 独立回车 | `NUMPAD_ENTER` |

## 全局热键保护

应用的开始、停止、暂停和录制热键可在 F7–F12 中配置。Windows 前台
`SendInput` 产生的事件会进入应用自身的全局键盘钩子，因此 `press` 在执行前
会读取当前热键配置：组合中只要包含任一当前保留热键，就拒绝注入并明确报错。

Windows 后台 `PostMessage` 只把消息投递给目标窗口，不会触发全局钩子，允许
发送同一个功能键。由此，F9–F12 并非永久禁用；是否受限取决于当前热键配置和
输入后端。

## 移动端限制

ADB 和设备代理可以映射多数普通键及标点键，但 Android `input keyevent` 不是
真正的桌面键盘按下/释放模型，组合键不保证与 Windows 一致。设备端无障碍和
Shell 后端只承诺 `ESC`、`HOME` 等系统全局动作。需要可靠组合键的工作流应限定
在 Windows 桌面输入环境运行。
