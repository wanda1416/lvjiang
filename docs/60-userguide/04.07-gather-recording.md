# 采集录制（实验性）

从「燕云 → 采集录制」建立路线，再从主界面第四个「采集」页执行。
它独立于脚本录制和地图编辑，当前提供 Windows 桌面的标记采集，单轮运行。
智能扫描和多人刷新循环尚未开放。

## 录制路线

1. 定位游戏窗口，选择桌面游戏环境和对应布局。
2. 手动传送到固定起点，打开所需资源的采集地图，选择单人或多人页。
3. 打开采集录制，填写路线名称和起点说明。起点说明应包含传送点、资源、地图页。
4. 确认开图键、自动识途键、采集键、识途超时及采集动作等待。默认分别为 `M`、`V`、`1`，要求已具备采集马。
5. 点击「开始选点」，回到游戏点击第一个采集点，按 **F1** 确认刚才的点击。
6. 按 **F2** 试跑：程序选择识途；若出现确认框，选择「识途直达」。到达判定通过后
   触发采集，等待动作时间，再打开地图。成功后该点加入录制草稿，并继续监听下一次选点。
7. 重复点击、F1、F2。完成后点击「结束选点」，再「保存路线」。

F1/F2 可在录制器中改绑；它们在选点期间注册为系统全局热键，只要主程序连接仍有效即可触发。
这些按键可能同时传给游戏，应选择没有游戏内冲突的键位。
地图位置依赖上一步的实际到达位置，录制过程中不要拖动地图或改变缩放。
窗口定位及连接有效性由主程序统一管理。列表支持撤销末尾点；不支持任意重排步骤。
撤销末尾点后，继续录制前需要先回到剩余路线的末点。

## 执行路线

回到录制起点，恢复相同布局、地图缩放和资源筛选，在「采集」页选择路线和执行用户。
按 **F9** 或「开始采集」启动，**F10** 停止，**F11** 暂停/恢复；修改过任务热键时
以界面显示为准。试跑也使用这套任务控制，录制窗口不会阻挡主窗口操作。
暂停或停止会阻止程序后续操作；游戏已经发起的自动识途可能继续，需要在游戏内手动取消。

每步先核验地图视口再点击；视口不符、识途失败或到达超时会停止整条路线。
此时不能直接从下一点继续，需恢复起点后重新启动。终点不会自动回到起点。

运行日志和任务历史会记录当前步骤、识途确认、到达、采集按键及失败原因。
执行时使用启动瞬间的路线副本，之后修改或保存路线不会改变正在运行的任务。
打开或编辑另一条路线也不会改变采集页当前选中的路线。

## 实验性限制

到达使用「主页操作区恢复、实景连续稳定、最短等待」的组合判断，行程时间只作为参考。
这不是世界位置验证，仍可能受到角色卡住、镜头和待机动画影响。识途超时会报错，
不会因为等够时间就当作到达。采集后当前使用设定的动作等待，**按键已执行不代表
产出已核验**；若动作没有完成，应增大采集等待后重新录制验证。

默认识别区域位于「场景管理 → 采集地图」，可以随布局重新标定。
主页操作区依赖桌面 HUD 中的 `TAB` 和 `Num` 提示；修改游戏键位或界面布局后需确认识别。
当前已完成离线截图识别和自动化回归，运动过程、卡住场景及连续采集仍待 Windows 真机验收。
