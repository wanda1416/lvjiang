# v0.13.5 — DSL 条件语义类型化、参数依赖与可选插件拆分

> 本文以 v0.13.4 正式版（提交 `11a8a705`）为基线。

本轮把 DSL 的条件判断从「靠真值性凑合」改成按类型判等，补上参数之间的依赖声明，
并把采集功能拆成可选的高级插件。**自行编写过 `.wf` 的用户请重点阅读不兼容变动
第 1～5 条**，其中几条会改变已有脚本里判断分支的走向；**使用免安装版的用户请看
第 7 条**，本次升级需要解压到新目录。

## ⚠️ 不兼容变动与升级指引

### 1. `== null` / `!= null` 从恒定结果变成真正的判空

- **现象：** `if $x != null` 此前**永远成立**，现在只在 `$x` 确实有值时成立；
  `if $x == null` 此前**永远不成立**，现在可以正常判空。依赖这两种写法的分支，
  走向会改变。
- **原因：** 相等比较此前只处理「两个字符串」和「两个可转数字」，其余一律落进
  「不可比」并返回不相等。`null` 没有数值形态，于是 `== null` 恒假；而 `!=` 是
  `==` 的取反，于是恒真。随包工作流里 `purchase_niaoniao.wf` 的两处无记录兜底
  就因此从未执行过。
- **如何调整：** 搜索自己的 `.wf` 里的 `!= null` 与 `== null`，确认每个分支的
  语义仍是你要的。此前靠「`!= null` 恒成立」当作无条件分支使用的写法需要改写。

### 2. 布尔可以直接比较，且只与布尔相等

- **现象：** `$flag == false` / `$flag != true` 此前分别恒假、恒真，现在按真实
  取值判断；`$flag == 1`、`$flag == "true"` 仍然为假。
- **原因：** 数值换算刻意不把布尔当数字（Python 中 `bool` 是 `int` 的子类，不拦
  就会让 `true == 1` 成立），但此前没有为布尔补上相等分支。
- **如何调整：** 真值写法 `if $flag` / `if not $flag` 一直是对的，无需改动。
  此前写了 `== true` / `== false` 而「一直没生效」的脚本，现在会真正生效，请确认
  这正是你要的。拿布尔和数字比较的写法需要改成布尔字面量。

### 3. `is_empty` 不再把 `0` 和 `false` 当成空

- **现象：** `if $count is_empty` 在 `$count` 为 `0` 时不再成立；`false` 同理。
  `null`、空白字符串、空列表与空字典仍然算空。
- **原因：** 此前实现是 Python 真值性取反，把「值为零」和「没有值」混成了一件事。
- **如何调整：** 三种「空」现在各有专属写法：判无值用 `== null`，判有串没内容用
  `is_empty`，判零用 `== 0`。此前依赖「0 算空」的脚本需要改成 `== 0`。

### 4. `in` 改用类型判等，`contains` 右侧不能为空

- **现象：** `$zero in [0, 1]`、`$flag in [false]`、`$empty in [""]` 此前恒为假，
  现在按值判断；`$x contains ""` 现在是解析错误，工作流加载即失败。
- **原因：** 成员判断此前先做真值性守卫，左侧只要是假值就直接返回不匹配；空的
  查找目标则会让 `contains` 恒真，属于写错而不是有效条件。
- **如何调整：** 依赖「假值一律不匹配」的写法需要改写。`contains` 的查找文本改为
  非空常量或确有内容的变量。

### 5. 布尔参数默认值只接受 `true` / `false` / `1` / `0`

- **现象：** `.wf` 头部写 `default: 'yes'`、`'no'`、`'on'`、`'off'` 的布尔参数，
  加载脚本时报元数据错误。
- **原因：** 这四种写法既不是 DSL 字面量，也不是 YAML 或 JSON 的布尔写法；此前
  元数据校验接受八种、而参数面板只认其中四种为真，同一个值在不同入口结果不同。
- **如何调整：** 改成 `true` / `false`（推荐）或 `1` / `0`。随包工作流没有用过
  这四种写法，仅影响自写脚本。

### 6. 采集相关能力改为可选的高级能力

- **现象：** 采集页、录制菜单与 `auto_gather` 工作流不再随主程序提供；随包配置里
  的地图资料（采集地图、中原地图及其桌面布局）与「风沙酒肆」脚本一并移除，脚本
  列表和场景列表中不再出现。
- **原因：** 采集相关能力拆分为可选插件，按插件注册机制加载，不再属于默认功能集；
  只服务于这些能力的场景、地图与脚本随之移出随包配置。
- **如何调整：** 不使用采集功能则无需任何操作；需要这些功能请使用提供该能力的
  高级版本。自己基于地图场景写过脚本的用户，需要改用自己的场景定义。

### 7. 便携版升级请解压到新目录

- **现象：** 免安装 ZIP 就地覆盖解压后，可能出现重复的脚本条目（同一个脚本 id 有
  两份文件，编辑器标红冲突，日常列表只显示其中一份）或早该下架的场景仍在列表里。
- **原因：** 随包分发的 `config/system` 在用户侧是只读出厂数据，但 ZIP 由用户自行
  解压，没有任何一方能删除上一版遗留、而新版已经删除或移动过的文件。本版起安装器
  与安卓 APK 都会在升级时先清空该目录再铺新的，唯独便携版做不到。
- **如何调整：** 免安装版请解压到**新目录**，再把旧目录的 `config/local`（自己的
  配置）与 `config/session`（账号、装备库、历史记录）拷过去。使用安装程序或安卓
  APK 升级的用户无需任何操作，残留会被自动清理。

### 8. 弓玦按方案实际生效等级计算，赛季默认等级改为 115

- **现象：** 没有记录弓玦等级的方案，其毕业率与 DPS 会变化——按南吕相和的新默认
  等级 115 计算，会心弓玦由 7.00% 升到 8.10%，会意由 3.50% 升到 4.00%，精准由
  6.20% 升到 7.20%。此外**已保存的角色基础属性仍按旧口径反推**（写入时
  `基础 = 面板 − 装备 − 弓玦`），计算时再按新口径加回更大的弓玦，总属性会被高估。
- **原因：** 游戏内弓玦已随更新升到 115，赛季配置此前仍按 110；同时弓玦加成改为
  优先使用方案自己记录的生效等级，会意弓玦按实测档位取值（110 为 3.5%、111–114 为
  3.75%、115 为 4.0%），其余类型仍按对应等级三率词条上限的一半，中间等级取相邻档
  中点。
- **如何调整：** 重新扫描一次备战装备，弓玦的实际生效等级会从弓玦详情写入方案；
  也可以在备战方案的战斗属性页直接填写（支持 113 这类中间值）。未设置的方案沿用
  赛季默认等级。角色基础属性同样需要重新扫描一次，按新口径覆盖旧值。

### 9. Profile 读写要求已绑定执行用户

- **现象：** 未绑定执行用户时调用 `profile_get` / `profile_set` 等函数，任务会
  明确失败并提示「Profile 操作缺少执行用户名」，而不是继续执行。
- **原因：** 此前未绑定用户时会回落到一个名为 `default` 的档案，数据被静默写到
  一个不属于任何人的地方。
- **如何调整：** 设备端在没有当前用户时先选定用户再启动任务。桌面端的日常与批量
  入口都会绑定用户，通常不受影响。

## ✨ 新增功能

- 工作流参数支持 `require` 依赖声明：条件成立时才在参数面板展示，语法与 DSL 的
  条件表达式完全一致（`$flag`、`not $flag`、`==`、`in [...]`、`and` / `or`，多条
  写成列表即全部满足）。引用的参数名、类型与比较值在加载脚本时校验，拼错会当场
  报错而不是让控件永远不出现。
- 随包工作流已应用该能力：`scan_role_base_attr.wf` 的目标方案与主副武学只在勾选
  「静默写入备战方案」后出现，`daily_jianghu.wf` 的「最大领取声望」只在勾选
  「领取奖励」后出现，`purchase_xinfa.wf` 的「最多打开数量」只在勾选「打开背包
  全部心法」后出现，两个条目准备工作流的「最大等待时间」只在关闭「角色在线跳过」
  后出现。
- 新增 `workflows/lib/` 纯逻辑过程库：`collections.wf`（去重、展开、分块、分组）、
  `ordering.wf`（快排、合并、二分查找）、`numeric.wf`（最大公约数、前缀和）。这些
  文件只定义过程，不出现在脚本列表中，`import "lib/ordering.wf"` 后即可调用。
- 备战方案记录弓玦的实际生效等级：扫描备战装备时从弓玦详情写入，也可在战斗属性页
  手动填写，支持 113 这类中间等级；未设置的方案沿用赛季默认等级。会意弓玦改用实测
  档位取值，不再一律按词条上限的一半推算。
- 插件系统支持声明依赖的插件 ID 并按 ID 扩展菜单，缺少依赖时在注册阶段报错。
- 场景截图默认改用 WebP 保存，减少本地占用与同步体积。压缩影响到某个视图的文字或
  图标识别时，可在截图旁的「管理」里把该视图的新截图格式改回 PNG 再刷新；设置只
  作用于当前布局、场景和视图之后新抓的截图，已有截图不会批量转换，参考图库不受
  影响。
- DSL 新增 `game_attr` 内置函数查询游戏属性，首批提供 `season_name`（当前赛季
  名称）。判断页面是否停在本赛季界面时不必再把赛季名写死在脚本里，换季不用改脚本。
- 新增 115 级破竹·樽毕业方案。

## 🔧 修复

- 属性单元的条目准备补回四个登录参数：最大滚动次数、角色在线跳过、最大等待时间与
  准备时允许重启应用此前被写死，参数面板里的配置一律不生效。
- 属性单元的条目准备工作流配错时改为在开始前拦截并说明改法，不再等到运行中逐个
  单元抛协议错误、整批空跑之后才暴露。
- 按下停止不再被报成「条目准备违反返回协议」：停止请求会让工作流提前返回，此前
  被当成正常结束且无返回值，于是触发协议门禁并打印一屏堆栈。
- 生命周期工作流返回 `stopped` 时整个批量立即结束，此前只结束当前单元并继续驱动
  客户端跑完其余单元。
- 批次准备失败时补齐进度与报告记录，此前进度表全部停留在「待执行」。
- 任务历史中的跳过状态显示为中文，不再显示内部英文键。
- `collections.wf` 的 `unique` 现在能对 `false`、`null`、`0` 与空串去重；此前这些
  值因相等比较恒假而完全去不掉。
- 系数表与配套方案的同源判定改为「存在一份同源方案即视为一致」，某流派新增更高
  等级的方案时，仍在使用的旧等级系数表不再被误报为已过期。
- 升级不再留下上一版的随包配置：安装程序在覆盖安装前清空 `config/system` 与程序
  自带的运行库目录，安卓 APK 在升级后首次启动时先清空再解压。此前只覆盖同名文件，
  上一版删除或移动过的文件会一直留在机器上——脚本换了目录就变成两份同 id 条目，
  下架的场景与布局也会继续加载。两端都不动 `config/local` 与 `config/session`。
  便携版仍需手动处理，见不兼容变动第 7 条。
- 主页面的执行控件尺寸与布局统一，调律页、批量页与主控制区的按钮不再各有一套
  高度和边距。
- 批量线程退出后再释放引用，避免停止过程中偶发的资源竞争。

## 📦 重构

- 布尔字面文本的识别收敛到公共实现，元数据校验与两处参数面板此前各有一套互不
  一致的判断。
- 批量配置移除已废弃的单元可见性字段与分组模块，旧配置中的残留数据在读取时忽略，
  下次保存时移除。
- 采集功能改为按插件机制注册的可选能力，不再属于默认功能集；只服务于它的地图
  资料与脚本随之移出随包配置。

## 📚 文档

- 条件语法文档新增「相等比较的类型规则」表，逐类说明字符串、布尔、null、数字与
  不可比类型的判等规则，并写明 `is_empty` 与 `== null` 的分工。
- 元数据文档新增 `require` 一节：语法、静态校验范围、允许引用的参数类型，以及
  「只控制 UI 展示、不裁剪运行时参数」的边界。
- 补充插件系统的依赖声明与菜单扩展说明；同步用户指南中的功能与调律判定描述。
- 游戏机制登记与基础属性基线文档同步弓玦等级。
- 用户指南补充升级指引：安装版直接覆盖安装，免安装版解压到新目录再迁移自己的
  配置与账号数据。
- 场景管理文档补充截图格式说明；打包手册记录各分发通道的升级清理能力。
