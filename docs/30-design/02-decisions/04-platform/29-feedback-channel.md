# 反馈与建议：内置提交通道与网页管理控制台

> 状态：已实现（2026-11-19，基线 v0.15.17）。

## 1. 需求

原来的反馈只有一个口子：打开 GitHub 新建 Issue。「帮助 → 反馈」里那份对话框只是
规范摘要加三个跳转按钮，**用户必须先去 GitHub、注册/登录、再自己整理截图和日志**。
结果是大量反馈根本不会提交，或者提交时缺日志缺截图，来回追问几轮。

服务端（`lvjiang.wyxj.net`）已经存在，具备账号体系与 D1，因此把反馈做进客户端：

- 客户端内直接写、直接贴图、直接附日志，提交进数据库；
- 作者侧在网页端有管理控制台，按状态处置；
- 回复走邮箱（不做内置工单对话）。

## 2. 分类：反馈 ≠ Bug

分类是**分类标签**，不是受理门槛。默认类型是「功能建议」，不是「功能异常」：
反馈通道一开场就把提建议的人放在一张 Bug 表格前，是最容易劝退的做法。

| key | 展示名 | 是否显示「复现细节」 |
|-----|--------|----------------------|
| `suggestion` | 功能建议（默认） | 否 |
| `bug` | 功能异常 | 是 |
| `recognition` | 识别或点击不准 | 是 |
| `workflow` | 工作流或脚本问题 | 是 |
| `crash` | 崩溃或闪退 | 是 |
| `performance` | 卡顿或性能 | 否 |
| `account_sync` | 账号与同步 | 否 |
| `doc` | 文档问题 | 否 |
| `other` | 其它 | 否 |

「复现细节」（步骤 / 预期 / 实际 / 频率）**全部可选**：客户端不校验、服务端也不因
缺字段拒绝。唯一必填项是 **类型、标题、描述、邮箱**。

## 3. 身份：邮箱必填，登录可选

- 回复走邮箱，所以邮箱必填——没有邮箱等于「找到了问题也找不到人」。
- **匿名也能提交**：会话失效或未登录一律按匿名处理，不因此拦截；登录只让作者在
  控制台里多一条追问近路（`account_id` / `login` 快照）。
- 防滥用靠限流与体积上限，不靠强制登录：同 IP 5 条/小时、20 条/天，同邮箱
  5 条/天，单条请求 256KB。（Turnstile 在 PyQt 里没有浏览器环境，不可用；
  Cloudflare 的 JS Challenge 也不能开——同一个域上还跑着客户端账号通道。）
- 账号注销时账号名下的反馈一并删除；匿名反馈不属于任何账号，不受影响。

## 4. 证据：截图 10 张 + 日志尾部

- 截图：Ctrl+V 直接贴进描述框即成为附件（拦截图片 mime，不往正文插字节）；
  也可选文件。上限 10 张，客户端按「最长边 1920 → PNG → JPEG q85 → 缩边重试」
  压到 **≤700KB**，因为服务端单值上限是 900KB（D1 单行 1MB 硬线之下）。
- 日志：默认勾选附带最近一天的**尾部 2000 行 / 1.5MB 原文**，脱敏后 gzip，
  实际通常 100~200KB。截断会在文件头写明「已截断」，不静默缩小。
- 脱敏在客户端做（`core/feedback/redact.py`）：本机用户目录、Token/Cookie/口令、
  ADB 序列号、匿名统计 install_id → 占位符；内网 IP、工作流名、错误码与堆栈保留，
  去掉它们日志就没用了。
- 「预览」把将要上传的全部内容（含环境快照与日志前 40 行）摊开给用户核对——这是
  这套渠道的信任基础，比一句「我们会保护你的隐私」有用得多。

## 5. 上传协议：正文先落库，附件逐张补

10 张截图 × 700KB，一次性 base64 会到 11MB，弱网必然超时且失败要全部重传。

```
POST /api/feedback/submit   {类型,标题,描述,邮箱,fields,env,attachments:[清单]}  ≤256KB
  → {id, ticket}
POST /api/feedback/attach   {id, ticket, seq, 元数据, payload_base64}             ≤1.5MB ×N
  → {stored, received, declared}
```

- `seq` 上有唯一索引，服务端 UPSERT：**弱网重传不堆行**，补传同一份序列幂等。
- 清单（`attachment_declared`）与实际行数之差就是「哪几张没传上来」，控制台里
  直接显示 `附件 7/10`，不需要额外状态字段。
- `ticket` 是匿名方补传附件的凭据（服务端只存 `sha256`）；登录用户也可用会话。

## 6. 服务端与数据

`server/migrations/0024_feedback.sql`：

| 表 | 作用 |
|----|------|
| `feedback` | 一条反馈一行：分类、正文、`fields_json`、`env_json`、邮箱、状态、优先级、内部备注 |
| `feedback_attachment` | **1:N**：一条反馈 N 个附件，每个独立行、独立重试、`seq` 幂等 |
| `feedback_event` | 状态/优先级/备注的变更流水（谁、何时、从什么到什么） |
| `admins` | 「谁能进控制台」的唯一权威 |

附件存 D1 BLOB（客户端 gzip、服务端透明存 + `zipped` 标志，与文档通道同约定）。
不引 R2：压缩后的截图与日志尾部本来就落在 1MB 以内；将来真要传原始大图/录屏，
再加一列 `r2_key` 即可，`payload` 语义不变。

**没有定时清理任务**：删除只有控制台一个口子（二次确认），不做 cron、不留孤儿。

## 7. 管理员与控制台

三层身份，互不复用：

| 层 | 凭据 | 能做 |
|----|------|------|
| 作者/运维 | `ADMIN_TOKEN`（Worker secret，只在命令行与 `admin/` 桌面工具里用） | 一切；**唯一能授予/撤销管理员** |
| 管理员 | 会话 + `admins` 行 | 看反馈、改状态/优先级/备注、删除反馈 |
| 普通账号 | 会话 | 提交反馈 |

- 不往 `accounts` 加 `is_admin`：账号表只回答「能不能登录」，`admins` 只回答
  「能不能管理」。删一行就撤权，账号注销时随外键消失。
- 管理员**不能**在网页里给自己或别人授权——那会把一次会话泄露放大成永久提权。
  第一个管理员用 `POST /admin/admins/grant` bootstrap。
- 演示页在 `#/console`：左栏列表（状态/类型/关键词筛选 + 游标分页），右栏详情
  （正文、环境表、按需加载的截图、日志下载、事件时间线），顶部三个动作
  「复制邮箱」「写邮件」「复制为邮件正文」——回复走邮箱，不做内置对话。
- 控制台入口按 `POST /api/console/whoami` 显示；服务端才是权威（非管理员 403）。

## 8. 取舍与不做

- **不做用户端工单/回复**：回复走邮箱，用户不必为了看一条回复回来登录。
- **不做后台重发队列**：正文没成功时用户就在对话框前，「重试」比一个看不见的
  队列更可靠。草稿落 `config/session/feedback/draft.json`，提交成功即删。
- **不做截图打码编辑器**：只提示 + 预览，用户自己遮挡。加编辑器会把范围撑大。
- **不做匿名 captcha**：见 §3。
- 隐私说明（`PRIVACY.md`）与用户指南（FAQ 9.10）同步更新——PRIVACY 是联网行为的
  唯一权威，新增通道不写进去就是违约。
