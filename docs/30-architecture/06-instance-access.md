# 多实例与用户执行隔离

同一数据目录只允许一个实例持有配置实例锁。桌面入口在加载插件和初始化配置前
竞争 `config/session/.locks/configuration.lock`，持有至进程结束。
未取得锁的进程自动成为只读实例；`--read-only` 可主动选择此模式。
已有只读实例不自动升级，重新启动时再竞争主实例身份。

## 数据边界

“只读”现在只隔离少量当前实例选择，并禁止打开场景管理；其他数据正常写入。

| 数据 | 只读实例行为 |
| --- | --- |
| 当前用户、激活方案、布局、图库、环境及部分当前页面 | 仅当前实例内存生效 |
| `session.json` 其他配置与运行状态 | 正常持久化 |
| 场景管理 | 菜单点击提示无法打开；F3 静默忽略 |
| 聚合配置、图库、脚本、参考数据、调律配置 | 正常持久化 |
| 用户 Session、装备方案、档案 | 正常持久化 |
| 任务历史、调律历史、报告 | 正常记录，不区分实例身份 |
| 公告、更新检查、在线配置同步及应用 | 所有实例正常执行 |

SessionStore 使用 `READONLY_TRANSIENT_PATHS` 集中声明不落盘的子树。只读实例
写入混合节点时，白名单字段只更新本实例快照，其余字段仍在文件锁内基于最新
磁盘状态合并并原子落盘；`reload` 刷新可写状态，同时保留本实例临时字段。
新增 Session 节点默认可写，不能因为属于 `session.json` 就自动扩大只读范围。

只读判断只放在场景管理的两个入口：菜单点击显示“只读实例无法打开场景管理”，
F3 快捷键直接返回。场景管理器内部不感知实例只读状态，避免控件遍历和后续
状态刷新重新启用写操作。ConfigResolver 不区分实例身份，开发模式只决定写
system 还是 local。

## 用户执行锁

用户数据文件的规范化路径是当前用户身份：用户名目前不可重命名，也直接
作为持久化文件键。未来增加用户名重命名时，必须先引入稳定 ID 并迁移锁身份。
锁文件位于 `users/.lock/<身份摘要>.execution.lock`。同目录也收纳各用户 JSON
文件的短时写入锁；两类锁只是集中存放，锁文件和生命周期仍彼此独立。

单次与专用工作流在读取用户 Session 前取得锁，暂停、人工等待、停止收尾
均继续持锁，最终保存和历史收尾后释放。批量执行按条目获取用户锁，覆盖
prepare、脚本及 finish 阶段，不预占其他用户。用户绑定的编辑器执行还由
WorkflowEngine 提供执行锁兜底；没有绑定用户的纯工具调用不属于用户任务。

同一进程也检查占用，不能依靠操作系统锁的进程级重入行为。
执行授权经上下文显式传递，子调用复用，不允许其他 UI 操作借用执行权限。
**执行锁只防止同一用户重复进入任务，不是用户数据读写锁。** 用户档案、
Session 和装备的读取、编辑不申请执行锁，执行中仍然可以浏览和维护用户数据。
实际一致性由各仓储的短事务保证：装备在独立文件写锁内读最新值并原子替换；
档案由 SQLite 事务负责；Session 使用下面的增量 CAS。
装备读取只返回快照，不初始化磁盘文件；首次修改才创建持久化数据。
筛选、排序等界面状态独立存放于 `session.json` 的按用户划分的 UI 节点，
旧装备文件里的 UI 状态仅作兼容读取，不随浏览回写装备快照。
编辑器试运行使用每次唯一的临时脚本，运行结束清理，不能覆盖其他实例的源码。

锁文件保留不代表仍被占用。异常退出由操作系统释放锁，不能删除锁文件抢占。
不同数据目录独立；不同用户名并不保证是不同游戏账号，用户需要正确建立映射。
本机制不负责解决不同用户任务对同一桌面鼠标、键盘或设备的输入争抢。

## 用户 Session 的增量 CAS

SessionManager.load 返回与 dict 兼容的 SessionSnapshot，携带独立的加载基线。
save 比较当前内容和基线，在用户 JSON 写锁内重新读盘，递归合并变更字段：

- 未修改字段保留磁盘值；缺失字段不表示删除。
- 磁盘值等于基线：允许写入；等于目标值：幂等成功。
- 同字段出现不同修改：整次保存抛 SessionConflictError，不部分提交。
- 字典按字段合并，列表和标量整体比较，缺失和 null 区分。
- 成功后更新本快照基线，不替换运行字典及其嵌套对象引用。
- 不带加载基线的普通 dict 只允许新增或幂等写入，不能盲目覆盖已有值。

需要删除或读取最新值后修改时使用 update(username, mutator)：在短期文件写锁
内读取最新数据，执行显式修改并原子保存，不受任务执行锁影响。
DSL save()、正常完成自动保存使用同一增量保存实现，失败向调用方传播。
批量脚本在标记任务成功前保存 Session，避免保存失败却记录成功。

全局 `session.json.lock` 仍是短期文件写入互斥，与配置主实例锁、用户执行锁
职责不同。用户 JSON 同样通过临时文件加原子替换写回；物理整文件替换不等于
业务上的旧快照覆盖。
