# DSL 解析性能与行为一致性

> 状态：已实现（2026-10-09，基线 v0.13.14）。本地验证完成，远端 Windows CI 待提交后运行。

## 需求与边界

降低首次读取及编辑后重新解析工作流的耗时，同时保持既有 DSL 写法、指令含义与 AST 一致。共享解析入口服务执行引擎、静态检查与编辑器；文件和编辑器已有缓存继续保留。

不改变工作流导航、运行逻辑、配置及持久化格式。合法脚本的指令类型、参数、顺序、源位置一致。非法脚本继续拒绝，错误行列必须正确；Lark 的具体异常子类型不是 DSL 契约。

## 验收

- 对 system 工作流及本地可用的 local 工作流，比较改造前后完整 AST。
- 覆盖鼠标按钮、方向、按键状态、等待子句、引用、表达式与续行的现有回归。
- 校验非法语法的拒绝与错误位置。
- Ruff、mypy、文档门禁、配置版本检查与全量测试通过，并报告实际结果与平台限制。
- 历史等价验证归入一次性工具，不引入运行期双解析或回退缓存。

实现契约见 [DSL 架构](../../30-architecture/32-grammar/README.md)。

## 验收记录

2026-10-09 在 Linux 开发环境完成全量 Python 测试（3,435 项通过）、Ruff、受跟踪源码的 mypy、文档门禁、配置版本检查与 Android `compileDebugKotlin`（本机 JDK 21）。本机未跟踪的扩展存在独立 mypy 错误，因此 CI 范围的类型检查在仅含受跟踪源码及本次修改的临时副本执行，未改动该扩展。

以改造前提交为基线，65 个实际工作流和 91 个测试常量片段的 AST 对照无差异，7 个非法输入的拒绝结果与语法错误位置一致。该对照包括全部 dataclass 字段与源位置。远端 Windows CI 尚未执行；本地验证不代表已经验证 Windows runner。
