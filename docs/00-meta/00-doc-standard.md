# 文档规范

> 最后更新：2026-10-09（基线 v0.13.14）。

本文是文档体系与写作纪律的**唯一来源**。导航与层职责见
[文档中心](../README.md)；本目录的 [README.md](README.md) 只做索引与治理说明。

## 一、八层各管一段

| 层 | 只写什么 | 不写什么 |
|----|----------|----------|
| 00-meta | 文档规范、路线图与阶段快照、待办、平台推进计划 | 功能实现细节 |
| 10-game | 游戏客观机制与律匠的评价规格（人可读） | 实现细节；机器规则放 `config/system/yysls/` |
| 20-requirements | 需求、边界与验收标准 | 实现细节、操作步骤 |
| 30-architecture | 数据模型、DSL、引擎、场景、平台接入、运行期能力的实现与契约 | 需求动机、操作指引 |
| 40-development | 按日期归档的开发日志（决策、排查、踩坑） | 现行规格 |
| 50-releases | 各版本发布说明 | 现行操作方式 |
| 60-userguide | 安装、配置、运行的完整操作指引 | 源码路径、配置 key、DSL API、内部协议 |
| 70-agent | 外部 Agent 的发现、授权和业务操作契约 | 机制正文副本、源码实现、未开放能力 |

判断标准：**同一事实只在一层写全，其它地方只链接**。写完后自问「这条结论
三个月后由谁来改」——如果答案不在本层，说明放错了地方。

## 二、目录与编号

- 层目录统一 `NN-name/`；层内文档统一 `NN-name.md`（两位数，从 `01` 起）。
- 子层目录用 `NN-name/` 且与层内编号不混用；子层内的文件从 `01` 重新编号。
- 同一目录内编号必须唯一；`03-` 与 `03.1-` 视为不同编号，但不要同时使用两套
  风格（例如 `03.1-` 与 `03.01-` 混排）。
- 归档目录叫 `archive/`，归档内容必须写明「状态止于某日」，且不从正文直链
  当作现状阅读。

## 三、每份文档要有形

- **一个一级标题**：文件名之外不要再起第二个 `#`。代码块的「文件路径标注」
  不要用 `#` 当标题。
- **活文档写清依据**：出现「当前 / 目前」的句子必须能被前 15 行里的时效锚住。
  层 README 用 `> 最后更新：YYYY-MM-DD（基线 vX.Y.Z）` 记录实际核对依据。
  日期与基线不要求跟随应用发版，禁止仅为了版本一致而刷新未修改的文档。
- **活文档写状态**：20-requirements 的每一篇（层索引除外）与 `00-meta/platforms/`
  下的平台进度文档，前 15 行必须有
  `> 状态：已实现|部分实现|规划（YYYY-MM-DD，基线 vX.Y.Z）。` 一行，取值只有这
  三种，后面可接补充说明；仅在正文实际变更时随同调整日期与基线。层索引里的状态列是摘要，权威
  写法在文档首行，两者不一致会被门禁拦下。
- **归档写止期**：`archive/` 下的文档前 15 行必须有 `> 状态止于 YYYY-MM-DD`。
- **需求文档写验收**：20-requirements 的文档至少交代边界与验收标准，不能只有
  一段描述。
- **相对链接**：一律用相对路径，禁止写死绝对路径与行号；引用源码写符号名，
  不写 `L123`。

## 四、编目自动化（不要手工维护索引）

| 脚本 | 职责 |
|------|------|
| `python scripts/docs_check.py` | 死链、锚点、孤儿、编号冲突、一级标题、时效锚、状态行与归档止期、层索引状态列与文档首行是否一致 |
| `python scripts/docs_index.py --check` | 按月归档的开发日志、发布说明索引是否与目录一一对应 |

两个脚本都接在 `.github/workflows/ci.yml` 的 `Docs check` 步骤上；改动文档后
本地先跑一遍。索引行的人工列（主题 / 说明）由脚本只在**新增行**时填，已有行
不会被覆盖。

## 五、生命周期

- **发布时**：只更新版本文件、`50-releases/` 索引与版本说明；其他文档仅在内容
  确实需要变更时修改，禁止批量更新未修改文档的日期或基线。不把开发期内部修正
  写成用户可见修复项。
- **归档时**：过期的规划与进度快照移入 `archive/`，正文只留一句指针。
- **迁移时**：历史日志不改写事实；若引用的文件名变了，允许把链接改成新路径，
  但不要改写当时的结论。

## 六、禁止事项

- 不在文档里写真实姓名、账号、API key、`config/session` 内容等私人设定。
- 不把未实现的能力写成「已可用」；未开放的能力要么标 `规划`，要么不写。
- 不用文档描述另一套与代码并行的流程；代码、需求、架构、用户指南四者冲突时，
  以代码与配置为准，并修正文档。
