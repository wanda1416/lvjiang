# v0.13.7 — 桌面布局改客户区口径，支持端游全屏

> 本文以 v0.13.6 正式版（提交 `bb95f495`）为基线。

本轮只有一条主线：**桌面布局的画布从「窗口矩形」口径改成「客户区」口径**，并由此
补上端游全屏支持。顺带给布局引入了可校验的画布尺寸要求，让「画面形态与布局对不上」
这类不会报错、只会让坐标整体偏移的错配在启动前就被拦下。

**自己改过桌面布局坐标、或基于桌面布局建过继承布局的用户请重点阅读不兼容变动第 1
条**；**端游全屏玩家请看第 2 条**，现在有专门的方案了；**非 20:9 的安卓设备用户请看
第 3 条**，未做屏幕标定的会被拦住。

## ⚠️ 不兼容变动与升级指引

### 1. 桌面布局的坐标基准变了，自定义的桌面坐标需要重标

- **现象：** 随包桌面布局本身已经换算好，照常使用无需操作。但如果你**自己改过桌面
  布局的区域坐标**（`config/local/layouts/desktop/` 下有文件），或**基于桌面布局建过
  继承布局**，那些坐标仍是旧基准，会整体偏移——画面中间几乎看不出，越靠边越明显，
  最多约 8px。
- **原因：** 窗口定位用的 `GetWindowRect` 包含 Windows 的不可见调整边框，1920×1080
  的端游窗口截出来其实是 1936×1119（左右各 8px 边框、顶部标题栏 31px、底部 8px）。
  旧画布只裁掉了标题栏，左右和底部的边框仍留在画布内，于是画布是 1936×1088 而不是
  客户区 1920×1080，一切按 1920×1080 推算的坐标都带 0.8% 的系统偏差。新画布正好等于
  客户区，随包的 1531 个坐标字段按绝对像素守恒一次性换算到新基准。
- **如何调整：** 自定义的桌面坐标请在场景管理里重新标定（「刷新截图」后逐个核对
  区域框）。自建的继承布局还要检查画布：它的画布比例是在旧基准下量的，需要重新
  用「编辑画布」框一次。没改过桌面布局的用户无需任何操作。

### 2. 端游全屏改用「端游全屏」方案，不要再用「端游」

- **现象：** 全屏玩家如果继续选「端游」方案，启动时会被拒绝并提示「当前布局画布区域
  尺寸不符合预定义要求，请修改布局后重试」。
- **原因：** 「桌面布局」的画布要裁掉标题栏和窗口边框，而全屏画面没有这些东西，硬套
  会多裁一圈，导致所有坐标整体偏移。此前全屏其实一直是不支持的——只是不报错。
- **如何调整：** 把主界面顶部的方案切成新增的「**端游全屏**」（绑定新增的「桌面全屏」
  布局）。窗口模式继续用「端游」。两个方案除布局外完全一致，都要求管理员权限。

### 3. 安卓布局要求 20:9，非 20:9 设备需先做屏幕标定

- **现象：** 画面比例不是 20:9 的设备，选「安卓布局」启动时会被拒绝，提示同第 2 条。
  例如 19.5:9 的手机偏差 2.50%，超过允许的 0.5%。
- **原因：** 「安卓布局」的坐标是按 20:9 标定的。此前比例不符也能启动，但识别与点击
  会整体偏移且不报错；本版把这条要求显式化，启动前校验。
- **如何调整：** 在手机上做一次屏幕标定（游戏停在大厅 → 悬浮图标 →「屏幕标定」→
  在参照图上点两个拉开距离的按钮 →「保存画布」），把画布裁到实际的游戏内容区；
  或按 [3.2 场景管理](../60-userguide/03.02-scene-management.md) 自建继承布局并
  在「编辑」里改画布尺寸要求。

### 4. 场景管理顶部按钮重新分组

- **现象：** 顶部按钮顺序变了：`布局下拉 → 编辑 / 新建 / 另存为 / 删除 → 保存 /
  放弃改动 → 刷新截图 → 编辑画布 → 创建分组 / 创建场景`。「保存」「放弃改动」从
  原来紧贴下拉框的位置挪到了布局增删改之后。
- **原因：** 原先保存和放弃夹在下拉框与「新建」之间，读起来像是在保存下拉框选的
  东西。现在按作用对象分三组：先是对布局这个对象的增删改，再是对当前改动的存弃，
  最后才是画面与场景的编辑。
- **如何调整：** 不需要操作，按钮功能未变。

## ✨ 新增功能

- **端游全屏支持**：新增「桌面全屏」布局（继承桌面布局，画布覆盖整张截图）与
  「端游全屏」预置方案。全屏画面没有标题栏和窗口边框，截到的就是客户区本身，
  所以两个布局共享同一套区域定义，只有画布不同，改根布局两边自动同步。
- **布局新增画布尺寸要求**：可以为布局声明画布裁剪后应有的宽高比（写 `20:9` 或
  `2.22`），并设定允许误差（默认 0.5%）。启动任务前校验目标窗口/设备，不符合就
  拒绝执行并给出当前画布尺寸、实际比例、偏差与容差。
  - 随包声明：安卓布局 `20:9`、桌面全屏 `16:9`（误差 0.5%）；桌面布局 `16:9`
    （误差 2%，因为画布是比例而窗口边框是固定像素，只有标定用的 1920×1080 裁得
    正好，2560×1440 会漂 0.67%）；投屏布局的边框因模拟器而异，不声明。
  - 它拦的是形态错配：全屏配窗口布局偏 2.75%、窗口配全屏布局偏 2.68%、19.5:9 设备
    配安卓布局偏 2.50%，三者都会被拦下，而 1280×720 到 4K 的窗口模式都放行。
- 场景管理新增「**编辑**」按钮，修改当前布局的名称、描述与画布尺寸要求（布局 key
  创建后仍不可修改）。
- 战斗属性页的判定三率补上**白字来源与溢出**：每一行显示对应的白字率，黄字达到上限
  后还会标出溢出的白字百分点，便于判断三率还值不值得继续堆。

## 🔧 修复

- 桌面端点击与识别的整体偏移：随包桌面布局的全部坐标换算到客户区口径，不再把窗口
  的不可见边框算进画布。1920×1080 窗口模式下现在是精确对齐。
- 16 个伸出画布的桌面区域裁回边界。它们当初贴着截图边缘定义，实际伸进了窗口的
  不可见调整边框——对 OCR 是桌面背景噪声，对主页九宫格更糟：那是移动拖拽区，落点
  取到边框上时按下拖动会被 Windows 当成改变窗口大小，指令根本进不了游戏。
- 场景管理「视图管理」的入口/跳转区加滚动条。条数由场景声明决定，设置页那批页签
  视图有近 20 条，原先会把视图列表和按钮排挤到最小高度以下，控件都在但挤成一片。
- 场景管理的 OCR 清洗组选项「不清洗」改名为「**默认规则（全局）**」。它从来就不是
  不清洗——全局规范化那层对所有 OCR 无条件生效，选它只是不叠加业务规则组；旧名字
  与配置里「默认层不可删除」的定义正好相反，也与「工具 → 图像识别」里同语义的选项
  叫法不一致。
- 禁用状态的勾选框、单选与说明文字现在会整体置灰。全局样式给所有控件写死了文字
  颜色，盖掉了调色板里的禁用色，此前这些控件被禁用后看上去和常态一样、只是点不动，
  容易被当成「自己没点到」。
- 主页面「清理日志」按钮移到级别筛选旁。
- 桌面布局的聊天、登录页、背包与物品详情坐标微调。

## ⚠️ 已知限制

- **桌面布局只在 1920×1080 窗口模式下精确对齐。** 画布用比例表达，而窗口边框是固定
  像素，所以其他分辨率的画布会有小幅偏移：2560×1440 偏 0.67%、3840×2160 偏 1.35%，
  靠边和靠底的区域会跟着偏几像素到二十几像素。这也是桌面布局的画布尺寸误差放宽到
  2% 的原因。彻底解决需要把截图口径改成直接抓客户区，那时画布恒等、漂移归零。
- 全屏支持覆盖**无边框全屏**。独占全屏能否被截图取决于显卡与驱动，与本次的几何改动
  无关。
- 后台截图仍是实验性能力，很多脚本暂时无法在该模式下跑通，该模式下的功能不可用
  问题暂不受理。
- 投屏布局未声明画布尺寸要求：模拟器的边框各不相同，无法给出统一值。
