# 离线 WF 模拟的回归门禁增强（计划）

> 状态：规划。本文只收**尚未实装**的增强项；已实现的范围、契约与拒绝清单见
> [全任务采集与离线工作流模拟（设计）](../../30-design/01-architecture/09-workflows/06-workflow-simulation.md)（仅源码检出）。
> 设计层 §10 已把外部方案逐条落定，其中「不采纳」的条目不再在本文重开。

## 1. 现状与缺口

模拟器已能：真实引擎 + 真实 OCR + 状态图设备、全任务无损录制、人工侧车转换、受控 WF 库打包、
静态能力预检、多进程并行与覆盖报表。缺的不是执行链，而是**把已知缺陷类型变成会失败的断言**：

- 无人值守下误用 `confirm()` 会让整批卡死，现在只能靠人发现（现状：人工交互一律不自动回答）。
- 结果只**输出** `visited_states`/`visited_edges`，没有「必须经过 / 禁止触碰」的断言。
- 动作未命中时只有文字原因，没有可视化的「期望落点 vs 实际落点」。
- 每次 scan/find 都跑真实 OCR，日常改控制流时反馈慢，但没有可信的加速档。
- 动作匹配是严格 `box`，重构导致 1–2% 坐标漂移就会红；缺一个**明确的、非门禁的**宽容档。

## 2. P0：把已知缺陷变成断言（纯增量，不改现有判定）

### 2.1 无人值守弹窗门禁

- **触发场景**：`environment.unattended = true` 的用例遇到 `confirm` / `input` / `choose`。
- **期望行为**：按 `core/batch/unattended.py` 的真实契约复刻——`pause` 记命中并抛中断（不卡死）；
  `confirm`/`input`/`choose` 若未在 fixture 的 `ui_script.responses` 显式授权，**立即判用例失败**，
  错误信息写明弹窗种类、消息与 WF 源码行号。
- **不能改变的语义**：不改产品侧 confirm/pause 行为，不自动回答，不引入新的引擎回调协议。
- **验收**：故意把一个 `pause` 改成 `confirm` 的脚本必须被稳定抓出；`ui_script.responses`
  显式授权后同一脚本恢复通过。

### 2.2 状态覆盖断言

- **新增字段**（`scenario.json` 的 `expectations`）：`must_visit` / `forbid`，元素是状态 ID。
- **判定**：`must_visit` 全部命中且 `forbid` 一个都不出现才算 passed；失败原因列出缺失/意外状态。
- **不能做的**：不把 `visited` 当成覆盖率——它只代表**这份 fixture 声明过的图**，不代表业务分支全覆盖。
- **验收**：删掉一条必经边后用例变红且原因指向具体状态 ID。

### 2.3 结果如实标注

- `result.json` 增加独立计数：`cached`（OCR 缓存命中）、`tolerated_mismatch`（宽容/停留档命中）、
  `recording_complete`（已存在）。这些是**标注**，不改变 passed 判定，也不写进任务业务状态。
- **验收**：开启缓存或宽容档时报告必须显示命中次数，未开启时字段为 0 而不是缺省。

## 3. P1：诊断力与速度（需设计取舍，非发版门禁）

### 3.1 失败 Diff 标注图

- 失败时输出一张当前状态原图 + 标注：期望出边的 `box`/容差（虚线）、本次实际请求坐标（实心叉）、
  顶部信息条（用例名、状态 ID、WF 文件与行号、偏差数值）。
- **坐标口径必须复用**诊断方案的规则：请求坐标 ≠ 实际落点；几何不可信时只显示文字，不画假红点。
- **验收**：`ReplayActionMismatch` 类失败必产出一张图，且图中点位与 `events.jsonl` 里的请求坐标一致。

### 3.2 两档 OCR 缓存（加速档）

- `--ocr-cache <dir>`：按 `(模型文件 hash, ocr_cleaner 版本, 布局 hash, image_sha256, crop_rect)` 命中，
  任一变动自动失效；命中项在结果里标 `cached`。
- **门禁**：发版/覆盖报表一律 `--no-ocr-cache`（真推理）；缓存命中率与耗时只在本地反馈里报告，
  不得用缓存结果宣称覆盖率或 OCR 质量。
- **验收**：改 `config/system` 下 OCR 清洗规则后旧缓存必须全部失效；同一 fixture 缓存开/关的
  passed 集合一致（不一致即为缓存键缺陷）。

### 3.3 宽容匹配档（明确非门禁）

- fixture 可显式开启 `tolerance`（比例容差）或 `match_direction_only`（固定方向滚屏）；
  默认仍走严格 `box`。命中宽容条件时结果标 `tolerance_hit`。
- **为什么**：重构脚本时常有 1–2% 坐标漂移，严格档会红；但要清楚这是「探索性跑通」，不是回归门禁。
- **不能做的**：不设全局容差、不把宽容档结果当发版通过依据、不在容差命中时隐藏原始偏差值。
- **验收**：同一 fixture 在严格档失败、宽容档通过时，报告同时给出两个档位的结论与偏差数值。

### 3.4 `mismatch_policy: stay`（自愈路径测试）

- 未命中时保持当前状态并记录 warning，用于验证「点空后脚本能不能自己重试/最终正确报错」。
- **强制约束**：必须配重试次数上限与整体步数上限；结果计数 `tolerated_mismatch`；不得把
  「点空 → 靠轮询走完」静默记 passed。
- **验收**：制造一次点空后，用例能观察到重试次数并按阈值判定，而不是死循环或静默通过。

## 4. P2：需先补能力模型

| 项 | 前置条件 | 说明 |
|---|---|---|
| Profile 账本断言（`profile_expected`） | 账本读写在模拟环境里可隔离建模 | 现状走 `environment.attributes` 只读快照；真实用户数据不入仓 |
| `wall-clock` / `quota` / 跨日刷新 | 时间源抽成可注入能力 | 现状只有显式 `wait` 与输入时长推进虚拟时间，`datetime` 逻辑一律 unsupported |
| 图片内容寻址去重 | 样本量证明收益 | 只共享图片字节，不合并事件与 `frame_seq`；去重后仍须可追溯到每次 capture |
| 夹具存储与归属 | 体积/仓库策略确定 | 现状用仓库内合成小图；不引入 LFS 作为前置 |

## 5. 验收与不做的事

- 每项增强都必须能回答「防止哪个真实回归」，并且在**关闭该增强**时现有行为与结论不变。
- P0 全部完成前，模拟器不宣称具备无人值守回归门禁；P1/P2 未完成前，报告里对应的加速/宽容结论只能当辅助信息。
- **明确不做**：不自动构建状态图、不把比例容差设为默认、不回放粘贴与输入轨迹、不替代现有
  单元/契约测试、不把未模型化的领域能力当 supported、不为了让用例通过而放宽断言。
