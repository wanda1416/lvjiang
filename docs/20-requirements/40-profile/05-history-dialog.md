# 变更记录对话框（统一历史查看器）
> 状态：已实现（2026-11-07，基线 v0.15.11）。

> 最后更新：2026-11-07（基线 v0.15.11）。实现如与本层描述不符，以代码为准。

## 1. 背景

Profile 的历史入口有三个：用户总览工具栏的「历史记录」（全账本）、列名右键
「查看历史记录」（某个键的全部用户）、单元格右键同名操作（某用户某个键）。
三个入口原本共用一个对话框，但差异靠参数和列号位移实现：全量模式多插一列
「键」、单用户模式隐藏「用户名」，列号整体手工偏移，加一列要改十几处。

真实的账本规模也不小：开发机三个月 3.1 万行、19 个用户、96 个键、95 种来源，
其中 27% 的记录没有来源。只有"最近 N 条 + 翻页"时，想找一条特定记录只能靠翻。

## 2. 目标

1. 三个入口保持不动，但**界面只有一个**：入口只决定"预先填好的筛选条件"。
2. 顶部提供关键词与时间范围，列头下提供**按列聚合的筛选行**。
3. 聚合候选默认只展示计数最多的 10 项，其余靠输入模糊查找。
4. 底部支持跳到任意页。
5. 列显隐、文本可编辑范围、撤销/删除的可用性判断沿用原有语义。

## 3. 入口与预设范围

| 入口 | 预设条件 | 首屏表现 |
|------|----------|----------|
| 用户总览工具栏「历史记录」 | 无 | 全账本 |
| 列名右键「查看历史记录」 | 键 = (模型, key) | 该键的全部用户 |
| 单元格右键「查看历史记录」 | 键 + 用户 | 单人单键 |

**预设不锁定**：顶部条件条把当前生效的条件摊成可取消的标签，点 × 就放宽该维度
（从"单人单键"直接放宽到全部用户）；右侧「恢复入口范围」回到入口默认值。

**列不随条件隐藏**：入口与筛选只体现在顶部标签上，表格始终是同一组 10 列。
早期版本在单用户/单键时收起对应列，结果是每次筛选都要重排列宽、对话框跟着
变宽变窄，观感上是一次次闪动；列固定后换筛选只换内容。

## 4. 界面结构

```
┌ 变更记录 · 用户 X · 键：库存：通宝 ────────────────────────────────┐
│ 范围  [用户：X ×] [键：库存：通宝 ×]                恢复入口范围 ↺ │
│ 🔍[搜索 值/来源/用户/键]  时间[全部▾] [起]~[止]   清除全部筛选       │
├────────────────────────────────────────────────────────────────────┤
│ 时间          │键      │用户名 │类型  │旧值  │新值  │变动量│来源  │同步来源│操作│
│  ▸ 筛选行     │[全部▾] │[全部▾]│[全部▾]│[包含]│[包含]│[全部▾]│[全部▾]│[全部▾]│    │
│ 2026-11-07 …  │通宝    │X      │● 覆盖│100   │110   │ +10  │日常  │       │撤销 删除│
├────────────────────────────────────────────────────────────────────┤
│ 每页[100▾]条 共 N 条 · 增加 +a · 减少 -b   第 i/p 页 · x–y 条 [n][跳至] │
│                                          [首页][上一页][下一页][末页] │
└────────────────────────────────────────────────────────────────────┘
```

列由一份列描述表驱动（`key / 标题 / 宽度策略 / 聚合维度 / 筛选控件类型`），
不再有列号偏移量。列序是「时间 → 键 → 用户名 → 类型 → 旧值 → 新值 → 变动量 →
来源 → 同步来源 → 操作」，先看是哪个数据项，再看是谁、怎么变。

宽度按字体度量计算且**不随内容变化**：时间列容纳完整的 `yyyy-MM-dd HH:mm:ss`，
键与来源列各容纳 10 / 9 个全角字，用户名列固定宽度（更长的名字省略显示，全文在
tooltip 与筛选弹层里）。筛选只改内容，不改列宽，表格不做横向重排。

## 5. 筛选语义

**顶部**只放"落不进某一列"的维度：关键词（值文本、来源、用户、模型、键名、
**键标签**）、时间快捷档位（全部 / 今天 / 近 7 天 / 近 30 天 / 近 90 天 / 自定义）。

**列筛选行**逐列给出控件：

| 列 | 控件 | 候选来源 |
|----|------|----------|
| 时间 | 无（用顶部区间） | — |
| 用户名 / 类型 / 键 / 来源 / 同步来源 | 可搜索多选（计数倒序，前 10 项） | 该维度聚合 |
| 旧值 / 新值 | 文本"包含" | — |
| 变动量 | 方向：全部 / 增加 / 减少 / 为零 | 固定枚举 |

三条硬规则：

1. **聚合候选按"除自己之外"的条件统计**。勾选一个来源后，来源候选仍是全部来源，
   否则想追加第二个来源只能靠记忆输入。
2. **默认 10 项，其余靠输入**：弹层顶部搜索框在候选列表里做模糊查找（按该维度
   的数据库 `LIKE` 过滤），并提示"另有 N 项未列出"。搜索不改变查询条件。
3. **空来源是真实取值**：`未记录` 与"不限"是两种状态，可单独筛出来。

变动量方向只认**可确认**的变动量：优先 `delta_value`，缺失时用新旧值之差；
连旧值都没有（例如某键的第一条记录）时既不算增加也不算减少——与「变动量」列
显示的「—」保持同一口径，不把"起点未知"伪造成"从 0 增加"。

## 6. 状态与交互规则

| 场景 | 行为 |
|------|------|
| 任一筛选变化 | 回到第 1 页；其余条件保留；候选与总数重算 |
| 关键词 / 旧值 / 新值输入 | 250 ms 防抖后再查询 |
| 撤销、删除成功 | 保留筛选与页码（页空则回退一页），刷新候选与总数 |
| 双击来源编辑 | 保留在原页；成功后刷新来源候选 |
| 关闭再打开 | 记住窗口尺寸与每页条数；筛选条件不记忆，按入口预设重来 |
| 空结果 | 表格中央提示并提供「清除全部筛选」 |
| 键位 | `Ctrl+F` 聚焦关键词 |

控制关系：筛选控件是唯一状态源，条件标签是同一份状态的另一种展示；程序化回填
控件时阻断信号，避免"为了展示而查询"。

### 6.1 布局稳定（重要）

对话框在筛选、翻页、撤销删除之间**不得改变尺寸或列宽**。实现上靠三条：

1. 列集合固定为 10 列，任何条件都不隐藏列、不改列宽；
2. 底部合计金额与页码用可省略标签：`sizeHint` 按全文宽度给，`minimumSizeHint`
   固定为 0，空间不足时省略成「…」，全文在 tooltip 里；
3. 顶部条件标签单条限宽省略，长关键词不会把整行顶宽。

回归测试直接断言"切换多种筛选后 `minimumSizeHint()` 不变"
（`tests/ui/profile/test_history_dialog.py`）。

## 7. 数据层

`HistoryQuery`（`core/profile/history_query.py`）是唯一的条件对象：精确集合
（用户 / 键 / 变动类型 / 来源 / 同步来源）+ 模糊词（关键词、旧值、新值）+ 时间
区间 + 变动量方向。`relaxed(dimension)` 给出"去掉本维度条件"的副本，聚合候选
用它实现排除自身语义。

仓储层新增：`history_page` / `history_count` / `history_facets` /
`history_facet_total` / `history_delta_totals`，条件构造只发生在 `_history_where`
一处；排序走白名单；`LIKE` 模式串统一转义 `%`、`_`、`\`。旧的
`get_history`/`count_history`（单用户 / 单键）保留为便捷入口，内部仍然走同一套
条件构造。

实测（3.1 万行、本机 SSD）：单维度聚合 8–10 ms，深页 `OFFSET 30000` 3.3 ms，
跨列模糊 6 ms。因此不引入预聚合表或缓存层；索引保持现有两条，等实测过百毫秒
再评估。

## 8. 非目标

- 不做服务端排序（除内部的 id/时间白名单）——本轮只按写入倒序。
- 不做保存筛选视图 / 命名查询。
- 不改写历史的写入、撤销与同步语义。
