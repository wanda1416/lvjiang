# 日常参数保存边界与连续输入合并

> 状态：已实现（2026-10-12，基线 v0.15.0）。2026-11-17 增加独立/全局双面板与
> 「工具 → 任务参数」入口。

- 日常参数保存只更新当前编辑对象的修改字段，不扫描脚本，不隐式删除其他
  任务配置。脚本刷新也不自动清理参数，临时解析失败不等于脚本被删除。
- 文本连续输入用 GUI 单次计时器合并，约 250ms 保存；显隐依赖即时更新。
  勾选、下拉选择即时保存；数字键盘编辑不逐个保存中间数字。
- 切换脚本、用户、参数来源、环境、执行目标，筛选、刷新、加载、打开
  「工具 → 任务参数」及正常退出前保存旧面板。日常与批量的参数快照必须在
  保存后构建。
- 编辑归属固定在面板构建时的脚本、参数来源和用户，不在计时器触发时按
  当前活动选择猜测。合并只更新实际修改的字段，不回写其他字段的旧副本。
- 临时外部脚本参数只保存在该临时项内存中；切换、筛选、刷新保留，加载
  新临时项时替换，不写入共享或用户参数配置。参数面板必须持有脚本配置对象
  本身，复制一份会让临时草稿写进无人读取的副本。
- 复用既有原子更新能力，不引入后台保存线程、全局配置缓存或格式迁移。
- 保存失败保留修改，批量不得继续启动；运行快照的只读展示不作为新编辑，
  任务结束或退出时不得将历史参数覆盖回最新配置。

## 独立参数 + 全局对照两块面板

勾选「使用独立参数」后，日常页在同一位置绘制第二块「参数设置（全局参数）」：

- 两块都是可编辑面板，各写各的归属：上块写该用户的 `workflow_params`，
  下块写全局 `wf_configs`；不存在"对照区只读"的第三种语义。
- 上块显示合并后的生效值，下块显示全局值；改全局值时，被该用户覆盖的字段
  保持用户值，其余字段同步刷新到上块并同时抬升上块基线——否则下一次保存会
  把"同步"误当成用户编辑写进独立参数。
- 正在编辑尚未落盘的字段不被同步覆盖。
- 两块的待保存改动互不牵连：切脚本时一起 flush 并重建；切执行用户只重建
  上块（全局值与该用户无关，重建会丢掉正在输入的全局改动）。
- 面板是否有内容由表单字段决定，不看可见性：切到批量 Tab 后整块日常页不可见，
  用可见性判断会让待保存的全局编辑永远不落盘。
- 共享模式只有一块：那时上块本身就是全局参数，再画一块会造成"两份全局"。

「全部用户参数」只读对话框已改为工具菜单里的「工具 → 任务参数」（非模态、
可编辑、按用户或按任务浏览），见
[30-batch/05-user-task-skip.md](../30-batch/05-user-task-skip.md)。

回归覆盖连续输入合并、立即启动批量读到最新值、切换不串写、字段合并不
覆盖其他更新、错误脚本配置不被清理、临时脚本参数往返，以及全局对照区
写全局、同步未覆盖字段、共享模式不出现第二块面板。
