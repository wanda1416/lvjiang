# 6. 工作流与日常任务

日常 Tab 是运行工作流的主入口：选择脚本 → 配置参数 → 执行。

---

## 6.1 日常 Tab 布局

```
┌──────────────────────────────────────┐
│  [开始执行 (F9)]  [暂停]              │
├──────────────────────────────────────┤
│  执行用户：[▼ 跟随当前用户]           │
├──────────────────────────────────────┤
│  脚本：[▼ 下拉选择] [加载]            │
├──────────────────────────────────────┤
│  说明：运行前请确认……                 │
├──────────────────────────────────────┤
│  参数设置                             │
│    参数1：[____]                      │
│    参数2：[☑]                         │
│    ...                                │
└──────────────────────────────────────┘
```

| 区域 | 说明 |
|------|------|
| 开始执行 (F9) | 启动当前选中脚本；运行中变为「停止 (F10)」 |
| 暂停 | 运行中可暂停；暂停后变为「恢复」 |
| 执行用户 | 默认「跟随当前用户」（顶部「当前用户」下拉框选的是谁就用谁）；也可固定选某个用户，启动时不再看顶部选择。仅对本 Tab 生效，不写盘，每次重启程序都回到「跟随当前用户」 |
| 脚本下拉 | 列出当前展示的脚本（在「工具 → 脚本编辑 → 脚本配置」里勾选、排序、改名） |
| 加载 | 切换脚本并加载其参数面板 |
| 说明 | 显示脚本 `#% note` 元数据；内容按左侧 Tab 宽度自动换行 |
| 参数设置 | 根据选中脚本动态生成；不同脚本参数不同 |

脚本可用单行或 YAML 多行文本声明说明。较长说明推荐主动分行，界面还会
根据左侧 Tab 的实际宽度继续自动换行：

```text
#% note: |-
#%   请先进入目标页面，确认出现操作按钮
#%   再开始执行脚本。
```

> 脚本列表与顺序通过「工具 → 脚本编辑 → 脚本配置」管理，可控制每个脚本是否在日常下拉中暴露、显示名和排序。

脚本放在哪个目录都行——发现层递归扫描 `workflows/` 全树，目录只用于归类，
不进入默认 id，也不表达任何语义。能不能被看到、能不能排进批量任务，由脚本自己
在文件头声明：

| 声明 | 效果 |
|------|------|
| `runnable: true` | 注册为脚本，出现在日常列表与「脚本配置」里 |
| `batchable: true` | 额外进入批量任务候选（隐含 `runnable`） |
| 两者都不写 | 不注册，例如只被 `import` 的过程库、批量生命周期钩子、归档脚本 |
| `_` 开头的文件或目录 | 编辑器临时文件与录制产物，一律不注册 |

所以「依赖用户先手动到达指定位置、不适合串联批量执行」的脚本，写在任意
目录里并只声明 `runnable: true` 即可。

## 6.2 运行控制

| 操作 | 热键 | 说明 |
|------|------|------|
| 开始 / 停止 | F9 / F10 | 启动当前脚本；运行中按 F10 停止（当前步骤完成后退出） |
| 暂停 / 恢复 | F11 | 运行中按 F11 或点击「暂停」，脚本在当前语句执行后挂起；再次操作则继续 |

暂停期间：
- 按钮文字切换为「恢复」
- 脚本不执行任何操作，但保持运行上下文
- 可以安全查看日志或切换窗口

停止后：
- 脚本完全退出，上下文清空
- 按钮恢复为「开始执行 (F9)」

## 6.3 工作流清单

以下为日常 Tab 中可用的全部工作流。每个工作流列出一句话说明、参数和前置条件（游戏需要停在哪个页面）。

### 每日江湖号令

刷新并执行江湖号令任务（换装、合影、情境、看报、醉意）。

| 参数 | 说明 | 默认 |
|------|------|------|
| 单任务最大刷新次数 | 单个 label 未命中目标任务时最多刷新几次 | 50 |
| 领取奖励 | 任务完成且卡片显示待领取的金色光效时，点击标签领奖；已领奖卡片会跳过 | 否 |
| 黄泉酿置信度 | 背包中识别「黄泉酿」的置信度门槛，档位 0.65 / 0.6 / 0.55 / 0.5；反复匹配不上时可逐级下调，但不要低于 0.5——阈值过低会把其他道具误认成黄泉酿 | 0.65 |

**前置**：停在江湖号令活动页或游戏首页（自动识别）。

### 每日自动签到

自动进入活动列表，按配置依次查找活动并领取奖励。活动名称和领奖关键字按行对应；
例如活动名称填写“朝夕共赏”，同一行对应的领奖关键字填写“签到”。工作流逐屏滚动
活动列表，并在每个视口检查所有尚未处理的活动，因此配置顺序不受列表顺序限制。

| 参数 | 说明 | 默认 |
|------|------|------|
| 左侧活动名称 | 每行一个，名称不能重复 | 朝夕共赏 |
| 右侧领奖关键字 | 每行一个，与活动名称逐行对应，支持包含匹配 | 签到 |

**前置**：停在游戏首页。

### 自动购买不肝

进入包裹 → 钱袋 → 购买不肝进度。

| 参数 | 说明 | 默认 |
|------|------|------|
| 战斗养成购买项 | 逐项勾选要买的类目（心法/武学/奇术/振玉/生活/宝钱/短陌钱） | 全选 |
| 购买营生 | 是否购买营生类目 | 是 |

赛季类目始终全买，不做成参数。

**前置**：停在游戏首页。

### 购买心法心得

可先打开背包普通道具中的全部心法心得，再进入商店购买心法。
进入循环购买前和循环结束后，任务会读取心得置换页的每周剩余库存，按
“600 - 剩余库存”同步 `xinfa_of_week` 本周已购买数量；识别失败不会覆盖已有值。
本周已购满 600 时任务直接结束，不再走一趟导航；批量执行也会在登录前跳过它。

| 参数 | 说明 | 默认 |
|------|------|------|
| 打开背包全部心法 | 扫描当前背包页及向上滚动一次后的普通道具，依次打开所有“心法心得” | 否 |

**前置**：停在游戏首页。

### 扫描备战装备

扫描当前已穿戴的八件装备，并写入任务启动时绑定的备战方案。

**前置**：停在游戏首页；先选择正确用户和目标备战方案。

| 参数 | 无 |
|------|---|

### 扫描全部装备

按所选部位扫描背包装备，解析后写入当前用户的公共装备池。支持最低等级截止和
最少普通词条数过滤，主副武器共享武器背包且只扫描一次。

**前置**：停在游戏首页；先选择正确用户。

| 参数 | 说明 | 默认 |
|------|------|------|
| 扫描部位 | 武器、环、佩、冠胄、胸甲、胫甲、腕甲，可多选 | 全部 |
| 装备最小等级 | 低于该等级时结束当前部位的有序扫描 | 110 |
| 最少词条数 | 普通词条不足时仍扫描但不写入；0 表示不过滤，定音不计数 | 0 |

装备数据的产生、去重和核对方法见[5.2 装备数据如何产生](05.02-equipment-data-acquisition.md)。

### 扫描钱袋货币

进入包裹 → 钱袋，识别各货币数量并写入 Profile。支持容差校验，防止异常值覆盖。

| 参数 | 说明 | 默认 |
|------|------|------|
| 通宝允许差值(万) | 新值与旧值差超过此值则跳过写入 | 0（不限制） |
| 么玉允许差值 | 同上 | 0 |
| 宝钱允许差值(万) | 同上 | 0 |
| 长鸣玉允许差值 | 同上 | 0 |

**前置**：停在游戏首页。

### 太极炸鱼

自动执行炸鱼循环操作。

| 参数 | 说明 | 默认 |
|------|------|------|
| 最大循环次数 | 最多执行几轮 | 500 |
| 技能按键 | PC 端用于炸鱼的技能键，可选 1–4 | 1 |

**前置**：停在炸鱼活动入口。

> PC 端的技能按键不支持后台输入。运行前必须关闭「后台模式」，
> 否则工作流会在执行任何操作前直接中止并说明原因。

### 输入兑换码

主页 → 菜单 → 设置 → 其他 → 兑换码，处理完毕后退回主页。

| 参数 | 说明 | 默认 |
|------|------|------|
| 兑换码 | PC 每行一个，可一次填写多行；安卓端留空，由弹窗提示手动输入 | 空 |

**前置**：停在游戏首页或菜单页。

> PC 端逐行通过剪贴板粘贴，跳过空行并清理每行首尾空白。
> **全部为空会在进入游戏页面之前直接报错中止**。
> 每条确认或取消后，必须识别到“其他”页的兑换码标签，才重新打开入口处理下一条。
>
> 安卓端的输入通道发不了文本，脚本会在输入框打开后弹窗等待——请自己
> 输入或粘贴一个兑换码，选择「是」后由脚本处理确认；选择「否」结束兑换并
> 保留当前游戏页面。无人值守仍会显示这个确认框，不会跳过兑换任务。
> 也可自行确认并回到其他页后再继续，此时脚本不会重复点击确认。
> 安卓不循环处理参数中的多行；如需多个兑换码，请在等待确认期间自行逐条操作。
>
> 确认后若仍未回到其他页，且未识别到“兑换奖励”，脚本按已兑换提示处理，
> 记录一次 warn 并取消一次；如果仍无法回到其他页，则中止后续操作。

## 6.6 查看任务历史

入口：「工具 → 任务历史」。**只要通过日常 Tab、批量 Tab 或专用页面（如调律 Tab）的
「开始」按钮启动过一次任务，都会在这里留下记录**，不区分脚本类型。对话框分两个页面：

### 「任务历史」页

| 列 | 说明 |
|----|------|
| 开始时间 / 耗时 | 本次任务的时间信息；结束时间在右侧详情中 |
| 用户 | 启动时绑定的执行用户（见 [2.2 用户管理](02-main-interface.md)） |
| 任务 | 脚本/工作流名称 |
| 状态 | 进行中 / 已完成 / 已中断 / 失败 / 跳过 |

- 左侧第一行选择日期，第二行选择执行目标类型（窗口 / 设备 / 未记录）和**状态**，点击「查询」生效
- **用户**与**任务**使用可搜索的纵向勾选列表；不勾选表示全部，标题显示已选数量。
  搜索隐藏的已勾选项仍参与查询，「清除」取消全部勾选。任务主要展示名称，重名时附加 ID 区分
- 左侧列表展示开始时间、用户、任务、状态与耗时。执行目标、性质、方式、结束时间、
  输入参数、错误、文件路径和完整记录 ID 均放在右侧「记录详情」中，可直接复制
- 选中记录后右侧直接显示**执行日志**；切换「执行结果」可查看返回结果，JSON 会格式化。
  双击记录切换到结果页签，无需启动 Notepad 或外部 JSON 阅读器
- **日志级别**默认 INFO，选择 WARNING 会同时显示 WARNING、ERROR 等更高级别。
  多行消息和异常堆栈一同过滤；切换级别不修改源文件。「刷新日志」可读取运行中任务的新日志
- 对话框默认比原来更矮，可拖动左右分隔条分配宽度，也可调整左侧候选区与列表的高度
  关闭后会记住窗口大小及任务、批量两页各自的左右栏比例，下次打开自动恢复。
  状态保存在 `interface.json` 的 `ui_state.task_history` 节点
- 更新后首次启动会自动把旧 `session.json` 中的界面状态、总览配置、告警和服务器状态
  移到 `config/session/interface.json`，提醒去重历史改为新文件的根节点。迁移成功后移除
  旧文件对应节点，其他运行设置保持不变；后续只读写新文件，手机同步也包含该文件

### 「批量历史」页

| 列 | 说明 |
|----|------|
| 开始时间 / 耗时 | 本次批量执行的时间信息；结束时间在右侧详情中 |
| 配置 | 使用的批量配置名称 |
| 状态 | 进行中 / 已完成 / 已中断 / 失败 |
| 任务数 | 本批次实际执行的单任务条数 |

批量历史同样支持日期、执行目标类型和状态组合筛选。选中一批后：

- **「查看全部单任务」**跳转到「任务历史」页，按该批量记录 ID 过滤，只看这一批下每个
  用户、每个脚本各自的执行记录。会清除用户、任务、状态、目标和候选搜索条件，并适配
  该批次的日期范围；页面顶部出现「返回全部任务」按钮，点击解除批次过滤
- 右侧**「批量报告」**直接显示报告原文；「记录详情」显示输入快照、执行目标、结束时间、
  文件路径与记录 ID。查看日志需下钻单任务，批次没有独立日志文件

### 内嵌预览范围

日志最多预览文件末尾 2 MiB，执行结果和报告最多预览开头 2 MiB；较大文件会明确提示
截取范围。缺失或无法读取的文件会在预览区提示，无效 JSON 按原文展示；原文件保持不变。

### 记录 ID

每次单任务都有唯一的**任务记录 ID**，每次批量执行另有唯一的**批量记录 ID**。批量中的
单任务同时携带这两个 ID；单独运行（非批量）的任务没有批量记录 ID。ID 在记录详情中展示。

查询最多返回最新 2000 条单任务或 1000 条批次；可缩小日期范围分段查看更早记录。

### 存储位置

任务历史与批量历史存于同一个 SQLite 库 `config/session/daily_history.db`（不区分用户，
删除某个用户不会清除其历史记录）；单任务独立日志在 `logs/daily/{用户名}/YYYY-MM/DD/` 下，执行结果文件在
`config/session/output/{用户名}/YYYY-MM/DD/` 下，批量报告在 `logs/batch/YYYY-MM/DD/` 下。
日期取任务或批量启动日期；旧文件保持原位，历史页面继续按已记录的实际路径打开。目前**没有自动清理**，
历史会持续累积，需要时手动清理上述文件与数据库。

> 这里记的是「任务什么时候跑的、跑成什么样」的**执行流水**；调律装备的**判定过程**（每件
> 装备为什么调律/跳过/回收）另有一套更详细的 [调律历史](04.06-running-tuning.md#调律历史)，
> 两者各自独立存储，不能互相跳转，只能靠时间和用户名对照。

### 江湖号令的执行结果

江湖号令的结果页在 `jianghu` 中展示整次摘要及逐项记录。`already_done` 表示处理前
或刷新中已确认完成；`completed` 表示执行后已有检查确认完成；`executed_unverified`
表示动作执行过但没有完成检查。未勾选、未实现、刷新上限、缺少道具或按钮、导航失败
均有独立结果和原因；任务状态与奖励状态分开记录。

奖励 `already_claimed` 表示已有识别显示奖励已领，`claim_attempted` 仅表示已经尝试
点击领取。本轮没有新增领取成功检查，不能据此统计实际领到多少奖励或声望。
当周声望记录的是原有同步过程采用的值，未知值为 -1；原始 OCR 一并保留。

结果按 `heying`、`huanzhuang`、`qingjing`、`kanbao`、`yinjiu`、`juezhanglin`
等任务类型 key 分组，各自的 `records` 保留首轮观察，不以卡片位置或 OCR 文案作 key。
首轮完整记录，补扫只新增此前未记录且仍需执行的新类型；已完成、确定跳过及已记录
类型不重复追加。未读取任务名称的首轮记录放在 `unidentified` 列表，不猜测其类型。
记录过滤不改变原有补扫动作，不会新增识别、点击或导航。

`finished=false` 表示尚未记录到明确终态，需结合任务历史的中断/失败状态查看。
没有读到的任务名称、没有检查的完成状态会保留为空或 unknown；框架异常仍使用原有
错误结果。这些业务记录不会改变任务历史状态、批量调度或重试行为。
