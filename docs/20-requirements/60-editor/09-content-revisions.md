# 配置修订记录与任务加载

> 状态：已实现（2026-10-12，基线 v0.15.0）；两种模式完成本地模拟验证，实际发行包待验证。

## 目标

开发版与发行版统一采用磁盘配置、解析缓存和任务快照。新任务使用启动时的最新配置，运行中的任务不受随后保存或在线更新影响。配置来源固定为 local 优先于 system。

## 修订记录

实体文件的 content_version 从 1 起步，实际修改自动递增，不参与来源仲裁。此次切换将受维护配置重置为 1；不改写已发布包或用户历史归档。界面仅展示本地或系统，不提供版本数字和手动提升入口。

config/session/content.json 保存当前生效文件的修订号，顶层 update_at 为 UTC 时间戳。scenes 按场景 key 组织，layouts 按布局 key、场景 key 组织，其他实体按相对路径组织。根目录 YAML 不收录，每次新任务重新读取。

记录缺失、损坏或所需 key 缺失时，重新加载并重建，不能因此阻止启动。每次任务启动记录并打印 update_at 与缓存复用或重载决策。

## 编辑与外部修改

程序内保存、删除、恢复覆盖、在线安装和手机同步维护索引。外部编辑和 Git 拉取由用户点击刷新或重启生效，不监听整个目录。启动与刷新强制重新读取配置并重建索引。

一轮布局或配置编辑会话保存多个文件时，索引及变更通知在批次结束时合并更新一次；
如果部分文件已写入后失败，也必须更新索引，不能让下一任务复用旧代次。
新建与另存为后的布局同样建立对象自己的文件基线，保存前检查涉及的布局名册和场景文件；
未保存的场景不能因保存其他场景而丢弃旧基线。

刷新放在场景管理顶部编辑与新建之间。存在未保存改动时只提示先手动处理，不代替用户保存或放弃，不改变主页面布局。

编辑器保存前检查打开时的磁盘基线。后台或其他窗口修改过文件时，用户确认后才保存，默认不覆盖。检查只读取实际涉及的文件；聚合配置仅提交草稿实际修改字段。

## 更新与存储

基底身份移至 config/session/baseline.json，仅供 r0 恢复和在线安装使用，不能决定任务是否建立快照。开发版禁止在线安装覆盖源码配置；发行版按 r0、public、member 组合 system，再叠加 local。手机同步保留手机自身基底和 updates，替换 system 后重建修订索引。

## 验收

- 开发版不安装在线内容，但磁盘刷新和新任务配置快照正常工作。
- 发行版安装公开及会员增量后，新任务读取最新场景和布局，旧任务不变。
- 连续启动且修订不变时复用实体解析；根目录 YAML 仍重读。
- 修订索引缺失、损坏、缺少场景或布局 key 时自动重建。
- 外部场景新增区域后刷新，坐标不被旧定义过滤，未保存改动阻止刷新。
- 文件发生并发修改时提示，不静默覆盖；无变化保存不递增。
