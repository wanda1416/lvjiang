# 用户 × 任务：跳过声明与「任务参数」工具

> 状态：已实现（2026-11-17，待随下一版本发布）。

## 1. 问题

批量按「N 个用户 × M 个任务」铺开执行计划。有些组合是用户明确**不需要**跑的：
那个号没有对应玩法、额度早已用尽、或者其他号才该刷这一项。此前只有三种方式表达
"少跑一格"，都不合适：

- 取消勾选任务：全局砍整列，砍不到单个交叉格；
- `batch_check`：数据驱动、逐轮逐格调用，表达不了"用户意志"；
- 用户锁冲突：被动跳过，不是声明。

于是每次批量都要白跑这些格子：登录、`batch_check` 求值、日志噪声、进度表里的
假"成功/跳过"。

## 2. 责任边界

- **声明属于用户资料**：`User.skipped_task_ids` 存稳定的 `task_id`，跨批量配置组
  生效。它回答"这个用户不需要这个任务"，不是"这一次先不跑"。
- **跳过与独立参数是两件事**，互不派生：`workflow_params[task_id]` 决定参数取值
  来源，`skipped_task_ids` 决定执行性。跳过后独立参数值原样保留，取消跳过即可复用。
- **执行快照冻结声明**：启动那一刻由 `collect_exclusions` 读一次用户资料，按本次
  勾选的脚本求交集，写进 `BatchRunSpec.excluded`；运行期不再回读。启动后再改声明
  不影响正在跑的这一批。
- **调度层只解释"跳过"这个通用结论**：不读 Profile、不判断业务条件。

## 3. 执行语义

| 场景 | 行为 |
|---|---|
| (用户, 任务) 被声明跳过 | 任务列与进度行**照旧生成**；执行时直接记「跳过」 |
| `batch_check` | 被跳过的组合**不调用**，不加载 wf、不求值参数 |
| 用户的任务全部被跳过 | 沿用既有"没有可执行任务"路径：不登录、不跑条目准备/收尾 |
| 与 `batch_check` 的关系 | 声明优先；未声明的组合照旧走检查，两者交集生效 |
| 属性单元模式 | 按成员用户名生效；成员任务全跳过即不进 `eligible` |
| 轮次 | 声明是稳定事实，对每一轮都生效 |
| 任务历史 | 不建任务历史（与 `batch_check` 判成跳过时一致） |
| 报告与进度 | 沿用既有「跳过」口径，不新增状态、不改统计分类 |

被跳过的组合在批次历史的 `input_snapshot.excluded` 里留痕，事后可核对
"这一格为什么没跑"。

## 4. 编辑入口：工具 → 任务参数

原来的「全部用户参数」只读对话框从日常页移除，升格为工具菜单里的
「工具 → 任务参数」（位于「任务历史」上方），非模态单实例窗口。两个视图是同一份
数据的两个切面，窗口默认打开**任务视图**（它排在左侧第一位）：

- **任务视图**：顶部选任务，左侧是「全局参数」+ 全部用户。选中「全局参数」时右侧
  只有可编辑的全局参数表单，没有两个开关——它没有"该用户"这层语义。
- **用户视图**：顶部选用户，左侧是该用户的全部日常任务，不出现「全局参数」。

只有当前视图那一维的下拉可见，另一维整列不显示：任务视图里挂一排用户名只会让人
以为它也在起作用。

顶部下拉右侧有「上一个 / 下一个」，切的是**当前视图顶部那个下拉**（任务视图切任务、
用户视图切用户），到两端自动禁用；`←` / `→` 与按钮同效，但焦点在输入框、多行文本与
数字框时方向键仍是光标移动。切换时保留左列表当前选中的那个对象（切任务不会把选中的
用户打回「全局参数」），否则每按一次方向键都要重新找人。

右侧固定顺序：`[] 当前用户跳过该任务` → `[] 当前用户使用独立参数` → 参数表单。
勾选跳过时参数区置灰但保留值；取消勾选即可继续编辑。

左侧列表用字体与颜色标注状态，跳过的条目另加 `⊘` 前缀，不单靠颜色表达：

- **使用独立参数** → 加粗；
- **声明跳过** → 灰色字（跳过后独立参数值仍保留，故两个标记可同时出现）；
- 条目之间留出行距，列表字号比默认大 2 号，长用户名与相邻任务不易看错行；
- 左区默认宽度按 14 个全角汉字留位（约 250px），只在首次填充时计算一次，
  用户拖动分隔条后不再回写。

底部一行左侧是「改动立即生效」，右侧是「关闭」；列表上方的说明行只讲方向键用法，
不再兼作状态提示。

编辑即落盘（文本输入 250ms 合并），因此窗口底部只有「关闭」：它是日常参数面板的
另一个投影，不是"打开快照、点保存整体覆盖"的配置对话框。

## 5. 日常页的对照区

日常页勾选「使用独立参数」后，参数区下方再显示一块「参数设置（全局参数）」：

- 两块都可编辑，各写各的归属：上块写该用户的 `workflow_params`，下块写全局
  `wf_configs`；
- 改全局值时，被该用户覆盖过的字段保持用户值，其余字段同步刷新——对照的意义就在
  这里；
- 正在编辑尚未落盘的字段不会被同步覆盖；
- 切执行用户只重建上块（全局值与该用户无关）；切脚本两块一起重建；
- 共享模式不显示下块：那时上块本身就是全局参数。

## 6. 不做的部分

- **不做「仅本次跳过」**：临时少跑用取消勾选覆盖；将来若需要，应与资料声明取并集，
  而不是再造一层语义。
- **不把跳过做成任务参数开关**：那需要每个 wf 作者改脚本，且仍要跑一次检查。
- **不让跳过拦截日常手动执行**：日常是用户显式选择的任务，声明只作用于自动调度。
