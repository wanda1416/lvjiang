# 外部 Agent MCP 接入与发行版能力包

> 状态：部分实现（2026-10-09，基线 v0.13.14）。桌面智能调律页、本机 MCP、文档打包、采集/分析接口、新配置生成与启动已实现；WorkBuddy GUI、Windows 发行安装及真实游戏闭环待实机验收。

## 1. 目标与交付边界

外部 AI Agent 通过律匠提供的 MCP 接口读取文档、查询授权数据、调用领域计算、
扫描全部备战方案、分析装备及培养方向、生成新的调律配置、启动任务并查询结果。
Agent 自行决定分析步骤和工具调用顺序；
律匠负责数据、计算、配置校验、授权和游戏执行，不依赖内置 AI 连接替 Agent 推理。

首版交付“Agent 配置并启动现有自动调律”：任务启动后，逐轮判断仍由现有基础规则
和毕业率智能调律执行。MCP 不在每轮等待外部 Agent 给动作，不改变现有评级、
材料、重置、回收及智能调律的含义。

用户只需安装发行版和配置支持 MCP 的客户端；完成接入后不需要源码、Git、
开发虚拟环境、原始 docs 目录或自行编辑 Python。发行版必须包含可用的服务入口、
连接说明、文档与接口定义，不能只交付开发者在仓库里运行的服务脚本。

首版由桌面律匠实例提供服务，复用该实例管理的 PC 或 Android 执行目标。
不包含 Android 本机独立 MCP 服务、远程公网托管、任意工作流执行、脚本编写、
备战方案自动应用、任意装备库编辑、自动执行培养/转律、概率模型、预算驱动决策
或运行中逐件 Agent 决策。授权扫描按既有流程更新方案、装备库与基础属性，
不属于任意数据编辑；培养建议只做分析和说明。

### 1.1 用户完整路径

1. 启动律匠，在“调律管理”旁打开同级“智能调律”页。
2. 页面展示 MCP 服务状态、接入说明、执行用户与目标的授权范围，提供复制/导出
   外部 Agent 接入配置。用户不需要找到安装目录或手写服务命令。
3. 用户在外部 Agent 中对话。Agent 检查数据是否完整、新鲜，提示用户扫描，
   或在已有扫描授权下直接调用“扫描全部备战方案”，等待完成后重新读取数据。
4. Agent 按实际方案读取相应玩法、评价规格与毕业率说明，并与用户确认想玩的
   流派/武学组合、玩法、目标方案和调律目标，不以当前穿戴或扫描默认玩法猜测意图。
5. Agent 调用计算，区分应替换的装备和现有装备可培养的空间，说明转律、承音、
   数值培养及定音等适用操作、前提和收益；无法计算的部分明确说明。
6. Agent 生成并校验全新的基础规则组、调律规则及与之匹配的运行选择，发布为
   可启动的配置结果。生成过程不修改随包配置或覆盖用户原有定义。
7. 智能调律页显示本次结果、目标、配置摘要、培养建议和“一键启动调律”。
   用户点击后，绑定该结果与显式用户/目标，复用现有预检和执行流程。
   用户也可在授权范围内通过 Agent 启动同一结果。
8. 任务进度和历史仍进入“调律管理”，Agent 可查询结果并与用户复盘。

以上是完整交付路径，不是强制 Agent 使用的固定提示链。已有完整数据时可以跳过
扫描；目标已明确时不反复询问。人工扫描、外部 Agent 和应用页面共享同一任务结果。

### 1.2 智能调律页与接入导出

新增页面由燕云插件右侧同级 Tab 注册，位置紧接“调律管理”，不是基础规则组
编辑器中的智能参数页。已有“启用智能调律”仍指毕业率判断开关；新页面负责
外部 Agent 接入、生成结果与启动，两者的状态和开关不能混用。

页面至少包含：服务启停/连接状态、复制与导出接入配置、简短操作说明、授权管理、
生成结果列表、结果详情及一键启动。启动软件后即可找到入口；无需填写律匠内置
AI 模型或 API Key。普通 UI 不展示内部规则 key 和源码路径；新下拉框使用
AutoWidthComboBox，运行中保留停止/暂停入口。

导出分为静态接入说明与本机连接配置：前者随发行包提供，后者由运行实例生成，
含所选接入方式要求的端点或已安装可执行程序、实例标识、客户端配置字段及导入
说明。导出结果必须足以配置支持该接入方式的 Agent，不只导出文档 ZIP。
不同客户端格式不统一时，明确提供通用描述和已验证格式，不宣称适用于所有客户端。

接入配置不打包用户装备或方案；如包含本机授权材料，页面标注为私人连接配置，
不进入公开发行包或源码，支持撤销和重新生成。导出不会启动扫描或调律，连接成功
也不会自动授予全部权限。文件仍指向用户选择的安装实例，实例不可用时给出恢复提示。

## 2. 已有事实与主要缺口

依据现有实现及已读取的 origin/dev 增量：

| 已有能力 | 现状 | 本需求要求补齐的边界 |
|----------|------|----------------------|
| AI 连接 | AIService 提供文本请求和连接测试 | MCP 是向外提供能力，不通过该接口调用模型 |
| 毕业率分析 | 有评分、假设投影、词条敏感度、最优组合与智能补全 | 建立可取消、可查询且口径明确的应用接口 |
| 调律配置 | 用户参数、规则定义和基础规则组已分离 | 创建独立新定义、成套发布及用户参数字段级更新 |
| 全部方案扫描 | scan_all_loadouts 已有逐方案装备与基础属性采集流程 | 开放专用授权任务，报告覆盖范围、逐方案成功/失败及写入结果 |
| 配置创建 | 规则管理器和基础组管理器已有创建/复制能力 | Agent 生成新对象并成套发布，不覆盖已有定义 |
| 调律启动 | TuningTab._start_tuning 收集配置、校验并构造 TuningRunContext | 抽出 UI 与 MCP 共同调用的启动服务 |
| 数据存储 | 用户元数据、loadouts JSON、Profile DB 与调律历史 DB 各有归属 | 按授权对象查询，不开放任意文件或 SQL |
| 发行打包 | Windows 复制 system 配置与运行依赖，未复制 docs | 加入独立 Agent 文档产物与打包后验收 |
| 文档 | 游戏机制、用户操作、需求、实现和过程分别维护，但个别正文混用 | 按[梳理清单](13-agent-docs-access.md)拆分正文与组织目录 |

本需求分析未将读取远端分支等同于本地工作区已经合入更新。未来公开的配置值与
计算结果必须取自连接实例的实际生效数据，不能固定使用本次分析的开发工作区值。

## 3. 首版能力

下表是业务能力要求，工具名称为拟定名称；实现时可合并同职责查询，但不得丢失契约。

| 能力 | 拟定入口 | 输入与可观察结果 |
|------|----------|------------------|
| 能力发现 | get_capabilities | 应用/API 版本、实际支持能力、已授权范围、可用执行目标摘要 |
| 文档发现与读取 | list_docs / search_docs / read_doc | 稳定文档 ID、主题检索、正文或明确章节；只读取包内清单 |
| 对象发现 | get_capabilities / list_targets / list_plans | 只列授权用户及目标；返回 ID、展示名和适用状态 |
| 方案上下文 | get_plan_context | 方案与装备/属性摘要、数据完整性、关联的玩法/毕业率文档 ID 及分析报告引用 |
| 方案扫描 | start_scan_all_loadouts | 用户、目标与公开扫描参数；异步任务 ID、范围及写入副作用，完成后可读取逐方案结果 |
| 装备查询 | query_equipment | 用户、部位和业务筛选、分页；返回真实/模拟身份、数据修订与采集时间 |
| 配置查询 | get_tuning_config / get_game_config | 有效配置、来源信息、修订与可写字段，不是只读取 system 默认值 |
| 模型发现 | list_graduation_schemes | 可用方案、适用玩法、等级和计算前提；不开放模型改写 |
| 分析 | evaluate_equipment / analyze_affix_impacts / search_best_combo | 明确用户、方案、候选及假设；返回计算结果、口径、未知原因和稳定结果引用 |
| 培养分析 | analyze_cultivation / simulate_transmute | 现有装备及方案；返回合法培养路径、转律与同名数值培养对照、收益、前提和缺失数据；不执行游戏操作 |
| 设置预览 | preview_generated_tuning | 完整新定义与运行选择；返回校验后的配置，不保存或修改已有定义 |
| 生成配置 | preview_generated_tuning / create_generated_tuning | 新基础规则组、新调律规则及运行选择；校验、预览后成套保存，返回稳定生成结果 ID |
| 生成结果查询 | list_generated_tuning | 返回授权用户的目标摘要、建议、规则/组引用、修订及可启动状态，供 UI 与 Agent 共用 |
| 保存用户选择 | update_tuning_config | 字段补丁、基准修订及已授权范围；不修改已有规则/组定义 |
| 启动预检 | validate_auto_tuning | 用户、目标、有效运行参数；返回阻断原因、警示、配置摘要及动作范围 |
| 启动任务 | start_auto_tuning | 生成结果 ID 或既有配置、用户、目标及幂等请求标识；返回任务 ID 和冻结摘要 |
| 任务控制 | get_task_status（action=status/pause/resume/stop） | 任务 ID；返回状态及控制结果，不能把停止请求已接收说成任务已结束 |
| 结果复盘 | get_tuning_results / query_tuning_history | 按授权用户、目标、任务及时间筛选和分页；返回实际产出与处置理由 |

查询接口可附带有效配置的 YAML/JSON 表示，但不接受客户端自定磁盘路径。
配置可用值和约束从现有领域模型及校验器获得，不在 MCP 另维护并行枚举和游戏规则。
没有可靠库存数据时返回未知及来源，不以 Profile 总览或旧历史猜测实时游戏库存。

较长的计算与游戏任务异步返回作业/任务 ID，并可查询、取消。工具响应大小有界，
列表分页，结果先提供摘要与引用，Agent 按需展开。实际支持能力来自运行实例，
不支持的模型、玩法或执行端返回明确原因，不静默换方案或目标。

## 4. 状态、设置与数据所有权

### 4.1 四种状态

1. 持久化定义：规则与基础规则组，供多用户复用。
2. 持久化用户选择：用户调律参数、所选规则/玩法、基础组及每组智能启用值。
3. 草稿：Agent 提议的修改与 UI 尚未保存的编辑内容。
4. 运行态：本次覆盖参数、实际执行顺序、配置和数据快照、任务进度及产出。

预览不保存、不改变 UI 编辑对象或默认选择。保存用户配置只更新所属字段；
start_auto_tuning 的覆盖参数只用于本次任务，不自动保存。API 不能把读取时的
陈旧整文件覆盖回磁盘，必须对最新对象做字段合并与修订冲突检查。

基础规则组和规则定义是共享对象。Agent 生成必须自动创建新基础组和新调律规则，
可从既有定义派生，但使用新的稳定 key，并拒绝所有已有 key 的覆盖，包括 local
中的同名对象。重做方案产生新版本；相同幂等请求重试返回原结果，不能重复建对象。
新建名称/文件/key 不含真实用户名、账号或设备信息；生成缘由与私人目标另存结果记录。
首版不开放 Agent 对既有组/规则的修改、删除、重命名或移动。

新基础组保存材料、扫描处理、调律处理与智能参数；新调律规则保存目标玩法、词条池、
部位条件及评级逻辑。规则无需一玩法一条，按实际语义组织。创建时复用公共游戏配置、
既有解析和合法性校验，不为新规则修改游戏事实或注册表。已有 schema 无法表达的
目标明确报告，不能声称目标已经落实；如需新字段，另行设计公共契约。

生成结果除基础组/规则外，包含部位、玩法选择、现有开关值和智能启用值等运行参数，
关联目标方案、数据修订、分析引用与培养建议。私人关联存于 session 的独立结果记录，
不写入共享规则 YAML。成套校验成功后才标记可启动；部分落盘失败不能发布半套配置。
新对象创建不修改活动方案、默认基础组或规则选择；一键启动用指定结果构造本次快照。
只有用户明确选择“设为默认”时才字段级保存用户选择。人工编辑已有生成规则后，
结果复核修订并提示差异，不能覆盖该编辑或不经复核启动。

### 4.2 扫描与目标交流

扫描复用 scan_all_loadouts 及其数据写入路径：切换游戏方案、采集装备和弓玦、
必要时反推基础属性并按既有规则保存。工具说明必须声明这些真实副作用。
启动同时需要目标任务执行与指定用户采集写入授权；查询授权不能启动扫描。

当前扫描仅覆盖游戏方案列表可见网格，不滚动；接口和 Agent 必须报告此限制，
不能把本次扫描结果宣称为游戏全部方案无遗漏。返回发现、成功、跳过、失败及原因，
全部失败不算成功；失败/遗漏/陈旧方案不作为已同步数据参加后续计算。
本需求复用现有覆盖范围，扩大到网格外另行实现并验收，不能在文档中提前承诺。

扫描不改变应用活动方案，但会切换游戏实际方案，保留既有弹窗处理与安全停止。
同名方案武学冲突、玩法不明、装备未扫全与基础属性不可靠沿用现有隔离规则。
首次创建的默认玩法只是采集绑定，不等于用户最终想玩的玩法。Agent 在对话中确认
目标并按选定玩法计算；可以暂存派生分析上下文，不自行改写用户原方案。

培养建议分别说明现状、合法操作、立即收益和培养假设下收益；模拟转律只生成建议，
不保存真实装备或方案转律目标。装备指纹与方案/槽关联必须可追溯，不能将模拟装备
当真实候选；未知材料需求不估造数值。不必更换的装备也给出保留/培养依据。

方案上下文提供匹配的公共文档 ID，避免 Agent 从名称猜测文档；生成的方案分析
报告属于授权用户的派生结果，记录目标、数据修订、装备关联及假设，供 Agent 和
智能调律页共同读取，不混入静态知识包。无适用毕业率模型时仍可读取机制及评级，
但不得编造毕业率数值或用另一流派模型替代。

### 4.3 查询与计算

授权用户通过服务端可解析的引用定位，不使用翻译文本、客户端文件名或界面当前项
定位。已有内部用户名保持原存储语义，对外引用不要求迁移用户文件。

备战方案、真实装备、模拟装备与计算副本分别标识。计算不修改来源对象；结果注明
数据修订、玩法、基准、培养假设、算法完成情况与适用范围。最大潜力不解释为概率，
候选在假设下的收益不解释为已经获得；未知不能转换成“没有价值”。

武学组合按无序匹配，主副装备槽仍分别定位。装备评级与毕业率分别返回。
数据不完整、无适用方案和单条异常在所属范围内隔离并给出可行动原因。

## 5. 授权与文件边界

智能调律属于 Lv1 功能。未激活 Lv1 时，所有 MCP 访问统一返回
“智能调律需要激活 Lv1，请在设置的「功能激活」中激活”，包括初始化、能力/工具/
资源发现、文档读取、公共配置和用户数据查询及所有写入、任务操作。门禁位于
服务传输入口，每次请求检查当前授权；已连接的客户端也不能绕过。页面保留入口，
显示激活提示并禁用开启接入和一键启动；关闭已开启的接入仍然可用。

授权采用文档阅读、公共配置读取、用户数据读取、采集写入、新配置生成、用户选择
保存、目标任务执行等独立范围，并限定用户、目标及动作。允许用户一次授权
连续操作；不要求每个普通查询和每个已授权字段更新再次确认。

权限必须由服务端逐次执行，文档不能代替检查。未授权的对象不通过列表、搜索、
错误或结果引用泄露。无法识别的授权范围、字段和动作拒绝，不自动扩权。
连接到服务不等于得到全部数据和执行权限；本地连接同样绑定实际授权。

任务预检及启动复核最终有效配置中的回收、重置、锁定、材料使用等动作，不只检查
工具名。如果超出授权则拒绝启动并指出对应配置；运行时也不得执行范围外动作。
共享配置变化、用户覆盖参数和“调满后回收”等间接路径不能绕过限制。
复用既有高风险 UI 的确认要求时，应在具体预览后提供明确授权入口，不用参数
confirmed=true 冒充真实授权，也不新增每轮阻塞式弹窗。

文件族、节点、可读可写范围和保存位置见[访问清单](13-agent-docs-access.md#4-配置与数据访问清单)。
system 和 remote 不可由 MCP 写入；修改按发行版语义落 local 或用户所属节点，
不提升 content_version。即使在开发工作区验证 MCP，也不能通过开发模式写 system。

不提供通用文件浏览、任意路径读写、SQL、Shell、Python 执行或任意脚本启动工具。
包内文档按稳定 ID 读取；实际路径验证不得允许越界、链接逃逸或凭据文件访问。
外部 Agent 若另有整机文件权限，那属于其宿主的授权，MCP 不能限制接口以外的访问。

## 6. 执行与观察

启动必须显式解析执行用户与目标，复用已有授权等级、目标占用、图库必需字段、
规则/玩法和基础组校验。MCP 不模拟点击 UI，不另建一套调律执行器。
UI 和 MCP 调用同一应用服务；Qt 控件更新经原有线程与信号边界进行。

任务启动冻结用户、目标、规则、基础组、参数、方案和执行顺序。启动前预览的内容
如已变化，重新校验并报告；运行中修改持久化配置只影响以后任务。

start_auto_tuning 的幂等标识在相同调用身份及作用域内复用时返回原任务，参数不同
则报告冲突。相同执行目标不能因并发请求重复启动。状态及控制接口按任务 ID 定位，
不得停止或恢复另一个用户/目标的任务。

客户端断连不取消已经启动的游戏任务；用户可重连查询与控制。律匠退出后不自动
重放任务；中断状态应可追踪。暂停/停止由本地任务层及时响应，服务查询、计算和
网络连接不能阻断这些操作。需要人工处理时返回 waiting_user 及原因，保留停止入口。

配置修改与任务动作记录调用来源、对象引用、实际差异/动作、配置修订和结果，
与现有进度及历史保持一致；不记录凭据、完整私有文件、超长原始响应或全部装备数据。
客户端可查询任务状态、阶段、处理统计、异常、终态和逐件结果；轮询是必需能力，
订阅属于可选优化，不依赖特定客户端支持。

## 7. Agent 文档包与发行输出

来源、拆分与排除清单见[文档梳理](13-agent-docs-access.md#2-现有文档梳理)。
源码目录按“共享领域正文 / Agent 操作契约 / 用户界面与维护文档”组织，发行产物
将允许收录的正文集中为 agent 目录。不得把开发需求和实施计划打包为可用功能说明。

```text
agent/
├── README.md
├── manifest.json
├── docs/
│   ├── domain/
│   ├── contracts/
│   ├── operations/
│   └── examples/
└── schemas/
```

README 只提供最小入口、能力发现、文档索引和使用边界。完整知识按主题读取，
不要求把所有文档一次塞进上下文。除 MCP Resources 外，提供文档发现、检索和
读取工具，让不主动加载 Resources 的客户端也能完成闭环；Prompts 为可选示例。

manifest 记录应用版本、API 契约版本、文档稳定 ID/主题、文件清单与摘要及能力
关联。公共 schema 从实际接口定义生成；清单不是运行授权的另一份真值。
文档数值示例明确是假定数据，动态枚举、上限、默认值以连接实例查询为准。
远端配置或 local 覆盖导致差异时返回实际内容及来源，不要求随覆盖重写静态正文。

构建按明确收录清单输出，不扫描全仓库或沿链接自动扩张。重写包内相对链接并检查
正文、锚点和必要附件闭合；拒绝必须依赖源码/维护文档才能理解的引用。
文本及 JSON 读写显式 UTF-8。打包、服务资源和独立 ZIP 使用同一构建结果。

首版输出：Windows 安装器和便携版均带 agent 目录；另输出
lvjiang-agent-vX.Y.Z.zip，可供离线查阅，不能单独执行任务。发行校验和包含新增
ZIP。服务入口必须随发行版可执行文件提供，不要求用户安装 Python 或下载代码。
公开接入模板不含凭据；智能调律页另行导出实际实例的私人连接配置，不能将其混入
静态文档包。导出字段、安装路径解析与客户端导入需在发行版中验证。

安装升级时官方 agent 目录按完整集合替换，处理旧文件残留；不清理 local、session
或用户数据。便携版继续遵守解压到新目录的升级约定。
API 契约版本用于发现不兼容行为，不等于应用版本或 content_version。
旧独立文档包与运行实例不匹配时提示使用实例随包文档与 schema，不静默按旧参数执行。

## 8. 实施顺序与影响范围

| 阶段 | 交付 | 涉及现有边界 |
|------|------|--------------|
| 1 | 按清单拆分正文、建立共享公开目录及 Agent 契约目录 | 更新活文档引用与索引，不重写开发历史事实 |
| 2 | 文档构建、manifest、schema 输出及独立 ZIP | Windows 打包、安装升级、发行校验和与产物检查 |
| 3 | 统一采集、培养分析、新配置生成、启动预检及任务控制服务 | scan_all_loadouts、评分/转律内核、规则管理器和现有任务宿主 |
| 4 | 智能调律同级页、MCP 适配、接入配置导出与生成结果管理 | 插件 Tab 注册、应用生命周期、用户/目标权限及 Qt 线程边界 |
| 5 | 从干净发行包完成端到端验收与用户接入说明 | 原 UI 流程和 MCP 入口一起验证 |

传输采用本机 Streamable HTTP，页面导出端点与私人令牌；首版要求同机连接到
已运行的律匠实例、支持多个安装实例的明确选择、隔离授权并可撤销。
不以公网服务替代本地交付，不启动不可见的第二套游戏任务宿主。

70-agent 层已建立，并纳入文档索引与检查；共享事实仍只在
10-game 维护，Agent 操作契约不承载源码实现说明。需求留在 20，架构留在 30，
接入步骤进入用户指南；接口和文档按实际实现维护，未验收客户端与平台明确标注。

## 9. 验收标准

以下均为待实施验收，不表示本次需求整理已执行。

| 场景 | 必须观察到的结果 |
|------|------------------|
| 未开通 Lv1，或连接期间清除激活 | 初始化、发现、文档与数据读取、写入和执行均返回 Lv1 提示，无工具/资源被调用；页面禁用开启接入与一键启动 |
| 干净发行目录，无 Git/源码/原始 docs/Python 开发环境 | Agent 完成发现、读文档、查询、分析、设置预览与保存、启动、跟踪和结果查询 |
| 软件启动后打开调律管理旁的智能调律页 | 可复制/导出接入描述，在已验证客户端接入；不要求内置模型配置 |
| 授权 Agent 扫描全部备战方案 | 复用采集路径，报告可见网格覆盖及逐方案结果；缺授权不执行，未完成数据不当作已扫描 |
| 对话目标与扫描默认玩法不同 | 按用户目标及合法武学组合分析，原活动方案和持久化玩法不被静默改变 |
| 分析现有装备培养与替换 | 提供实际数据支持的建议及假设，计算副本不写回真实装备，转律不自动执行 |
| 客户端不加载 Resources | 文档工具仍提供足够上下文，无需访问仓库 |
| 包内链接与清单检查 | 所有收录文档和必要附件完整，未收录文件不因链接被自动带入 |
| 新旧安装包升级 | 删除旧官方 Agent 文件，保留用户配置与数据 |
| 文档、schema 与服务对照 | 能力及字段一致；模型不适用、未实现能力返回明确原因 |
| local/remote 覆盖 system | 查询返回有效值与来源，保存只落允许层且保留内容版本 |
| 查询后 UI 或另一进程修改同对象 | 更新拒绝陈旧修订；无关字段不回滚，失败不留下部分写入 |
| 预览、临时运行、编辑组切换 | 不改变持久化默认；运行重排不反写配置，重载按持久化值构造 |
| Agent 生成新配置，已有 system/remote/local 定义存在 | 新基础组和新规则独立 key；已有定义完全不变，无私人身份进入 YAML/key/文件名 |
| 重试生成、重做方案或保存中途失败 | 重试幂等，重做创建新版本，失败不发布半套可启动结果 |
| 用户点击生成结果的一键启动 | 使用该结果的组、规则与参数快照，复核修订和授权；不默认改变用户持久化选择 |
| 未授权用户/目标/动作，包括间接回收路径 | 查询及执行均被拦截，不泄露其他对象，不静默扩大授权 |
| 重复/并发启动与取消请求 | 相同幂等请求无重复任务；目标占用冲突明确；取消不串任务 |
| 客户端断连、重连与应用退出 | 状态可追踪，重连可控制，退出后不自动重放 |
| 搜索、服务请求或人工等待期间点击停止 | 本地停止入口可用并最终返回正确终态 |
| 计算与原对象对照 | 真实/模拟/派生结果可区分，数据不变，毕业率口径与原引擎一致 |
| 发行产物检查与默认 GBK 环境 | 无私人配置、凭据或开发数据；文档构建与读取使用 UTF-8 |

持续业务边界编写最少代表回归；真实游戏端到端与发行包安装检查采用发布验证或
显式手动验收，不为某次本机数据建立常驻用例。测试只用临时目录和 fake。
