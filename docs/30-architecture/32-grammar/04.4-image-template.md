# by image — Region 模板匹配

`by image` 使用固定 UI 小图做灰度相关匹配。它由 `scan` 和 `find` 共用，但两条
指令解决的问题不同：

| 指令 | 回答的问题 | 搜索范围 | 返回值 |
|------|------------|----------|--------|
| `scan ... by image` | 哪个候选 Region 命中自己的模板 | 每个 Region 自身 | 首个命中的 Region key，或 `""` |
| `find ... by image B` | 模板 B 在哪里 | 全画布或显式范围 A | 实际命中的 `FoundRegion`，或 `""` |

模板的布局数据见
[场景与布局定义](../34-scene/01-scene-layout-definition.md)，编辑器操作见
[场景布局编辑](../34-scene/02-scene-layout-editing.md)。

---

## 一、scan：在各 Region 内判断

### 语法

```text
scan [scene].[r1, r2] as $hit by image
scan [scene] as $hit by image
scan [scene].[r1] as $hit by image where confidence >= 0.9
```

`scan` 的 `by image` 后面不写 target。每个候选 Region 使用它在**当前布局**绑定
的模板，并且只在该 Region 外框内部搜索。引擎只截取一次画面，按 Region 声明
顺序匹配，首个命中立即返回：

```text
scan [general_control].[confirm, cancel] as $button by image
if $button
    click [general_control].$button
end
```

返回的 `$button` 是字符串 key，例如 `"confirm"`，不是图像命中的坐标。后续
`click [scene].$button` 仍按布局 Region 激活；若 Region 有 `click_rect`，点击使用
该显式落点范围。

### 候选选择规则

- 显式列出的 Region 必须全部存在、处于启用状态并绑定有效模板；配置缺失直接报错。
- `scan [scene] ... by image` 只选择当前布局中启用且已绑定模板的 Region，跳过未绑定项。
- 禁用 Region 不能作为显式 scan 候选。
- 匹配窗口严格限制在各 Region 内，不会向外扩展。
- Panel 和 Point 不支持该形式。
- `scan ... by image "name"` 和 `scan ... by image [scene].[region]` 均非法；scan
  的模板来源就是每个被扫描 Region 自己。

## 二、find：用模板 B 在范围 A 内定位

### 推荐语法：Region 模板绑定

```text
# A 省略：在整个布局画布中寻找 B 绑定的模板
find as $back by image [game_menu_page].[back]

# A = popup.body：只在该范围寻找 B 绑定的模板
find [popup].[body] as $back by image [game_menu_page].[back]
```

这里有两个相互独立的角色：

- `find` 后、`as` 前面的 **A 是搜索范围**。它可以是 Region 或 Panel；省略时搜索
  整个布局画布，而不是画布以外的原始截图区域。
- `by image` 后面的 **B 是模板来源 Region**。引擎从当前布局读取 B 的
  `template.name`、录制画布尺寸和默认阈值；B 自身的矩形不是搜索范围。

因此，同一份工作流可以在桌面、投屏等布局下自动选择各自模板，不需要在脚本里
写布局目录名。

### disabled Region 作为纯模板载体

B 可以设置 `disabled: true`。这种 Region 只负责为当前布局保存模板绑定：

- 不允许通过 `click [scene].[B]` 激活；
- 不会成为 `scan [scene] ... by image` 的候选；
- 仍可被 `find ... by image [scene].[B]` 读取模板；
- B 的坐标和禁用状态都不会限制 find 的搜索位置。

B 仍必须在当前布局中存在并拥有有效的 `template` 绑定。模板文件不存在属于配置
错误，会立即报错，而不是当作画面未命中返回 `""`。

### 兼容语法：显式模板名

```text
find as $icon by image "extract_icon"
find [map].[canvas] as $icon by image "extract_icon"
find as $icon by image $template_name
```

字符串或变量直接指向 `templates/<name>.png`，适合不随布局变化的全局模板。布局
相关 UI 应优先使用 Region 引用，避免脚本写死 `<布局根>/...` 路径。

### 返回与点击

`find` 返回模板实际命中的归一化矩形 `FoundRegion`；未命中返回 `""`：

```text
find as $back by image [game_menu_page].[back]
if $back
    click $back
end
```

`click $back` 点击实际找到的位置。不要写 `click [game_menu_page].[back]`，后者尝试
激活模板载体 B，既不是命中位置，在 B 被禁用时也会报错。

## 三、置信度阈值

```text
find as $back by image [game_menu_page].[back] where confidence >= 0.9
scan [scene].[r1, r2] as $hit by image where confidence >= $threshold
```

| 情况 | 使用的阈值 |
|------|------------|
| Region 绑定且未写 `where` | 该绑定的 `template.min_score` |
| 显式模板名且未写 `where` | 全局默认值 `0.8` |
| 写了 `where confidence >= x` | `x` 覆盖上述默认值 |

匹配采用 OpenCV `TM_CCOEFF_NORMED`，分数按 `0..1` 使用。低于阈值属于正常未命中，
返回空值，不抛出错误。

## 四、模板文件和布局元数据

`templates/` 目录只存图片：

```text
config/system/templates/<name>.png
```

用户层可在 `config/local/templates/` 放置同名覆盖。匹配所需的其他数据全部保存在
Layout JSON 的 Region 绑定中：

```json
"template": {
  "name": "desktop/game_menu_page/back",
  "min_score": 0.8,
  "record_w": 2400,
  "record_h": 1080
}
```

- `record_w` / `record_h` 是截取模板时的布局画布尺寸。
- 运行时按 `当前画布宽 / record_w` 计算基准缩放，并尝试基准值及其上下 10%；
  同时保留 `1.0` 作为兜底。
- 显式字符串模板没有 Region 布局元数据，只尝试原始尺寸及其上下 10%。
- 场景编辑器自动生成 PNG 和 Region 绑定，不生成 sidecar JSON。
- 编辑器“解除绑定”随布局保存同时清理当前可写层的 PNG，避免废弃模板累积；
  用户模式不会越权删除系统下发的只读模板。

自动生成的模板逻辑名为：

```text
<布局根>/<scene key>/<region key>
```

脚本使用 `[scene].[region]` 引用后，该内部名称不再暴露给工作流作者。

### 截取范围

模板裁剪与 `click_rect` 完全独立：

- “截取模版”直接使用完整 Region 外框；
- “部分截取”使用本次在 Region 内拖出的紫色框；
- `click_rect` 只控制点击落点，既不限制也不扩大模板图片。

手动框选只是一次性裁剪选择，不在布局中增加第三个矩形字段。

## 五、错误与空结果

| 情况 | 结果 |
|------|------|
| 模板存在，但当前画面得分低于阈值 | 返回 `""` |
| `scan` 显式候选未绑定、已禁用或没有模板 | 配置错误，终止执行 |
| `find` 的搜索范围 A 未绑定或已禁用 | 配置错误，终止执行 |
| `find` 的模板来源 B 不存在或未绑定模板 | 配置错误，终止执行 |
| 模板 PNG 不存在或无法解码 | 配置错误，终止执行 |
| 截图失败 | 返回 `""` 并记录截图失败日志 |

静态引用能够确定时，工作流预检会提前报告缺少 Region、模板绑定或模板文件。

## 六、与 recognize / find_icons 的区别

- `by image` 是固定 UI 模板的灰度相关定位，适合按钮、Logo、状态图标。
- `recognize` 是参考图库分类，回答“这个槽位中的对象是哪一种”，使用 ORB 特征。
- `find_icons` 用颜色和轮廓一次寻找多个同类图标，详见
  [06.4-vision-functions.md](06.4-vision-functions.md)。
