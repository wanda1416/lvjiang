# v0.15.3 — 无线设备发现重做、任务运行中回传历史与 Shizuku 自动启动

发布日期：2026-10-22。以 v0.15.2 正式标签（`e9db152a`）为基线。

本版本是 0.15.2 的补丁版本：重做手机无线调试的设备发现，允许任务运行中回传历史与日志，
并新增连接端侧执行前按需启动 Shizuku 的开关。官方配置内容未变化（`content_version` 未提升），
不需要重新下发配置；建议 0.15.x 用户升级。

## ⚠️ 不兼容变动与升级指引

本版本没有配置结构、`.wf` 语法、布局与场景键名上的不兼容变动，`config/local` 与数据库
不需要迁移；新增的 Shizuku 自动启动开关默认关闭，升级后行为与 0.15.2 一致。
以下一项是升级后能直接观察到的变化。

### 任务运行时工作目录下会出现 `.task`

- **现象：** 执行任务期间，工作目录（程序所在目录）下会出现 `.task` 目录，里面是本次
  任务的配置副本；任务结束或程序正常退出后自动清空。
- **原因：** 0.15.2 及更早把配置副本放在系统临时目录。受限环境（低完整性令牌、沙箱控制台）
  里临时目录整体不可写时，整份副本会被倒进当前工作目录，且强杀进程后不会回收。
- **如何调整：** 无需操作。该目录可以随时删除，下次运行会自动重建；请不要在任务运行期间
  手动清空它。若上次是强杀退出，超过 24 小时的旧副本会在下次启动时自动清理。

## ✨ 新增功能

- **任务运行中也可以回传历史与日志**：历史导出只取已结束的记录，运行中的任务与未结束批次
  由导出查询自动跳过，结束后再次回传即可补齐。因此不再要求先结束手机任务：PC「回传到电脑」
  区域在任务运行中保持可用，设备端只在 PC 正在控制设备时才拒绝回传。导出不再持有任务控制锁，
  不会阻塞启动、配置下发或批量保存。
- **连接端侧执行时按需自动启动 Shizuku**：设置 →「高级设置」→「Android 连接恢复」新增
  「连接端侧执行时自动启动 Shizuku 服务」，默认关闭。手机重启后 Shizuku 服务进程会死亡，
  需要重启游戏的任务会直接失败；开启后在建立端侧执行连接前做一次只读检测，仅当服务未运行时
  才启动一次并轮询确认。路径按设备实际安装位置动态解析，不受每次安装随机目录影响；未安装
  或启动后仍未就绪只提示、不阻断连接。

## 🔧 修复

- **Android 11+ 手机无线调试连不上**：0.15.2 逐 IP 探测 5555 端口，而 Android 11+ 的无线
  调试使用随机端口，永远发现不了；先做 ping 预筛还会把息屏手机直接判死。现在先读
  `adb mdns services`，再读系统 ARP 邻居表（先发 UDP 触发解析，不依赖 ICMP 存活），
  只对少量候选做 TCP 确认；两条通道都没有候选时才回退逐网段扫描，覆盖跨 VLAN 场景。
  确认后的端点按 IP 去重；同一网段出现异常多的「开放端口」时提示疑似 TUN/VPN 代理接管了
  出站连接。无需手动改配置。
- **任务快照不再占用系统临时目录**：受限环境里系统临时目录不可写时，配置副本会落到当前
  工作目录且强杀后残留。现在固定使用工作目录下的 `.task`，进程退出回收，并清理超过 24 小时
  的旧代次。用户无需操作。

## 📦 重构

- 仓库内无线连接脚本 `scripts/adb_wireless.py` 改为复用应用内的完整发现流程，不再单独维护
  一套逐端口扫描，避免它与主程序行为不一致。仅影响开发脚本，不影响客户端使用。
- 预置打包改为只读 git 索引跟踪的官方文件，并把文本行尾归一为 LF 后再计算摘要；编辑器运行
  快照、录制草稿与 `_testwf/` 等私人脚本固定写入 `config/local`，开发模式下不再落进
  `config/system`。官方预置摘要未变化，已发布预置不需要重发。

## 📚 文档

- 移动设备指南与离线任务需求补充：回传历史不再要求结束手机任务，运行中的记录自动跳过。
- 设备代理协议更新 `history_begin` 的语义：任意状态下都可冻结历史包，只取终态记录。
- 配置分层与 Android 预置需求补充编辑器草稿固定写 local、打包只读索引并按 LF 归一的口径。
