# 装备领域模型定义

本文档定义装备数据的严格结构化格式，作为 OCR 识别、数据清洗、工作流处理、毕业率计算等模块的共同契约。

> 游戏规则（调律/转律/承音机制等）参见 [装备系统介绍](../10-game/01-equipment-system.md)。

---

## 一、装备结构定义

一件装备由以下字段组成：

```json
{
  "slot": "main_weapon",
  "type": "剑",
  "level": 110,
  "quality": "gold",
  "is_chengyin": true,
  "base_attr": { "name": "外功攻击", "value": [100, 232] },
  "base_attr_2": null,
  "affix_1": { "name": "最大外功攻击", "value": 114.1, "is_transferred": false },
  "affix_2": { "name": "会意率", "value": 6.6, "unit": "%", "is_transferred": false },
  "affix_3": { "name": "势", "value": 72.2, "is_transferred": true },
  "affix_4": { "name": "最大外功攻击", "value": 114.1, "is_transferred": false },
  "affix_5": { "name": "剑武学增伤", "value": 9.2, "unit": "%", "is_transferred": false }
}
```

---

## 二、字段详细说明

### 2.1 部位 `slot`

共 10 个部位，核心调律考虑前 8 个：

| 键名 | 中文名 | 类别 | 是否考虑 |
|------|--------|------|----------|
| `main_weapon` | 主武器 | 武器 | ✓ |
| `sub_weapon` | 副武器 | 武器 | ✓ |
| `ring` | 环 | 首饰 | ✓ |
| `pendant` | 佩 | 首饰 | ✓ |
| `head` | 冠胄 | 防具 | ✓ |
| `chest` | 胸甲 | 防具 | ✓ |
| `leg` | 胫甲 | 防具 | ✓ |
| `wrist` | 腕甲 | 防具 | ✓ |
| `bow` | 弓 | 特殊 | ✗ |
| `shoot_jade` | 射玦 | 特殊 | ✗ |

### 2.2 类型 `type`

武器类型的枚举值（主武器和副武器共享同一类型）：

| 类型 | 对应流派 |
|------|----------|
| 剑 | 鸣金·虹、鸣金·影 |
| 枪 | 鸣金·虹、鸣金·影、裂石·威 |
| 扇 | 牵丝·玉、牵丝·霖 |
| 陌刀 | 裂石·威、裂石·钧 |
| 双刀 | 破竹·风 |
| 伞 | 牵丝·玉、牵丝·霖、破竹·尘 |
| 绳镖 | 破竹·风、破竹·尘、破竹·鸢 |
| 横刀 | 裂石·钧 |
| 手甲 | 破竹·鸢 |
| 舞绫鼓 | 牵丝·翊 |
| 扇 | 牵丝·翊 |

### 2.3 装备等阶 `level` + `is_chengyin`

| 字段 | 类型 | 说明 |
|------|------|------|
| `level` | int | 装备等阶数字（如 96、100、105、110） |
| `is_chengyin` | bool | 是否为承音装备 |

### 2.4 装备品阶 `quality`

装备的品质稀有度，决定装备的基础色调和上限潜力：

| 枚举值 | 中文名 | 颜色 |
|--------|--------|------|
| `gold` | 金色 | 金/橙色边框 |
| `purple` | 紫色 | 紫色边框 |
| `blue` | 蓝色 | 蓝色边框 |
| `green` | 绿色 | 绿色边框 |

品阶从高到低为：金色 > 紫色 > 蓝色 > 绿色。

### 2.5 基础属性1 `base_attr`

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 属性名称 |
| `value` | int \| [int, int] | 武器为二元组 `[min, max]`，防具为单一整数 |

**武器基础属性**：
- 名称固定为 `外功攻击`
- 值为取值范围二元组，如 `[100, 232]`

**防具基础属性**：
- 名称为 `气血最大值` 或 `外功防御`
- 值为单一整数

### 2.6 基础属性2 `base_attr_2`（仅防具）

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 属性名称（固定为 `外功防御`） |
| `value` | int | 属性值 |

**武器和首饰该字段为 `null`**。

### 2.7 词条 `affix_1` ~ `affix_5`

每件装备固定 5 条词条，每条结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 词条名称（见第三章枚举） |
| `value` | float | 词条数值 |
| `unit` | string \| null | 单位，百分比类为 `"%"`，否则为 `null` |
| `is_transferred` | bool | 是否为转律产出 |

## 四、OCR 原始输出格式

OCR 识别输出为原始文本，需经过清洗才能转换为上述结构化格式：

```json
{
  "main_weapon": {
    "equip_type": "踏雪含光 | 武器·剑",
    "equip_level": "承音 | 110阶",
    "base_attr": "外功攻击100~232",
    "affix_gong": "最大外功攻击荐114.1",
    "affix_shang": "会意率荐 6.6%",
    "affix_jue": "［转]势荐72.2",
    "affix_zhi": "最大外功攻击荐114.1",
    "affix_yu": "剑武学增伤荐9.2%"
  },
  ...
}
```

### 清洗规则

| 原始字符 | 处理 |
|----------|------|
| `荐` | 移除（OCR 噪声） |
| `[转]`、`【转]`、`［转]` | 标准化为 `is_transferred: true` |
| `\|` 分隔 | 拆分 `equip_type` 为名称和类型 |
| `承音 \|` | 解析 `is_chengyin: true` |
| `XX阶` | 提取数字为 `level` |
| `攻击100~232` | 解析为二元组 `[100, 232]` |

**数据清洗模块**：词条清洗逻辑待实现，将作为 OCR 后处理步骤集成到工作流引擎（`WorkflowEngine` + `.wf` DSL）中。

## 六、装备指纹 `_fp`

每件装备在存储时携带一个 `_fp` 字段作为去重标识，用于背包管理、装备/卸载、模拟装备等场景。

### 6.1 计算规则

```
拼接字符串 = type + level + quality + is_chengyin + affix_1~5(name:value)
_fp = MD5(拼接字符串)[:8]   # 取前 8 位十六进制字符
```

各部分用 `+` 连接，示例：

```
剑+110+gold+True+最大外功攻击:114.1+会意率:6.6+势:72.2+最大外功攻击:114.1+剑武学增伤:9.2
```

### 6.2 参与字段

| 字段 | 参与 | 说明 |
|------|------|------|
| `type` | ✓ | 装备类型（如 "剑""环"） |
| `level` | ✓ | 等级（如 110） |
| `quality` | ✓ | 品阶（"gold""purple"） |
| `is_chengyin` | ✓ | 是否承音（True/False） |
| `affix_1` ~ `affix_5` | ✓ | 每条词条的 `name:value` |
| `dingyin` | ✗ | **定音词条故意不包含** |
| `base_attr` | ✗ | 基础属性不参与 |
| `_extra` | ✗ | 扩展标记不参与 |

**定音词条不参与指纹的原因**：装备可能切换定音，五个词条数值完全相同的概率极低，包含定音会导致同一件装备换定音后被误判为不同装备。

### 6.3 模拟装备约定

模拟装备的 `_fp` 使用 `mock_` 前缀：

```python
_fp = f"mock_{make_fingerprint(equip_data)}"
```

这确保模拟装备指纹与真实装备指纹永不冲突。**每次编辑模拟装备的词条/数值后必须重新生成指纹。**

### 6.4 存储位置

| 类别 | JSON 节点 | 说明 |
|------|-----------|------|
| 真实装备 | `bag_items` | 按部位分组，以 `_fp` 为 key |
| 模拟装备 | `mock_items` | 结构同上，以 `mock_` 前缀 `_fp` 为 key |

两者结构相同（`{ group_key: { _fp: equip_data } }`），但在扫描工具 (wf) 扫描时必须分离，因此分开存储。UI 展示时将两者合并，模拟装备卡片带「模拟」标签。
