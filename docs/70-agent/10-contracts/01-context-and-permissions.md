# Agent 对象与权限契约

所有 MCP 访问以 Lv1 激活为前提，包括初始化、发现、文档和公共配置读取。
收到 lv1_required 错误时，请提示用户在律匠设置的“功能激活”中激活 Lv1；
已有连接同样受此限制，不应换工具或资源尝试绕过。

用户在律匠授予当前连接指定用户与执行目标的读取、扫描、生成、任务执行权限。
回收、重置、狗粮和锁定分别授权；授权可以撤销，不需要在每轮调律重复确认。
必须先读 get_capabilities。未获授权时向用户说明需要在智能调律页调整哪项权限。

查询返回本地方案，不证明与游戏当前状态一致。start_scan_all_loadouts 会切换游戏
方案，并按既有采集规则更新装备库、方案及反推基础属性。当前仅覆盖可见网格，
不要宣称列表外方案也已扫描。使用任务 ID 轮询 get_task_status，成功后重新读取；
scan_results 标记每套成功、跳过、失败和基础属性结果。部分失败不能说成全部成功。

游戏任务只能启动在律匠已连接且当前选中的授权目标，忙碌时拒绝，不停止别的任务。
启动提供非空 request_id；相同请求重试幂等，不同内容使用新 ID。客户端断连不停止
已启动任务，get_task_status 可查询及执行 pause/resume/stop；取消请求不是终态。

公共配置只读；新生成的规则和基础组只落 local，所有已有 system/remote/local
定义保持不变。生成结果是私人运行计划，不能把用户名、账号、设备、方案 ID 或
真实装备数据写进规则名字、字段和文件名。目标和建议写在生成结果记录中。

预览不保存，生成不设默认，一键启动只使用该结果的运行快照。生成结果的规则
被人工修改后必须重新核对，不能覆盖修改或静默继续。分析不会应用备战方案、
执行转律或修改真实装备。可查询的模拟与真实装备必须区分。

服务不提供任意路径、Shell、SQL、Python 或任意工作流工具。工具报错时按原因
修正输入或让用户处理，不改系统配置来绕过校验。没有实时材料数据时返回未知，
不得拿历史库存当作目前可用材料。
