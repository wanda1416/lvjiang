## ⚠️ 不兼容变动与升级指引

### 工作流结果 JSON 改存 `logs/output/`

- **现象：** 任务与批量的结果文件从 `config/session/output/{用户}/{年-月}/{日}/`
  改到 `logs/output/{用户}/{年-月}/{日}/`，与任务日志（`logs/daily`）、批量报告
  （`logs/batch`）、调律说明（`logs/tuning`）同根。任务历史里点开结果与日志的行为不变。
- **原因：** `config/session/` 该只放用户数据与运行状态。产出一旦堆在里面，
  「打包 session 给作者排查问题」会把整批结果 JSON 一起带走，用户也分不清哪些真需要备份。
  搬到 `logs/` 之后，同一次运行的结果与日志也落在同一棵目录树里，排查时不用两头找。
- **如何调整：** 什么都不做也能正常用——历史记录里存的是相对客户端目录的路径，
  旧记录继续指向旧目录，旧文件照旧打得开。想把旧结果收拢到新目录，用一次性脚本
  （需要本机有 Python；脚本不随安装包分发，从 GitHub 仓库自行获取）：

  ```
  python scripts/one_off/migrate_output_to_logs.py           # 干跑，只列计划
  python scripts/one_off/migrate_output_to_logs.py --apply   # 执行
  ```

  它把 `config/session/output` 下的文件搬到 `logs/output`，同时改写历史库里指向旧目录的
  `result_path` / `log_path` / `report_path` / `markdown_path`。安全边界：默认干跑；
  先移文件后改库，中断可重跑收敛；目标位置已有不同内容的同名文件时不覆盖，源文件与
  对应记录一起留在原地；改写前把数据库备份到 `logs/one_off/migrate-output-<时间戳>/`。
  旧目录不会被自动删除，空了之后可自行清理。

- **外部脚本注意：** 如果你自己的脚本、快捷方式或监控按 `config/session/output` 取结果，
  改成 `logs/output`。不跑迁移脚本的话，旧结果仍然只在旧目录里。
- **跨端回传：** 回传包本来就要求电脑端与手机端版本一致，这一版不需要额外操作；
  没有迁移的旧记录在回传时会被正常打包——程序同时接受新旧两种路径前缀。
