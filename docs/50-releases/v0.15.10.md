# v0.15.10 — 初始同步与同步状态重建

这一版把账户同步改成显式的「初始同步」模型：登录后先建立一次同步状态，之后才走立即/自动同步。云端为空时上传本地并创建初始快照；云端已有数据时先把本地用户、总览定义与总览数据备份再拉取云端，杜绝同名互相覆盖。同步表改为四行，快照只挂在「总览」行。新实例不再自动创建 default 用户。

## ⚠️ 不兼容变动与升级指引

### 新实例不再自动创建 default 用户

- **现象：** 全新实例打开后没有用户，主窗口状态栏提示先创建用户或登录账户。
- **原因：** 去掉「没有用户就默认造一个 default」的行为。
- **如何调整：** 在「用户管理」里创建用户；或在「账户管理」登录后点「初始同步」把云端用户拉回本地。

### 登录后不再自动同步，必须先「初始同步」

- **现象：** 登录账户后，「立即同步」与自动同步都不可用，直到点一次「初始同步」。
- **原因：** 同步状态必须先显式建立，避免新实例一登录就静默上传/拉取。
- **如何调整：** 点「初始同步」一次即可，此后照常。

### 初始同步在云端已有数据时会备份并替换本地三件套

- **现象：** 本地的 `users/`、`profile.db`、`profile.yaml` 被移入
  `config/session/_backup-initialsync-<时间戳>/`，随后以云端数据为准重建。
- **原因：** 云端是唯一权威；本地与云端同名用户不允许并存。
- **如何调整：** 无需操作。被移走的本地数据仍在备份目录，可手工找回。云端为空时不会备份，改为直接上传本地并创建初始快照。

### 「清除同步」语义改变

- **现象：** 现在会**清空云端**的全部同步数据（定义、用户、文档、总览），需要红色警告 + 密码确认；此前版本只清本地进度。
- **原因：** 需要一条「彻底清空远端、重新开始」的路径。
- **如何调整：** 账号与登录态保留。清空后回到未建立状态，任何实例可重新初始同步。

### 「刷新快照」改名「创建快照」，移到总览行

- **现象：** 同步表最后一列只有「总览」行有「创建快照」按钮，其余三行留白。
- **原因：** 快照只服务总览回放，其它通道不涉及。
- **如何调整：** 无需操作。

## ✨ 新增功能

- **初始同步**：一次性建立本实例与云端的同步状态。云端空 → 上传定义/用户/文档并创建初始快照；云端有数据 → 备份本地三件套后拉取远端四通道。
- **同步表四行**：定义 / 用户 / 文档 / 总览；仅总览行有「创建快照」。
- **清除同步**：密码确认后清空远端同步数据，保留账号与登录态。
- **离线包可声明不携带总览数据**：PC 云端模式下发配置时，`manifest.profile=false` 的包不再带 `profile.db` / `profile.yaml`，手机总览由账号同步更新；安装端校验声明与内容一致，旧包缺省按携带处理。

## 🔧 修复

- **全新实例登录同步拉不到任何用户**：下行不再要求本地先有该用户，云端用户会直接创建到本地并纳入名册。
- **本地 `profile.yaml` 缺失时不从云端拉取**：现在缺失会拉回并重载 schema（初始同步备份后依赖此路径）。
- **名册有名字但本地缺资料文件会上传空资料**：会把云端真实属性按 LWW 冲成空对象；现在缺文件的行直接跳过，只从云端补回。

## 📦 重构

- `users_sync`：上行跳过缺文件行、空 payload 不推；下行创建缺失用户；名册合并采用云端顺序并纳入远端新增用户。
- 同步状态集中为 `sync_established` 标志（落 `account.json`），按钮与自动同步都以此为准。
