# v0.10.0 — 调律历史、场景契约与玩法配置

## 律匠 v0.10.0

> **发布状态：正式发布。发布日期：2026-09-02。** 本文以 `v0.9.0` 为基线，
> 汇总 0.10.0 的正式发布内容与升级要求。

本版本把自动调律从“运行时日志 + Markdown 报告”扩展为可实时查看、可持久化管理的
结构化历史；补齐用户头像、便利贴和按任务选择执行用户；为场景多视图、跨场景引用
和页面跳转建立可编辑、可校验的声明契约。燕云配置同时拆分武学、流派与玩法，并让
调律目标和毕业率基础数据使用一致的来源。

**升级前请先阅读下面的“不兼容变动与升级指引”。本版本调整了调律规则中玩法定义
的存储方式；曾经编辑过调律规则玩法的用户必须手动重新设置。**

---

### 🔎 本次发布重点

- **必须人工迁移**：自定义或修改过的调律玩法不会自动迁移到公共玩法配置。
- **自动调律安全**：重置次数无法明确识别时只跳过；回收状态异常时由用户明确选择
  “已回收 / 保留装备 / 结束任务”，不再凭模糊状态污染结果。
- **新持久化数据**：新增 `config/session/tuning_history.db`、用户便利贴和
  `config/session/avatars/` 头像库。
- **配置结构演进**：`scenes.yaml` 升级到 schema v2，但保留 v1 兼容读取；普通用户
  不需要手动转换，真正保存场景结构时才会写成 v2。
- **正式版本**：Python 包与 Android `versionName` 已升级为 `0.10.0`；Android
  `versionCode` 已因系统配置变化从 36 递增至 37。

### ⚠️ 不兼容变动与升级指引

#### 1. 调律玩法从规则内部拆分为公共玩法配置（必须手动处理）

- **影响范围**：曾经在“调律配置 → 规则管理 → 玩法设定”中增加、删除或修改过玩法，
  或者修改过玩法的主副武器、增伤词条、属性、绑定开关的用户。只使用系统默认规则且
  从未编辑过玩法的用户不受影响。
- **现象**：旧版本把玩法完整定义保存在每一条调律规则内部；0.10.0 改为由
  “游戏配置 → 玩法配置”统一保存玩法定义，调律规则只保留玩法引用。用户以前编辑过的
  旧玩法不会自动迁移到新的公共玩法配置。自定义玩法可能无法加载；与系统玩法同名的
  自定义内容也可能回到系统默认定义。玩法绑定开关属于规则本身，也需要逐条核对。
- **风险**：受影响的规则可能加载失败、缺少玩法，或者采用与升级前不同的武学、增伤、
  属性及开关判定。自动调律包含不可逆的装备回收操作，未核对规则前不要直接运行。

**升级操作：**

1. 升级前备份 `config/local/yysls/tuning_rules/`；如果曾修改玩法，建议同时截图或
   记录每个玩法的主副武学、增伤词条、属性和绑定开关。
2. 升级到 0.10.0 后，打开“游戏配置 → 玩法配置”，重新创建自定义玩法，并重新填写
   自己修改过的玩法定义。
3. 打开“调律配置 → 规则管理”，逐条检查所有自己编辑过的规则，重新添加或选择该规则
   需要的玩法。
4. 逐条恢复并核对“绑定开关”。绑定开关属于具体规则，不会跟随公共玩法定义自动恢复。
5. 确认相关规则已启用、需要的玩法已添加。首次运行请使用少量装备验证评级和处置结果，
   确认无误后再恢复正常自动调律。

> **结论：凡是自己编辑过玩法的调律规则，升级后都必须重新设置玩法。不要把旧规则
> 能够显示或暂时能够加载视为已经完成迁移。**

#### 2. “火九”玩法更名为“九剑”，不再自动绑定单体奇术开关

- **现象**：升级后，旧配置中按名称保存的“火九”玩法不会自动对应到“九剑”；“九剑”
  和“走地玉”也不再因为玩法选择而自动开启“保留单体奇术增”。
- **原因**：“火九”名称强调了单体奇术取向，但单体奇术现在是与玩法正交的独立选择，
  不应由玩法名称或玩法绑定隐式决定。
- **如何调整**：原来选择“火九”的用户需要重新选择“九剑”。是否保留单体奇术增，
  请单独设置“保留单体奇术增”开关，不要依赖玩法自动开启。

#### 3. 系统场景与布局更新不会覆盖本地副本

- **现象**：升级后仍使用自己改过的场景或布局时，可能看不到新版增加的多视图、跳转、
  `blank_area`、`return_good`、安全关闭区域和新坐标，相关自动化可能继续按旧位置操作。
- **原因**：`config/local` 无条件优先于 `config/system`；升级程序不会擅自覆盖用户保存的
  本地副本。
- **如何调整**：未自定义过对应内容的用户无需操作。修改过主页、菜单、背包、装备详情、
  调律、训练或外观场景/布局的用户，应先备份本地文件，再删除对应本地覆盖以恢复系统版，
  或在编辑器中对照新版逐项同步新增实体、视图、跳转和坐标。

#### 4. 调律重置视图键修正，旧拼写不再存在

- **现象**：自定义脚本或本地场景若仍引用 `reset_confrim`，升级后会报告实体/视图不存在；
  正确键名为 `reset_confirm`。
- **原因**：0.10.0 修正了历史遗留的 `confrim` 拼写错误，并统一调律重置页面契约。
- **如何调整**：全文搜索自定义 `.wf`、本地场景和布局中的 `reset_confrim`，全部替换为
  `reset_confirm`。未引用旧键的用户无需操作。

#### 5. 工作流和布局按键校验提前且更严格

- **现象**：含未知按键名、重复组合键或无效布局激活键的自定义内容，可能在加载或保存时
  直接报错，而不是运行到按键步骤时才失败。
- **原因**：DSL 字面量按键、组合键和布局激活动作现在共用平台无关的合法键名校验。
- **如何调整**：按错误提示把按键改为键名参考中列出的标准名称；左右修饰键使用
  `LSHIFT/RSHIFT`、`LCTRL/RCTRL` 等明确名称。合法的旧脚本无需修改。

### ℹ️ 兼容性说明（无需普通用户手动迁移）

#### 场景结构升级到 schema v2，但旧结构可兼容读取

- **影响范围**：维护 `config/local/scenes.yaml`、开发场景包或外部配置工具的用户。
- **行为**：旧的 `layout_scenes + group_names` 结构仍按 schema v1 读取，不会仅因升级
  自动重写文件；下一次真正保存场景结构时，编辑器会统一写成 schema v2 的
  `scenes` 分组结构。
- **如何调整**：普通用户无需操作。配置作者应避免让外部工具继续假定保存后的文件必然
  是 v1，并在覆盖系统场景时核对新增的视图、引用和跳转声明。

### ✨ 新增功能

#### 自动调律总览与历史管理

- **本次装备总览**：运行中可查看全部已形成终态的装备，按部位、处理结果、评级和名称
  筛选；关闭总览不影响正在运行的任务。
- **独立评级筛选**：增加“未评级 / 垃圾 / 一般 / 优秀 / 顶级”，与“已调律 / 已回收 /
  已跳过”等处理结果正交组合。“已调律 + 顶级”只展示本轮实际调成顶级的装备，不把
  进入任务前已经顶级、且本轮未调律的装备算进去。
- **结构化历史**：每次自动调律及逐件装备结果增量写入独立 SQLite 数据库
  `config/session/tuning_history.db`；异常退出前已经形成终态的装备仍可查看。
- **历史任务管理**：历史列表展示时间、状态、用户、部位、处理数、异常数、总轮次和
  规则；可打开与实时总览一致的详情，也可确认后删除整次本地任务。
- **逐轮决策记录**：保存每轮狗粮选择、理由、库存、是否真正执行，以及调律后的词条；
  因狗粮不足在准备阶段中止的轮次显示为“本轮未执行调律”，不计入完成轮数。
- **重置生命周期拆分**：成功重置前后的装备在历史中拆成两条独立记录，避免重置后的
  冷却、回收或评级覆盖重置前结果。
- **识别异常可见**：无法明确识别重置次数会作为独立异常展示在装备卡片、历史任务和
  总体统计中，而不是伪装成“次数耗尽”。
- **当前任务标题区分**：正在运行的详情标题改为“调律记录详情·当前正在运行任务”，
  与带时间的历史详情明确区分。

#### 用户头像、便利贴与执行用户

- **用户头像库**：在用户信息中导入或粘贴图片，通过正方形网格裁剪并保存为 512×512
  PNG；也可直接从当前设备或窗口刷新截图后裁剪。
- **历史头像管理**：编辑窗口可预览并选用全部已保存头像；历史头像支持右键删除，正在
  被用户引用的头像会阻止删除。
- **直接编辑**：双击主页面头像即可进入头像编辑，退出后直接返回主页面，不经过用户管理。
- **会话级存储**：头像文件统一保存在 `config/session/avatars/`，`session.json.users`
  只记录安全文件名；同一头像可被多个用户选择。
- **每用户便利贴**：用户信息页可新增、编辑和删除便利贴，字号服从系统权威设置；界面
  采用左侧头像、右侧便利贴，头像延迟加载以避免阻塞面板内容。
- **按任务选择执行用户**：日常和调律页顶部新增“执行用户”选择器，默认“跟随当前用户”，
  也可临时固定任意用户。选择不持久化，任务启动时会把 session、保存回调和输出目录
  一并绑定到所选用户，运行中切换主界面用户不会串数据。

#### 场景、多视图与页面跳转契约

- **场景 registry schema v2**：场景分组、项目和禁用项统一进入版本化结构，并保留旧
  schema 的兼容读取。
- **多视图归属**：同一区域或坐标可归属于多个视图；非基底视图区分同页滚动状态的
  “同层视图”和需要入口的独立页面视图。
- **页面跳转声明**：场景实体可以声明目标场景或目标视图，编辑器和“视图管理”展示每个
  视图的入口与跳转，并能发现目标不存在或独立视图没有入口的问题。当前声明用于编辑与
  校验，尚不替代既有 Python / DSL 导航执行逻辑。
- **快速编辑本场景视图**：区域编辑器底部可直接管理本场景视图，无需重复选择分组和场景；
  跳转选择采用“分组 → 场景 → 视图”三级级联。
- **跨场景引用增强**：区域和坐标点均可引用其他场景实体；引用来源改为“分组 → 场景 →
  area”三级选择，引用区域也能在各视图中正确绘制。
- **契约强化**：不可点击、没有坐标的实体不能配置跳转；从未绑定坐标的禁用实体不再被
  强制写入四个零坐标，已有坐标则继续保留。
- **保存可靠性**：编辑跳转会正确标记 dirty 并持久化；修复切换场景后界面仍显示、但详情
  和重启后跳转数据丢失的问题。
- **激活动作校验**：布局实体可绑定并验证键盘等激活动作，场景编辑器展示动作来源。

#### 游戏配置、玩法与毕业率

- **武学独立注册表**：武学成为武器和属性的唯一来源；流派引用武学，玩法再描述调律方向，
  防止“武器与武学互相矛盾但仍能保存”。
- **玩法绑定流派**：玩法配置可选择现有流派或“自定义”；绑定流派后自动填充并锁定属性、
  主武学和副武学，自定义玩法继续允许自由组合。
- **防御定音按流派分组**：绑定流派时直接使用“指定技能增效”中的同名流派分组，兼容
  不以武学名开头的合法技能词条；自定义玩法展示全部候选。
- **目标对齐毕业率基础表**：内置输出玩法的两门武学增伤和防御定音以 `data/excel` 满值
  属性为基础；纯奶、纯唐和飞天玉作为治疗或低输出玩法保留人工定义。
- **满词条最终评级**：按装备当前仍可合法达到的转律上限定级；首次转律穷举所有非首
  词条，105 级及以上的非承音装备可在已有转律槽上穷举再次转律，承音装备或不支持
  无限转律的等级不会虚构可达结果。
- **输出定音统一**：全部内置玩法（包括火拳）都要求外功穿透；破竹·风的防御定音改为
  “粟子游尘鼠鼠增伤”，并映射到“老鼠定音”。
- **玩法说明字段**：增加全武学增伤、奇术增伤和对单位增伤要求；奇术与单位增伤都可选
  “不需要”。这些字段目前只用于配置和展示，不参与评级、自动调律或毕业率计算。
- **备战方案绑定玩法**：按两门武学匹配候选玩法；“满定音”计算可按所选玩法替换目标定音，
  没有玩法时继续使用旧口径。

#### 编辑与工具窗口

- **四个工具窗口非模态化**：场景管理、图库管理、脚本录制和脚本编辑可与主窗口并行使用；
  重复打开会前置已有窗口，避免重入创建多个实例。
- **任务交互窗口非模态化**：日常、批量和自动调律触发的确认、选择、暂停、输入及 OCR
  结果表单只暂停对应自动化步骤，不再禁用主界面；用户仍可查看日志、切换页面或执行
  其他界面操作。
- **关闭语义**：上述窗口按 Esc 会先显示确认，点击标题栏 X 保持直接关闭；原有未保存内容
  保护仍继续生效。
- **图库信息**：参考图列表可查看图片像素尺寸，并修正裁剪元数据的输入处理。
- **调律界面统一**：当前任务的首行布局与历史记录统一，进度和详情入口更清晰。

### 🛡️ 自动化安全与稳定性修复

- **重置次数严格解析**：从“重置调律(N)”明确提取数字；只有读到明确的 `0` 或命中本地
  永久门槛才按“次数耗尽”处置。空串、错字或未渲染完成一律记识别异常并跳过，不会因
  OCR 软失败触发回收。
- **冷却与材料安全跳过**：剩余次数大于 0 后才进入重置检查；没有识别到“次数”按冷却期
  跳过，材料按装备等级的最低要求校验，不足或识别失败都只跳过当前装备。
- **重置确认恢复**：首次确认未出现时安全跳过；二次确认异常时暂停交给用户处理并复查，
  避免在未知模态状态下继续处置装备。材料返还弹窗统一点击安全 `close_btn`。
- **回收确认专用判定**：同时读取“确认”和“取消”，任一命中都说明弹窗正常，再激活确认；
  不再复用会污染其他页面调用方的通用确认方法，也不再循环复扫。
- **回收平台差异**：不再用“回收按钮是否仍可见”推断锁定，兼容 Android 与 PC 的不同表现；
  Android 锁定后收起“更多”菜单，PC 不做多余关闭。
- **回收异常人工三态**：确认/取消均未识别且不在背包页时，提示用户手动处理并选择“已回收 /
  保留装备 / 结束任务”；记录服从真实操作结果，不再一律写成锁定。
- **狗粮与重置返还弹窗**：使用无副作用的 `close_btn`（PC 绑定 Space）关闭；`blank_area`
  只作识别区，避免与按钮重叠时误触。
- **心法心得购买兜底**：背包扫描循环增加收束保护，避免道具未消耗或格位未补位时反复点击
  同一格造成无限循环。
- **自动调律结果日志降噪**：自动调律仍保存专用报告和结构化结果，但结束时不再向控制台及
  日志重复打印可能长达数千行的 JSON。

### 🔧 其他修复

- **实时与历史结果一致**：实时 Store 补齐 `round_prepared` 订阅，狗粮不足导致的未执行轮次
  不再只在事后历史中出现。
- **遥测异常可重试**：只有明确不符合 schema 的历史事件才进入 `rejected`；投影中的意外异常
  保持 `unreported`，下次继续尝试，避免一次配置加载故障永久丢弃最多一批历史数据。
- **分析脚本不再静默换库**：向 `analyze_tuning_affixes.py` 传入目录时，不会偷偷改读仓库默认
  `tuning_history.db`；选用其他来源时会明确说明。
- **模拟装备毕业率刷新**：编辑正在穿戴的模拟装备后立即重新计算毕业率，手动刷新也会按
  新数据更新。
- **破竹·风数据修正**：毕业率表存在两个指定技能定音时不再解析错位；“粟子游尘鼠鼠增伤 /
  老鼠定音”能够作为真实输入传入毕业率计算，固伤和食物加成使用正确行。
