# 画布组选区与整组平移
> 状态：已实现（2026-10-06，基线 v0.13.12）。

## 问题

场景画布原来只能一个个挪实体。吸附对齐能把一个实体贴到别人的边或中心线上，
但表达不了「一组实体相对位置保持精确不变地整体平移」。

战斗、移动这类定义的区域和坐标之间要求严格相等的相对位置。逐个挪动时每个实体
各自落点、各自吸附，相对关系必然在小数位上散掉，而散掉之后没有任何地方会报错
——`click_rect` 的子集校验只管单个区域自洽，区域之间的关系没有校验。

## 修饰键语义

| 修饰键 | 含义 | 范围 |
|---|---|---|
| `Shift` | 取消吸附 | 区域移动/缩放、网格移动/缩放、引用外框移动/缩放、坐标点移动 |
| `Ctrl` | 进入/扩展组选区 | 仅默认的区域编辑模式 |

`Shift` 在本次之前就已实现，本次只是补文档。箭头的绝对端点不参与边线吸附
（它有自己的「停手吸附到附近坐标点」机制），因此 `Shift` 在那里无意义。

## 组选区

### 参与的实体

区域、坐标、网格三类，可混选。

不参与的两类及原因：

- **跨场景引用外框**：内部实体跟随外框整体变换，外框进组会让内部实体被
  位移两次。
- **方向（arrow）**：它没有「位置」，只有两个端点，进组会被位移两次。

### 方向跟随

定义在组内坐标点上的方向必须跟着一起走，否则整组挪完方向就全变了。两种终点
形态的处理不同：

| 终点形态 | 处理 |
|---|---|
| 吸附态（`to_key`） | 不管。终点绑在另一个点上——那个点在组里就自动跟随，不在组里就该被拉长 |
| 绝对态（`to_cx/to_cy`） | 起点的点在组里时，终点跟着同一个位移平移 |

跟随的终点也要**参与组的位移区间计算**：否则整组贴边时它被单独夹在 `0..1` 上，
方向当场改变——而「方向跟着走」正是把它纳进来的理由。

### 选区如何存

按 `(kind, key)` 存，**不存索引**。实体列表会因刷新、视图过滤或删除而重建，
索引会指向另一个实体。表格那边已经为此踩过坑（视图过滤后 row 不再对应场景
定义的索引，代码改成按 key 查）；在选区上指错实体的后果是把错的东西挪走。

成员对象每次按 key 现查，不缓存对象引用。

### 状态迁移

| 操作 | 结果 |
|---|---|
| `Ctrl` + 空白处拖拽 | 橡皮筋框选，释放时把**完全落入**框内的实体加入选区 |
| `Ctrl` + 单击实体 | 该实体加入/移出选区 |
| 拖拽选区内任一成员 | 整组平移（**不要求按 `Ctrl`**） |
| 不按 `Ctrl` 单击选区外的实体 | 清空选区，改为单选该实体 |
| 不按 `Ctrl` 按下空白画布 | 清空选区 |
| `Esc` | 清空选区 |

**松开 `Ctrl` 不清空选区。** 如果移动期间必须持续按住，松手顺序就成了隐性
要求（先松 `Ctrl` 还是先松左键会得到不同结果），中途手指一滑整组选区就没了。
`Ctrl` 只负责进入与扩展，选区本身是黏的。

**框选用「完全落入」而不是「相交」。** 框选一组紧挨着的实体时，相交判定会把
边上擦到的邻居一起拉进来，而组移动挪错一个实体很难当场看出来。

**点空白处取消选区不会留下垃圾区域。** 空白处按下会先 append 一个 0 尺寸区域，
释放时宽或高不足 1% 的矩形本来就被丢弃，所以这个手势天然是空操作，新建区域的
交互完全不受影响。

## 整组平移

### 夹取按组做

逐个成员夹 `0..1` 时，先撞到边界的成员停下、其余继续走，组被剪切变形——而保住
相对位置正是这个功能存在的理由。正确做法是先求整组能走多远（每个成员各自的
允许区间取交集），把同一个位移夹一次，再无条件应用到所有成员。

坐标点的区间要留出半径，否则圆会被切掉一半。组比画布还大时区间会反过来，此时
只能原地不动。

### 不吸附

整组移动期间不吸附、不画参考线：

- 成员之间互相吸附会直接破坏组内相对位置。
- 向外部实体吸附会让整组落点变得不可预期。

因此 `Shift` 在整组移动期间是**空操作**，不反转成「按住才吸附」——同一个修饰键
在不同上下文里含义相反最容易记错。

代价：整组没有办法对齐到别的实体。这是可以接受的——组内相对位置才是核心契约，
组的落点是看着画面判断的。真需要时应该加一个显式的「对齐到…」动作，而不是往
修饰键上压。

### 其他边界

- 复用 `_beyond_dead_zone`：死区内不改数据，否则点击选中时的手抖会把整组挪掉，
  比挪单个更难察觉。
- 位移按「原始坐标 + 完整位移」一次算出，不累加，所以不会出现跨过死区阈值时
  跳一下。
- 跨场景引用成员置 `position_overridden = True`，与单体移动一致，否则本场景的
  位置覆盖不会落盘。
- 纯点击选中（坐标没变）不触发脏标记；坐标点有改动时额外刷新 POI 列表。

## 可见性与安全

- 组选区在右侧列表里没有对应表现，**必须在状态栏说出来**：选中数量、按类型的
  分项，以及如何取消。否则它是一个看不见的状态。
- 成员用独立颜色描边 + 半透明填充，画在所有实体之上，否则会被网格或引用盖住。
- **组选中时 `Delete` 不删**，只提示先取消多选。批量删除按 UI 约定要展示受影响
  对象并二次确认，不能挂在一个裸按键上。

## 与既有模式的优先级

组选区的接入点必须排在**引用、网格、坐标点的命中判定之前**。那三条分支一命中
就 `return` 并启动自己的单体拖动，组分支放在后面时，点一个已经入组的坐标点或
网格只会挪走那一个——这是实现时真实出过的问题。

`Ctrl` 只在默认的区域编辑模式下介入，并且排在「空白处拖拽新建区域」兜底分支
**之前**。模板裁剪、网格放置、引用放置、点击区域标定、画布编辑这些有待定状态的
模式在更前面就已返回，`Ctrl` 在那里不生效——它们各有自己的框选语义，混进来只会
制造歧义。

不按 `Ctrl` 且没有选区时，所有行为与本功能引入前完全一致。
