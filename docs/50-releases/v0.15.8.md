## ⚠️ 不兼容变动与升级指引

### 百业商店周期配额拆为四份，`baiye_raoliang_of_month` 的来源收敛

- **现象：** 新增 `baiye_raoliang_shengwang_of_month`（银百叶页内绕梁之音的声望货币
  那份，月上限 2）；`baiye_raoliang_of_month` 的「来源」由「百业声望 + 银百叶」收敛为
  仅「银百叶」。已有档案文件里这两个 key 的定义不会被改写：`declare_profiles` 只创建
  缺失项，不覆盖既有定义。
- **原因：** 银百叶页内「绕梁之音」有两种货币各 2 个，「百业惊喜礼盒」有月/周两种库存，
  屏幕上完全同名。原先只用一份 key 记账，买到哪一行都记同一项，账面无法区分。
- **如何调整：** 不处理也能继续用——新 key 会在下次运行时自动创建，历史数据按 key 归属
  存在档案库里，不受定义变化影响。若希望来源标签与新定义一致，删掉 `profile.yaml` 里
  `baiye_raoliang_of_month` 那一段，下次运行会按注册表重建（数值不会丢）。
  如果你自己的脚本在为百业采购记账，注意声望货币那份要记到
  `baiye_raoliang_shengwang_of_month`——继续记旧 key 会让两份绕梁挤在同一条配额上。

### 百业商店场景删除三个区域

- **现象：** `baiye_main` 场景移除 `restock`（补货周期）、`quantity`（购买数量）、
  `purchase_glow`（购买按钮金色）三个区域，双端布局同步删除，`content_version` 递增。
  同批把 `reputation` 区域的显示名从「百业声望」改为「金百叶」，银百叶入口坐标上移。
- **原因：** 购买判定只用 `purchase` 按钮文本与 `stock` 周期标签，这三个区域从 0.15.7
  起已无任何工作流引用；金百叶已无可买商品，这一栏实际是金百叶页签。
- **如何调整：** 若你自己的脚本或自建场景引用了 `restock` / `quantity` /
  `purchase_glow`，删掉对应引用即可。`reputation` 只是显示名变化，按 key 引用的脚本
  不受影响。

### 八音窍商店场景随版本内置（名称 `shop_bayinqiao`）

- **现象：** 这个商店的场景不需要自己录制了：版本自带场景（17 个区域）与安卓布局。
  如果你此前自己录过同一商店的场景，自建那份仍会覆盖内置版本，页签可能报
  「页面归属无法解析」。
- **原因：** 自建场景的两个视图没有声明页面归属与页签跳转，内置版本补齐了这两项。
- **如何调整：** 删掉自建的那份场景，脚本里改用 `shop_bayinqiao`。PC 端坐标尚未取证，
  需要在电脑上跑这个商店的话，自行补一份 layout 即可。

## ✨ 新增功能

### 脚本编辑器「内置函数」浏览面板

- 脚本编辑对话框新增第三个页签，按 15 个分类列出全部 103 个内置函数（core 76 +
  yysls 插件 27）：分组树、参数表（参数名与默认值取自真实签名）、返回值说明、
  试算与「定位到用法」。
- 内置函数元数据（分组、摘要、参数含义、返回类型）随函数对象登记进注册表，打包后
  仍可读；新增 `describe_function` / `signature_params` / `validate_function_meta`
  查询与校验接口，并加了元数据一致性门禁。
- 浏览是纯静态扫描（你自己写在用户脚本目录里的函数也会一并列出），不执行脚本。

### DSL 支持 `import` 外置 Python 脚本注册函数

- 脚本里 `import "辅助函数.py"` 即可把该文件里 `@builtin_func` 声明的函数注册给当前
  任务。只允许放在用户脚本目录（安装目录下的 `config/local/workflows`），指向版本内置
  目录时直接报错，避免随版本下发的配置通道变成任意代码执行入口。
- 注册进引擎私有命名空间，不污染全局函数表，并发引擎互不覆盖；生命周期绑定单次任务，
  批处理相邻任务彼此隔离。
- 首参 `_engine` 自动注入并提供 `should_stop()`，长循环可自行响应停止；每次执行从源码
  重新编译，改完即生效（不受 `__pycache__` 同秒旧字节码影响）。
- 编辑器 LSP 放行 `.py` import，并按与引擎一致的层级规则给出诊断。
- ⚠️ `import` 的 `.py` **等价于直接运行一个 Python 脚本**（顶层代码、第三方 import
  都会真实执行，能读写本机文件与网络）。只 import 你自己写的或逐行看过的脚本；别人
  发来的 `.py` 不要放进配置目录，更不要提示试算就点。试算会真的执行脚本，耗时脚本
  会让界面一直等它返回。

### 玩家档案：按用户锁定 key

- Profile 总览右键菜单新增「锁定 / 解锁」（位于「查看历史记录」上方，二次确认）。
  锁定后该用户这个 key 视为**物理失效**：单元格显示为深灰空白且不可编辑，合计行与
  告警都不再统计它，用户详情页同样留空。
- 引擎侧完全忽略锁定值：`profile_get` 返回空、任何写入立即被拒并记 error 日志、
  周期重置与 regen 计算停止、快照写回（CAS）与历史撤销一并拒绝。值永久停在锁定
  时的状态，随时可解锁恢复。
- 新增内置函数 `profile_locked(key, username?)`，供工作流先判锁再决定购买或记账。
  档案库版本升到 v8（`profile_entries` 增加 `locked` 列，升级前自动备份）。
- **工作流作者注意：** 锁定后 `profile_all` 里该项的 `value` 为 null（保留 key 的
  存在性并带 `locked: true`），与 `profile_get` 口径一致；不要拿它跟上限比较。

### 江湖号令：「多人模式保持」参数

- 新增开关 `keep_multiplayer`（默认关）。不勾选时脚本结束一定回到单人模式，不会把
  账号留在多人状态；勾选后，如果本次脚本从未切换过模式，就保持用户原有模式不动。
- 起始模式改为在脚本本就打开菜单页时顺带读「模式」标签（不做额外点击）；收尾按
  「脚本切过 / 勾选保持 / 起始即单人且未切过 / 起始多人或未识别」四种情况分别处理，
  避免无谓地多开一次菜单再关掉。

### 二级密码弹窗检测与无人值守感知

- 新增 `is_unattended()`：批量勾选无人值守或命令行执行时为真，普通界面执行为假。
- 购买心法心得在回收确认后检查标题亮字是否出现「输入密码」：有人值守时暂停等待用户
  处理；无人值守时自动点取消、逐级返回并记录 `password_dialog` 事件后结束，避免书票
  不足后空转。
- `general_control` 场景登记密码验证视图与三个区域（取消、确认、标题），双端坐标已
  取证（取消配 ESC、确认配 SPACE），PC 与安卓均自动生效。

## 🔧 修复

- **并发时脚本函数串桶：** 脚本注册捕获栈改为线程隔离。工作流跑在任务线程、面板试算
  跑在界面线程，原先共用全局栈会让一方的函数落进另一方的桶；面板 `with` 变换同时
  补齐 `_engine` / `_wf` 首参注入，与调用规则一致。
- **批量「恢复默认顺序」后开始按钮不刷新：** 刷新发生在重建执行顺序之前，读到旧空表
  导致「请至少勾选一个脚本」提示与灰按钮残留，只有切换配置组才恢复。现在重建执行顺序
  的函数自己重算开始状态，调用顺序不再影响结果（脚本页与单元页都修）。
- **编辑器插件对 CRLF 文档误报语法错：** 解析入口统一把 CRLF / 纯 CR 归一为 LF。
  引擎读文件时本来就做了通用换行，而插件直接看文档原文，导致同一份脚本「本地能跑、
  插件语法错」。
- **日志占位符静默丢参数：** 9 个模块原先用 `logging.getLogger` 与 loguru 混用，
  printf 风格占位符在 loguru 下会静默丢参数；统一改为直连 loguru，44 处占位符
  改为 `{}`，`exc_info` 改为 `opt(exception=True)`。
- **八音窍场景视图不可达：** 两个视图补 `kind: page` 并给在售/公示页签声明跳转目标，
  `validate_transitions` 不再报「页面归属无法解析」。
