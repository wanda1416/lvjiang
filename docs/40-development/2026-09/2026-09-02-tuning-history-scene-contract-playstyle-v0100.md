## 一、调律历史：从「日志 + Markdown」到结构化持久化

### 1.1 本次装备总览与历史管理（`ee3328e3`、`6348c1b7`）

- **本次装备总览**：运行中可查看全部已形成终态的装备，按部位、处理结果、评级和名称筛选；关闭总览不影响正在运行的任务；
- **独立评级筛选**：「未评级 / 垃圾 / 一般 / 优秀 / 顶级」与「已调律 / 已回收 / 已跳过」正交组合。「已调律 + 顶级」只展示本轮实际调成顶级的装备，**不把进入任务前已经顶级、且本轮未调律的装备算进去**；
- **结构化历史**：每次自动调律及逐件装备结果**增量**写入独立 SQLite `config/session/tuning_history.db`——增量而非收尾一次性写，异常退出前已经形成终态的装备仍可查看；
- **逐轮决策记录**：每轮狗粮选择、理由、库存、是否真正执行，以及调律后的词条；因狗粮不足在准备阶段中止的轮次显示为「本轮未执行调律」，不计入完成轮数；
- **重置生命周期拆分**：成功重置前后的装备在历史中拆成两条独立记录，避免重置后的冷却、回收或评级覆盖重置前结果；
- **识别异常可见**：无法明确识别重置次数会作为独立异常展示，**而不是伪装成「次数耗尽」**。

### 1.2 调律历史成为唯一结构化来源（`f130bb7f`）

Markdown 保留为人类可读报告，**不再嵌入隐藏的 `TUNING_DATA_JSON`**；最近七天匿名统计改为从本地历史白名单投影，08-25 引入的专用探针已移除。

统计投影分层：本地完整历史、匿名事件 schema 和上传状态分离；不上传用户名、装备名、截图、路径或本地主键。

> **已知非阻断项**（写在 v0.10.0 发布文档里）：`build_job()` 的持久化数据源采集仍在 Qt 主线程读取历史 SQLite，本版本已加入耗时日志。

### 1.3 任务与批量执行历史（`9f1373cf`）

单任务 / 批量两级 ID、参数与产出查询、独立日志。与调律历史**两套独立、不能互跳**——这条写进了用户手册，避免用户以为是同一份数据的两个视图。

## 二、自动调律安全性重做（`06e55507`）

这一组的共同判据：**回收不可逆，所以任何「模糊状态」都不能推进到处置**。

- **重置次数严格解析**：从「重置调律(N)」明确提取数字；只有读到明确的 `0` 或命中本地永久门槛才按「次数耗尽」处置。空串、错字或未渲染完成一律记识别异常并跳过，**不会因 OCR 软失败触发回收**；
- **冷却与材料安全跳过**：剩余次数大于 0 后才进入重置检查；没有识别到「次数」按冷却期跳过；材料按装备等级的最低要求校验，不足或识别失败都只跳过当前装备；
- **重置确认恢复**：首次确认未出现时安全跳过；二次确认异常时**暂停交给用户处理**并复查，避免在未知模态状态下继续处置装备；
- **回收确认专用判定**：同时读取「确认」和「取消」，任一命中都说明弹窗正常，再激活确认；不再复用会污染其他页面调用方的通用确认方法；
- **回收平台差异**：不再用「回收按钮是否仍可见」推断锁定，兼容 Android 与 PC 的不同表现；
- **回收异常人工三态**：确认/取消均未识别且不在背包页时，提示用户手动处理并选择「已回收 / 保留装备 / 结束任务」，**记录服从真实操作结果，不再一律写成锁定**；
- **心法心得购买兜底**：背包扫描循环增加收束保护，避免道具未消耗或格位未补位时反复点击同一格造成无限循环。

## 三、场景 schema v2 与页面跳转契约（`6b6863a9`、`7f2eb549`）

- **场景 registry schema v2**：场景分组、项目和禁用项统一进入版本化结构。**保留 v1 兼容读取**——旧的 `layout_scenes + group_names` 结构不会仅因升级自动重写，下一次真正保存场景结构时才写成 v2；
- **多视图归属**：同一区域或坐标可归属于多个视图；非基底视图区分同页滚动状态的「同层视图」和需要入口的独立页面视图；
- **页面跳转声明**：场景实体可以声明目标场景或目标视图，编辑器与「视图管理」展示每个视图的入口与跳转，并能发现目标不存在或独立视图没有入口。**当前声明用于编辑与校验，尚不替代既有 Python / DSL 导航执行逻辑**；
- **跨场景引用增强**：区域和坐标点均可引用其他场景实体；引用来源改为「分组 → 场景 → area」三级选择；
- **契约强化**：不可点击、没有坐标的实体不能配置跳转；从未绑定坐标的禁用实体不再被强制写入四个零坐标，已有坐标则继续保留；
- **保存可靠性**：修复切换场景后界面仍显示、但详情和重启后跳转数据丢失的问题。

顺带修正了历史遗留的 `reset_confrim` 拼写（→ `reset_confirm`），这条进了不兼容变动清单。

## 四、武学 / 流派 / 玩法三层拆分（`c7e93a8a`）

**这是 v0.10.0 唯一需要用户人工迁移的改动。**

旧版本把玩法完整定义保存在**每一条调律规则内部**；0.10.0 改为由「游戏配置 → 玩法配置」统一保存，调律规则只保留玩法引用。用户以前编辑过的旧玩法**不会自动迁移**。

- **武学独立注册表**：武学成为武器和属性的唯一来源；流派引用武学，玩法再描述调律方向，防止「武器与武学互相矛盾但仍能保存」；
- **玩法绑定流派**：绑定后自动填充并锁定属性、主武学和副武学，自定义玩法继续允许自由组合；
- **「火九」更名为「九剑」**，不再自动绑定单体奇术开关——单体奇术现在是与玩法正交的独立选择，不应由玩法名称隐式决定；
- **目标对齐毕业率基础表**：内置输出玩法的两门武学增伤和防御定音以 `data/excel` 满值属性为基础；纯奶、纯唐和飞天玉作为治疗或低输出玩法保留人工定义。

### 4.1 满词条最终评级与承音转律（`99aacca2`、`075e5e74`）

按装备当前**仍可合法达到**的转律上限定级：首次转律穷举所有非首词条；105 级及以上的非承音装备可在已有转律槽上穷举再次转律；原生 110 级的「流星/吴钩」装备承音后仍可在固定槽无限转律。

**承音分支只读取原始等级的「无限转律」与「承音后转律」两项能力，不读取当前等级**；原始等级只按等阶名称识别，无法匹配时按 0 处理，不会仅凭当前等级虚构可达结果。

这条派生出第二个人工迁移项：**修改过等级配置的用户必须为 110 级补上 `allow_retransfer_after_chengyin: true`**——用户保存过的本地等级配置优先于新版系统默认，旧配置里没有这个新字段。

## 五、用户头像、便利贴与执行用户（`8a9f0cda`）

- **用户头像库**：导入或粘贴图片，通过正方形网格裁剪并保存为 512×512 PNG，也可从当前设备/窗口刷新截图后裁剪。文件统一保存在 `config/session/avatars/`，`session.json.users` 只记录安全文件名，同一头像可被多个用户选择；
- **每用户便利贴**；头像**延迟加载**以避免阻塞面板内容；
- **按任务选择执行用户**：日常和调律页顶部新增「执行用户」选择器，默认「跟随当前用户」。选择不持久化；任务启动时把 session、保存回调和输出目录**一并绑定到所选用户**，运行中切换主界面用户不会串数据。

## 六、工具窗口非模态化（`4047a394`、`67ec59eb`）

场景管理、图库管理、脚本录制、脚本编辑四个工具窗口改为非模态，可与主窗口并行使用；重复打开会前置已有窗口。

**窗口注册表会在调用 Qt 方法前剔除已销毁的 C++ 对象包装引用**（`67ec59eb`），修复脚本录制窗口关闭后再次打开触发 `wrapped C/C++ object ... has been deleted` 的崩溃——与 08-27 的 `strip_focus_rect` 同源的一类问题：Python 侧还持着已被 Qt 释放的包装。

任务交互窗口（确认、选择、暂停、输入、OCR 结果表单）同样非模态化：只暂停对应自动化步骤，不再禁用主界面。

## 关键设计决策

1. **历史增量落盘而非收尾一次性写**：异常退出前形成终态的装备必须还能看到。
2. **调律历史是唯一结构化来源**：Markdown 回归「人类可读报告」，隐藏 JSON 与专用探针一并移除。
3. **模糊状态一律不推进到处置**：OCR 软失败记异常并跳过，二次确认异常暂停交给用户——因为回收不可逆。
4. **scenes schema v2 只在真正保存时写入**：升级本身不重写用户文件。
5. **页面跳转声明先只用于编辑与校验**：不急着替换既有导航执行逻辑，避免一次改两层。
6. **承音转律只看原始等级**：按当前等级推断会虚构出不可达的评级上限。
7. **执行用户在任务启动时整体绑定**：session、保存回调、输出目录一起绑，才不会运行中串数据。
