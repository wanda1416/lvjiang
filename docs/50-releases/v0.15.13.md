# v0.15.13 — 总览排版可跨端搬运、批量参数改为运行期与识别更省 CPU

这一版有三块主要变化：用户总览的分组、列与列宽独立成 `profile.json`，可以上传到云端、
在另一台机器下载回来；批量配置组不再固化生命周期参数，参数改为「本次执行」的运行期设置，
并新增安卓「允许竖屏」启动；PC 端识别默认限到 2 线程，CPU 占用降到约三成，墙钟反而更快。

其余改动集中在稳定性：主页判定在 OCR 漏读小字号时用图标模板复核，同步通道遇到过期令牌
自动换一次再试，周期恢复不再用过期基线推算并覆盖其他设备的真实消耗。

## ⚠️ 不兼容变动与升级指引

### 用户总览的可见结构迁到 `config/session/profile.json`

- **现象：** 总览的分组、组内列顺序、合计行开关与列宽从 `config/session/interface.json`
  移到独立的 `config/session/profile.json`。升级后第一次打开会一次性迁移，旧的
  `profile.*` 与 `ui_state.profile_overview` 节点会被清理，迁移前的内容写入
  `config/session/_backup-<时间戳>/profile-layout-before.json`。
- **原因：** `interface.json` 只是本机界面状态，换机器就丢，也没法参与云端同步；
  列宽原来按下标数组保存，增删一列就要手工搬整段数组。
- **如何调整：** 无需操作，自动迁移。若 `profile.json` 内容损坏，程序保留原文件、
  记错误日志并按默认结构展示，不会静默重建；需要回退时把备份文件内容手工恢复即可。

### 页面结构改为按按钮上传 / 下载，手机端只读

- **现象：** 用户总览工具栏新增「上传排版」「下载排版」（原「上传页面结构 / 下载页面结构」
  改名）。它们**不参与常规同步**：启动同步与定时同步都不会搬运它。上传时若云端版本来自
  别的设备，会先给出确认（显示来源设备、时间与组/列数对比），默认不覆盖；下载固定两次
  确认，落地前先校验内容，成功后把旧结构备份到 `_backup-<时间戳>/`。手机端只能下载，
  点击上传会提示「页面结构以 PC 为准」。
- **原因：** 排版是用户手工排出来的，整体替换不能混进逐项合并的常规同步；写入也必须有
  唯一权威来源，否则手机端会把 PC 的排版回退成旧版。
- **如何调整：** 无需操作。想在新机器上恢复排版，登录后点「下载排版」并按两次确认。

### 批量配置组不再保存生命周期参数

- **现象：** 旧 `batch.json` 里的 `workflow_params` 不再读取，也不做迁移；配置组的生命
  周期参数回落到工作流文件头的默认值，下次保存配置组时该字段自然消失。参数现在的编辑
  入口是桌面「批量 → 参数」页与手机「执行」设置。
- **原因：** 参数属于「这次怎么跑」而不是「配置组是什么」；原来存进配置组后，改参数
  要进配置对话框，运行中也没法单独调整。
- **如何调整：** 到「批量 → 参数」重新设置一次需要的值。启动时参数会冻结成执行快照，
  运行中再改不影响当前批次，下一批才生效。

### 安卓批量「允许竖屏」需要异常恢复与条目准备

- **现象：** 「批量 → 参数」新增「允许竖屏」。它只有在配置组同时配好「异常恢复」与
  「条目准备」两个工作流时才可用；缺任一项时开关置灰，手机端保存会被拒绝。
- **原因：** 竖屏起步时程序会先借异常恢复把客户端收回登录主页，之后只有条目准备能把人
  重新送进游戏。少了条目准备，整批会停在登录页逐条失败。
- **如何调整：** 在「工具 → 批量配置」为配置组补上这两个工作流，或先把手机转为横屏再跑。

### 武学、玩法、流派配置改为「名称 → 定义」映射

- **现象：** `config/system/yysls/game_config/` 下三份配置从列表改成以名称为键的映射，
  键序就是展示顺序。如果你在 `config/local/yysls/game_config/` 里保存过旧的列表格式，
  升级后加载会报错并跳过这些条目，武学 / 玩法候选会缺项。
- **原因：** 列表没有稳定键，改名会变成两条记录；映射让用户改动只覆盖对应的那一个键，
  系统后续新增的条目仍然出现。
- **如何调整：** 把本地覆盖文件改成映射格式，或删除 `config/local` 里对应的覆盖，
  改用随包配置。系统模式下三个配置面板支持拖动排序（用户模式没有排序入口，顺序由
  系统配置决定）。

### PC 端识别默认并行度改为 2 线程

- **现象：** 未配置过这一项的用户，PC 识别默认使用 2 个识别线程、1 个并行算子线程，
  CPU 占用明显下降（同帧实测约从 8.44 CPU 秒降到 2.38 CPU 秒），墙钟还略快。
- **原因：** RapidOCR 出厂把检测 / 方向 / 识别三个模型都设为开满物理核，多个线程池互相
  争抢，并行效率反而下降。
- **如何调整：** 无需操作。若你的机器识别变慢或小字漏检增多，到「图像识别 → 识别配置 →
  识别性能」调整识别线程数（1–16）、并行算子线程数（1–8）与检测输入短边（480–1920px）；
  保存后下一次识别自动重建会话，不需要重启。

### 主页布局、登录等待与自动剧情脚本的位置变化

- **现象：** `game_main_page` 两端布局重新标定并新增图标模板（安卓 `ditu`、桌面 `dongzuo`），
  主页判定在文字全部漏读时会改用该图标复核；登录加载等待从 10 拍放宽到 20 拍，主页确认
  从 8 拍放宽到 10 拍。自动剧情跳过脚本从 `story/auto_skip.wf` 移到
  `standalone/story_auto_skip.wf`（工作流 id 仍是 `story_auto_skip`）。
- **原因：** 「限时」等小字号入口在缩放、低对比与过场帧下会被 OCR 整批漏读，导致明明在
  主页却被判成未知页面；弱网与慢机器的登录加载时间也超出旧轮数。
- **如何调整：** 无需操作。如果你改过 `config/local/layouts/` 里的主页布局、把登录或
  页面判定工作流复制到了 `config/local/workflows/`，或自定义脚本引用了旧的
  `story/auto_skip.wf` 路径，需要手动同步或改成新路径；`config/local` 的覆盖优先于
  随包内容。

## ✨ 新增功能

- **用户总览排版跨端搬运。** 页面结构独立成 `config/session/profile.json`，工具栏新增
  「上传排版 / 下载排版」；列宽按列 key 保存，增删列不再错位，用户名列宽只存一份、各分组
  天然一致。跨机器按文件记录的字体像素与缩放比折算，再用当前字体实测表头宽度兜底，
  折算结果不回写，避免两台机器互相拉扯。
- **「创建快照」挪到用户总览工具栏。** 与上传 / 下载同属「云端基线」一组动作；PC 才能
  创建，手机端点击会提示原因，未登录先提示登录。账户管理同步表因此去掉只为它存在的
  「功能」列（6 列 → 5 列）。
- **批量生命周期参数改为运行期设置。** 桌面在「批量 → 参数」编辑并防抖落盘，手机在
  「执行」设置里调整；启动时冻结为执行快照，wf 脚本仍实时读取。档案键改名会同步改写
  草稿里的 `profile_key`，不会下次运行报「Profile key 不存在」。
- **安卓批量允许竖屏启动。** 起步画面交换宽高后匹配布局时放行，先借异常恢复回到登录主页，
  再按生命周期进入游戏；缺少恢复或条目准备工作流时开关置灰并说明原因。
- **批量脚本页「全不选」改为「反选」。** 逐行翻转勾选状态，按当前行序重建执行顺序并写入
  草稿；运行期间同样锁定。
- **识别配置新增「识别性能」分组。** 可调识别线程数、并行算子线程数与检测输入短边；
  改配置后下一次识别自动重建会话，不用重启。
- **DSL 新增单行守卫与 `to_flag`。** `if <任意条件> -> <一条语句>` 与 `env:"x" -> ...`
  归一到同一个 `If` 节点；`to_flag(x)` 按 `if $x` 的真值口径把结果压成 1 / 0，方便返回
  页面判定或累加计数。
- **主页判定增加图标模板复核通道。** 文本通道全部未命中时，安卓只扫 `ditu`、桌面只扫
  `dongzuo` 做模板匹配；只认本端指定的区域，对应区域未绑定模板按配置错误终止。
- **游戏配置支持系统模式拖动排序。** 流派、武学、玩法三份配置的键序即展示顺序，按属性
  分组展开；武学删除守卫补上玩法 `arts` 引用检查。
- **数据模型复制定义原样带出 Key 与标签。** 复制后所有字段照抄，Key 仍可编辑；沿用原 Key
  保存仍按占用校验拒绝，不会意外覆盖已有定义。

## 🔧 修复

- **同步通道遇到过期令牌会一直报「未登录」。** 别处刷新过令牌后，每分钟的自动同步与手动
  「立即同步」会持续失败，直到心跳把令牌刷回来。现在收到 `unauthorized` / `token_expired`
  时换一次令牌重试，只重试一次，非鉴权错误不触发刷新。
- **周期恢复用过期基线覆盖其他设备的真实消耗。** 启动后首次拉取完成前，本地锚点还是上次
  同步的状态，推算出的准点恢复被写成绝对值上行（体力 450 被覆盖成 2500）。现在本进程
  未完成首次干净拉取前不推算、不物化周期恢复；确实没有登录凭据时照常本地推进，凭据库
  读不到时按「可能有登录态」保守拦住。
- **空闲断流后横幅消不掉、「重新检查」无效。** 断开目标或切换目标时横幅会残留；空闲状态
  点「重新检查」只往没人等待的事件上 set 一次。现在横幅按目标归属管理，断开前先收起，
  切换目标跟随；空闲重查直接重建画面流，成功即收起横幅，失败把原因留在横幅上可再试。
  连接信息列按运行状态着色（未运行 / 运行中 / 暂停中 / 异常），选中行不覆盖高亮。
- **登录与主页等待轮数不够。** 登录加载等待 10 → 20 拍、主页确认 8 → 10 拍；记「最后一轮
  决策帧」的判断同步改为引用变量，不再写死在旧的 8 拍上。
- **主页文字漏读导致误判不在主页。** 「限时」等小字号条目整批漏读时，导航与批量会把主页
  判成未知页面并反复 pause；现在由本端图标模板复核，背包页仍统一排除。
- **wf 语言服务器 Outline 整体失败。** 单行守卫没有 `end` 却被当成块开头，符号范围退化成
  零宽区间，客户端校验 `selectionRange` 不合法后 Outline 全部失败；现在按语法识别真正
  需要 `end` 的块，未闭合时退到最后一个非空行。
- **「创建快照」在账户管理里位置不对。** 它改的是总览数据本身，却挂在同步表里；现在搬到
  用户总览工具栏，并去掉只为它存在的「功能」列。

## 📦 重构

- **登录态收敛为进程内单会话，刷新改单飞。** 账号对话框、页面结构上传下载与手机端账户
  桥接原来各自持有 `AccountSession`，同时刷新会把对方的令牌顶掉；现在共用唯一会话，
  同一会话的刷新串行执行，内存里已是新令牌就直接复用。
- **系统工作流的单步早退改用单行守卫。** 登录、导航、页面判定、江湖任务、批量恢复等脚本
  的 `if 条件 / 一条语句 / end` 统一写成 `if 条件 -> 语句`，行为不变，脚本更短。
- **自动剧情跳过归到 `standalone/`。** 只支持安卓、不可批量执行，与其它独立活动脚本放在
  一起；文件内容与 id 不变。
- **删除从未被引用的 `huoyun_card` 占位场景**，并同步去掉组件分组登记与空壳桌面布局。
- **三份游戏配置的加载与保存按映射结构重写。** 变更判定改为按序列化文本比对，只调整顺序
  也会写盘；`resolve_school` 命中多个流派时记 warning。
