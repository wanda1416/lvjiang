# 备战方案管理

## 范围与状态归属

备战方案按用户分别保存在 `{user}.loadouts.json`。主页面的方案下拉框只负责
切换当前用户的活动方案；旁边保留「新建」「管理」。流派、主武学、副武学、玩法
在主页面只读展示。管理窗口左侧选择编辑用户，右侧按持久化顺序展示该用户的方案；
切换用户、选中方案或排序都不得改变主页面的活动用户和该用户的活动方案。

## 管理操作

- 右侧提供新建、删除、上移、下移和方案列表；双击方案整体编辑名称、流派、
  主武学、副武学、玩法。编辑以方案 ID 定位，单次原子保存，不覆盖装备池。
- 选择明确流派时，两门武学由流派填入并锁定；切换到「自定义」才可手动修改。
  「自定义」只是编辑模式，不是第二份流派数据。保存后仍由两门武学的无序组合
  解析流派。玩法按武学无序组合过滤，明确流派时再限于该流派。
- 管理窗口新建方案不自动切换活动方案；主页面直接新建仍切换到新方案。
  删除至少保留一个方案；删除活动方案时由相邻剩余方案接替，公共装备池不删除。
- `plan_order` 保存方案 ID 顺序。旧数据没有该字段时按现有 `plans` 顺序展示，
  普通读取不写盘；上移、下移仅修改顺序，不改变方案 ID 或活动方案。

## 全部方案扫描

- 游戏内「方案管理」是独立场景 `training_plan`：`base` 为方案列表与详情，`fill`
  为智能填充弹窗，`confirm` 为切换确认弹窗。培养场景 `training_main` 仅保留进入
  方案管理的入口；方案页返回后再经培养页、菜单回到主页。
- 扫描任务先进入游戏的「主页 → 菜单 → 培养 → 功法 → 方案管理」，按游戏列表顺序
  扫描当前可见的 `plan_list` 网格。格内文本去空白后长度大于零即为已有方案；空格
  跳过。第一版仅处理网格行数内的方案，不滚动、不去重，超出可见网格的方案暂不支持。
  确认有方案后，直接在当前页面选择第一套；扫描并返回主页后，才为下一套重新进入。
  每套均按发现的名称定位、读取方案标题和两张武学卡片，点击「使用方案」。
  缺装备弹窗点击「智能填充」，未保存搭配弹窗点击「切换」。单套方案识别或切换
  失败但仍在可操作的方案列表时记录原因，直接选择下一套；若弹窗未处理完或列表
  状态不确定则停止，避免误点。扫描成功的方案返回主页读取装备后才重新进入列表。
  全部方案均未完成装备扫描时，任务最终返回失败，不把空结果记为成功。
  不根据本地方案清单猜测游戏里有哪些方案。
- 游戏方案只有名称和两门武学。本地有同名方案时，无序核验武学后直接使用，不改动
  其玩法；同名但武学不符或重名时跳过写入。没有同名方案时创建一套本地方案：流派由
  武学无序组合解析，玩法只在匹配这组武学的候选中选择；方案名称包含某个玩法名称时
  使用该玩法，否则使用系统配置声明顺序中的第一个候选。没有候选玩法时允许创建，
  但本轮只扫描装备，不静默写入基础属性。创建和切换游戏方案均不改变主页面活动方案。
- 成功切换后才把本次 WF 的装备写入目标绑定到同名本地方案；此绑定不改变主页面
  活动方案。每次扫描八件装备均成功后，继续读取角色面板。基础属性按现有口径
  由面板减去**该方案实际扫描的装备**及该方案弓玦反推，保存为流派下的
  `用户名_备战方案名`，并将该基础属性名称关联回该方案。同一玩法的不同方案分别
  保存各自的基础属性，不要求反推数值一致。未配置玩法、装备未扫全或基础外功区间
  识别不可靠时禁止静默覆盖。
- 原「扫描基础属性」任务默认继续弹出确认表单；显式选择静默写入时，按主页面
  当前活动方案保存，并返回主页。全部方案扫描始终走静默路径，逐方案回到主页
  后再切换下一套。
- 「扫描备战装备」「扫描基础属性」两个直接运行入口均可传入方案名称及主副武学；
  留空时仅由入口读取当前活动方案作为参数。真实扫描分别封装为
  `scan_equipped_plan(name, main_art, sub_art)` 与
  `scan_role_base_attr_for_plan(name, main_art, sub_art, silent_write, scroll_count)`。
  `import` 只注册这两个子过程，不执行被导入任务的顶层指令。全部方案扫描把目标
  方案名称和武学直接传入子过程；写入按名称定位本地方案，不切换主页面活动方案。
- 全部方案扫描可选择跳过任务开始时本地已经存在的同名方案；判断在切换游戏方案前
  完成，默认不跳过。单套方案的装备或属性识别/写入失败应拒绝本套写入并安全回主页，
  再扫描下一套；只有无法确认已回到主页等导航不安全情况才停止整批。
