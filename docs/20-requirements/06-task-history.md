# 任务历史与批量历史

## 1. 目标

统一记录日常任务和专用任务的执行维度信息。自动调律等专用任务原有的业务历史继续保留；
统一任务历史不解析装备、轮次等业务数据，只记录一次任务如何启动、何时结束以及产出了什么。

入口：`工具 → 任务历史`。

## 2. 两级执行 ID

| 字段 | 含义 |
|------|------|
| `task_id` | 任务定义 ID，例如 `daily_checkin`、`auto_tuning` |
| `task_run_id` | 一次单任务执行的唯一 ID；单独运行和批量运行都会生成 |
| `batch_run_id` | 一次批量执行的唯一 ID；单独运行的任务为空 |

批量执行先创建 `batch_run_id`，随后每个用户、每个脚本的实际执行分别创建
`task_run_id`，并引用所属的 `batch_run_id`。因此可从批量历史下钻查看该批次的全部单任务，
也可从单任务反查所属批次。

## 3. 持久化

元信息数据库固定为 `config/session/daily_history.db`，包含：

- `batch_runs`：批量配置、输入行与脚本快照、起止时间、耗时、状态、批量报告路径；
- `task_runs`：用户、任务定义、任务性质、输入参数、起止时间、耗时、状态、结果 JSON、
  独立日志、错误信息，以及可空的 `batch_run_id`。

每次任务的日志写入 `logs/daily/{用户名}/`。日志文件名包含任务定义、时间和
`task_run_id` 的短前缀；日志 sink 按执行线程过滤，避免混入其他后台线程的输出。
任务结果继续写入现有的 `config/session/output/{用户名}/`，数据库只记录定位路径。

历史持久化或独立日志创建失败只能告警，不得阻断原任务。进程异常退出时未收尾的记录保留
`running` 状态，便于识别非正常退出。

## 4. 查询与查看

任务历史支持用户多选、任务多选、开始日期和结束日期组合筛选。每条记录展示任务性质、
执行方式、状态、起止时间、耗时、`task_run_id` 和 `batch_run_id`，详情展示输入参数、
错误与文件路径，并可直接打开结果 JSON 和执行日志。

批量历史按日期范围查询，展示批量起止时间、耗时、配置、状态、任务数和
`batch_run_id`。选择“查看全部单任务”后，任务历史切换为该 `batch_run_id` 的全部子任务。
