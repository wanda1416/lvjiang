## 一、匿名使用统计与调律数据回收（`513b46e6`）

本轮体量最大的一块，客户端 + 服务端 + 文档 + 141 个测试一次落地。

### 1.1 客户端（`core/telemetry/` + `apps/yysls/telemetry/`）

- **opt-in 三态同意**：首启一次性弹窗，选择记入 `server_config.telemetry.consent`，此后不再询问；设置页新增「网络与隐私」Tab，离线总闸 + 公告 / 更新 / 统计三个分开关，点击立即生效，不经「保存」按钮。
- **字段白名单是唯一 PII 防线**：`core/telemetry/schema.py` 的 `EventSchema.validate()` 是唯一能产出 `ValidatedEvent` 的入口，`str` 字段没有 `choices`/`pattern` 直接拒绝注册，由结构性测试兜底。
- **心跳通道**：启动时 ≤1 次/日；`install_id` 存 `config/local/telemetry/` 而**不是** `config/session/`——后者用户会打包发来排查问题。
- **调律事件通道**：采集点卡在 `auto_tuning.py` 的 `collect_new_affix()` 之后，不走 `_emit_progress` 信号（那个 payload 带完整词条组合）；词条名 / 材料 / 部位一律走 `game_config.yaml` 实时枚举校验，识别不出**整条丢弃**，不落 unknown 兜底值。
- **两段式 NDJSON 本地缓冲**：不用 `session.json`——一次调律几百次 roll 会把整个 session 重写几百遍；`os.replace` 原子封口，不需要文件锁。
- **上报线程绝不写 SessionStore**：写锁超时会从调用线程弹原生模态框，非主线程弹窗是未定义行为。payload 在主线程构造后作为不可变对象传入。

### 1.2 服务端（`ops/stats-worker/`，Cloudflare Workers + D1）

- **写入粒度**：一次调律会话存一行、payload 整体存 JSON，不是一次 roll 一行——写入量与用户数挂钩、与单次会话 roll 数无关（按旧粒度 500 DAU 就会打满免费额度）。
- `POST /v1/report`（心跳 + 批次）、`POST /v1/forget`（自助删除）；全部维度字段落库前经枚举 / 正则白名单校验。
- **不读取 `CF-Connecting-IP`**，无任何 IP 派生字段；`env.DISABLED` 一键熔断。
- 生产地址 `https://lvjiang-stats.wyxj.net`（Custom Domain 绑定），已做端到端验证。

### 1.3 文档

新建 `PRIVACY.md`（仓库唯一隐私说明）与 `docs/30-architecture/06-telemetry.md`（服务端表结构、写入粒度设计、校验边界、分析查询）。

**两条红线由测试守住**：未同意时零请求零本地缓冲；PII 冒烟测试用真实装备数据断言零泄漏。

## 三、技能轴查看器（`6fd677fd`，08-24）

毕业率方案只给一个 DPS 数字，看不出伤害来自哪个技能。新增只读查看器，从原始的毕业率计算器 Excel 读竞速轴，把 DPS 拆回到每个技能。

**为什么必须回到 Excel**：编译成方案 JSON 时技能名会被丢弃。鸣金·虹的编译产物有 5690 个节点，字符串常量只剩一个「期望」，`total_damage` 退化成 sum 节点加一串匿名数值。数值精确，但无法还原技能身份——按子图常量做指纹聚类试过，139 次命中聚出 110 组、97 个单例，不同 buff 层数和段数都会改变常量组合，聚类不可靠。

三个踩过的坑写进了实现与文档：

1. **必须按表头名定位列**：11 份表列位置不一致，技能列出现在第 17 和第 18 列，类型列在 33/34/35/38/39 都出现过，只有表头名统一。写死列号会在约一半的表上解析错位。
2. **用 `iter_rows` 而非 `read_only` + 随机 `cell(r,c)`**：后者在最大的一份表（786KB / 314 行轴）实测 7.4 秒，按行迭代只要 80ms。
3. **入口位置**：`EquipStatusTab` 自己那排 `action_row` 在 `LoadoutPanel` 里被 `set_embedded_mode(True)` 整个隐藏，加在那儿用户根本看不到。

入口最终收在「最优组合」对话框首行最右侧，扁平样式 + tooltip 标明「实验性」。11 份真实 Excel 全部通过总伤 + DPS 双项对账。

## 四、Qt 生命周期：两处崩溃根治

### 4.1 装备卡片交互不再在事件处理里跑嵌套事件循环（`8e36feff`）

扫描全部装备时点卡片上的「!」必崩：Windows `0xc0000374`（堆损坏），栈顶停在 `_IllegalBadge.mousePressEvent` 的 `QMessageBox.warning`。

成因是三件事叠在一起：

1. `QMessageBox.warning` 是模态框，会在事件处理内部跑嵌套事件循环；
2. 扫描过程中 `equipment_ingest` 持续发 `equipment_changed`，`EquipStatusTab._rebuild_grid` 会 `takeAt` + `deleteLater` 掉全部背包卡片；
3. 这个 `deleteLater` 是在嵌套循环里发出的，同一个循环就会处理掉它。

于是模态框的 parent（徽标）与当前调用栈上的 `self` 双双变成已释放对象，模态框关闭返回时踩坏堆。

改法是**不在事件处理里阻塞**：「!」点击把窗口与原因文本按值取出，`QTimer.singleShot` 排队到事件循环里再弹；背包卡片右键菜单从 `exec()` 改 `popup()`。槽位卡片不受影响（`_refresh_slots` 复用实例不销毁），其 `exec()` 保持原样。

### 4.2 解释器退出前有序释放 Qt 对象（`c05a793c`）、等待工作流线程退出后再释放（`17ac76f7`）

同一类问题的另外两个出口：进程收尾阶段 Python 对象已开始回收而 Qt 仍在派发事件。

### 7.1 最优组合的「排除模拟」此前无论勾不勾都没有模拟装备（`678f3c48`）

`EquipmentInventory` 把背包拆成两个集合：`bag_items` 只含真实装备，模拟装备在 `mock_items`。`_load_candidates` 只读 `bag_items`，于是模拟装备**从来没有机会进入候选池**——这个开关唯一起作用的地方只有已穿戴槽位。

- 未勾选排除时把 `inv.mock_items` 一并并入候选来源；
- 开关接上 `toggled` → 重建候选池。候选池只在对话框构造时加载一次，而本项默认勾选，用户根本没有机会在加载前取消，不重建等于开关不存在；

### 7.2 调律规则文档里游戏产不出的装备例子（`23123b66`，08-24）

`01-huiyi.md` 的判定例子有 6 行描述的装备在游戏中不可能存在，逐行用判定器复核后替换：

## 关键设计决策

1. **遥测的 PII 防线放在 schema 注册处**，不是上报前过滤：没有 `choices`/`pattern` 的字符串字段直接拒绝注册，防线在最上游且由结构性测试守住。
2. **D1 写入粒度按会话而非按 roll**：写入量与用户数挂钩，与单次会话长度无关。
3. **`install_id` 存 `config/local/` 而非 `config/session/`**：后者会被用户打包发来排查问题。
4. **上报线程绝不写 SessionStore**：写锁超时会从非主线程弹原生模态框。
5. **不在 Qt 事件处理里跑嵌套事件循环**：模态框改 `QTimer.singleShot` 排队、菜单改 `popup()`。
6. **随发行包分发的工作流不带 `_` 前缀**：该前缀同时是打包排除规则。
