# v0.15.12 — 十二种界面语言、画面流故障等待恢复与配置不再冻住

这一版最大的变化是界面语言从 2 种扩到 **12 种**（新增繁中、日、韩、德、法、西、葡、俄、泰、越），
并修掉 v0.15.11 打包漏带翻译文件、语言下拉框只剩简体中文的问题。其次是画面流：
连接断掉以后不再拿着冻结的最后一帧继续识别和点击，而是进入等待恢复。

其余改动集中在两件事：把「静默失败」改成「当场报错并说明原因」；让用户自己改过的配置
不再挡住后续版本新增的内容。

## ⚠️ 不兼容变动与升级指引

### 画面流断开后不再在冻结画面上继续点击

- **现象：** 手机息屏、数据线松动、投屏窗口被关闭后，任务会停下等待恢复并给出提示
  （红色横幅；有运行实例时另外弹窗）。等不到恢复就报「执行通道中断」并结束本次运行。
  只有点击、不含截图的动作脚本也一样受保护。
- **原因：** 旧实现断流后 `capture()` 继续返回最后一帧，识别和点击全在冻结画面上进行，
  跑完还写「（正常完成）」。用户看到的是「任务说成功了，游戏里什么都没发生」。
- **如何调整：** 无需操作。若某个脚本确实需要在断流后立刻结束而不是等待，把
  「建立流式传输尝试次数」调成 1。

### 批量任务遇到执行通道中断会整批中止

- **现象：** 过去通道坏掉之后，批量的每一项都算一次「条目失败」并继续下一项，跑完仍写
  「（正常完成）」「脚本执行 0 次」。现在整批中止，报告写「执行通道中断，整批中止」并给出
  归因、次数、耗时、条目、用户与脚本。
- **原因：** 通道故障是设备/会话级问题，逐项重试只会空转；继续跑也拿不到可用的画面。
- **如何调整：** 无需操作。恢复连接后重新运行即可。批处理历史里这类记录的状态是
  `channel_fault`，与普通失败区分开。

### Android 连接恢复次数默认 3 → 5，并新增「建立流式传输尝试次数」

- **现象：** 新装用户或从未改过这一项的用户，默认阶梯变成「流式 5 次 → 代理重连 5 次 →
  ADB 5 次」，间隔 2 秒，仍不可用则无限等待人工处理。**已经存过 3 次的老用户不会被改**，
  仍按 3 次跑。分组名也从「Android 连接恢复」改为「Android 连接设置」。
- **原因：** 3 次在弱网、scrcpy 启动慢的情况下常常一次失败就要人工介入。
- **如何调整：** 想用新默认值，到「高级设置 → Android 连接设置」把三项改成 5（或改成你想要
  的值）。存量配置不会被自动重写。

### 系统配置里的显示名改成了中英双语映射

- **现象：** `config/system/app.yaml` 里环境名、方案名、等待参数标签的值从单个字符串变成
  `{zh_CN: 安卓, en_US: Android}`。英文界面下这些名字终于显示英文。
- **原因：** 界面文案属于软件，配置显示名属于配置数据，两者所有者与生命周期不同，不能放进
  同一张翻译表；写进配置自己身上才能随界面语言切换。
- **如何调整：** 无需操作。**如果你自己改过这些名字**（改动落在 `config/local/app.yaml`），
  你的纯字符串覆盖依然生效，英文界面下显示的就是你写的那个名字；想看到随包译名请删掉
  local 里对应的那条覆盖。

### 改过环境名或方案名之后，后续版本新增的仍然会出现

- **现象：** 以前只要改过某个环境或方案的名字，`config/local/app.yaml` 就把整张 `envs` /
  `plans` 冻住，之后版本新增的环境、方案在这台机器上永远不出现，除非手动删掉本地覆盖。
  现在 local 只记录你真正动过的那几条。
- **原因：** 整键替换改成按稳定 key / id 的增量合并（`__added__`）。
- **如何调整：** 无需操作，下次在设置页保存时会把旧的整表覆盖自动转成增量形式。注意预置
  环境与方案在用户层**不可删除**——可以改值、可以新增自己的，但不能删掉随包内容。

## ✨ 新增功能

- **十二种界面语言。** 除简体中文与英文外，新增繁体中文、日本語、한국어、Deutsch、
  Français、Español、Português、Русский、ไทย、Tiếng Việt。设置页「界面语言」下拉框直接切换，
  保存后提示重启生效（提示语用**你刚选的那门语言**显示）。各地语言的完成度与生成方式见
  [多语言词表现状](../10-game/20-translation/08-i18n-language-status.md)。
- **画面流健康判定与等待恢复。** 断流判定按四条事实组合（socket EOF、亮屏 3 秒零字节、
  亮屏 5 秒无新帧、连续解码失败），息屏与尺寸切换期间豁免。故障后进入「等待恢复」，
  设备状态仍算已连接，不会因为「请先连接设备」把开始与批量挡在外面。
- **语句执行前校验画面通道。** 每条语句前查一次通道健康（健康时只是一次布尔判断），
  纯输入脚本因此一并受保护；运行期取帧改走 `capture_for_run()`，故障时阻塞等恢复或抛
  `ChannelFaultError`，不再把陈旧帧交给识别。
- **在线配置改为后台下载。** 启动不再等下载，窗口立刻出现；下载到的修订在下次启动、读取配置
  之前安装，本次运行不替换配置；设置页显示已下载待安装的修订号。边界见
  [在线配置后台下载与下次启动安装](../20-requirements/50-platform/26-online-config-background-download.md)。
- **游戏配置支持删除自建套装。** 表格上方新增「删除套装」，选中后二次确认；被同一份配置里
  的攻具套装登记为关联防具时，确认框会列出引用者，删除后自动解开这条关联。备战方案与装备
  记录里引用该套装的部位按未知套装处理，不会自动清空。新套装编号取当前最大序号加一，
  不补中间空号；删掉最大编号后新建会复用它。
- **词条配置右侧拆成基础属性 / 等级属性两个子 Tab**，整页滚动，长列表不再把页面撑到几千像素。
- **窗口尺寸、位置与最大化状态会被还原。** 重启后窗口回到上次的大小、屏幕位置与最大化状态，
  连接分栏宽度一并保存。此前只存了尺寸，换显示器或改缩放比例后会被还原到不适用的位置。
- **数据模型定义支持右键复制**，「变更记录」对话框统一并扩充为同一套视图。

## 🔧 修复

- **语言下拉框只剩简体中文。** v0.15.11 的发行包漏带 `config/i18n`，界面语言列表扫描不到
  任何语言文件，只显示简体中文且不报错。本版发行包随包携带翻译目录。
- **断流后把冻结画面当成正常画面**（现象与影响见「不兼容变动」第一节）：识别读到的是上一帧，
  点击落在游戏已经变化的界面上。
- **批量「正常完成」的口径**（见「不兼容变动」第二节）：通道中断不再算逐项失败后继续跑完。
- **重启后窗口大小变化很大。** 旧实现只存窗口尺寸、且没有位置与最大化状态，多显示器与
  缩放比例变化后还原到错误的位置或尺寸。
- **无毕业率模型时不再抛异常。** 例如 110 阶的「鸣金·霆」没有模型，最优组合页过去直接抛
  「未找到对应流派的毕业率方案」，改为空状态提示并说明该流派/阶数暂无模型。
- **切换执行目标后，任务候选集没有跟随该目标的环境**，导致可运行列表与实际目标不匹配。
- **回放同步没有写入本地账本。** 从其他设备回放过来的记录过去只进内存视图，重启后消失；
  行身份改用「来源设备 + 来源 local_id」，重复回放不再产生重复行。

## 📦 重构

- **翻译词表按模块拆分。** 从三个大文件拆成 `config/i18n/{lang}/*.yaml`（19 个模块文件 +
  主文件只留 `meta`），每个模块内按源文件命名段落，`zh_CN` 侧是 `en_US` 每个键的同名自映射。
  加载器合并读取，`tr()` 调用方无感。
- **在线配置下载与安装解耦。** 同步段只保留本地回滚（`recover_installation()`），下载进后台
  线程，候选登记到更新暂存区；`prune_archives()` 把待安装候选算进保留集合，否则下次启动会
  把刚下载的内容当垃圾清掉。会员候选只暂存密文，安装时重新取一次授权解密，不把会员明文
  留在磁盘上。
- **`envs` / `plans` 改为按身份增量合并**（见「不兼容变动」第五节）。

## 📚 文档

- **新增 10 种语言的词表现状**（[多语言词表现状](../10-game/20-translation/08-i18n-language-status.md)），
  说明各语言的来源、完成度与生成方式，明确「英文回退」的完成度指覆盖率而非本地化程度。
- **新增游戏术语中英对照**：`docs/10-game/20-translation/` 下 7 张分类对照表，以及国际服客户端
  翻译文件的位置、容器格式与解码方式。
- **新增「配置显示名的载体」需求与架构小节**，把「配置显示名走 `tr()` 词表」这句过期说法改正，
  并补上 `tr_in()` 的用途与边界。
- **更正 v0.15.11 说明里两处过宽的说法**（历史发布说明保持原样，以本节为准）：
  - 「下一个任务就会读到新的配置」：只有 `.wf` 脚本正文、YAML 缓存（按修改时间与大小失效）
    和每次开跑前读取的布局会立即生效。场景注册表、游戏配置、调律规则、OCR 清洗组是进程单例，
    不随任务重建；Git 拉取与外部编辑需要界面刷新或重启。
  - 「未建模来源不会静默按零计入」：数值上先按 0 参与求值，同时进入 `unmodeled` 清单并写日志，
    属性来源里可见，由 residual 兜底。
- **补一张刷新语义表**（用户指南）：立即生效 / 需界面刷新 / 需重启三类分别是哪些内容。
- **`AGENTS.md` 2.5 改正**：任务快照只覆盖环境、参数、用户、脚本与执行顺序；配置直接读磁盘，
  进程单例由程序内变更通知维护，并明确不得把任务配置快照重新引入。
