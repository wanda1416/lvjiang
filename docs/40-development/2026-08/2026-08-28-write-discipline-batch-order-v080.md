## 一、写盘纪律：两处「我什么都没动，它却写盘了」

这两个问题表面完全不同，真正的危害是同一个：**`config/local` 的实体文件是整文件遮盖，一次误触就让该场景/该配置从此收不到出厂更新与在线下发**——正是 08-27 刚做完 remote 下发之后最需要守住的那条线。

### 1.1 场景编辑器画布拖拽死区（`9b19e79c`）

**现象**：在场景编辑器里只是点一下画布上的某个区域，什么都没调，却提示「场景布局发生了变更」；保存后 `git diff` 又看不到任何改动。

**不是 dirty 判定漏写了对比**——按下/松开两端确实比较了几何，真·零位移的点击本来就判为未修改。问题出在**真实鼠标**：点击瞬间常有 1-2 px 抖动，触摸板更明显，于是一次「点击」变成一次真实拖动。实测 1 px 抖动即可让 `x_ratio` 从 0.2 变成 0.20125：屏幕上完全看不出来，但数据确实变了，所以标记 dirty 并不算误报。

「没有 diff」则是另一回事：用户模式下保存写的是 `config/local` 影子，而 `/config/local*` 在 `.gitignore` 里。两个现象叠在一起才显得像「提示我改了但根本没改」。

**修法**：widget 像素层面设 4 px 死区，位移未越过阈值一律不改数据，越过后仍按 `_drag_orig` + 完整位移重算（跨过阈值不会突跳，已用「一步到位 vs 分 20 步」结果一致验证）。**区域、坐标点、面板、画布框四条直接拖动路径统一处理**——它们写的是同一个场景文件，只修区域等于明知故留三个同样的坑。

取 4 px 而非 Qt 默认 `startDragDistance()`（10 px）：后者是给「从控件里拽出一个拖放」用的，对画布直接拖动太大，会把有意的小幅微调也吃掉。

> **测试踩坑**：必须走 `QApplication.sendEvent` 而不是直接调 `mousePressEvent`——`RegionCanvas` 的 MRO 是 `(QWidget, CanvasInteractionMixin, ...)`，直接调会落到 `QWidget` 的空实现上，静默什么都不做。

### 1.2 OCR 清洗规则改为显式保存（`ecc4f4ea`）

清洗规则页边改边写、**打开即写盘**：`cellChanged` 直接回写整份配置，而填表用的 `setItem` 同样会触发 `cellChanged`——于是光是打开对话框就把配置原样回写了 **22 遍**（实测）。

改成显式保存：填表期间屏蔽表格信号；用户改动只记脏不落盘；底部新增「保存 / 取消」，无改动时「保存」置灰；取消 = 从已保存配置重载；带着未保存改动关窗口先弹三选一确认（走 `reject()` 覆盖，X 和 Esc 都拦得住）。

> 注意：真正挡住写盘的是「处理器只记脏」，屏蔽信号是第二道——两者都去掉才回到原来的行为，测试按这个事实分层覆盖。

### 1.3 拒绝运行时访问禁用布局对象（`afc004ad`）

同一方向的第三条：运行期读到被禁用的布局实体直接报错，而不是拿零坐标继续点。

## 二、批量：可见顺序即执行顺序（`059f7c37`）

起因是「上移/下移点了没反应、实际执行顺序还是乱的」。查下来这两个症状是同一个根因，顺着把批量这条链路上同一类「显示与执行各算一套」的偏差一并清掉。

脚本页的行顺序一直是 `list_exposed_scripts()` 的**目录顺序**，跟执行顺序毫无关系。`_move_selected_script` 交换的是 `_script_order`，然后只重写「执行顺序」列那个四字宽的数字——**行本身纹丝不动**，所以看起来像按钮坏了。更糟的是勾选走 `append`，执行顺序实际等于「点复选框的先后」，完全不可见。

改为**可见行顺序就是执行顺序**：新增 `_reorder_script_rows()`，勾选的按 `_script_order` 排在前、未勾选的按候选顺序在后，移动/勾选后都重排并保持选中态（否则连点两次上移，第二次会因为丢焦点静默失败）。

## 三、调律规则的两个安全缺陷

### 3.1 威威 / 玉玉规则漏掉「对玩家单位增效」（`bd8cc1d3`）

`huixin_modao` 和 `huixin_yuyu` 的胫甲 pattern 引用了「对玩家单位增效」，但两个规则的 `affix_pool` 里都没有这一条（七个内置规则里只有这两个漏）。判定第一步就把池外词条判成垃圾，根本轮不到四档条件，于是 `keep_wanjia`（「保留对玩家增效」）对这两个流派是个**死开关**。实测同一件胫甲、开关打开：

```
会心大外        → EXCELLENT
威威大王(beta)  → JUNK  垃圾词条: 对玩家单位增效
玉玉大王(beta)  → JUNK  垃圾词条: 对玩家单位增效
```

用户明确勾了保留，装备照样被回收，**而回收不可逆**。

另加一条内置规则守护：**pattern（含 first 与四档条件）引用的词条必须在本规则 `affix_pool` 内**。解析层的 `_check_names` 只按全局词表查名，不看是不是本规则池内的，拦不住这类。

### 3.2 桌面端按 X 退出调律后执行回收（`7a5a08df`）

端游的回收入口与安卓不同，退出详情后需要补一次回收动作。

## 四、note 模型的上限开关真正生效（`da97ce8a`）

note 存的是自由文本，但配置里一直给它保留着「上限 / 软上限 / 展示上限」三个开关——而这些开关此前对 note **完全不起作用**。

现在按开关的字面语义补齐：

**写入**（`profile_ops.normalize_note_text`，覆盖 UI 单元格编辑、备注文本对话框和 DSL 写入三条路径）：

```
能转成数字 → 取整；有硬上限再截断到上限
软上限     → 只取整不截断（沿用数值模型「仅提醒」的语义）
转不成数字 → 原样存，跳过取整与取上限
```

**展示**（`cell_formatting`）：勾了展示上限且确实配了上限才显示 `X/Y`；值是不是数字不影响这里——数字在写入时已归一。

这样就不会再出现 `12.7/20`、`25/20` 这种两边不同量纲、自相矛盾的显示。**归一化由 cap 本身决定，与 `show_cap` 无关**：关掉展示开关，硬上限照样截断，只是不显示后缀。

### 6.2 改按字体定宽，Windows 下不再截断文字（`5fdb1e21`）

CI（windows-2022）红在 `test_profile_definition_dialog_buttons_all_styled`：四个工具栏按钮写死 `setFixedWidth(70)`，Linux 上 CJK 文字量出来 48~53 装得下，**Windows 的 Segoe UI 超出 70，文字被切掉**。开发机全绿，只有 CI 能发现——而 Windows 用户看到的一直是被截断的「新增/上移/下移」。

新增 `button_styles.fit_button_width()`：取各按钮 `sizeHint` 与 minimum 的较大者并统一应用。顺带修了调用顺序：原来 `setFixedWidth` 在 `apply_button_style` **之前**，而样式表的 padding 参与 `sizeHint` 计算，先定宽再套样式量的是没有内边距的旧尺寸。

验证方式：本机把应用字体调到 10/12/14/16/20pt 模拟更宽的系统 UI 字体，修复后全部通过；退回写死 70 则从 11pt 起复现，且报出的按钮列表与 CI 完全一致。

### 7.1 发布门禁抓到的一个真 bug

CI 的 mypy 报出 `versioning.py` 两处 `read_text(encoding=..., newline="")`。**这不只是类型问题**——`newline` 参数是 Python 3.13 才加到 `Path.read_text` 的，而本仓库 `requires-python` 为 `>=3.10`、Android 侧 Chaquopy 固定跑 3.10，在那里是运行期 `TypeError`，且不在原有的 `(OSError, UnicodeDecodeError)` 捕获范围内。

触发路径正是本版本的头号新功能：`read_version` 由 `_remote_supersedes` 调用，只在 `config/remote` 下确实存在该文件时才走到，所以尚未下发配置的用户碰不到，**一旦真的开始在线下发，Android 端就会炸**。

改为新增的 `read_text_preserving_eol()`（`read_bytes().decode("utf-8")`），保住 `newline=""` 原本的用意——不做换行转换，否则 CRLF 的出厂配置每次盖版本号都会被改写成 LF，产生整文件 diff。

**根因是 mypy 默认跟着开发机解释器（3.13）走**，所以本地全绿而 CI 报错。`[tool.mypy]` 钉 `python_version = "3.12"` 与 CI 对齐。真实下限 3.10 钉不了：numpy 自带 `.pyi` 要求 `>=3.12`。

## 关键设计决策

1. **`config/local` 影子是整文件遮盖，所以误触写盘是真危害**：画布死区与 OCR 显式保存都是为这条服务。
2. **同一失效方式的多条路径必须一起修**：区域/坐标点/面板/画布框写的是同一个文件。
3. **可见顺序即执行顺序**：任何「显示一套、执行另一套」都会变成用户报障。
4. **规则 pattern 引用的词条必须在本规则池内**：全局词表校验拦不住这类静默失效，而代价是不可逆回收。
5. **按钮不写死像素宽**：CJK 字宽随平台字体变，写死宽度在 Windows 上一定截断。
6. **mypy 的 `python_version` 必须与 CI 对齐**：否则本地绿、CI 红，且漏掉真实的运行期不兼容。
