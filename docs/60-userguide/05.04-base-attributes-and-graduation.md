# 5.4 角色基础属性与真实毕业率

毕业率不是八件装备评级的平均值。系统先把角色基础属性、弓玦和当前方案装备聚合成完整战斗属性，再交给所选流派的毕业率方案计算 DPS，最后与该方案的 100% 基准 DPS 比较。

---

## 先区分两种“基础属性”

| 名称 | 含义 | 示例 |
|---|---|---|
| 装备基础属性 | 装备固有的攻击、气血或防御，随部位、等级和品阶变化 | 武器外功攻击、胸甲气血 |
| 角色基础属性 | 不含装备和弓玦的角色自身属性快照 | 基础外功攻击、会心率、穿透、增伤 |

本章的“创建基础属性”和“编辑基础属性”均指角色基础属性。装备基础属性来自扫描结果和游戏配置，不能在战斗属性面板中直接修改。

## 毕业率输入链

```text
角色基础属性
  + 当前弓玦属性
  + 八件装备基础属性
  + 八件装备普通词条与定音
  + 劲/势/敏等五维转换
  ↓
统一应用当前等级的判定抗性与增益抗性
  ↓
标准战斗属性 CombatAttributes
  ↓
所选流派 + 所选毕业率方案
  ↓
DPS、总伤害、战斗时间
  ↓
毕业率 = 当前 DPS ÷ 100% 基准 DPS
```

流派决定属性系别、武器关系和可选方案；毕业率方案决定具体公式、战斗环境、战斗时间及 100% 基准 DPS。

## 第一次准备角色基础属性

建议先完成以下条件：

1. 选择正确用户；
2. 当前备战方案已经扫描并穿戴八件真实装备；
3. 主副武学组合已经解析出正确流派；
4. 游戏内打开角色最终面板，并确认使用的是同一套装备和弓玦；
5. 关闭“满承音、满定音、满等级”等假设开关。

如果本地装备与读取面板时的游戏装备不同，反推结果会把差额错误地记入角色基础属性。

## 创建基础属性

在战斗属性区域：

1. 选择流派；
2. 选择当前弓玦套装；
3. 点击 **「新建属性」**；
4. 把游戏面板中的攻击属性、判定属性、增益效果和伤害加成填入；
5. 输入容易识别的名称，例如“110级无药日常面板”；
6. 保存并在基础属性下拉框中选中它。

创建时系统执行反推：

```text
角色基础属性
= 用户填写的游戏面板属性
- 当前八件装备的基础属性
- 当前八件装备的词条和五维转换
- 当前弓玦属性
```

这是为了让同一套角色基础属性可以换装复用。换上一套装备后，系统重新把基础属性与新装备相加，不需要再次抄写面板。

### 填写注意事项

- 三率填写游戏面板的白字；
- 百分比字段按界面显示的百分数填写，例如 `8.5` 表示 `8.5%`；
- 装备专属属性无需填写；
- 外功穿透和当前属攻穿透填写基础值，不包含装备定音；
- 空字段按 0 处理；
- 名称重复时系统会询问是否覆盖。

穿透采用特殊规则：创建时用户填写的穿透值直接作为基础值保存，不再扣除装备贡献。

## 编辑已有基础属性

选择基础属性后点击编辑按钮，系统会打开：

```text
游戏配置 → 流派配置 → 当前流派 → 当前基础属性
```

可以逐字段修正、重命名或删除。修改会自动保存，返回备战方案后重新选择或刷新即可重新计算。

角色基础属性保存在：

```text
config/session/yysls.json
```

当前实现按流派和名称保存，但不按用户隔离；多个用户可以选择同一套基础属性。为避免误用，名称中应包含角色或账号标识，例如“角色甲-110无药”。

## 选择毕业率方案

方案下拉只显示当前流派已经注册的毕业率方案。方案数据由 Excel 在导入时编译成 JSON；正常计算阶段不直接打开或修改 Excel。

选择方案后，任何下列变化都会触发后台重新计算：

- 用户或备战方案变化；
- 穿戴、卸下或应用最优组合；
- 流派、角色基础属性、弓玦变化；
- 满承音、满定音、满等级变化；
- 游戏配置影响战斗属性的字段变化。

新请求会使旧请求失效，避免快速切换用户或方案后显示上一套数据。

## 如何读取结果

顶部显示两项：

| 指标 | 含义 |
|---|---|
| DPS | 当前输入在所选毕业率方案中的每秒伤害 |
| 毕业率 | 当前 DPS 相对该方案 100% 基准 DPS 的比例 |

悬浮可以查看总伤害、基准 DPS 和战斗时间。毕业率可以超过 100%，这通常表示当前输入超过方案建立时的满值基准，或者基准 DPS 被人工调整过。

## 培养建议：分析当前配装的提升空间

入口：装备状态 Tab 顶部 **「培养建议」** 按钮（需先选好流派和毕业率方案，否则会提示先去
角色详情页选择）。这是词条培养分析，回答"当前这套装备，换哪个词条最值"，与搜索全新
组合的 [最优组合](05.06-optimal-equipment-combination.md) 是两件互补的事。

打开后先看三个指标：**当前毕业率**、**可培养词条数**、**最高单项提升**。下方两个页签：

- **培养建议**：按部位列出每个词条位置的「当前词条 → 建议转为」和对应的单项提升百分比。
  勾选 1~3 件装备后点 **「计算联合提升」**，会为每个词条位置比较多个候选目标、重新计算
  整套毕业率，**不是把各件的单项提升直接相加**
- **理论敏感度**：不代表游戏里能单独获得或失去一条词条，只是"新增按当前等级词条满值、
  扣除按当前实际值"算出的参考区间，帮你判断哪个词条对毕业率影响更大

装备存在词条组合异常（如非法值）时会被排除出培养计算，对话框顶部会列出具体是哪件装备、
哪里异常，需要先按 [5.3 装备管理](05.03-equipment-management.md) 校正。

## “真实毕业率”检查表

要得到当前角色的真实结果，应同时满足：

- 当前用户正确；
- 当前备战方案与游戏穿戴一致；
- 使用真实扫描装备，不用模拟装备替代；
- 基础属性由同一套游戏面板和装备反推；
- 流派、弓玦和毕业率方案正确；
- 满承音关闭；
- 满定音关闭；
- 满等级关闭。

“仅黄字”只改变属性展示方式，不改变毕业率输入。

## 常见异常

| 现象 | 原因与处理 |
|---|---|
| DPS/毕业率显示 `--` | 未选择用户、流派或方案，或当前流派没有计算方案 |
| 下拉里的基础属性提示「需要重新填写」 | 五维换算系数已修正，见下节 |
| 换装后变化异常大 | 基础属性可能用另一套装备反推，重新核对游戏面板 |
| 结果始终偏高 | 检查三个满值假设开关是否开启 |
| 穿透不正确 | 创建基础属性时穿透应填写基础值，不含装备定音 |
| 切换用户仍出现同名属性 | 基础属性当前为会话共享数据，应使用带角色名的配置名称 |
| 修改 Excel 后结果不变 | 用户运行时读取编译后的 JSON，需要重新导入毕业率方案 |

## 五维换算修正后需要重填基础属性

早期版本的劲/势/敏 → 战斗属性换算系数不准（敏被高估约 11%）。装备侧
算多了，反推出来的角色基础属性就等量偏低。

系数已修正。由于创建基础属性时只保存了反推结果，没有保存当时的游戏
面板值和装备快照，**系统无法自动补回差额**，只能重新填一次。

判断方法：战斗属性面板的基础属性下拉中，鼠标停在条目上会提示是否需要
重填。修正前创建的都需要。

处理方法：按[创建基础属性](#创建基础属性)重新走一遍——游戏内打开角色
最终面板，确认用的是同一套装备和弓玦，把面板数值重新填入并保存（用同
一个名称即可覆盖）。

不重填的影响：换装前后的对比、词条培养建议和最优组合的**排序仍然正确**
（这些按修正后的系数现算），受影响的是毕业率的绝对数值，通常偏差 1%
以内。装备上五维词条越多，偏差越大。

技术细节见[毕业率计算引擎](../30-architecture/36-graduation/README.md)，用户日常使用无需维护公式编译器。
