# 3.2 场景管理（F3）

入口：「通用 → 场景管理」或按 **F3**。

场景编辑器用于定义游戏画面中的坐标区域。内置场景坐标按分辨率自适应缩放，正常情况无需校准。

### 何时需要校准

- 游戏版本更新导致界面布局变化
- 使用了与内置布局差异较大的分辨率/窗口比例

### 界面结构

```
┌──────────────────────────────────────────────┐
│  布局选择 + 截图按钮 + 识别按钮               │
├──────────────┬───────────────────────────────┤
│  场景分组     │  画布（截图底图 + 区域框）     │
│  · 背包       │  · 框选区域                   │
│  · 调律       │  · 拖拽/缩放区域              │
│  · ...        │  · 吸附对齐参考线             │
│              │                               │
├──────────────┴───────────────────────────────┤
│  区域列表：名称 / Key / 类型 / 含文本 / 可点击  │
│  [＋ 创建区域] [删除区域]                      │
└──────────────────────────────────────────────┘
```

### 基本操作

| 操作 | 说明 |
|------|------|
| 截图 | 从当前连接的设备/窗口截取画面作为底图（需先完成定位/连接） |
| 创建区域 | 在画布上框选矩形区域，填写名称、Key、类型 |
| 编辑区域 | 双击区域列表中的行，或拖拽画布上的区域框 |
| 删除区域 | 选中区域后点「删除区域」 |
| 识别 | 对当前画面做 OCR，验证区域坐标是否正确 |

### 区域类型

| 类型 | 说明 |
|------|------|
| text | 文本识别区域（OCR 读取文字） |
| click | 可点击区域（点击操作的目标） |
| 其他 | 由工作流定义的特殊用途区域 |

### 区域属性

| 属性 | 说明 |
|------|------|
| 名称 | 中文显示名 |
| Key | 英文标识符（不可与同场景下其他区域/点/面板重复） |
| 含文本 | 勾选后该区域参与 OCR 识别 |
| 可点击 | 勾选后该区域可作为点击目标 |

### 视图管理

同一页面可能有多个滚动态（如背包的不同页），场景编辑器支持**多视图**：

- 视图用于把同一页面的多个滚动态分屏排布，避免坐标叠在一起
- 入口：场景编辑器内的「视图管理」按钮
- 选定视图时只展示该视图自身的定义，选「全部」才展示所有视图
- **同层视图**与基底视图处于同一个图层，只是滚动或翻页后的另一处取景；它没有入口、
  但仍可声明跳转。取消“同层视图”表示这是独立页面，此时需要声明入口

### 多张截图与子场景

场景和子场景都可以在画布上方切换截图，点击「管理」可以预览、排序、删除截图，
或指定当前展示的截图。多张截图共用同一套坐标定义；切换截图只改变编辑时的
底图，不会为每张截图创建一份独立区域。普通场景可再按视图组织定义，
**子场景没有视图选择器**。

新抓取的场景截图默认以 WebP 保存，减少本地占用和同步体积。若当前视图的文字
或图标识别受压缩影响，可打开截图旁的「管理」，把「当前视图新截图格式」改为
PNG，再点击「刷新截图」重新抓取。该选择只作用于当前布局、场景和视图之后
刷新或追加的截图；已有截图不会批量转换。截图与参考图库分开存储，参考图格式
不受此设置影响。

需要在多张任务卡片里复用相同按钮时，可在「场景管理」中把一个普通场景设为
「可作为引用子场景」，再到父场景的「引用」列表绑定实例。子场景先用「裁剪画布」
框住组件的实际内容，随后在这块裁剪画布里标注区域、坐标和模板。父场景中的
实例可以移动、缩放；子场景内部标注要回到子场景编辑。

给子场景区域截取模板时，先切到符合当前图标状态的截图，再选择「截取模版」
或「部分截取」，查看编辑器中的匹配得分，最后点击**「保存布局」**。
模板记录的宽高来自子场景的裁剪画布；运行时按父场景中各引用实例的尺寸
缩放。若图标周围有黑边、不同状态会反色，应核对裁剪边界与模板内容；
深浅反色可使用「兼容反色图标」。修改截图、裁剪画布或模板后，应在实际
画面上重新测试匹配，不要只凭编辑器里看到的截图判断。

### 跨场景引用

同一块屏幕区域有时会在多个场景里出现（如调律页里嵌入的通用确认按钮），无需重复标注：

- 区域面板和坐标面板都提供「+ 引用区域」/「+ 引用坐标」按钮，从其他一级场景（非子场景）
  中选一个已有的区域或坐标接入当前场景
- 引用行在列表中**整行置灰**，与本场景原生定义一眼区分；「来源」列显示来源场景名称，
  「跳转」列显示该实体在源场景配置的页面跳转
- 引用项**只读**：坐标、名称都跟随源场景实时同步，双击不会弹出编辑框，改坐标要去源场景改
- 选中引用行后点「移除引用」即可解除，不影响源场景的定义

### 尺寸信息栏

编辑器底部显示当前截图尺寸/比例和画布相对截图的坐标尺寸/比例，
方便确认缩放关系。

## 布局继承机制

布局在界面中使用中文名称展示，内部则使用创建时确定的布局 key
保存目录和引用。新建和另存为时都需填写两者；key 创建后不再变更，
且 key 与布局名称都不允许重复。另存为不会覆盖任何已有布局。

### 画布中间层

场景编辑器在「截图」和「区域」之间引入了**画布（Canvas）**中间层：

```
截图（含边框） → 画布（裁掉边框，只留游戏内容区） → 区域（坐标相对于画布）
```

普通场景使用**布局级别**的画布；引用子场景另外保存自己的裁剪画布。
调整布局画布后，普通场景的区域坐标会自动适配；子场景模板的录制尺寸
仍以它的裁剪画布为准，不能填写父布局的整张画布尺寸。

### 根布局与继承布局

| 类型 | 说明 |
|------|------|
| **根布局** | 拥有完整的场景定义（所有区域的坐标数据） |
| **继承布局** | 场景定义全部复用根布局，仅画布（Canvas）独立 |

继承布局不产生任何场景文件，所有区域数据实时从根布局读取。修改根布局的区域后，所有继承它的布局自动同步。

### 设计用意

这个机制解决的核心问题是：**不同投屏环境的边框不同，但游戏内容区域相同**。

例如：

- 「安卓布局」是根布局，画布覆盖整个窗口（无边框）
- 「投屏布局」继承自「安卓布局」，画布缩小以裁掉投屏窗口的边框

两个布局共享同一套场景区域定义，区别仅在于画布在截图中的位置。当你切换布局时，所有场景的区域会自动跟随画布调整，无需重新校准。

### 何时创建继承布局

- 你的投屏窗口有边框/黑边，需要裁剪画布
- 不同投屏软件的边框大小不同，需要多套画布方案
- 不想重新校准所有场景，只想调整画布范围

> 如果你的屏幕比例与基准不同（非 20:9），仅调整画布不够，还需要新建根布局并重新校准场景区域。见 [1.4 布局适配](01-quick-start.md#14-运行前检查布局适配)。
