# v0.9.0 — 可复用场景、工作流配置治理、PC 自动调律完善

## 律匠 v0.9.0

本版本为场景和工作流编辑补上了可复用组件能力：一个场景可以标记为引用场景，定义独立裁剪画布，再由其他场景多次引用；工作流可通过三段式路径直接访问引用内部的区域、面板和识别结果。脚本编辑器同时升级为配置分层合并后的文件树，并增加根相对 import、越界保护和单行环境分支。

燕云功能方面，江湖号令新增任务完成校验、领奖声望上限与档案同步，百业货运补齐 PC 流程，不肝商店新增振玉；PC 自动调律则重新梳理了装备详情遮罩、回收和重置的页面生命周期。配置解析、场景编辑器和调律规则页的热启动速度也得到明显改善。

### ⚠️ 不兼容变动与升级指引

#### 1. 出厂图库改为“手游 / 端游”，默认选择手游

- **现象**：原来的“默认”图库改名为“端游”；没有有效选择或旧 session 仍记录“默认”时，升级后会直接选择“手游”。
- **原因**：两套出厂图库按实际平台明确命名，避免“默认”既像回退项又实际代表 PC 截图；默认运行环境按手游处理。
- **如何调整**：手游、模拟器用户无需操作；PC 端游用户升级后在主窗口顶部把图库切换为“端游”。旧“默认”选择和配置不迁移。

#### 2. 不肝商店新增“振玉”，默认参与购买

- **现象**：升级后运行“购买不肝商店”，即使旧配置里没有“振玉”选项，也会默认购买振玉。
- **原因**：购买类别新增“振玉”，为保持“未配置时全买”的既有语义，旧参数会自动补成启用。
- **如何调整**：不希望购买振玉的用户，升级后先在日常任务参数中取消勾选“振玉”，再运行脚本。

#### 3. 江湖号令领奖默认受 1500 声望上限约束

- **现象**：已启用“领取奖励”的旧配置，升级后当周已领取声望达到 1500 时会停止继续领奖；任务文字未消失时也不会误领。
- **原因**：新增“最大领取声望”参数，默认值为 1500，并在每次领奖前校验任务确实完成及当前累计声望。
- **如何调整**：需要其他上限的用户，在运行参数中修改“最大领取声望”；不领取奖励的用户不受影响。

#### 4. `session.json` 的激活项写入后迁移到 `actives`

- **现象**：升级本身不会丢失用户、布局和图库选择；任一激活项首次写入后，旧顶层 `active_user`、`active_layout`、`active_space` 会被删除并迁移到 `actives`。此后若降级到 0.8.0，旧版可能恢复为默认选择。
- **原因**：三个分散的激活项统一收进 `session.json` 的 `actives` 节点；0.9.0 兼容读取旧格式，但 0.8.0 不认识新格式。
- **如何调整**：正常升级无需操作，迁移自动完成；计划降级的用户应先备份 `config/session/session.json`。

#### 5. 自定义工作流的 `import` 改为工作流根相对路径

- **现象**：使用 `../`、依赖“相对当前脚本目录”解析，或试图引用工作流根目录之外文件的自定义脚本会在加载时失败。
- **原因**：所有 import 统一从工作流根目录解析，并增加真实路径越界检查，避免不同入口得到不同结果或逃出配置沙盒。
- **如何调整**：把 `import "../subcall/navigation.wf"` 一类写法改为 `import "subcall/navigation.wf"`；被引用文件必须位于当前工作流配置根目录内。

#### 6. 场景与布局的本地覆盖可能遮住新版引用结构

- **现象**：如果用户本地重画过江湖号令、游戏菜单、盟主、百业、火云等相关场景或布局，升级后可能看不到新的引用卡片、区域或坐标，脚本表现为找不到三段式实体。
- **原因**：`config/local` 仍然无条件高于随版本安装的 system 配置，本地整文件覆盖不会自动合并新版结构。
- **如何调整**：先备份自己的配置，再在场景编辑器中手动同步新实体；不需要保留自定义坐标时，可删除对应 local 覆盖以恢复系统版本。

#### 7. `content_version` 改为显式提升

- **现象**：开发模式下编辑场景、布局或调律规则后，普通保存不再自动增加 `content_version`；如果线上已有更高版本，保存后可能提示当前 system 内容尚未生效。
- **原因**：`content_version` 用来区分远端下发代次，不应随着每次编辑或自动保存增长。
- **如何调整**：普通本地开发无需操作。只有准备新的远端下发代次时，开发者才应在场景编辑器点击“提升至 vN”，或在调律规则页点击“提升”；不要手工批量修改版本号。

#### 8. Profile 的 Python 扩展导入路径调整

- **现象**：直接 import `lvjiang.apps.yysls.core.profile_engine` 或旧 yysls Profile UI 模块的第三方扩展会导入失败；普通用户界面和 DSL Profile 函数不受影响。
- **原因**：Profile 已从燕云插件内部模块提升为主引擎共享能力。
- **如何调整**：扩展代码改用 `lvjiang.core.profile`、`lvjiang.ui.profile` 和 `lvjiang.workflows.builtins.profile` 下的新路径。

### ✨ 新增功能

- **可复用引用场景**：场景可标记为引用组件并设置独立裁剪画布；其他场景可多次放置引用实例，内部区域按二次坐标变换映射到真实画布。
- **三段式场景访问**：`scene.reference.entity` 可用于 click、scan、recognize 等动作，并支持编辑器绘制、命中、对齐、复制和删除引用边界。
- **工作流文件树**：脚本编辑器展示 system、remote、local 合并后的目录树，隐藏配置分层细节并保留来源信息。
- **单行环境分支**：DSL 新增 `env:"desktop" -> ...` 形式，适合表达简短的平台差异动作。
- **配置版本显式治理**：场景、布局和调律规则界面展示当前来源与版本，可由开发者主动提升远端下发代次。
- **主界面图库选择**：用户与环境之间新增图库空间选择，选取即激活；出厂空间明确为“手游 / 端游”，图库管理中的入口继续保留。
- **江湖号令完善**：新增任务完成判断、处理前跳过已完成任务、领奖声望上限、当周声望识别及可选 Profile 同步。
- **百业货运 PC 支持**：导航改用统一子过程，补齐端游路径并接入记录子过程。
- **不肝商店购买振玉**：购买类别加入振玉，并兼容旧 session 参数。
- **评级诊断日志**：自动调律输出行为评级命中的具体规则名称，便于解释“顶级/优秀”等决策来源。

### 🔧 修复

- **PC 自动调律网格遮罩**：不再通过偏移网格点击绕过装备详情；仅在确实存在装备详情时按 ESC，确保后续图像对齐不被遮罩破坏。
- **空槽与异常装备区分**：等级和类型均无法确定时按空槽处理；能确定等级但类型未知时记录异常并安全跳过，不再误判背包到底。
- **PC 重置调律不生效**：改为按 R 打开重置，材料校验通过后按两次空格确认，中间保留 6–7 秒冷却等待；安卓仍使用区域点击。
- **PC 锁定装备回收后误按 ESC**：回收被锁定时 X 已退出详情，不再额外 ESC 退回上一级页面。
- **武库遍历缺失数据**：强化指纹去重、滚动与缺失字段处理，避免异常 OCR 破坏遍历状态。
- **Python 工作流失败未传播**：正确向调度层返回失败结果，不再把失败任务显示成成功。
- **用户总览分组被意外清空**：只有分组或列的明确增删改才写入 `overview_groups`，告警等无关操作不再覆盖列定义。
- **测试写入真实配置**：测试全局禁止写入项目根目录 `config/*`，测试数据统一隔离到临时目录。
- **切换环境重置日常任务**：环境变化后保留当前选中的任务，不再自动跳到列表第一项。
- **更新与公告失败提示**：简化网络失败路径，避免次要服务异常影响正常启动。
- **调律配置下拉框过窄**：基础规则和三大处理页按内容保留下拉框宽度，窄窗口改由表格横向滚动承接。

### 📦 重构与性能

- **Profile 主引擎化**：数据模型、存储、同步、界面和 DSL 内置函数迁入通用核心，燕云只保留自己的周期定义与业务配置。
- **输入后端解耦**：统一键名和输入接口，拆分拖拽执行，减少桌面、Android 与设备端实现之间的重复判断。
- **配置解析缓存**：每次读取仍检查文件状态，内容未变化时复用 YAML 解析结果并向调用方返回深拷贝，避免缓存污染。
- **调律规则懒加载**：打开配置时只创建当前规则页，其他规则首次访问时构建；规则名称直接复用 manager 已解析的数据。
- **场景编辑器懒加载**：编辑器按需创建，减少主窗口启动成本，并修正切换场景时的瞬时窗口闪烁。
- **配置层术语统一**：界面与文档统一使用“本地 / 系统 / 远程”，来源和覆盖关系更直观。
