# 测试、预发布与正式版本

## 目标与边界

允许提供测试包，但不向普通客户端提示升级到测试包。手动安装测试包的用户，在
同版本正式包上线后可以收到升级提示。不引入测试订阅通道，不改变当前版本号，
本轮不执行 Git 发布、标签推送或 APK 安装。

## 版本与入口

采用 PEP 440 的规范子集：`X.Y.ZbN` 是测试版，`X.Y.ZrcN` 是预发布候选，
`X.Y.Z` 是正式版；N 从 1 开始。数字比较，`b2 < b10 < rc1 < 正式版`。
既有 `X.Y.Z.N` 保留为正式系列修订，不作为测试版标识；自动发布入口仍只支持
三段及其 b/rc 后缀。应用版本、标签及附件名使用同一规范字符串，不接受 beta
别名、构建元数据或 epoch。无效版本不伪装成 0，也不触发升级提示。
公告原有范围规则不因软件升级比较改变。

公开标签触发完整发布流水线；另提供手动运行 Release 的测试入口，只能指定已
存在的 bN/rcN 标签。正式版必须通过 master 包含关系门禁，测试版允许从独立测试
提交构建。两类包均校验三份版本字段、标签提交、发布说明、全量回归、四项产物
和 APK 签名；不能用“测试”作为跳过门禁的理由。

GitHub 测试与候选包标记 Pre-release、非 Latest，正式包标记 Latest。新旧客户端
继续请求 releases/latest；新客户端额外拒绝预发布标记、草稿和 b/rc 标签。
测试包通过明确链接手动下载，不自动提示下一测试包。

Android versionCode 每次对外发布递增，包括测试包，必须超过已有应用标签记录
的所有版本码，不能只按标签字典顺序找“上一版本”。正式版复用同一应用 ID 和
签名，从测试包升级保留数据；已发布的测试标签也不能复用或覆盖附件。

## 配置归属

软件升级按完整版本比较；配置清单按目标三段系列匹配。b1 与 rc1 的目标系列均为
X.Y.Z，公开包仍须匹配预置摘要，会员包仍须授权与依赖检查。
安装资料分别保存在 `updates/vX.Y.Zb1`、`updates/vX.Y.Zrc1`，与正式版
`updates/vX.Y.Z` 隔离，包括 r0、索引、归档和状态。事务恢复回写原命名空间。
既有正式四段修订继续共享同系列基底，前提是预置摘要不变。
admin 默认计划使用三段目标系列，不把 b/rc 后缀写入配置清单 key。
控制台的维护版本检查也只比较三段系列，b/rc 或第四段改变不单独使配置计划失效。
配置发布及会员范围上下限只接受三段版本；运行在测试、候选或第四段修订的客户端
均将对应三段系列视为自己的配置版本。
手机在线配置更新仍未开启，PC 同步方向不变。

## 验收与验证边界

- 测试包不会进入正常升级提示，同目标正式版高于测试与候选包。
- 无效或不一致版本拒绝发布，手动测试入口不能发布正式包。
- 正式版仍验证 master 归属，versionCode 检查包含测试标签。
- 测试与正式 r0、恢复状态隔离，配置授权与摘要边界不变。

单元与配置定向回归在本地验证；真正的 Windows/Android 构建、签名与 GitHub
发布必须在实际流水线完成后确认，不能凭工作流配置报告发布成功。
