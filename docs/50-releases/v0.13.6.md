# v0.13.6 — PC 后台截图（Beta）、基础配置重排与聊天场景补齐

> 本文以 v0.13.5 正式版（提交 `13249347`）为基线。

本轮的主线是 PC 端**被遮挡也能截图**：输入侧早就有后台模式（PostMessage），截图这
一半一直卡在「谁盖在游戏窗口上就抓到谁」。本版补上基于 Windows Graphics Capture
的取帧通道，并把它做成**实验性能力**——能取到帧不等于所有脚本都能在这个模式下跑通，
所以开关上标了 `(Beta)`。顺带重排了「基础配置」页，并补齐聊天场景的区域定义。

## ⚠️ 不兼容变动与升级指引

### 1. 「基础配置」页项目改名并重新分组

- **现象：** 配置管理 → 基础配置的项目名和顺序都变了：「窗口输入模式」→
  **窗口输入**、「默认窗口标题」→ **窗口标题**、「安卓输入方式」→ **安卓输入**、
  「安卓截图方式」→ **安卓截图**；顺序按功能分成三组（界面语言 / 窗口 / 安卓），
  组间有分隔线。「窗口输入」也从下拉框改成两个单选，和安卓那两项一致，并按
  「前台在前、后台在后」排列，与下面「窗口截图」的两项一一对应。
- **原因：** 同一页里一处下拉、一处单选，长短不一的名字又混着排，看不出哪几项
  属于同一件事；新增的「窗口截图」必须紧贴「窗口输入」（两者有约束关系），借这次
  一并把名字缩短、按功能聚合。
- **如何调整：** 不需要任何操作。配置项的存储键没有变化，已保存的设置照常沿用。
  照着旧文档或旧截图操作的用户，按上面的对应关系找新名字即可，用户指南已同步。

## ✨ 新增功能

- **PC 后台截图（Beta）**：新增基于 Windows Graphics Capture 的取帧通道，游戏窗口
  被别的窗口盖住时照样能截到画面。开关在主页面「扫描窗口」模式下，勾选「后台模式」
  后可用，仅本次运行期间生效（与「红框标定」同口径，不落配置）。安卓设备模式下
  隐藏——设备截图本就来自设备，不存在遮挡问题。
  - **解决不了最小化**：窗口最小化后没有被合成的客户区表面，取帧随之停止。这条路
    的上限是「被遮挡也能跑」，不是「最小化挂后台」。
  - 必须同时使用后台输入。光标输入要求窗口在前台，这时后台截图没有意义；反过来
    「只开后台截图、输入仍走前台」会让人以为可以把窗口盖起来，一盖输入就失效，
    现象却是「脚本点了没反应」，很难自己定位。所以取消后台模式会连带关掉它，
    运行中也不允许切换（换截图后端会把正在使用的实例停掉）。
  - 不可用或建会话失败时自动退回前台截图并复位开关，不会把你留在截不到图的状态。
  - 与前台截图输出逐像素同构：取帧交付的是窗口可见边界（比窗口矩形窄若干像素，
    Win10 两侧各约 8px 不可见调整边框），后端按差值贴回窗口矩形尺寸，**已有布局
    标定不用重做**。
- 「基础配置」新增 **窗口截图**，可把后台截图设为默认，不必每次连接后手动勾选。
  它是绝对的默认值，不受「窗口输入」选择影响；但后台截图要求输入同时走后台，所以
  主界面只有在勾选「后台模式」后才会按它自动勾上「后台截图」，未勾选时该开关整体
  置灰并说明原因。
- 采集面板新增 **刷新** 按钮：与「截屏」的唯一区别是不落盘，只更新预览。
- 主页面日志页新增 **清理日志** 按钮，清空当前窗口的全部日志，包括被级别筛选
  隐藏的部分。
- 关于对话框补上许可证名称与免责声明；发行包随附 `LICENSE.txt`，「许可证」按钮
  优先打开随包全文，离线也看得到条款。
- 场景编辑器的「视图管理」设置关联视图时改为 **分组 → 场景 → 视图** 级联选择，
  并可选「无关联视图」清除关联；此前需要在一个长列表里自己找。
- 随包场景补充区域定义：
  - 同游主界面新增境界相关区域（安卓与桌面两套布局）；
  - 聊天场景补齐整条送礼链路——新增 gift / item / shop 三个视图、13 个区域与
    2 个面板（会话列表 6×1、赠礼道具格桌面 5 列 / 安卓 4 列，均用 even 校准配固定
    网格）。同游商店与结义商店是同一张社交商店页的两个左侧页签，共用一套区域。
    桌面侧绑 SPACE / ESC，安卓侧绑对应按钮坐标，同一份脚本两端通用。

## 🔧 修复

- 「截屏」保存的图与看到的预览不再是两回事：改成「取一帧 → 更新预览 → 保存同一帧」。
  此前截屏只落盘不刷新预览，而为了刷新预览另抓一帧又可能抓到已经变化的画面。
- 采集面板的按钮补上悬停与按下两态，此前点下去毫无反应——项目共用的按钮样式本来
  就带这两态，是这个面板漏了。
- 禁用状态的勾选框、单选与说明文字现在会整体置灰。全局样式给所有控件写死了文字
  颜色，盖掉了调色板里的禁用色，此前这些控件被禁用后看上去和常态一样，只是点不动，
  容易被当成「自己没点到」。
- 关于对话框里「本项目完全开源免费」改为「源码公开、免费使用」：所用许可证限制
  商业用途，不符合 OSI 的开源定义，旧说法不准确。
- 配置管理里的截图方式文案改为「Scrcpy 流式截图」（英文同步为 Scrcpy Streaming
  Capture）：「scrcpy 视频流」听起来像在说录屏，实际是与旁边「ADB screencap
  静态截图」并列的取帧方式选项。

## 📚 文档

- DSL 鼠标指令文档写明 **`scroll` 与 `drag` 的方向词含义相反**：`scroll up` 说的是
  滚轮怎么拨（看上面的内容），`drag up` 说的是位移往哪走（内容上移，看到的是下面
  的内容）。触摸后端用滑动模拟滚轮、按手指方向实现，所以 ADB / 设备端手势上
  `scroll` 的效果与桌面滚轮相反，设备端更是完全不支持——触摸端一律用 `drag`，
  文档给出 `is_device()` 分流的写法。另记一条桌面侧的不确定性：用户可能开了系统级
  反向滚动，引擎读不到也纠正不了，要方向确定就用 `drag`。
- IO 后端文档补充后台截图通道及其边界（被遮挡可用、最小化不可用、需配后台输入）。
- 场景管理文档补充关联视图的级联选择说明。
- 用户指南的基础配置一节按新分组重写，补上此前漏列的「界面语言」，并新增
  「窗口截图」说明。

## ⚠️ 已知限制

- **后台截图是实验性能力**：取帧路径与一部分脚本的识别、时序假设还没磨合好，
  很多脚本暂时无法在该模式下跑通。开关标注了 `(Beta)`，该模式下的功能不可用问题
  暂不受理；需要稳定运行请使用前台截图。
- 后台截图对**最小化**的窗口无效，也无法让游戏在没有被合成的情况下继续出帧。
- 后台截图依赖 Windows 专属可选组件，仅 Windows 可用；组件缺失时自动退回前台截图。
