# 10. 脚本工作台与脚本作者须知

> 最后更新：2026-10-09（基线 v0.13.14）。

本页面向要自己写或改 `.wf` 脚本的用户：脚本工作台的操作、指令怎么选、画布怎么取坐标，以及脚本文件与运行性质的约定。日常使用不必读它；日常任务的启动与排队见 [6. 工作流与日常任务](06-workflows.md)。

也可在 VS Code 中安装仓库的 WF 扩展编辑 `.wf`。扩展提供高亮、片段及
可用 Python 环境下的静态诊断、补全、跳转及过程引用/重命名；缺少环境时
基础文本编辑仍可用，
详细安装和边界见[编辑器说明](../20-requirements/60-editor/01-wf-editor-plugin.md)。
VS Code 扩展不负责运行或单步，需使用下述脚本工作台。编辑系统脚本前应
确认配置层：日常使用时 local 同路径文件会覆盖 system 版本。

入口：「工具 → 脚本编辑」（不设键盘快捷键）。三栏：左侧全部 `.wf` 脚本（标注 `[system]` 系统 / `[local]` 本地），
中间依次为「代码」「元数据」「录制」三个 Tab，右侧为「指令」「调试」两个 Tab。

在代码页按住 Ctrl，鼠标停在 `call` 的过程名上时，该名字显示下划线。点击后打开定义这个过程的脚本，并定位到对应的 `def` 行。定义可以在当前文件，也可以在 `import` 进来的文件里。内置函数、注释，以及当前脚本解析失败或过程未定义时，不会出现下划线。脚本正在运行时暂停跳转，以免换文件打乱当前行高亮。跳到另一个文件前，若当前脚本有未保存修改，会先询问是否放弃。

「元数据」页用表单编辑文件开头连续的 `#%` 声明：名称、说明、环境、运行能力、
脚本性质、批量声明及参数定义都在这里。参数列表可增删和调整顺序；选中参数后
填写类型、默认值、选项、显示环境与显示条件。长文本输入框右侧的「展开」可切换
多行编辑，收起时仍保留完整内容。点击「应用到代码」只更新代码缓冲区，仍须点击
「保存」才能写入文件。无法由表单解释的声明会显示原因，可到「代码」页修正。

「脚本配置」页分为「日常」「专用」两个子标签，按脚本元数据声明自动归类。
两页都可以勾选是否在日常入口展示、修改显示名，并用上移/下移调整同类脚本顺序。
保存会同时保存两页修改，撤销会恢复两页；切换标签不会保存或清空草稿。
脚本性质只能通过元数据声明调整，原先在脚本配置中保存的性质覆盖不再生效；
如需调整 `.wf` 脚本性质，请在「元数据」页修改并保存脚本。

「保存位置」位于元数据页的 `id` 上方，决定文件写入 `local` 还是 `system`，
不是 `#%` 声明。普通用户新建脚本固定保存到 `local`；系统和远程脚本只读，
需先右键复制到本地。开发者可选择两层，已有脚本切换位置后点击「保存」才迁移；
目标同路径文件存在时会先确认覆盖。开发者编辑本地脚本时，普通保存仍写回本地。

### 指令：不记语法，像快捷指令一样选操作

「指令」Tab 列出全部可用操作，按 交互 / 感知 / 图色 / 控制流 / 数据与输出 分组，顶部可搜索
（中文名或英文指令名都行）。选中一个后下方出现它的槽位表单：

| 槽位类型 | 怎么填 |
|---------|--------|
| 场景 / 区域 | 下拉（区域下拉随场景变，含区域 / 坐标点 / 面板） |
| 延迟 | 下拉：配置管理里的命名等待参数 |
| 模板 | 下拉：`config/system/templates/` 里的图 |
| 坐标 / 区域 / 颜色 | 点「取画布」用调试画布最近一次取点 / 框选的值（画布已有值时自动预填） |
| 文字 / 变量 / 数值 | 直接输入（文字自动加引号，变量自动补 `$`） |

带 `*` 的必填，其余留空就不出现（例如「操作后等待」留空就没有 `after wait`）。
预览区实时显示生成的语句，缺必填项会标红说明；「插入到脚本」落到编辑区光标处
（光标行已有内容时自动另起一行，并沿用当前缩进；`if` / `loop` 这类块会带好 `end`，光标停在块内）。

### 画布：截图上取坐标 / 取色 / 框区域

先在主窗口定位窗口或连接设备，再点「刷新截图」。画布按当前布局的 canvas 裁过，
取到的就是脚本里直接能用的归一化坐标：

| 操作 | 效果 |
|------|------|
| 鼠标移动 | 底部实时显示 `x= y= rgb=#…` |
| 左键点一下 | 取点 + 取色 → 「插入坐标」写 `(x, y)`、「插入颜色」写 `"#rrggbb"` |
| 左键拖框（可拖角调整） | 取区域 → 「插入区域」写 `(x, y, w, h)` |
| 右键拖 / 滚轮 | 平移 / 缩放 |

插入的 `(x, y, w, h)` 赋给变量后就是一个矩形坐标，可 `click $r`，也可喂 `color_ratio($r, …)`、
`find_icons($r, …)` 等图色函数；`(x, y)` 同样可直接喂 `pixel($p)` / `bright($p)`。

### 运行与单步

| 按钮 | 作用 |
|------|------|
| 运行 | 把编辑区内容存成临时脚本 `_editor_run.wf` 后在后台线程执行 |
| 单步 | 未运行时：以单步模式启动，停在第 1 条语句前；运行中：执行当前高亮行，停在下一条 |
| 继续 | 退出单步，跑到结束 |
| 暂停 | 在下一条语句前停住（不打断正在执行的动作） |
| 停止 | 立即结束（包括停在断点上的脚本） |

执行到哪一行，编辑区就高亮哪一行；变量表每条语句前刷新一次，日志区显示本次运行的引擎日志。
运行期间编辑区只读（改了行号，高亮就对不上）。运行环境（截图、输入、OCR、布局、用户）
与日常页执行完全相同。

`import` 和所有 `call` 在单步调试中各算一条语句。`import` 只高亮并放行导入行；
`call` 会一次执行完整过程，在返回调用方后才停到下一条语句，不进入被导入文件或
过程体逐行调试。

| 按钮 | 作用 |
|------|------|
| 新建 | 输入脚本 id（即文件名）和显示名；开发者还可选保存位置。生成带 `#% name` / `#% env` 头的模板，新脚本自动加入日常下拉 |
| 保存 | 写回当前脚本，随后自动做语法 + 当前布局引用校验，结果显示在底部 |
| 另存为 | 以新 id 复制一份 |
| 删除 | 删除当前脚本 |
| 检查 | 只做语法检查，不需要保存 |

> 普通用户的改动写在 `config/local/workflows/`，不会动系统文件。**系统脚本不可删除**，
> 删除按钮对它们是灰的；不想在日常页看到某个脚本，请在「工具 → 脚本编辑 → 脚本配置」
> 里取消勾选。你自己新建的脚本可以随时删除。
> 脚本 id 不能以 `_` 开头——`_` 前缀文件被当作临时脚本，不会出现在列表里。

### 同一画面识别与失败留图

需要从同一张截图继续识别其他区域时，在 `scan`、`find`、`recognize` 的
`as $var` 后写 `from last`。装备详情的基础字段、冷却字段、锁状态和详情已
采用同帧读取。复用不会重新截图，也不增加帧序号。

```text
scan [game_menu_page].[baoguo, peiyang] as $menu
if not ($menu.baoguo contains "包裹" or $menu.peiyang contains "培养")
    log error "未识别到菜单入口"
    screenshot from last
    eval pause("请检查菜单页面后继续")
end
```

`screenshot from last` 保存用于判断的原始帧；`screenshot` 重新截取当前画面。
图片保存在 `logs/image/`，info 日志给出完整路径与 `frame_seq`，识别 debug
日志使用同一序号。菜单导航已在打开后校验失败的分支中，于暂停和重试前留图。

最近帧可能被后续识别、图色、面板图像对齐或普通 `screenshot` 替换，留图
应紧接失败判断。`wait stable` 的内部采样不影响最近帧或诊断帧序号。普通坐标
点击或普通等待不会刷新最近帧，操作后要识别新画面时应
省略 `from last`。无最近帧的识别复用会报错；诊断留图缺帧或保存失败只记录
原因。引擎不会自动判断异常并保存图片，其他失败分支可按脚本需要显式添加
留图，也可写在已有的 `try/catch` 中。

### 页面校验诊断的记录范围

公共导航、登录、购买、签到、江湖号令、兑换码和游戏方案扫描已在明确的
页面校验失败分支留图。确认和异常暂停之前均会保存判断帧；一些直接返回
失败的页面检查也会记录，不要求弹出 pause 才能诊断。

正常轮询、翻页查找、可选弹窗未出现及成功的替代校验不额外留图。
例如背包 tab 读不到但识别到“整理”，或方案已选中而没有“使用方案”按钮，
仍按正常流程处理。上层任务转发公共导航失败时不重复保存。

账号搜索耗尽会记录最后观察帧和当前列表；登录主页确认耗尽会记录最后的
主页判断帧及自动关闭弹窗后的当前现场。查看日志中的帧来源与 frame_seq
可以区分两张图。商品名不合规和异常恢复重启的记录在页面清理之前完成。
