# 国际化模块与翻译查找契约

> 最后更新：2026-10-09（基线 v0.13.14）。

## 2. 技术方案

### 2.1 总体架构

采用 **YAML 翻译文件 + Python tr() 包装函数** 方案，不依赖 Qt 的 .ts/.qm 工具链。

```
┌─────────────────────────────────────────────┐
│              lvjiang.i18n 模块               │
│                                             │
│  init_i18n(language)  ← 启动时调用，加载核心层│
│  load_app_i18n(app_id) ← 插件加载时调用      │
│  tr(text)             ← 统一入口，不分 QObject│
│  set_language(code)   ← 运行时切换（重启生效）│
│  available_languages() ← 扫描核心层翻译文件  │
│                                             │
│  内部：核心层 + 已加载插件层合并成一张扁平表  │
│  查找以中文原文为 key；找不到 → 返回中文原文  │
└─────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────┐
│         config/i18n/ 翻译文件目录             │
│                                             │
│  zh_CN.yaml            ← 核心层中文基准      │
│  en_US.yaml            ← 核心层英文翻译      │
│  apps/{app_id}/zh_CN.yaml ← 插件层中文基准   │
│  apps/{app_id}/en_US.yaml ← 插件层英文翻译   │
└─────────────────────────────────────────────┘
```

**核心层 / 插件层是两份独立文件，合并到同一张查找表**：`init_i18n()` 启动时
只加载核心层 `config/i18n/{lang}.yaml`；`load_app_i18n(app_id)` 在插件加载
时按需加载 `config/i18n/apps/{app_id}/{lang}.yaml` 并**合并**进同一张
`_translations` 表——查表以中文原文为 key，同一句中文若在核心层和插件层
都出现（或插件层内部自己重复），后加载的会覆盖先加载的，核心层总是先于
插件层加载，所以插件层能覆盖核心层的同名条目。这不是设计上鼓励的行为
（见 `tests/core/test_i18n_consistency.py` 的重复源文冲突检查），只是
实现上如实允许，写文案时应避免让同一句中文在两处出现不同译法。
`tr()` 本身是单一入口，调用方不需要关心某个字符串来自哪一层。

### 2.2 翻译文件格式

翻译文件顶层 key 按"模块/文件"分层，各模块自己是一个平级 dict，
**不套一层 `ui:`/`messages:` 之类的大类包装**：

```yaml
# config/i18n/zh_CN.yaml
meta:
  language: zh_CN
  display_name: 简体中文
  version: 0.2.5          # 未接自动化流程，长期停留在这个值，不代表文件没更新

main_window:
  title: 律匠 - 通用视觉 RPA 引擎
  menu_general: 通用
  # ... 每个模块一个顶层 key，按需再往下分层

settings_dialog:
  title: 配置管理
  language_label: 界面语言

messages:
  err_layout_not_found: '无法加载布局: {name}'
  err_panel_not_defined: 布局中未定义 panel {scene}.{panel}

config:
  layout_default: Default Layout
  delay_step_wait: Step Interval

# 机器抽取的占位段：手工整理进具体模块之前的字符串先落在这里，
# key 直接就是中文原文本身。见 §3.3。
auto_strings:
  '未选择窗口': '未选择窗口'
```

`en_US.yaml` 结构完全一致，值替换为英文。

### 2.3 tr() API

**统一使用 `tr()` 函数**，不区分 QObject 内外。`tr()` 以中文原文为 key，在翻译文件中查找对应值；找不到则返回原文（中文 fallback）。

```python
from lvjiang.i18n import tr

# UI 字符串
settings_menu = menubar.addMenu(tr("通用"))

# 含变量的字符串
QMessageBox.information(self, tr("发现新版本"),
    tr("发现新版本 v{latest}\n当前版本: v{current}\n\n是否前往下载？")
    .format(latest=latest, current=current))

# 错误消息
raise WorkflowUserError(tr("布局中未定义 panel ..."))
```

### 2.4 语言配置

在 `session.json` 的 `settings` 节点存储 `language` 字段：

- `"zh_CN"` — 中文（默认）
- `"en_US"` — 英文
- `"auto"` — 跟随系统 locale

启动时读取该配置，加载对应翻译文件。语言切换后需重启应用生效。

### 2.5 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 翻译文件格式 | YAML | 项目已重度使用 YAML，团队熟悉 |
| 翻译 key 策略 | 中文原文作 key，找不到时返回原文 | 未翻译的条目不会空白，直接显示中文 |
| 日志消息 | 引擎日志保持中文，UI 面板日志走翻译 | 开发者调试不受影响 |
| 运行时切换 | 重启生效 | 避免热切换的 UI 重建复杂度 |
| 默认语言 | zh_CN | 当前用户群以中文为主 |
| 文档字符串 | 不翻译 | 面向开发者，保持中文 |

## 翻译内容一致性

### auto_strings：机器抽取占位段与一致性检查


`tr()` 调用不会自动进翻译表——新增一句 `tr("新文案")` 后，如果没人手动
往 `zh_CN.yaml`/`en_US.yaml` 补对应条目，找不到翻译时会静默 fallback 回
中文，不报错也不会在 CI 里被发现。为此两份核心翻译文件末尾各有一个
`auto_strings:` 段，key 直接是中文原文本身（`'某句话': '某句话'`），
先把缺口占住，再逐步搬进具体模块分类。

`tests/core/test_i18n_consistency.py` 用 AST 扫描全部 `tr("字面量")` 调用，
和翻译表比对，跑两条棘轮（只许下调，不许上涨）：

- **missing**：代码用了、表里没有的字符串数
- **orphan**：表里有、代码已经不再 `tr()` 的字符串数

同时检查一条更隐蔽的错误：**同一句中文如果在不同 key 下配了不同译法，
后加载的静默胜出**（查表是纯粹的"中文原文 → 译文"扁平字典，见 §2.1）。

模块位置为 src/lvjiang/i18n，核心和插件翻译由同一入口合并；用户语言选择属于设置，切换后重启生效。
