# v0.15.9 — 账户同步与总览多端账本

这一版的核心是：电脑可以登录账户，把角色名册、文档和玩家档案总览同步到云端；手机可以选择跟云端对等同步，或继续只用电脑下发的离线包。档案历史改成能多端回放的账本。结果文件和锁文件换了存放位置。

不登录、不点同步的用法保持原样：任务、批量、档案都还在本机。

## ⚠️ 不兼容变动与升级指引

### 工作流结果 JSON 改存 `logs/output/`

- **现象：** 任务与批量的结果文件从 `config/session/output/{用户}/{年-月}/{日}/` 改到 `logs/output/{用户}/{年-月}/{日}/`，与任务日志（`logs/daily`）、批量报告（`logs/batch`）、调律说明（`logs/tuning`）同根。任务历史里点开结果与日志的行为不变。
- **原因：** `config/session/` 只放用户数据与运行状态。产出堆在里面时，打包 session 排查问题会把整批结果 JSON 一起带走。
- **如何调整：** 不迁移也能继续用。历史记录里存的是相对客户端目录的路径，旧记录仍指向旧目录，旧文件照旧打得开。想把旧结果收拢到新目录（需要本机有 Python；脚本不随安装包分发）：

  ```
  python scripts/one_off/migrate_output_to_logs.py           # 干跑，只列计划
  python scripts/one_off/migrate_output_to_logs.py --apply   # 执行
  ```

  脚本把 `config/session/output` 下的文件搬到 `logs/output`，并改写历史库里指向旧目录的 `result_path` / `log_path` / `report_path` / `markdown_path`。默认干跑；先移文件后改库，中断可重跑。目标位置已有不同内容的同名文件时不覆盖。改写前把数据库备份到 `logs/one_off/migrate-output-<时间戳>/`。旧目录不会被自动删除。自己的脚本若按 `config/session/output` 取结果，改成 `logs/output`。回传同时接受新旧两种路径前缀。

### 锁文件统一到 `config/session/.locks/`

- **现象：** 运行时锁不再散落在数据目录旁（不再产生 `users/.lock/`、`yysls/.locks/`、`session.json.lock` 这类侧车），集中到 `config/session/.locks/`，文件名是 `<类型>_<摘要8位>.lock`。
- **原因：** 旧锁目录换过几套命名，数据目录里留下一批分不清是否仍在使用的残留。
- **如何调整：** 无需操作，下次启动按需重建。退出全部律匠窗口后，可用一次性脚本清掉旧位置的残留（需要本机有 Python；脚本不随安装包分发）：

  ```
  python scripts/one_off/cleanup_obsolete_locks.py --config config
  python scripts/one_off/cleanup_obsolete_locks.py --config config --apply
  ```

### 玩家档案历史改为账本

- **现象：** 档案库首次启动升到 schema v9。历史里的 `action` / `override` / `undo` 统一变成 `set`；`tick`（自动恢复）和 `reset`（周期归零）保留。历史窗口的类型标签是「覆盖 / 增量 / 恢复 / 重置」。撤销不再改旧行，而是再写一条反向记录，来源为「撤销：原来源」，所以撤销本身还能再撤销。同时去掉两张只给迁移核对用的表（`profile_history_legacy`、`profile_key_renames`）。
- **原因：** 总览要在多端按账本回放，必须分清这条记录给的是绝对值还是增量。旧库里绝对写入也记成 `action`，无法还原。
- **如何调整：** 无需操作，启动时自动升级。已有数值不丢。自己写的脚本若按旧的历史类型字符串过滤，改为 `set` / `delta` / `tick` / `reset`。

### 百业声望绕梁的注册 key 改名

- **现象：** 系统注册表里的 `baiye_raoliang_shengwang_of_month` 改为 `baiye_rl_sw_of_month`（标签仍是「百业绕梁之音·声望」，月上限 2）。`declare_profiles` 只认注册表里的名字；脚本仍声明旧 key 时，这一次声明整批失败，不会创建其中任何一个 key。已经写在 `profile.yaml` 里的旧 key 和它的数值不会被升级程序改掉。
- **原因：** 注册名缩短。声明只创建缺失项，不负责把已有档案改名。
- **如何调整：** 自己的百业脚本里把声明和记账 key 改成 `baiye_rl_sw_of_month`。希望账面也改到新 key 时，在数据模型编辑器里重命名；重命名会带走全部用户的当前值和历史。不改脚本、不重命名也能继续用旧 key 上已有的数，只是新注册名不会自动接上旧数据。

### 第二个实例可以保存配置

- **现象：** 同一安装目录里后打开的实例不再被拦下「不能保存」。配置、场景、脚本、批量配置、用户数据和档案定义都能写盘。窗口标题仍标 `[只读实例]`。它不注册全局热键，也不能启动智能调律的 MCP 服务。同一用户仍然不能被两个实例同时执行。
- **原因：** 原先用「只读」同时表达了「不能抢热键」和「不能写任何配置」，后面这条会挡住正常的多开编辑。写入冲突改由文件锁、内容版本和覆盖确认处理。
- **如何调整：** 无需操作。若你的自动化依赖「第二个实例保存一定失败」，这个拒绝不再出现。命令行 `--read-only` 仍然只影响热键和 MCP。

## ✨ 新增功能

### 账户、名册与总览同步

- 主窗口可打开「账户管理」：登录、修改密码、查看本账号下的设备。登录对话框提供注册入口和密码可见切换。登录后按分钟自动同步，也可以手动同步或停止。同步表分四行：定义（`profile.yaml`）、名册、文档、总览，并带逐行进度。
- 总览同步分两层。定义是各端共用的 key 列表。账本是每个用户的数值变更：电脑或手机写出的覆盖、增量和周期归零会上传；另一端先拉定义，再按时间回放。周期中的自动恢复不逐条上传。云端还没有快照时，需要先在一台电脑上「刷新快照」。
- 在数据模型里重命名 key 后，会给仍有数值的用户补一行当前值，随下次同步让其他设备落到新 key。脚本和注册表里的字面 key 不会被自动替换。
- 便利贴和角色基础属性在本机仍是明文。上传到云端时用登录口令派生的密钥加密，服务器只存密文。解不开时保留本机文件，不用云端内容覆盖。改密码之后，下一次同步会用新密钥重新上传。

### 手机总览来源

- 手机设置里可以选择总览从哪来。**云端**（默认）：在线同步先拉定义和账本，再把这台手机自己写下的变更传上去。**PC 端**：总览随电脑下发的离线包整库更新，在线同步跳过总览。
- 从 PC 端改到云端之前，要先「清除本地总览数据」，否则手机会拒绝用云端快照覆盖已有库。从云端改到 PC 端可以随时切，切之前会二次确认并提示未同步的变更数。下发配置时，手机的登录状态和实例标识会保留。
- 悬浮窗收成两种形态。未启动时并排显示当前用户和任务，下面是「启动任务」和「关闭悬浮窗」。运行中显示任务名、计时和日志，操作是暂停、结束；需要确认时换成确认和拒绝。

### 江湖弈

- 内置场景补了单人流程和结算相关区域。注册表新增 `wulujuan_level`（乌鹭卷等级，赛季配额）。你自己录过同名场景时，自建场景仍盖住内置版本。

## 🔧 修复

- **按速率恢复的数值（心力等）记错账：** 一次消耗会把「上次写入至今自动恢复的部分」和这次消耗写进同一条历史，恢复量对不上。现在先落一条「自动恢复」，再记这次消耗。已经写过的历史不回改。

## 📦 重构

- 账户管理重做为页签布局，登录与账号操作、数据同步进度、设备管理分开承载。
- 设备身份拆成机器级和实例级，凭据按实例隔离；同一安装目录内第二个实例的保存范围放宽（见「不兼容变动」）。
- 文档同步通道改为声明制，core 不再硬编码插件文件。
- 离线包改为按文件覆盖安装，不再整目录替换 `config`。
- 结果文件、锁文件等落盘位置调整见「不兼容变动」。
