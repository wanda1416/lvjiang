# Agent 对象、状态与执行契约

所有 MCP 访问以 Lv1 激活为前提，包括初始化、发现、文档和公共配置读取。
收到 lv1_required 时，提示用户在律匠设置的“功能激活”中激活 Lv1。

启动 MCP 服务即开放本实例已有能力。没有单独的固定用户、目标白名单或逐项
“授予”操作。先调用 get_capabilities 或 list_users 获取 current_user 和全部
users，再在工具 user 参数中选择用户。主界面切换用户后重新查询即得到新上下文，
其他用户仍可处理，连接配置不需要改变。不存在的用户拒绝处理，不自动创建用户。

list_targets 返回全部窗口/设备的 id、ready、selected、busy 和 current_target_id。
扫描与调律的 target_id 可显式指定；省略时使用调用当时的当前目标。服务会沿用
律匠既有目标切换及执行器，不要求用户额外选中“授权目标”。设备必须已连接且
可用，目标或用户被占用时拒绝启动，不停止其他任务。接口返回限制或关闭原因时
向用户解释原因并按需重试，不把修改连接配置当作解法。

start_scan_all_loadouts 会切换游戏方案并更新装备库、方案及基础属性，当前只覆盖
可见网格。用任务 ID 查询进度，完成后重新读数据；逐方案失败不能说成全部成功。
启动提供非空 request_id，相同内容重试幂等，不同内容使用新 ID。客户端断连或
关闭 MCP 不停止已启动任务；可由 get_task_status 请求 pause/resume/stop，人工
弹窗未处理时不能强行恢复。历史任务不自动重放。

新规则与基础组只创建于 local，不覆盖已有 system/remote/local 定义。生成不设
默认，启动使用冻结快照；update_tuning_config 只在用户要求保存时合并自己拥有
的字段。原方案与模拟分析副本保持分离。规则中的回收、重置、锁定和狗粮按最终
配置执行，Agent 应向用户说明会发生哪些动作，页面不要求再次逐项授予。

服务不开放任意路径、Shell、SQL、Python 或任意工作流执行。用户可经 MCP 读取
所有用户的业务数据，不因此开放账号凭据或 API Key。未知材料库存不解释为可用。
