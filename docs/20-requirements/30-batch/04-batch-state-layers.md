# 批量的状态分层

> 状态：已实现（2026-10-08，基线 v0.13.14）。
>
> 数据归属、协调算法、`batch.json` v2 迁移与落点见
> [39-runtime/06-batch-state-layers.md](../../30-architecture/39-runtime/06-batch-state-layers.md)。

## 1. 问题

批量原来只有一个扁平的配置项，「批量配置」窗口和主页面批量页都直接改它，划分依据
是哪个界面方便，而不是语义。后果：

- 主页面的一次临时勾选、拖拽、轮数调整**全都写回配置组**，于是"上次运行的勾选"
  和"下次打开的初始值"是同一份数据，说不清"恢复默认"该恢复到哪；
- 任务页的拖拽顺序落盘，用户页的拖拽顺序不落盘——同一个窗口里两种语义；
- 决定可见性与生命周期契约的**定义级设置长在主页面**，而依赖它的「单用户直通」
  勾选框长在配置窗口，于是出现一个"灰着、勾着、在本窗口里找不到任何理由"的控件；
- 配置窗口保存前要把主页面拥有的字段读盘搬回来，这段反向合并代码的存在本身就是
  所有权没划清的证据；
- 启动时活动组来自磁盘，而用户名与脚本来自页面控件——执行快照由两个可能不一致的
  源头拼出来。

## 2. 四种状态

| 状态 | 回答的问题 | 谁能改 |
|---|---|---|
| 配置组定义 | 这批任务长期包含哪些任务与用户、用什么调度单元与生命周期 | 只有「批量配置」窗口 |
| 配置编辑器草稿 | 本次编辑尚未保存的内容 | 对话框自己，点保存才落盘 |
| 本次运行草稿 | 这一次跑哪些、按什么顺序、跑几轮、是否无人值守 | 只有主页面批量页 |
| 执行快照 | 已经开跑的这批到底包含什么 | 点「开始」时冻结，之后不可变 |

两阶段的用户流程因此成立：**先定义配置组，再准备本次执行，点开始后冻结为不可变
计划。**

## 3. 字段归属

### 3.1 定义层

可见任务与初始顺序、可见用户与初始顺序、默认勾选、调度单元、Profile 排序键与方向、
生命周期工作流及其参数、单用户是否跳过生命周期。

- **可见与默认勾选是两件事**，所以配置窗口里一行两个勾选框（可见 / 默认执行）。
  只有一个勾选框时它必须同时表达"出现在主页面"和"默认要跑"，那正是旧版把主页面
  的临时选择写回配置组的根源。
- **默认勾选只是集合，不承载顺序。** 初始顺序由定义层的可见顺序决定；默认勾选
  回答的只是"首次加载或恢复默认时勾哪些"。
- **调度单元属于定义**：它决定主页面候选列表的内容、生命周期契约（多出单元相关
  变量）、条目准备 wf 的合法性（`#% batch_unit_prepare`），以及生命周期能不能跳过。
  这些都不是"本次启动"级别的决定。
- **Profile 排序键定义的是"能力"**，不代表已经排过；排完的实际顺序属于运行草稿。

### 3.2 运行草稿

本次勾选与实际顺序、本次轮数、本次是否无人值守，以及主页面当前配置组。

- 顺序与勾选**分开存**：合在一起的话，取消勾选就会丢掉条目的位置，重新勾上只能
  落到末尾。
- 草稿按**稳定配置组 ID** 隔离。用名称做 key 的话，重命名要搬迁状态，删掉再建
  同名还会继承上一个组的草稿。
- 存在会话状态里是为了"应用重启后恢复上次页面状态"，但它仍然是运行草稿，**不得
  因此反写定义层**。

### 3.3 定义变化与草稿的协调

配置组保存后不能清掉用户刚调好的本次顺序：

1. 已不在候选里的条目丢弃（配置组删了，或该属性值不存在了）；
2. 仍在候选里的条目保留草稿中的勾选与顺序；
3. 新出现的候选按定义层顺序追加，勾选状态取定义层默认值；
4. 只有用户点「恢复默认」才完整重建；
5. 切换配置组只换对应草稿，不修改任何定义。

空草稿走同一条路径，所以"配置组第一次使用"不需要第二套代码。属性单元的候选是
从用户资料动态生成的，适用同一套规则。

### 3.4 执行快照

点「开始」时由定义层与运行草稿合成。调度器只认它：运行期不再读配置组、不读会话
状态、不看控件。启动之后改配置、改用户资料、在主页面重新勾选，都不影响正在跑的
这一批。

无人值守在执行快照里存的是**有效值**：本次勾了无人值守、且定义层确实配了异常恢复
工作流，才为真。

## 4. 不兼容切换

用户感知到的变化是：**本次勾选、执行顺序、轮数、无人值守不再跨配置保存在配置组
文件里，而是按配置组记在本机会话状态里；首次打开按配置组的"默认执行"列勾选。**
旧格式只读一次即转换，不保留常驻兼容层。

## 5. 配置窗口的紧凑设置区

固定设置按四行双列编排：调度单元／指定排序、批次准备／批次收尾、条目准备／条目收尾、
异常恢复工作流／单个执行单元时跳过生命周期（复选框在右侧）。空间不足时回到单列，
字段标签共用宽度，不截断关键内容来挤出双列。
生命周期短参数按定义顺序并排，多行文本、普通文本与勾选组选项保留整行。参数区
设滚动及高度上限，上方任务和用户列表保留至少六行所需空间；保存和取消固定在底部。

布局不拥有配置值：require 仅控制整个字段的显隐，隐藏或重新排布不删除控件、不重置值。
调度单元切换保留既有跳过选项，恢复用户单元时按原值展示；编辑组切换仍不改活动组。
