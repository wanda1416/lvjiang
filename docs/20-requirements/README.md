律匠需求文档 v5

1. 运行环境

| 项目 | 说明 |
|------|------|
| 游戏运行 | 手机端燕云十六声手游 |
| 投屏方式 | 手机投屏到 PC 端（以 vivo 自带投屏为蓝本，不绑定特定品牌） |
| 投屏要求 | 必须支持反向控制（PC 端操作可转发到手机） |
| 控制方式 | Python 模拟鼠标点击 PC 端投屏窗口 |
| 输入特性 | 只有点击事件被转发到手机，移动轨迹无关 |
| 反作弊策略 | 模拟操作发生在 PC 端，不直接注入手机端，规避手游反作弊检测 |

1.1 架构链路
```
手机运行游戏
    ↓ 投屏（视频流 + 反向控制通道）
PC 端投屏窗口（画面显示 + 鼠标事件注入）
    ↓
律匠工具（截屏识别 → 决策 → 模拟点击投屏窗口）
    ↓ 点击事件经投屏协议转发
手机端执行操作
```

1.2 投屏方案说明
- 以 vivo 系统自带投屏为参考实现（USB/WiFi 投屏，支持反向操控）
- 工具本身不依赖特定投屏品牌/协议，只要求：
  1. PC 端存在一个可截屏的窗口（显示手机画面）
  2. 该窗口支持鼠标点击事件转发到手机
- 用户自行完成投屏连接，律匠只负责找到并控制投屏窗口

1.3 工具形态
- **PyQt6 图形界面应用**，提供完整的可视化交互
- 主窗口：投屏窗口定位、流派选择、模式选择、执行状态展示
- 坐标校准工具：内嵌于主界面，支持截图+框选区域+生成坐标配置
- 实时日志面板：显示每步决策信息
- 统计报表：处理装备数量、保留/回收/精调汇总

3. 核心机制：顶级装备自动判定
3.1 为什么需要这个机制
表格
场景	说明
用户要调"会心双刀"	但身上穿了极品"会意"装备
会意 vs 会心	不同流派顶级词条不同，但都是T0级
用户可能不懂	不知道这件会意装备其实价值很高
工具的责任	自动识别并保护，避免误回收
3.2 顶级装备判定规则（跨流派通用）
T0级词条（任何流派都认的顶级）：
表格
部位	T0初始词条	T0调律词条组合
武器	大外攻、敏、势	大外攻 + 任意2条三率/劲敏势
环	大外攻	大外攻 + 全武学增效 + 任意1条三率
佩	大外攻（仅金）	同环
头	三率任意	3条三率
胸	三率任意	3条三率
腿	劲	劲 + 2条三率
腕	劲	同腿
判定逻辑：
Python
def is_top_tier_equipment(equip: Equipment) -> bool:
    """
    跨流派顶级装备判定
    只要满足任一条件，自动保留
    """
    
    # 条件1：初始词条是T0级
    if equip.initial_affix.name in T0_INITIAL_AFFIXES[equip.slot]:
        # 且调律词条至少有2条T0级
        t0_count = sum(1 for a in equip.tuning_affixes 
                      if a.name in T0_TUNING_AFFIXES[equip.slot])
        if t0_count >= 2:
            return True
    
    # 条件2：调律词条4条全T0（初始词条稍差但调律极品）
    all_t0 = all(a.name in T0_TUNING_AFFIXES[equip.slot] 
                 for a in equip.tuning_affixes)
    if all_t0:
        return True
    
    # 条件3：特殊稀有词条
    if has_rare_affix(equip):  # 武学增效、首领增伤等
        return True
    
    return False

4. 流派规则引擎
4.1 用户只勾选"目标流派"
单选，不是多选。例如：
我要玩"会心双刀" → 所有调律决策按会心双刀规则
4.2 流派规则 vs 顶级判定规则的区别
表格
规则类型	用途	触发时机
顶级判定规则	保护装备不被误回收	扫描穿戴装备时
流派调律规则	决定调律方向和目标	处理背包装备时
关系：
顶级装备 → 不参与调律，直接保留
非顶级装备 → 按目标流派规则评估是否值得调律
4.3 流派规则结构（简化版）
Python
@dataclass
class FlowRule:
    """单流派规则"""
    name: str  # "会心双刀"
    
    # 各部位目标词条优先级（用于调律决策）
    slot_targets: Dict[Slot, List[str]]
    
    # 最低接受标准
    min_acceptable: Dict[Slot, int]  # 最低目标词条数
    
    # 必须包含词条（硬性要求）
    required_affixes: Dict[Slot, List[str]]

5. 批量筛选模式
plain
遍历选中部位的背包装备
    ↓
对每件装备：
    1. 点击打开详情
    2. OCR识别词条
    3. 检查是否在"顶级保留列表"（当前穿戴的顶级装备）
       → 是 → 跳过（已保护）
    4. 按目标流派规则评估：
       ├─ 初始词条不合格 → 回收
       ├─ 评分 < 当前穿戴的非顶级装备 → 回收
       ├─ 有潜力 → 进入精调队列（暂停等待或自动处理）
       └─ 已达标 → 保留入库存
    5. 执行决策
    6. 下一件
6. 精调模式
plain
选择一件装备（从背包点击，或从批量筛选转入）
    ↓
OCR识别当前词条
    ↓
循环：
    1. 评估当前状态
    2. 决策：
       ├─ 4条全目标词条 → 保留，结束
       ├─ 有垃圾词条 → 转律（选库策略）
       ├─ 缺目标词条 → 继续调律
       ├─ 材料不足/次数超限 → 暂停
       └─ 连续无改善 → 放弃，回收
    3. 执行操作（点击）
    4. 等待动画
    5. 重新识别
