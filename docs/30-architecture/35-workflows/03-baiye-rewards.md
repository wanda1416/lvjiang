# 流程：Android 百业周期领奖

入口为 `config/system/workflows/weekly_baiye_rewards.wf`，声明 Android 环境、日常与
批量可运行。复用导航、Profile 注册表和 `visual_state.wf`，没有新增引擎内置函数。

## 场景与导航

`baiye_main` 保留原有区域，扩充分红、活动和领奖浮层；四个完整可见活动卡片
使用 `baiye_activity_card` 子场景。独立 `baiye_shop` 描述左侧分类、商品列表和
右侧购买详情，避免套用坐标不同的通用购买页面。布局仅标定 Android，投屏布局
继承 Android 标定；不增加桌面入口。

主页 → 菜单按文字寻找百业 → 分红 → 商店 → 百业首页 → 活动列表 → 菜单 → 主页。
百业记住上次页签，工作流显式选择页签。百业页眉书法字的 OCR 不稳定，因此通过
“首页”和“分红”两个页签确认页面，有限轮询等待实测的黑屏过渡；商品名称消除
OCR 框间分隔后精确核对。

## 颜色与领取证据

| 区域 | 金色像素规则 | 状态阈值 |
|---|---|---|
| 分红卡片金光 | R≥140，G≥120，R−G≥−5，G−B≥25 | ≥0.30 可领，≤0.10 不可领，否则 unknown |
| 活动底栏、购买按钮 | R≥100，G≥90，R−G≥−5，G−B≥8 | 同上 |

活动采样底栏背景，避开金色奖励图标；不可领与已领取不等价。分红和活动操作前
保存当前截图，领取后确认“获得”浮层、关闭后确认百业页面、再次确认金光消失。
unknown、结果浮层缺失或页面不符均停止，保留现场，不继续点击背景。

活动由顶部开始，跳过“已结束”占位，遇到首个不可领奖卡片便停止。仅四张完整卡片
都处理完才滑动两行推进奖励前缀；不扫描下方未完成列表。翻页有 12 屏运行上限。

## 库存与 Profile

四项 quota 由 `subcall/profile_registry.wf` 声明，不声明业务分组。绕梁之音两个
商店入口共享 `baiye_raoliang_of_month`，以记录满额决定是否尝试另一入口，不按
日期猜测商品已经迁移。活动不写周期完成标记，后续新完成活动仍可领取。

商店只查指定名称；先确认名称、周/月库存标签和固定库存总量，再用
`总库存−剩余库存` 调用 `profile_observe`。库存回退会被 increment_only 拒绝。
新 key 尚无数值时仍检查商店，不能用 `null < 上限` 判定待办。

选择最大数量后核对数量不超过剩余库存，并确认按钮文案和颜色。购买后商品详情
必须仍为目标，库存减少量必须与数量一致，再记录实际已购买量。库存不变不重试
购买、不标记成功；购买没有必然出现的全屏“获得”浮层。币不足仅保留剩余配额。

## 验证边界

颜色标定来自单台真机的领取前后截图；私人样本不进入系统配置、测试或发布包。
永久测试保护未知状态不操作、领取结果缺失不回写、库存变化确认、共享月记录、
顶部活动停止、空档案首次执行及自定义分组保留。实际月度购买与迁移后新界面仍需
到时实机验收。

完整真机运行返回 0，确认返回主页；临时 Profile 识别周礼盒 0/3、绕梁之音 0/2、
月礼盒 0/3，并领取新完成的顶部活动。未改真实角色档案，未新增购买。跨屏奖励
前缀仍待连续跨屏领奖的实机样本。
