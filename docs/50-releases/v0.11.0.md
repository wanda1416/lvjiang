# v0.11.0 — 用户与批量配置重整、装备管理增强、场景和工作流扩展

## 律匠 v0.11.0

> **发布状态：正式发布。发布日期：2026-09-09。** 本文以 v0.10.4
> 发布完成后的代码树为基线。

本版本重整用户资料、用户运行状态和批量配置的职责，完善装备筛选、批量操作、
培养分析和调律石管理，并扩展 Android 应用控制、场景跳转与工作流参数能力。

### ⚠️ 不兼容变动、已知限制与升级指引

#### 1. 用户资料和运行状态会自动迁移到独立文件

- **现象：** 首次启动 v0.11.0 时，`session.json` 的用户对象会变成按顺序排列的
  用户名列表；用户资料存入 `users/<用户名>.json`，工作流运行状态存入
  `users/<用户名>.session.json`。
- **原因：** 用户资料与工作流 Session 已拆分，避免账号、角色等长期资料混在批量
  表格和运行状态中。
- **如何调整：** 无需操作，主实例会在启动时按 `session.json` 顶层 `version`
  自动完成一次迁移，并保留 `session.pre-v2.json` 备份。只读实例发现旧格式时不会
  迁移，请先启动一次主实例。

#### 2. 用户名不再允许空格

- **现象：** 新建用户名只能包含中文、字母、数字、下划线和连字符，最长 32 个字符；
  带空格或其他符号的名字会被拒绝。
- **原因：** 用户名现在同时作为用户资料和 Session 文件名，需要稳定、安全的文件名。
- **如何调整：** 现有用户名均符合规则时无需操作。若手工创建过带空格或特殊符号的
  用户，请在升级前改为合法用户名，并同步批量配置中的引用。

#### 3. 批量配置不再保存用户属性

- **现象：** 批量配置只保留执行用户名及顺序，以及批次初始化、条目前置、条目收尾、
  批次收尾四个生命周期工作流；账号、角色、角色序号和尾号等属性改由用户管理维护。
- **原因：** 同一用户的资料不应随批量配置组重复保存，批量执行器也不再向工作流注入
  任意业务属性。
- **如何调整：** 无需操作，旧批量行中的属性会在首次启动时迁移到对应用户资料。
  后续请在「用户管理」中新增、删除或修改键值属性。

#### 4. 只读实例不能打开场景管理

- **现象：** 只读实例中的「场景管理」菜单项及 F3 快捷键处于禁用状态；环境、当前
  用户、当前布局等实例选择只在本实例内生效，不覆盖主实例选择。
- **原因：** 场景和布局编辑属于共享配置写入，同一时间只允许主实例管理。
- **如何调整：** 需要编辑场景或布局时使用主实例。只读实例中的其他普通配置和用户
  数据仍按原有入口保存。

#### 5. 同一用户不能被多个实例同时执行

- **现象：** 一个实例正在为某用户运行任务时，另一实例不能再次启动该用户的任务。
- **原因：** 用户 Session 和业务数据由用户名共享，并发执行会互相覆盖运行状态。
- **如何调整：** 等待当前任务结束，或为另一实例选择不同用户。

#### 6. 外观场景合并，系统场景与布局有较大更新

- **现象：** `waiguan_yigui` 和 `waiguan_qingjing` 合并为 `appearance_main`；同时新增
  游戏设置、通用购买、商店详情和聊天等场景。引用旧场景名的自定义脚本或本地布局
  可能无法通过校验。
- **原因：** 衣柜与轻境属于同一页面的不同视图，统一场景后才能正确描述页面内跳转；
  本版本也补齐了购买和设置流程所需的场景定义。
- **如何调整：** 自定义脚本请把旧外观场景引用改为 `appearance_main` 的对应视图。
  若 `config/local` 中存在同名场景或布局覆盖，请删除覆盖以使用随包版本，或手工同步
  新的场景、视图、区域和面板定义。

#### 7. Python 工作流程必须由 WorkflowEngine 启动

- **现象：** 直接实例化 Python 工作流程并调用依赖点击、按键或 Panel 的方法会明确
  报错，不再绕过引擎自行执行输入。
- **原因：** DSL 与 Python 工作流程现在共用同一套输入和 Panel 原语，确保暂停、环境
  检查及后台输入行为一致。
- **如何调整：** 普通用户无需操作。自定义 Python 工作流程应通过现有工作流程运行器
  或 `WorkflowEngine` 执行。

#### 8. Android `versionCode` 递增到 42

- **现象：** Android 首次启动新版本时会重新解压设备端场景、布局和工作流配置。
- **原因：** 本版本修改了设备端会读取的 `config/system` 内容。
- **如何调整：** 无需手动操作。

> 本轮明确提升了 `activity_jianghu` 与 `game_menu_page` 的 `content_version` 至 2；
> 其余存量配置未因应用发版而批量提升版本。用户自己的 `config/local` 内容仍无条件
> 优先于 system，存在本地覆盖时请按上述指引自行同步。

### ✨ 新增功能

- 用户管理改为通用键值属性编辑器，支持新增、删除、改名和保存任意用户属性；窗口
  同时精简了重复标题与尚未实现的数据统计占位区。
- 批量执行按用户名列表和可见顺序运行，生命周期工作流可读取当前用户、上一个用户、
  当前序号和批次状态，自行决定是否切换账号。
- 装备管理新增来源、品阶、等级、状态等组合筛选，支持冷却装备管理、批量删除、
  批量复制模拟装备，以及跨用户查看和合并承音装备。
- 最优组合界面完善候选评级、详情查看和装备写回；模拟装备支持按真实扫描装备的培养
  限制评估可达状态。
- 调律配置新增各品阶、等级的调律石消耗和返还规则，并在运行时维护库存、校验消耗，
  更准确地处理调律、重置和回收结果。
- ADB 无线扫描支持多网卡网段，并新增本机模拟器常用端口扫描。
- Android 应用配置支持按环境选择包名和 Activity；工作流可启动、停止或重启应用，
  scrcpy 连接可在应用重启后刷新。
- 工作流参数新增多行文本类型，桌面端新增剪贴板粘贴动作，并内置兑换码批量输入工作流。
- 场景系统支持声明当前场景位置和调用方返回语义；场景管理完善跨场景引用、实体排序、
  视图归属和网格定义编辑。
- OCR 支持将多个区域批量拼接后一次识别，减少重复推理开销。

### 🔧 修复

- 修复每周进度识别在不同页面路径下的结果不一致，并避免失败回退覆盖已经存在的档案
  数据。
- 修复工作流暂停期间主窗口无法正常交互的问题；暂停和确认仍由统一 UI 通道处理。
- 修复 scrcpy 服务端协议版本不匹配时错误信息不清晰的问题，现在会直接提示设备端与
  当前程序版本不一致。
- 修复 Android 调律回收后重复打开「更多」菜单造成流程偏移的问题。
- 修复百业活动返回、江湖活动标签视图、主界面商店入口与限时活动入口的场景绑定和
  布局坐标。
- 修复炸鱼工作流没有明确技能键且不适合后台输入的问题，现在使用配置技能键并显式
  禁用后台模式。

### 📦 重构

- 用户资料、用户 Session 和批量编排拆分为独立存储职责，并以 `session.json`
  `version: 2` 作为长期迁移入口。
- Session 写入保留单次文件锁与原子替换，移除交互式重试和用户 Session 的递归冲突
  合并；需要基于最新磁盘状态修改的入口统一使用锁内读改写。
- 多实例访问收口到实例锁和用户执行锁；只读实例只隔离明确列入白名单的临时选择。
- 场景网格定义与布局坐标绑定分离，跨场景实体识别和页面跳转使用统一解析路径。
- DSL 与 Python 工作流程统一使用 WorkflowEngine 的点击、按键和 Panel 原语。
- 参考图识别入口和返回结构统一，工作流、场景识别及 OCR 测试工具共享同一规则。
