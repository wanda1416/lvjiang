# 出装搭配与总词条分配

`BuildDefinition` 与 `BuildRepository` 独立管理 `yysls/game_config/builds.yaml`。
文档包含 `common_requirements` 和按稳定 ID 索引的 `builds`，不加入整份游戏配置保存列表。
用户模式遵循 system/remote/local 合并；保存加进程锁，重读并只修改当前搭配，比较编辑时快照
以拒绝同对象并发覆盖。装备落盘使用白名单，不持久化数值、角色信息或装备运行状态。

`distribute_affixes` 是无 UI、无写入的领域入口：输入词条计数、槽位模板、等级与数值口径，
返回真实词条装备字典、可获取位置和不可行原因。整数最小费用流将需求连接到各装备首词条、
普通词条去重门及属攻/神力容量门；优先填满八个首词条，再尽量保留模板位置。
候选、上限与合法性来自现有游戏配置和装备校验器，不新增另一套词条库。

`swap_affixes` 在装备派生副本上交换两个位置，复用首词条候选、普通词条候选和
`validate_combination_dict` 双向判断，返回合法副本或拒绝原因。表格在启动拖拽时
预计算全部目标，放下时重新验证；合法副本进入当前编辑草稿，重算依据模板恢复普通
词条顺序，保存与加载使用同一草稿位置偏好，不修改真实装备。

`BuildEditor` 同时服务玩法配置和角色计算器。编辑态、持久化搭配、当前角色方案互不代替。
角色入口打开时构造 `PlanScoringContext` 并复制装备；切换搭配不改变活动方案。
模拟重新叠加搭配的弓玦，使用 `LoadoutScorer` 聚合装备基础数值、词条及套装并评分；
面板展示未扣抗性的属性，评分使用共享有效属性口径。合法草稿可保存，但强制要求满足状态单独展示。

当前仅提供总量到合法装备位置的推荐，不进行全局 DPS 优化，也未连接自动调律执行器。

## 分配与计算约束

- 总词条通过带容量的最小费用流分配到首词条与普通词条位置，复用游戏配置候选与
  装备合法性校验：普通词条同名最多一次、属攻最多两条、神力最多一条；首词条独立
  计算。
- 本属在武器上只展开无相，非武器展开玩法属性；外属保留具体名称，避免折叠不同外属
  后丢失多条共存能力。
- 分配尽量保留参考装备的原位置。
- 属性计算复用 `PlanScoringContext` 与 `LoadoutScorer`，不复制毕业率公式。
- 模拟器向属性面板注入打开时冻结的流派、基础属性、世界等级与当前模拟装备，不读取
  随后变化的外部方案状态。

## 界面

- 两处入口：备战方案的「模拟计算器」是独立窗口；「创建模拟装备」在删除筛选装备／
  批量复制装备左侧，只创建当前用户的单件模拟装备。
- 左区用「装备词条」「词条约束」两个页签承载数量配置与原出装要求；右区不设页签与
  额外标题，直接纵向展示八件装备表格及备战方案全屏模式的完整战斗属性面板，不另拆
  页签或第三分栏。
- 战斗属性的增益卡片在全屏与半屏统一只展示「全奇术增伤」；旧装备携带的单体、群体
  奇术增伤在装备属性聚合时折入全奇术增伤，不改写原装备；卡片须容纳最多四条不同的
  防具定音技能且不与固定属性重叠。
- 分配表逐列展示宫商角徵羽，武器后紧接环佩，保持攻具与防具套装分组；位置候选留在
  引擎内部。
- 界面参照模拟器截图采用词条卡片、圆形加减按钮与满值说明，保持项目主题与按钮语义。
