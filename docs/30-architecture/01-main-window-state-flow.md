# 主窗口状态机流程

本文档描述律匠主窗口的状态定义、转移规则与 UI 反馈机制。

## 当前实现位置

| 模块 | 文件路径 |
|------|----------|
| 主窗口本体（构造/UI 骨架/宿主 API） | `lvjiang/ui/main/window.py` |
| 运行控制混入（启停/工作流调度） | `lvjiang/ui/main/run_control.py` |
| 窗口操作混入（扫描/定位/截屏） | `lvjiang/ui/main/window_ops.py` |
| 菜单与对话框入口混入 | `lvjiang/ui/main/menu_ops.py` |
| 启动检查链混入（公告/更新/统计） | `lvjiang/ui/main/startup_ops.py` |
| 会话状态持久化混入 | `lvjiang/ui/main/ui_state.py` |
| 覆盖层边框绘制 | `lvjiang/ui/overlay.py` |
| 截屏与捕获区域 | `lvjiang/core/capture.py` |

| 连接目标注册表 | `main/execution_targets.py` |

## 状态定义

| 状态 | 含义 | 关键数据 |
|------|------|----------|
| 未连接 | 注册表中没有可用目标 | `registry.active() is None` |
| 已扫描 | 候选列表已刷新，既有连接不变 | `_scanned_windows` 有候选 |
| 连接草稿 | 下一次连接所用参数，与目标实际状态无关 | `WindowConnectionDraft` / `AndroidConnectionDraft` |
| 已连接 | 注册表保存一个窗口和/或多台设备 | `ExecutionTarget.ready` |
| 已选择 | 一个已连接目标被明确选作执行目标 | `active_target_id` |
| 运行中 | 任务已冻结执行目标 | `_running_target_id` 与 `_running` |

连接目标和执行目标是独立状态。窗口目标固定 ID 为 `window`，Android 目标按
`android:<serial>` 保存。兼容字段 `_capture/_input/_device/_target_window` 只是当前
执行目标的投影；运行期间执行目标列表锁定，工作流继续持有启动时装配的资源。
候选区复选框只读写连接草稿；已连接目标的输入、截图和设备端执行状态只保存在
`ExecutionTarget`，通过目标行右键菜单修改。两者不得互相刷新或反写。

## 主流程

1. **启动程序**
   - 初始状态为“未连接”
   - 运行按钮显示「未连接」，背景黄色 `#FFC107`
   - 允许点击但点击时通过日志与状态栏提示先连接目标，不弹窗

2. **点击扫描窗口或扫描设备**
   - 仅刷新对应类型的候选列表
   - 不断开任何已连接目标
   - 不改变当前执行目标

3. **在候选列表中选择目标**
   - 窗口候选启用“定位”，设备候选启用“连接”
   - 右侧复选框设置下一次定位/连接采用的参数
   - 候选本身不能执行，必须先建立目标连接

4. **点击"定位/连接"**
   - 实时查询窗口当前位置（`_refresh_window_rect`）
   - 窗口登记为唯一窗口目标；Android 按 serial 追加为独立目标
   - 用 Win32 透明置顶边框标记目标窗口
   - 边框颜色为红色，表示"已定位但未运行"
   - 首个连接自动成为执行目标；后续连接不抢占
   - 目标列表同时展示窗口 hwnd 对应信息和所有设备
   - 运行按钮切换为「开始执行 (F9)」，背景绿色 `#4CAF50`

5. **点击"开始执行"或按 F9**
   - 非运行状态下，运行按钮显示「开始执行 (F9)」
   - 当前执行目标未就绪时阻止启动
   - 未连接提示不使用弹窗，避免打断操作流
   - 目标就绪且方案兼容时进入运行中状态
   - 按钮切换为「停止 (F10)」，背景红色 `#F44336`
   - 边框改为绿色

6. **点击运行按钮或按 F10 停止**
   - 运行状态下，运行按钮显示「停止 (F10)」
   - 退出运行中状态
   - 保留全部连接及当前执行目标，允许用户再次开始执行
   - 按钮切回「开始执行 (F9)」，边框改回红色

7. **切换执行目标**
   - 空闲期从目标列表选择，不重建连接
   - 运行中列表锁定，并提示任务使用启动时目标
   - 断开只释放选中目标，其他连接继续保留

8. **修改连接方式**
   - 候选区复选框只改变下一次连接草稿，不重建现有目标
   - 目标行右键菜单只改变该目标的实际输入、截图或执行通道
   - Android 目标使用“重新连接”，窗口目标使用“刷新位置”

## 状态转移规则

```text
启动
  -> 未连接

未连接
  --扫描成功--> 有候选、仍未连接
  --定位/连接--> 已连接且已选择
  --F9/点击运行按钮--> 阻止并提示（按钮可点但被拦截）

已有候选
  --选择候选--> 启用定位/连接按钮
  --点击定位/连接--> 已连接；首个目标自动选中
  --F9/点击运行按钮--> 阻止并提示
  --重新扫描--> 只替换候选

已连接且已选择
  --F9/开始执行--> 运行中
  --扫描/连接其他目标--> 原连接与执行选择保持
  --选择另一目标--> 切换执行目标，不重建连接
  --点击 × / 右键断开--> 释放指定目标，选择剩余目标或回到未连接

运行中
  --F10/停止--> 已连接且已选择
  --切换/断开目标--> 阻止并提示目标已锁定
```

## UI 反馈约定

| 场景 | 日志 | 状态栏 | 边框 |
|------|------|--------|------|
| 重新扫描 | 输出候选数量；现有连接不变 | 正在扫描 / 等待选择 | 不变 |
| 扫描成功 | 找到窗口或设备数量，提示选择候选 | 已扫描，等待定位/连接 | 不变 |
| 定位成功 | 输出窗口标题、位置、大小、DPI | 已定位信息 | 红色显示 1 秒后隐藏；勾选「红框标定」时持续显示 |
| 未连接时点击运行按钮或 F9 | 提示先连接执行目标，不弹窗 | 未连接目标 | 无 |
| 切换执行目标 | 输出目标名称 | 状态栏保持当前运行提示 | 跟随窗口目标状态 |
| 开始执行 | 输出流派和模式，按钮切换为停止 | 执行中 | 不改变标定框显示状态 |
| 停止执行 | 输出停止，按钮切换为开始执行 | 已停止 | 不改变标定框显示状态 |

## 运行按钮三态

| 状态 | 按钮文字 | 颜色 | 可点击 | 行为 |
|------|----------|------|--------|------|
| 未连接 | 未连接 | 黄色 `#FFC107` | 是（但被拦截） | 提示先连接，不弹窗 |
| 已选择 | 开始执行 (F9) | 绿色 `#4CAF50` | 是 | 用当前执行目标启动工作流 |
| 运行中 | 停止 (F10) | 红色 `#F44336` | 是 | 请求停止 |

## 菜单栏结构

```text
设置
  ├─ 用户管理 (F2)        → UserManagerDialog
  ├─ ──────────
  └─ 场景管理 (F3)        → SceneEditorDialog（场景/区域/POI 配置）

工具
  ├─ 毕业率计算器          （占位，暂未启用）
  ├─ ──────────
  └─ 图像识别              → OCRDialog

帮助
  └─ 关于                  → 关于对话框
```

菜单样式：`QMenuBar::item` padding `6px 16px`、`QMenu::item` padding `8px 32px`、hover 高亮 `#d4d4d4` / 选中 `#0078d4`。

## 日志线程安全桥

工作流运行在 `QThread` 中，loguru 的 `QtSink.write` 由后台线程调用，不能直接操作 GUI。通过模块级类 `_LogBridge(QObject)` 暴露 `pyqtSignal(str)`，后台线程 `emit` → 主线程事件循环排队 → `log_text.append`。`pyqtSignal` 必须定义在模块级类属性上，否则跨线程信号无法正确路由。

## 输入控制

`lvjiang/core/input.py` 的 `InputController` 已移除 `pyautogui` 依赖，改用 `ctypes` 直接调用 Win32 `user32`：
- `_smooth_move_to` 通过 `SetCursorPos` 分步平滑移动
- `_send_mouse_event` 通过 `SendInput` 发送 `MOUSEEVENTF_LEFTDOWN/UP`
- 规避 `pyautogui` 偶发崩溃与 `FAILSAFE` 导致的 `QThread` 硬崩溃

## 截屏超时保护

`lvjiang/core/capture.py` 的 `ScreenCapture.capture(timeout=5.0)` 在独立线程执行 `mss.grab`，超时返回 `None`，防止 Win32 GDI 死锁时主线程永久阻塞。`get_capture_size()` 返回捕获区域宽高而不触发截屏，供 `_region_to_screen` 等纯坐标换算使用。
