# 工作流截图复用与诊断记录

> 状态：已实现（2026-10-08，基线 v0.13.14）。偶发菜单失败仍待实机取证。

## 需求与边界

页面导航可能操作成功但识别未命中。诊断必须保存作出判断的原始帧，而不是
提示出现后重新截图。是否属于异常、何时留图、是否暂停或重试均由 WF 的
分支和 try/catch 决定；引擎不增加自动异常截图、日志拦截或 pause 留图行为。

## DSL 契约

- `scan`、`find`、`recognize` 在 `as $var` 后支持 `from last`，其余子句和返回值不变。
  普通区域、动态区域、子场景、面板单格/范围/整面板均遵守相同语义。
- `screenshot from last` 保存工作流最近一次完整原始截图；`screenshot` 仍重新截图。
- 复用帧不截屏、不增加帧序号、不修改帧来源和时间，只重新裁剪、识别或保存。
  不把 numpy 图像放入 DSL 变量，不增加截图历史队列或命名快照。
- 最近帧包括正常识别、图色、align 和 screenshot 实际获取的帧。
  `wait stable` 的内部采样不写入或清空最近帧缓存，也不生成诊断帧序号。
  普通坐标点击和等待不会自动刷新它；脚本必须在需要观察新画面时省略 `from last`。
- 快照仅属于当前工作流；运行开始清空，更新快照的截图返回空或抛错时使旧快照失效。
  无快照的识别复用抛出可由 DSL catch 捕获的错误，不能回退为重新截图。
- screenshot 作为诊断记录，缺帧或保存失败只报告原因，不掩盖原业务失败。
- 图片保存成功以 info 记录完整路径、frame_seq、帧来源和帧年龄；识别 debug
  日志带同一 frame_seq。序号标识实际截图，不是 scan 指令执行次数。
  帧年龄从引擎取得该帧时计算，不代表串流后端的原始采集时间。

## 应用

装备基础字段、冷却字段、锁状态和详情使用同一原始帧。

页面诊断由期待到达目标页的调用处拥有，不放进 `is_in_*` 纯判定过程。
公共导航、登录、购买、签到、号令、兑换码、游戏方案与角色属性收尾的明确
失败分支显式保存判断帧；confirm 和 pause 分支共用交互前的记录。直接返回
失败的页面校验也留图，上层仅传播失败时不重复保存。人工处理后再次识别
仍失败属于新观察，可以再留图。

以下中间状态不新增留图：背包 tab 为空但整理按钮确认成功、方案已选中而
没有使用按钮、可选弹窗未出现、角色在线按策略跳过、尚有预算的轮询和翻页、
不支持调律的装备缺少调律入口。商品或活动没有候选、空槽、纯配置/参数错误
也不按页面失败留图。

- 账号两轮搜索耗尽：保存最后扫描帧，再截取滚动后的当前列表，在 pause 前完成。
- 登录主页八轮校验耗尽：最后一次失败判断后立即保存原始帧，随后沿原流程处理
  战令/关闭弹窗；最终 pause 前另存当前现场。轮询次数和页面操作路径不变。
- 商品名不合规：在返回购买面板之前记录；未确认页面而准备重启恢复时，在
  重启之前记录，账号参数缺失的返回不新增截图。
- 号令区域查找失败后全图查找成功：沿用已有的诊断记录，改用 find 的原始帧。

所有诊断图片测试都重定向到 tmp_path，不写项目 logs/image。

## 回归边界

验证复用不访问后端且跨区域仍基于同一帧；新截图替换帧并增加序号；空帧、
捕获异常、运行边界不会泄漏旧图；面板与图像/参考识别可复用；保存路径和
识别日志共享序号，保存失败不会把业务失败改成另一个异常。
