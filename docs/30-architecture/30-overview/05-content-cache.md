# 配置修订缓存与运行快照

## 文件职责

session/content.json 是可重建索引，session/baseline.json 只标识原始官方预置（r0），用于生成和确认 r0.zip，不参与和远端发布的比对；updates 保存安装事务、r0 与 rN 归档。三者不参与 local 优先于 system 的读取规则。

基底记录缺失、损坏、缺少摘要或属于其他应用版本时，仅跳过在线恢复并记录 DEBUG 原因，
任务仍加载当前磁盘配置。不以基底记录是否完整决定任务能否启动。
多文件保存通过 resolver.batch_changes 合并索引更新与变更通知，批次内立即失效对应
文件的读取缓存，批次退出（包括部分写入后失败）时维护一次索引。
独立模型/规则目录使用 ConfigResolver.for_single_directory，锁归属该目录，
不维护客户端 content.json；同一安装实例的派生 resolver 必须沿用原 config_dir。

实体编辑遵循先读后写：resolver 为已读取的版本化实体记录字节基线；
布局、场景、地图和编辑会话另外保留对象自己的基线，不能依赖共享读取缓存。
新构造、尚未读取的对象首次写入按新建处理；无基线的程序化写入不承诺检测此前的外部修改。
根 YAML 不进入实体修订索引，但布局等编辑器仍可显式检查自己的名册基线。
冲突由 checked_write 统一请求覆盖确认；取消或确认期间再次变化时抛 ConfigWriteConflict。
布局保存保留已有布尔返回契约，同时提供具体失败原因；地图和其他编辑器保留专用异常。

修订号属于文件副本，不是跨来源的全局序号。新 local 影子从 1 开始，因此当前有效
修订值可从 system 的较大值变成 1；索引只用来判定代次变化，不比较大小或仲裁来源。

```json
{
  "update_at": "2026-10-12T20:00:00.000000+00:00",
  "scenes": {"sample": 1},
  "layouts": {"android": {"sample": 1}}
}
```

根目录 YAML 不记录修订。注册实体的路径去除扩展名形成索引 key。索引原子写入，缺失或不完整时从磁盘重建，不把缓存故障提升为配置加载错误。

## 缓存生命周期

ConfigResolver 的实际写入维护修订及索引。运行入口读取索引；索引变化或本进程尚无缓存时，从磁盘构建独立资源代次，场景及布局解析结果在该代次复用。任务拥有自己的运行对象，不能原地修改共享解析结果。

启动或手动刷新强制重建索引。在线安装替换 system 后刷新 update_at 并使资源代次失效，避免沿用旧缓存；
修订号未变化时不触发安装。缺失 key 的检查使用目录与文件名，不读取全部实体内容；只有重建或新代次构建读取实体。

根目录 YAML 每次启动重新读取，作为任务专属输入。脚本及其他非修订资源的写入也要使资源代次失效。已经运行的任务保留旧代次直到结束。

WF 不含 content_version，保留脚本编辑的热加载行为：任务入口检查工作流目录内 WF 与轨迹文件的 mtime 和大小，不读取其内容判定。变化后构建新资源代次，导入链与旧任务保持隔离。

## 保存一致性

编辑会话记录来源层及文件内容基线，保存前只检查受影响文件。修订号是常规修改标记，同修订的手工编辑仍可由内容基线发现。冲突交给 UI 确认，核心不依赖 Qt。确认后再次检查，避免确认期间发生二次修改。

实际文件写入、索引更新与任务读取使用配置锁；弹窗期间不能持锁。文件写入成功而索引更新失败时删除索引，下次重建，不保留可误导任务的旧记录。

## 两种运行模式

模式只决定保存位置和是否允许在线安装。快照不再以基底存在作为门禁。已有基底时与更新安装共享锁和恢复事务；无基底时仍能获取最新配置及固定快照。

在线安装只比较修订号：远端最新修订与本机记录相同就不下载归档、不改动配置；不同（含远端回退到较早修订）
则从 r0 重建整棵 system 后再叠加该修订。`baseline.json` 与 r0.zip 只用于确认原始预置本身；
r0 缺失、损坏或与记录不符时，退回当前 system 作为重建底座并记录告警，不阻断安装。
已发布归档不被改写。
