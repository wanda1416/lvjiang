# 主窗口状态机流程

本文档描述律匠主窗口的状态定义、转移规则与 UI 反馈机制。

## 当前实现位置

| 模块 | 文件路径 |
|------|----------|
| 主窗口与菜单/对话框 | `lvjiang/ui/main_window.py` |
| 运行控制混入（启停/工作流调度） | `lvjiang/ui/run_control.py` |
| 窗口操作混入（扫描/定位/截屏） | `lvjiang/ui/window_ops.py` |
| 覆盖层边框绘制 | `lvjiang/ui/overlay.py` |
| 截屏与捕获区域 | `lvjiang/core/capture.py` |
| 日志线程安全桥 | `main_window._LogBridge`（模块级 `QObject` + `pyqtSignal`） |

## 状态定义

| 状态 | 含义 | 关键数据 |
|------|------|----------|
| 未定位 | 没有可用于执行任务的目标窗口 | `_target_window is None` |
| 已扫描待定位 | 已刷新窗口列表，但用户还未确认目标窗口 | `_scanned_windows` 有候选，`_target_window is None` |
| 已定位 | 用户已从当前扫描结果中定位目标窗口 | `_target_window` 保存窗口信息，边框为红色 |
| 运行中 | 任务已启动 | `_running is True`，边框为绿色 |

## 主流程

1. **启动程序**
   - 初始状态为"未定位"
   - 运行按钮显示「未定位」，背景黄色 `#FFC107`
   - 允许点击但点击时通过日志与状态栏提示先扫描并定位窗口，不弹窗

2. **点击"扫描窗口"**
   - 仅在非运行中允许
   - 每次扫描都会刷新候选窗口列表
   - 如果之前已定位过窗口，旧定位必须立刻失效
   - 旧边框必须隐藏，`_target_window` 必须清空

3. **在窗口列表中选择一个候选窗口**
   - 启用"定位"按钮
   - 此时仍不能开始执行，因为尚未确认定位

4. **点击"定位"**
   - 实时查询窗口当前位置（`_refresh_window_rect`）
   - 将窗口信息写入 `_target_window`
   - 用 Win32 透明置顶边框标记目标窗口
   - 边框颜色为红色，表示"已定位但未运行"
   - 截屏预览展示在右侧预览区
   - 运行按钮切换为「开始执行 (F9)」，背景绿色 `#4CAF50`

5. **点击"开始执行"或按 F9**
   - 非运行状态下，运行按钮显示「开始执行 (F9)」
   - 如果 `_target_window is None`，必须阻止启动，并通过运行日志和状态栏提示用户先扫描并定位窗口
   - 未定位提示不使用弹窗，避免打断操作流
   - 如果已定位，则进入运行中状态
   - 按钮切换为「停止 (F10)」，背景红色 `#F44336`
   - 边框改为绿色

6. **点击运行按钮或按 F10 停止**
   - 运行状态下，运行按钮显示「停止 (F10)」
   - 退出运行中状态
   - 保留当前定位窗口，允许用户再次开始执行
   - 按钮切回「开始执行 (F9)」，边框改回红色

7. **停止后再次点击"扫描窗口"**
   - 旧定位失效
   - 回到"已扫描待定位"或"未定位"状态
   - 用户必须重新选择并定位窗口后才能开始执行

## 状态转移规则

```text
启动
  -> 未定位

未定位
  --扫描窗口成功--> 已扫描待定位
  --F9/点击运行按钮--> 阻止并提示（按钮可点但被拦截）

已扫描待定位
  --选择候选窗口--> 已扫描待定位（启用定位按钮）
  --点击定位--> 已定位
  --F9/点击运行按钮--> 阻止并提示
  --重新扫描窗口--> 已扫描待定位 / 未定位

已定位
  --F9/开始执行--> 运行中
  --重新扫描窗口--> 已扫描待定位 / 未定位，旧定位失效

运行中
  --F10/停止--> 已定位
  --扫描窗口--> 阻止并提示先停止任务
```

## UI 反馈约定

| 场景 | 日志 | 状态栏 | 边框 |
|------|------|--------|------|
| 重新扫描导致旧定位失效 | `[状态] 重新扫描窗口，旧定位已失效` | 正在扫描 / 等待重新定位 | 隐藏 |
| 扫描成功 | 找到窗口数量，提示选择目标窗口 | 已扫描窗口，等待定位 | 隐藏 |
| 定位成功 | 输出窗口标题、位置、大小、DPI | 已定位信息 | 红色 |
| 未定位时点击运行按钮或 F9 | 提示先扫描并定位窗口，不弹窗 | 未定位窗口 | 无 |
| 开始执行 | 输出流派和模式，按钮切换为停止 | 执行中 | 绿色 |
| 停止执行 | 输出停止，按钮切换为开始执行 | 已停止 | 红色 |

## 运行按钮三态

| 状态 | 按钮文字 | 颜色 | 可点击 | 行为 |
|------|----------|------|--------|------|
| 未定位 | 未定位 | 黄色 `#FFC107` | 是（但被拦截） | 提示先定位，不弹窗 |
| 已定位 | 开始执行 (F9) | 绿色 `#4CAF50` | 是 | 启动工作流 |
| 运行中 | 停止 (F10) | 红色 `#F44336` | 是 | 请求停止 |

```text
设置
  ├─ 用户管理 (F2)        → UserManagerDialog
  ├─ ──────────
  └─ 场景管理 (F3)        → SceneEditorDialog（场景/区域/POI 配置）

  ├─ 毕业率计算器          （占位，暂未启用）

  └─ 关于                  → 关于对话框
```

## 日志线程安全桥

工作流运行在 `QThread` 中，loguru 的 `QtSink.write` 由后台线程调用，不能直接操作 GUI。通过模块级类 `_LogBridge(QObject)` 暴露 `pyqtSignal(str)`，后台线程 `emit` → 主线程事件循环排队 → `log_text.append`。`pyqtSignal` 必须定义在模块级类属性上，否则跨线程信号无法正确路由。

## 输入控制

`lvjiang/core/input.py` 的 `InputController` 已移除 `pyautogui` 依赖，改用 `ctypes` 直接调用 Win32 `user32`：
- `_smooth_move_to` 通过 `SetCursorPos` 分步平滑移动
- `_send_mouse_event` 通过 `SendInput` 发送 `MOUSEEVENTF_LEFTDOWN/UP`
- 规避 `pyautogui` 偶发崩溃与 `FAILSAFE` 导致的 `QThread` 硬崩溃

## 截屏超时保护

`lvjiang/core/capture.py` 的 `ScreenCapture.capture(timeout=5.0)` 在独立线程执行 `mss.grab`，超时返回 `None`，防止 Win32 GDI 死锁时主线程永久阻塞。`get_capture_size()` 返回捕获区域宽高而不触发截屏，供 `_region_to_screen` 等纯坐标换算使用。
