# 3.4 批量任务

批量任务用于**多账号/多角色**场景：按配置中的用户名顺序切换用户并执行指定脚本。

入口：主窗口左侧 **「批量」Tab**。

---

## 3.4.1 批量 Tab 四页

```
┌──────────────────────────────────────┐
│  [开始批量执行 (F9)]                  │
│  当前配置组：[下拉选择]                │
├──────────────────────────────────────┤
│  脚本 │ 用户 │ 进度 │ 参数              │
│  ─────────────────────────────────── │
│  （子页内容）                         │
│                                      │
└──────────────────────────────────────┘
```

### 「进度」页

执行进度表，显示 **条目 × 脚本** 的矩阵状态：

| 列 | 说明 |
|----|------|
| 条目 | 内部用户名 |
| 脚本 | 脚本名称 |
| 状态 | 待执行 / 运行中 / 成功 / 失败 / 跳过 |

状态用颜色区分：
- 灰底 = 待执行
- 蓝底 = 运行中
- 绿底 = 成功
- 红底 = 失败
- 黄底 = 跳过

### 「脚本」页

只展示当前配置组允许使用的任务。勾选结果会按配置组保存，执行顺序始终采用
批量配置中的任务顺序。任务参数直接采用「日常」页维护的全局或用户独立参数。

### 「用户」页

| 操作 | 说明 |
|------|------|
| 当前配置组 | 三个子页上方的下拉框用于切换配置组 |
| 选择执行用户 | 只展示该组允许使用的用户；勾选结果按组保存，执行顺序采用批量配置中的用户顺序 |

### 「参数」页

「执行轮数」决定完整用户序列连续执行多少次，默认值为 1。轮数跟随当前
配置组保存在 `batch.json` 中，但不出现在「批量配置」对话框里。切换配置组时，
主页面会载入该组上次保存的轮数。下方四行只读显示当前配置组定义的批次准备、
条目准备、条目收尾和批次收尾工作流；工作流仍统一在「批量配置」中编辑。四个
工作流通过文件头 `#% parameters` 声明的参数，会按“批次准备”“条目准备”
等阶段分别生成参数组；没有参数的阶段不显示参数组。参数值按当前配置组保存，
批量启动时会一次性冻结这些生命周期参数。

---

## 3.4.2 批量配置

入口：「工具 → 批量配置」。

批量配置对话框管理多个命名配置组。每组定义可见任务、可见用户及其顺序，
并保存四个生命周期工作流；账号和角色属性统一在「用户管理」中维护。

### 界面结构

```
┌──────────────────────────────────────────────┐
│  配置：[下拉选择] [新建] [删除]                │
│  ┌──────────────────┬──────────────────┐    │
│  │ ☑ 每日签到       │ ☑ 用户A          │    │
│  │ ☑ 自动购买不肝   │ ☑ 用户B          │    │
│  │ 可见任务及顺序   │ 可见用户及顺序   │    │
│  └──────────────────┴──────────────────┘    │
│  批次准备：  [________] [浏览...]          │
│  条目准备：  [________] [浏览...]          │
│  条目收尾：  [________] [浏览...]          │
│  批次收尾：  [________] [浏览...]          │
│                              [保存] [取消]    │
└──────────────────────────────────────────────┘
```

### 配置管理

| 操作 | 说明 |
|------|------|
| 新建 | 输入配置名，创建空配置 |
| 删除 | 删除当前配置（不可恢复） |
| 切换 | 下拉框切换不同配置 |

### 两级选择

批量配置窗口中的勾选决定任务和用户是否会出现在主页面，拖拽顺序是唯一的执行
顺序。批量主页面只决定实际勾选哪些任务和用户，不改变排列。两级选择都会保存到
当前配置组。新加入配置组的任务和用户默认勾选；从配置组移除后，对应的主页面
勾选一并删除。

批量配置组不保存任务参数。批量执行与日常执行共用同一入口：先应用工作流声明的
默认值，再应用日常页保存的全局任务参数；某个用户启用独立参数后，由用户独立参数覆盖。
执行开始时会冻结全部“用户 × 任务”参数，运行中不再读取配置文件。

### 用户与属性

列表来自「用户管理」。勾选决定该配置包含哪些用户，拖拽决定执行顺序。
内部用户名只负责 Session、结果和执行锁归属；游戏账号名、角色名、角色序号、
账号尾号均在「用户管理」中编辑，可以与内部用户名不同。

#### 内置 `prepare_item.wf` 需要的四个属性

「用户管理」本身是通用的 Key/Value 属性编辑器，不限定业务字段。下面四个英文
Key 是内置 `batch/prepare_item.wf` 约定读取的用户属性，Key 必须完全一致：

| Key | 填写内容 | 在 `prepare_item.wf` 中的用途 |
|-----|----------|-------------------------------|
| `account` | 自己用来区分游戏登录账号的名称，例如 `账号甲` | 比较前后两个用户是否属于同一登录账号；值相同时跳过账号切换，只切角色。它只是账号标识，不要求等于内部用户名，也不是密码 |
| `role` | 游戏内显示的角色名，例如 `角色甲` | 识别登录页当前显示的角色是否已经是目标角色，并用于运行日志。一个账号有多个角色时，每个用户分别填写自己的角色名 |
| `role_index` | 角色选择页中的位置，填写 `1`、`2`、`3` 或 `4` | 打开角色列表后点击第几个角色；序号从上到下按 1 开始 |
| `tail` | 账号选择列表中能唯一识别该账号的尾号或末尾文字，例如 `1234` | 切换账号时在账号列表里查找包含该文字的条目。它不是任意备注，应填写界面上实际可见且足以区分账号的末尾内容 |

内置条目准备工作流启动时会检查 `account`、`role` 和 `role_index`。批次初始状态
没有已确认账号，因此第一位用户通常还会执行账号切换并要求 `tail`；实际配置时应给
每位参与批量任务的用户完整填写四项。属性值都按文本保存，`role_index` 也直接填写
文本 `1`～`4`。

#### 配置步骤

1. 打开「通用 → 用户管理」或按 **F2**。
2. 在左侧选中要参加批量任务的内部用户。
3. 在右侧「用户属性」中点「新增属性」，分别添加 `account`、`role`、
   `role_index`、`tail` 四行。
4. 双击 Key 或 Value 单元格可以修改内容；填写完点「保存属性」。Key 不能为空或
   重复，大小写也不要改变。
5. 对每个批量用户重复设置，然后到「工具 → 批量配置」选择任务、用户并排列顺序。

例如，内部用户 `用户甲` 对应账号 `账号甲`，角色是该账号角色列表的第 1 个，
账号列表显示尾号 `1234`：

| Key | Value |
|-----|-------|
| `account` | `账号甲` |
| `role` | `角色甲` |
| `role_index` | `1` |
| `tail` | `1234` |

同一个登录账号下有两个角色时，应创建两个内部用户。两个用户的 `account` 和 `tail`
填写相同值，`role` 填各自的角色名，`role_index` 填各自在角色列表中的位置。例如：

| 内部用户名 | `account` | `role` | `role_index` | `tail` |
|------------|-----------|--------|--------------|--------|
| `用户甲` | `账号甲` | `角色甲` | `1` | `1234` |
| `用户乙` | `账号甲` | `角色乙` | `2` | `1234` |

批量配置只引用这两个内部用户名并规定顺序，不再复制以上四项。执行到第二个用户时，
工作流根据相同的 `account` 判断仍是同一账号，直接在角色列表中选择第 2 个角色。

## 3.4.3 工作流槽位

每个配置有四个可选的生命周期 wf 槽位：

| 槽位 | 调用时机 |
|------|---------|
| **批次准备 wf** | 整个批次开始时调用一次；仅 `success` 才建立批次 |
| **条目准备 wf** | 每个启用条目执行前调用；首条和后续条目行为一致 |
| **条目收尾 wf** | 条目准备成功、业务脚本执行后调用 |
| **批次收尾 wf** | setup 成功后，在遍历结束或停止时调用一次 |

### 生命周期 wf 的变量传递

生命周期 wf 接收以下通用变量：

| 变量 | 说明 |
|------|------|
| `batch_users` | 本次执行的用户名列表，顺序与实际执行顺序一致 |
| `batch_index` | 当前用户在列表中的序号（从 0 开始）；批次级阶段为 -1 |
| `batch_round` | 当前轮次（从 1 开始）；批次准备阶段为 0 |
| `batch_rounds` | 本次批量执行的总轮数 |
| `batch_phase` | 当前阶段名 |
| `batch_state` | 跨阶段透明传递的业务私有状态工作副本（dict） |
| `batch_item_result` | 条目/批次执行摘要；无摘要时为空 dict |

批量层不注入账号、角色或其他用户属性。生命周期 wf 使用
`user_get(username, key)` 从用户管理资料中读取，例如
`user_get($batch_users.$batch_index, "account")`。

Python 批量控制层不会读取 `batch_state` 内的账号、页面或角色等字段。条目准备
wf 应依据其中记录的**已确认真实状态**决定最小切换操作，不应通过
`batch_index - 1` 推断当前游戏状态。

每个阶段收到的是上一已提交状态的深拷贝。wf 可以原地修改这份工作副本，但
只有通过返回协议返回合法 `state` 时修改才会提交；异常、非法返回或无返回值
都会保留阶段开始前的状态。

### 返回协议

生命周期 wf 返回以下字典；空槽位或不返回值等同成功且保持原状态：

```wf
return {"status": "success", "message": "", "state": $batch_state}
```

| 字段 | 约定 |
|------|------|
| `status` | `success`、`skipped`、`failed` 或 `stopped` |
| `message` | 面向日志和用户的说明文字 |
| `state` | 下一阶段收到的业务私有 dict；控制层只透传 |

`prepare_item` 返回 `skipped` 或 `failed` 时，该条目的业务脚本不会执行，但
返回的 `state` 仍会传给下一条目。这使“账号已登录、角色不可用”等部分成功
状态能够被精确保留。

### 选择 wf 文件

点「浏览...」按钮选择 `.wf` 文件。默认打开 `config/system/workflows/` 目录。
也可以使用手动输入相对路径。

### 花蕊织轮次调度

安卓端使用“周常花蕊织速刷”做多用户轮次调度时，建议建立独立配置组，并设置：

| 槽位 | 工作流 |
|------|--------|
| 条目准备 wf | `batch/prepare_huaruizhi.wf` |
| 条目收尾 wf | `batch/finish_huaruizhi.wf` |

Profile 数据模型需定义配额字段 `huaruizhi_of_week`，上限为 3000。任务进入
渡尘墟后会点击总计区域，读取本周进度并通过公共周进度解析器同步该字段。
若同步后的进度已经达到 3000，任务会直接结束，不再切换匹配模式或开始新的
AI 对战；批量条目收尾随后关闭客户端并回到桌面。

条目准备会先读取当前用户的 `huaruizhi_of_week`：达到 3000 时直接跳过该用户，
不会启动、登录或关闭 APP。未满时先检查当前画面是否已经是登录页：已经在登录页
就直接进入登录流程；不在登录页时，若客户端进程仍在运行则先结束进程，再重新
启动游戏，然后轮询启动页的返回按钮并点击它回到登录页。登录页背景动画常驻，
不存在稳定帧，所以启动后不等画面稳定，只认返回按钮。若上一轮
对战尚未结束，登录确认会按“角色在线跳过”和“角色在线最大等待时间”处理；关闭
立即跳过后，每次检测到在线都会取消提示，等待 30 秒后重新点击角色入口并检查，
直至角色可登录或达到等待上限。花蕊织任务在
批量模式下开始 AI 对战后立即返回，条目收尾随后关闭客户端，让对战继续在服务端
运行。最后一个用户也会关闭客户端。日常页单独运行花蕊织时同样会在开始对战后
立即结束任务，但不会自行关闭客户端。

批量配置统一保存在 `config/session/batch.json`。本格式不读取旧版
`session.json.batch` 数据，升级后需要重新建立配置组。

## 3.4.4 执行流程

点「开始批量执行 (F9)」后的完整流程：

```
1. 调用批次准备 wf
2. 按设定轮数重复完整用户序列；每个用户依次：
   - 调用条目准备 wf，从登录页进入该用户的游戏角色
   - session 切换（按当前内部用户名切换用户）
   - 顺序执行勾选的脚本
   - session 落盘（有脚本成功时保存）
   - 调用条目收尾 wf，退出并回到游戏登录页
3. setup 成功时，调用批次收尾 wf
```

### 执行中的行为

| 场景 | 行为 |
|------|------|
| 条目准备返回 `skipped` | 跳过该行所有脚本，继续下一行 |
| 条目准备返回 `failed` | 记录准备失败并跳过该行，继续下一行 |
| 批次准备返回非 `success` | 现场准备失败，立即结束；不执行条目或批次收尾 |
| 条目阶段返回 `stopped` | 停止后续条目并进入批次收尾 |
| 脚本执行异常 | 记录失败，继续执行下一个脚本 |
| 按 F10 停止 | 当前条目完成后停止（不中断当前脚本） |
| 无启用用户 | 日志提示「暂无启用的用户，请到用户页勾选」 |
| 无勾选脚本 | 日志提示「请至少勾选一个脚本」 |

### 运行期间

- 配置组下拉框、脚本页和用户页被锁定（不可修改）
- 进度表实时更新状态
- 运行日志输出 `[批量]` 前缀的日志

## 3.4.5 脚本结果落盘

脚本执行后如果有返回值（dict 或 list），结果自动保存到：

```
config/session/output/{用户名}/{script_id}_{时间戳}.json
```
