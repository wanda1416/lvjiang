# v0.15.20 — 三档界面主题、全文档端到端加密与 Android 通道稳定性

本版本面向用户的变更集中在四项：桌面端界面主题由深浅两档扩展为**纯白 / 宣纸 / 玄墨**三档；账号数据同步由
「便利贴与角色属性加密」扩展为**全文档先压缩再端到端加密**后上云；管理员待受理反馈以菜单栏提示呈现；
Android 多目标切换与断线恢复路径上的崩溃、界面卡顿与按键失效问题一并修复。

其余内容以工程优化为主：目录与模块重构、测试与文档治理、内部接口收口，功能与操作方式不变。
**仅运行既有任务、且不需要界面主题与云端加密的用户，可以跳过本版本升级。** 升级前需确认的仅有三项：
加密上线后的多端互通（第 1 条）、自写脚本的校验变化（第 2 条）、配置读取的路径限制（第 3 条）。

## ⚠️ 不兼容变动与升级指引

### 1. 全文档端到端加密上线，旧版客户端同步文档将被服务端拒绝

- **现象：** 升级后角色属性、便利贴、备战方案、玩法预设、批量配置、工作流参数、袅袅之音等文档改用
  「先 gzip 压缩再 AES-GCM 加密」后上云，云端不再持久化保存文档明文。仍为旧版客户端的设备再次同步文档时，
  会收到「请升级客户端」的提示并被拒绝，本地文件不会被写坏。
- **原因：** 服务端在文档通道启用了 426 升级门禁——若允许旧客户端继续上传明文，已加密账号的数据会被旧端覆盖为明文。
- **如何调整：** 将使用同一账号的 PC 与手机都升级到本版本。旧明文与无压缩的旧密文仍可正常读取，首次同步后自动升级为
  新密文。修改密码后无需手动重传，下一次同步会用新口令派生的密钥重新加密并推送全部文档。**请勿在未备份本地配置的情况下
  使用管理员重置密码**——云端不保存该密钥，重置后旧口令派生的密钥无法再解密云端已有密文。

### 2. 脚本与引擎的校验变严：原先被静默接受的情形改为显式报错

- **现象：** 下列写法此前或产生错误结果、或完全没有执行，本版本起一律报错并给出行号：
  除 0 与模 0（此前返回 0）、过程调用多传实参（此前静默丢弃）、`goto` 无限回跳（此前一直执行至手动停止）、
  过程递归超过 64 层、`to_number("inf")` / `"nan"` / `"1e400"`（此前转换成功并使比较恒真或恒假）、
  子场景引用外框为零或负尺寸、`scene` 声明指向子场景、用户模式配置读取 `../system/x.yaml` 或绝对路径。
- **原因：** 这些静默分支把脚本错误表现为功能异常；在无人值守批量中还会持续占用 CPU 或导致整批停滞。
- **如何调整：** 自写脚本按报错行号调整：确认除数与模数非零、移除多余实参、把依赖 `goto` 回跳的循环改为
  `loop while`（有限回跳仍受支持，仅在超限时中断）、将递归改为迭代、把子场景的 `scene` 声明改为父场景。
  官方脚本与随包内容已按新规则复核，无需操作。

### 3. 配置读取拒绝越界路径

- **现象：** 用户模式下引用 `../system/xxx.yaml` 或使用绝对路径会被拒绝。
- **原因：** 此类路径可绕过「system 只读 / local 覆盖」的层隔离。
- **如何调整：** 在脚本或配置中改为同名文件的相对引用，个人改动放在 `config/local`。

### 4. 备战方案扫描的终点确认由二选一确认框改为暂停提示

- **现象：** 扫描完成返回主页时若未能识别主页，此前弹出「是重试／否结束扫描」确认框；现改为暂停提示：
  有人值守时暂停，待手动返回主页后确认重新检查；**无人值守时由引擎中断本次扫描并执行异常恢复**，不再等待人工点击。
- **原因：** 无人值守场景下该确认框无人应答，整批扫描会长期停滞。
- **如何调整：** 无需操作。「连续三次确认仍未回到主页」才返回失败，调用方原有的失败分支继续有效。

### 5. 主题菜单改为三档

- **现象：** 右上角主题项由「切换到浅色/深色主题」改为「纯白 / 宣纸 / 玄墨」三选一，菜单栏同时显示当前主题。
- **原因：** 新增宣纸（暖白纸色）与玄墨（深色）两档，原有深色对应玄墨。
- **如何调整：** 无需操作。配置中的 `theme` 取值仍为 `light` / `dark`，新增 `paper`；原有 `dark` 设置继续生效。

### 6. Android 端 shell 命令改为 30 秒超时

- **现象：** 端侧执行的单条 shell 命令超过 30 秒时，以 `command timed out after 30000ms` 失败。
- **原因：** 此前未设超时会无限等待，单条阻塞命令即可长期占用通道。
- **如何调整：** 无需操作。现有截图与输入调用的耗时远低于该阈值；若自写脚本包含长耗时 shell 操作，请拆分为多步。

### 7. Android 恢复流程的状态语义调整

- **现象：** 重连恢复成功后恢复询问框**自动静默关闭**；「等待目标」期间开始按钮禁用、配置锁定、允许停止，
  暂停按钮仍仅在运行与暂停态可用。
- **原因：** 此前任务已恢复仍保留旧弹窗，误点「否」会终止正常任务；等待重连时界面又显示为空闲。
- **如何调整：** 无需操作。若此前习惯通过恢复弹窗的「否」结束任务，请改用主界面的停止按钮。

### 8. 批量执行的判定更严格

- **现象：** 批量中 `batch_check` 未通过的单个脚本不再继续执行；通道故障会中止剩余脚本并跳过收尾阶段；
  批次停止时不再写入未完成的 session。
- **原因：** 此前会继续执行并留下看似成功的残缺记录。
- **如何调整：** 无需操作。被跳过的脚本会在批次结果中给出原因。

## ⚠️ 已知限制

- **任务诊断与全任务采集仍属开发预览。** 菜单「任务诊断」（最近帧缓存）默认关闭、重启后恢复关闭，
  仅作用于下次启动的任务；离线工作流模拟只提供源码检出的命令行入口，不随可视化界面发布。

## 🔧 修复

- **Android 多目标切换与断线恢复会无提示闪退或卡死。** 修复覆盖运行中的设备线程导致的 Qt 崩溃
  （Windows 实测退出码 `0xC0000409`）、退出或断网时点击开始导致界面卡顿 10–50 秒、恢复运行后暂停按钮与 F11 永久失效、
  通道横幅在恢复、切换与停止后不消失或重新出现、恢复询问框残留导致正常任务被误终止、某一目标的空闲流重建阻塞其他目标等问题。
  运行中重连现在先释放旧端侧租约、再按目标交接，悬浮球不再弹回，转发端口不再泄漏。
- **行尾注释会把下一行并入当前语句，甚至使整份脚本静默不执行。** `log "a"  # 说明` 此前直接语法错误；
  注释中出现半个括号或引号会使整份文件解析为 0 条语句——不报错，也不执行。现在注释只作用于行尾，续行预处理
  同样不受注释内容干扰。
- **静态引用检查漏检条件表达式、函数参数与 call 实参中的引用。** 布局漏绑时执行前门禁放行，直到执行到该行才因坐标
  未绑定而失败；现在执行前即可检出。
- **`drag` 的距离不接受中文变量名。** `drag … up $次数` 此前语法错误，而 `wait $次数` 正常；现已一致。
- **场景编辑器保存会永久删除手写的无效引用。** 此前任意一次保存都会使无效的 `references` 从 YAML 中消失；
  现改为登记为无效引用、界面照常显示。同时修复实体与场景改名后坐标文件成为孤儿、热刷新期间并发读者读到空表等问题。
- **`account.json` 并发写入会抹掉登录态。** 前台心跳与手动同步并发时后写覆盖前写，最坏情况下读到残缺 JSON 后
  整份回写，将 `login` / `account_id` / 密钥一并抹除；现收敛为单点原子写、锁内重读再合并。
- **登出或被踢下线后 E2E 密钥仍残留在内存与磁盘。** 派生密钥等价于口令，现在随会话失效一并清除，重新登录时用新口令重新派生。
- **Android 自动同步在单次意外异常后即停止。** 心跳线程遇到 IO 异常直接终止、仅留下一次堆栈，需等下次回到前台才可能重启；
  现在任何异常只作废本轮，失败原因同时显示在同步摘要行。
- **安装更新或撤回会员会静默清除 `state.json` 中的待安装节点。**
- **OCR 清洗组保存时会覆盖识别设置。** 现仅合并自身负责的归一化字段，不再整份回写 `ocr.yaml`。
- **识别区域坐标为负时会裁取到整张图。** 此前负坐标被 NumPy 视为自尾部索引，实际取得近乎全屏的图像；现钳位至图像边界。
- **OCR 推理过程中关闭引擎会抛出 `TypeError`。** 推理与关闭现互斥，不再将正在使用的后端置空。
- **告警面板与套装编辑器在启动瞬间会闪现独立小窗口。**
- **装备状态页能把未勾选的 key 设为默认。** 现取消勾选即清除焦点并禁用按钮，默认值始终落在候选内。
- **备战方案扫描在无人值守下会长期停滞**（见升级指引第 4 条）。

## 📦 重构

- **Kotlin 目录分层**：`com/lvjiang/app/` 拆分为 `bridge/`（Python、OCR、ONNX 桥）、`channel/`（AgentServer、ShellService、
  无障碍通道）、`ui/`（工作台、悬浮、设置、标定），文件内容不变。
- **拆解体量超过 2000 行的 Python 热点文件**：`run_control.py` 拆出 `adb_device_ops` / `run_selectors` / `run_worker`，
  `batch_tab` 拆出 `batch_execution` / `batch_widgets`，装备状态页拆出 `status_filters` / `status_dialogs`，
  自动调律拆出 `auto_tuning_actions`（68 个函数全部保留，属纯代码移动）。
- **模块归位**：`workflows/analysis` 收拢静态检查与引用分析，`core/about`、`core/plugin_runtime`、`ui/background`
  等薄模块归位；`tests/` 按 `apps/yysls` 分域重组，`scripts/` 拆分为 `ci/` 与 `yysls/`。
- **文档生命周期治理**：废除 `90-develop`，文档按「计划 → 设计 → 参考」单向流转；计划层拉平为一篇一文件，
  在线配置后台下载等已实现方案迁入设计决策。
- **开发预览能力**（默认关闭）：任务诊断入口与有界最近帧缓存、全任务采集与离线工作流模拟测试。
