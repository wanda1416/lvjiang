# v0.10.3 — PC 端账号切换、scroll 间隔与登录页布局重整

## 律匠 v0.10.3

> **发布状态：正式发布。发布日期：2026-09-06。** 本文以 v0.10.2
> 发布完成后的代码树为基线。

本版本让批量任务在 PC 端也能完成账号切换，重整了登录页的场景定义与两套布局，
并补上 DSL 的 scroll 逐格间隔与实参字面量支持。

### ⚠️ 不兼容变动与升级指引

#### 1. 登录页区域改名与重整：`users_icon` → `user_icon`，新增 `online_label`

- **现象**：如果你改过登录页布局（存在
  `config/local/layouts/<布局名>/game_login_page.json`），升级后批量任务的账号
  切换会中止并提示「区域未绑定坐标: user_icon」或「online_label」。自写 `.wf`
  里引用 `[game_login_page].[users_icon]` 的语句同样会被静态检查拒绝执行。
- **原因**：登录页只有一个用户图标，`users_icon` 这个复数 key 是笔误，本版本
  更正为 `user_icon`；角色在线的判定从复用 `general_control.confirm` 改为登录页
  自己的 `online_label` 区域（原来靠弹窗文案「其他角色」判断，文案一变就误判）。
  同时 `cancel` / `confirm` 改为跨场景引用 `general_control`，两套布局里 `cancel`
  的同名残留坐标一并清掉；不再使用的 `user_2` / `user_3` 也已移除。
- **如何调整**：**`config/local` 无条件优先于 system，系统这份修正到不了你。**
  二选一：
  - 在「通用 → 场景管理」中重新标定登录页的 `user_icon` 和 `online_label`；
  - 或删除 `config/local/layouts/<布局名>/game_login_page.json`，让系统随包
    下发的那份生效（会丢掉你对该页其他区域的全部本地微调）。

  自写脚本里的 `users_icon` 需手动改成 `user_icon`。没改过登录页布局的用户
  无需任何操作。

#### 2. 布局加载会丢弃无场景定义支撑的孤儿坐标

- **现象**：启动日志出现
  `布局中 <场景> 有 N 条坐标已无场景定义，已丢弃: <key 列表>`。
- **原因**：删除区域定义只改场景 YAML，布局 JSON 里的坐标不会跟着走，这条残留
  记录在编辑器列表中根本不显示（列表按场景定义遍历），运行期却照常参与查表，
  还会把同名跨场景引用的展开顶掉——引用从此指向一份再也不会同步的陈旧坐标，
  而且完全静默。
- **如何调整**：**无需操作。** 清理只发生在加载期的内存中，不改写你的布局文件。
  若日志点名的 key 是你仍在使用的，请在场景管理中把对应的区域定义补回来，坐标
  会重新生效。

#### 3. 词条百分比与「超上限」校验改为现算

- **现象**：已有装备快照的词条着色、平均百分比、排序权重、毕业率边际收益以及
  「超上限」角标，数值和结论可能与升级前不同。
- **原因**：`cap_pct` 是给调律 DSL 快速读取用的派生缓存字段。历史数据里存在
  `value` 被改过而 `cap_pct` 没跟着重算的情况（value 已是承音上限、cap_pct 还
  停在旧值），拿它当权威会让超上限校验漏报、让换词条收益算错。现统一由 `value`
  与等级上限现算，并允许半步显示误差，正好顶满的词条不再被误报成超上限。
- **如何调整**：**无需操作，不做数据迁移。** 遥测的历史观测仍按当时记录值上报，
  不会被今天的配置重算。

#### 4. `app.yaml` 新增 `plans` 键，预置三套连接方案

- **现象**：升级后连接方案列表多出「手游」「端游」「手游投屏」三条，选中后
  名称、图库、环境、布局、模式五项均为只读，删除按钮禁用。
- **原因**：连接方案支持随安装包分发。开发者预置的方案存 `app.yaml`，属于发行
  配置，普通用户不应改动。
- **如何调整**：**无需操作。** 你自己创建的方案仍在
  `config/session/session.json`，照旧可编辑可删除；当前选中项（`actives.plan`）
  不变。

#### 5. DSL：空列表字面量 `[]` 的求值修正

- **现象**：`eval $x = []` 之后 `if $x` 由真变假；`for i in []` 由循环一次变成
  不循环。
- **原因**：解析器只滤掉了内部占位符，没滤掉 lark 为可选元素组填入的 `None`，
  于是 `[]` 求值成 `[None]`——一个长度 1 的真值列表。判空、for 迭代和传参全部
  走偏。`[null]` 走的是另一条规则，行为一直是对的，不受影响。
- **如何调整**：按字面意思写的脚本不受影响，本次修正让它们开始正确工作。如果
  你的脚本恰好依赖了 `[]` 恒为真来绕过某个判断，改用显式条件。

#### 6. Android `versionCode` 递增到 40

- **现象**：Android 端首次启动会重新解压配置。
- **原因**：本版本修改了 `config/system`（登录页场景定义、两套布局坐标、
  `general_action` 新增 `kanbao_back`、`app.yaml` 的 plans）。
- **如何调整**：**无需操作，自动完成。**

> 本轮**没有**提升任何 `content_version`，即不下发新一代远端配置。上述系统配置
> 修正随安装包生效；被 `config/local` 覆盖的部分见第 1 条。
>
> 除以上六条外，本版本没有默认值、快捷键、Profile 落盘格式的不兼容变动。

### ✨ 新增功能

#### 批量任务支持 PC 端切换账号

- `prepare_item.wf` 的账号切换按 `desktop` / `android` 分流：PC 端需要先「登出」
  才能触发选择账号，安卓端可直接切换。
- PC 端账号列表改用 `scroll` 翻页（安卓端仍是 `drag`）；登录页的「进入游戏」、
  「退至桌面」、「返回登录页面」在桌面布局上绑定了 `activation_key`，改由按键
  激活。
- 「登出」在 PC 端是浅色文字、OCR 时有时读不到，补了一层兜底：识别不到「登出」
  时改判「进入游戏」是否存在，两者都读不到则视为尚未登出，继续走登出流程。

#### DSL：`scroll` 支持逐格固定间隔

```
scroll [inventory].[list] up 5 interval 0.1    # 每格间隔 100ms
```

- 省略 `interval` 时沿用后端默认的 20~50ms 随机间隔，行为不变。
- 仅对逐格发送事件的桌面后端（SendInput / PostMessage）生效；ADB 与设备端是单次
  连续手势，没有逐格间隔的概念，参数被忽略。
- 非数值或负数不会中断工作流：记 error 后按默认随机间隔执行。

#### DSL：实参位支持 `[]` `{}` 等字面量常数

- 内置函数实参（`arg`）与过程实参（`call_arg`）此前各写各的分支，只认字符串、
  数字、变量和字段访问。`check_env(["android"])` 这种连内置函数自身文档都在示范
  的调用，在实参位解析不过，只能先 `eval` 到变量再中转。
- 现在两处对齐到同一套分支，都支持 `[...]`、`{...}`（可嵌套）、`null` / `true` /
  `false`、`(x, y)` 与 `(x, y, w, h)` 元组。容器内的 `$var` 在调用方作用域求值后
  再注入形参。

#### 连接方案可分发到 `app.yaml`

- 每条方案带一个「分发」标志决定去向：不勾选存 `session.json`（本机配置，
  原行为），勾选存 `app.yaml`（随安装包发布）。
- 标志不落盘——它就是「这条方案存在哪」的同义词，从加载来源推导，不会与实际
  存储位置脱节。同一条方案不会两处各留一份。
- 「分发」勾选框只在开发模式显示；配置管理里的「方案管理」改称「连接方案」。

### 🔧 修复

- **批量参数未落盘**：日常页改完脚本参数直接启动批量时，批量线程会读到上一次
  保存的值。参数控件的变更信号改为实时写回 `wf_configs`，批量启动前再兜底同步
  一次；切到批量 Tab 后参数面板不可见但取值仍然有效。
- **销毁运行中 QThread 导致崩溃**：自定义的 `finished` 信号遮蔽了
  `QThread.finished`，`deleteLater` 于是挂在 `run()` 内部 emit 的信号上，主线程
  可能先销毁仍在运行的线程，进程直接退出。信号改名 `succeeded`，`deleteLater`
  挂回真正的 `finished`。
- **孤儿坐标顶掉跨场景引用**：见不兼容变动第 2 条。
- **超上限误报与收益算错**：见不兼容变动第 3 条。
- **承音合并**：同一件装备的两份快照存在两种数值口径（游戏显示 1 位小数、内部
  承音上限是两位小数），1e-6 的容差会把同一件装备在两个方向上都判成「数值下降」，
  这类配对永远合不了。改为按显示步长的半步（0.05）比较，并去掉「必须存在可见
  变化」的前提——数值完全一致、仅小数位口径不同的两份快照，正是最该合并的对象。
- **武学换位**：备战方案的主/副武学对调后不再被当成两套不同配装。
- **购买补天石**：补齐 `bugan_detail` 的场景坐标，修正两套布局的区域位置。
- **登录页与主页坐标校准**：桌面布局的「进入游戏」按钮范围收紧；两套布局的
  主页顶部入口（菜单、活动、武林录、商店、战令、鹤鸣）与「显示」区域重新标定。

### 📦 重构

- `cap_pct` 收口为纯派生缓存，新增 `core/affix_cap.py` 作为唯一现算入口，
  校验、毕业率、卡片着色、排序与最优组合全部改为现算；写入侧凡是写过 `value`
  就无条件重算，去掉会留下脏数据的「已有 cap_pct 就跳过」守卫。
- 登录页 `cancel` / `confirm` 改为跨场景引用 `general_control`，不再在本场景
  重复维护坐标。
- 测试用例整理：删除只断言样式与像素的脆性用例，合并重复的参数矩阵。

### 🐛 可观测性

- `scan ... by` 未命中时记录各区域**实际读到的 OCR 文本**。此前只有命中那条
  打印 text，未命中只记 key 列表，于是「框标歪了读到别的字」「OCR 把标签拆成
  多个检测框、被 ` | ` 分隔导致 contains 落空」「整个框一个字也没检出」三种
  完全不同的成因，在日志里长得一模一样，只能靠猜。
