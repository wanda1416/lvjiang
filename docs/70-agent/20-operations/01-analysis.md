# 方案与装备培养分析

先查询 list_plans、get_plan_context 和 get_game_config 的玩法/流派配置，与用户
明确实际想玩的两门武学、玩法、目标方案和养成目标。主副武学按无序组合匹配；
装备主副槽仍按实际武器类型分别定位。采集创建的默认玩法不等于用户意图。

list_plans 每个方案的 plan_id 是详情与分析接口使用的稳定 ID，按用户给出的名称找到方案后传递该 ID，不能用方案名替代 ID。get_plan_context 的 plan 同样返回 plan_id。读取已有数据分析毕业率不要求设备空闲，也不需要生成调律配置的结果 ID；只有需要重新扫描装备或启动调律时才进入设备执行检查。不要因设备忙或尚无调律配置而阻断已有方案的分析。

analyze_cultivation 接受 user、plan_id，以及可选 overrides：playstyle、
graduation_scheme、base_attribute。覆盖只在本次分析副本上生效，不改原方案。
可用毕业率模型见 list_graduation_schemes；八件装备、基础属性和毕业率方案缺失
时先说明缺失，不擅自使用另一个流派或填造数值。

接口返回 job_id，使用 get_analysis_job 查询或 cancel=true 取消。结果包含当前
毕业率、满等级/满承音/满定音假设下潜力、词条敏感度、联合转律建议及数据修订。
转律比较合法替换和同名词条培养的对照，建议不代表游戏动作已经执行。
潜力不等于成功概率，也不等于现在换上就获得的收益；承音和培养资格沿用引擎。

search_best_combo 搜索装备库真实候选，排除模拟装备，不应用结果。先说明八个
部位的候选是否足够，结果仅对本次候选和计算口径成立。组合搜索的候选数量限制
及剪枝可能影响全库最优性，不能把有限搜索的最好结果说成无条件全局最优。

与用户交流时分别列出：值得保留的装备、现有装备的培养操作及前提、需要替换的
部位、缺失数据和目标词条。无可靠材料成本不估造数量。后续调律规则只能表达
现有 schema 支持的条件；无法表达的目标注明，不能声称规则已保证所有养成收益。
