## 一、属攻词条双重身份匹配 + 动态词条标准命名（`a2e3467`）

### 1.1 背景

游戏事实：武器部位只掉大/小无相（如「最大无相攻击」），非武器部位只掉
具体属攻（如「最大鸣金攻击」「最小裂石攻击」）。

此前规则 YAML 在非武器部位也写「最大无相攻击」，引擎 `_normalize` 把装备上
的具体属攻归一化为无相后匹配。但这导致：

- 规则读起来不直观（非武器部位实际掉的是具体属攻，不是无相）；
- 无法区分「规则想要无相」还是「规则想要具体属攻」。

### 1.2 改动

- 武器部位：规则仍引用字面无相（`最大/最小无相攻击`），引擎不归一化；
- 非武器部位：规则可写具体属攻（如 `最大鸣金攻击`）或动态词条
  （`最大本属攻击` / `最小本属攻击` / `最大外属攻击` / `最小外属攻击`）；
- 判定时装备具体属攻以**双重身份**参与匹配：
  - 字面名匹配（如 `最大鸣金攻击` 直接命中）；
  - 按玩法属性归类（own_attr 展开）后以动态词条身份匹配
    （如鸣金流的 `最大鸣金攻击` 同时视作 `最大本属攻击`）。
- 8 个具体属攻词条候选/校验均不排除；
- 含通用玩法（混搭流）的规则仍禁引动态词条（避免歧义）。

### 1.3 标准命名

- 动态词条统一命名：`最大本属攻击` / `最小本属攻击` / `最大外属攻击` /
  `最小外属攻击`（旧名 `最大/最小X攻击` 废弃）；
- 全库 grep 同步（规则 YAML / 引擎 / UI / 测试）。

## 二、pynput 退出竞态崩溃根治（`b754132`）

### 2.1 背景

pynput 全局热键（`GlobalHotKeys`）在应用退出时可能触发竞态：主线程已销毁
Qt 事件循环，但 pynput 回调仍在尝试访问已释放的资源，导致崩溃。

### 2.2 改动

- `SystemHook._handler` 新增防护补丁：回调入口检查 `_shutting_down` 标志，
  退出流程开始后直接丢弃回调；
- `MainWindow._on_quit()` 先置 `_shutting_down = True`，再停止 pynput 监听器。

## 四、退出崩溃根治 + UnhandledExceptionFilter 回调防 GC（`48e9ab4`）

### 4.1 背景

Windows 下应用退出时，若 Python 解释器已开始 finalize，但 UnhandledExceptionFilter
回调仍被系统调用（如 GC 触发的析构崩溃），会导致崩溃日志为空（crash 文件
只有 header）。

### 4.2 改动

- UnhandledExceptionFilter 回调新增防 GC 机制：回调函数引用保持到进程退出，
  避免被 GC 回收；
- 空崩溃日志自动清理（启动时扫描 `logs/crashes/`，删除 0 字节或只有 header
  的文件）；
- 配套 pynput 退出竞态防护（`b754132`），彻底根治退出崩溃。

## 六、五部位重复条件组上提至 common_conditions（`573120a`）

### 6.1 背景

五个非武器部位（冠胄/胸甲/胫甲/腕甲/环佩）的条件组大量重复（如「垃圾条件」
对所有部位都相同），规则 YAML 冗余严重。

### 6.2 改动

- 规则 YAML 新增顶层 `common_conditions` 段：
  ```yaml
  common_conditions:
    junk:
      - count_max: {symbols: [对首领单位增伤], max: 0}
    normal:
      - contains_all: [劲, 会心率]
  ```
- 各部位 `patterns.{part}` 的条件组可省略，默认继承 `common_conditions`；
- 若部位需要覆盖，显式声明即可（如武器部位的特殊垃圾条件）。

## 八、调律材料策略配置与规则模型扩展（`c422323`）

### 8.1 背景

调律材料（律准石、转律石）的投入策略此前硬编码在工作流中，无法按规则/

### 8.2 改动

  ```yaml

    small_stone_budget: 50        # 单件装备最多投入小律准石数量
  ```

- 模型扩展：`MaterialSettings` dataclass（强类型）+ 加载校验。

## 九、狗粮规则引擎重构——有序规则表替代品阶映射（`276b916`）

### 9.1 背景

旧狗粮（调律材料）决策基于「品阶映射」：装备品阶 → 固定狗粮类型。但实际
决策应基于「装备价值」：值得调律的装备用好狗粮，不值得的用差狗粮。

### 9.2 改动

- 新增「有序规则表」：
  ```yaml
  food_rules:
    - condition: {rating: [顶级, 优秀]}
      food: large_stone
      reason: "高价值装备，投入大律准石"
    - condition: {rating: [一般]}
      food: small_stone
      reason: "中等价值，投入小律准石"
    - condition: {rating: [垃圾]}
      food: none
      reason: "垃圾胚子，不投入"
  ```
- 决策引擎按顺序匹配规则，命中即返回；
- 旧品阶映射代码删除；
- 狗粮决策 reason 文案统一为「本轮添加」（`6ba3152`）。

## 十、材料区同名幽灵槽不再掩盖真实库存（`6f8ddee`）

### 10.1 背景

调律材料区（7 个槽位）OCR 识别时，若某槽为空但上一轮有材料残留，会误读为
「仍有材料」（幽灵槽），导致材料计数虚高。

### 10.2 改动

- 材料区识别新增「幽灵槽检测」：连续两轮读空即标记为幽灵槽，后续忽略；
- 真实库存以最新一轮识别为准；
- 配套调律结果弹窗关闭后补扫（`65c5e06`），避免遗漏。
