# 任务历史与批量历史
> 状态：已实现（2026-10-07，基线 v0.13.13）。

> 执行端快照字段与展示边界见
> [05-concurrent-target-execution.md](../50-platform/05-concurrent-target-execution.md#9-任务历史与执行结果)。
> 当前数据库已记录单任务和批次绑定的执行目标。

## 1. 目标

统一记录日常任务和专用任务的执行维度信息。自动调律等专用任务原有的业务历史继续保留；
统一任务历史不解析装备、轮次等业务数据，只记录一次任务如何启动、何时结束以及产出了什么。

入口：`工具 → 任务历史`。

## 2. 两级执行 ID

| 字段 | 含义 |
|------|------|
| `task_id` | 任务定义 ID，例如 `daily_checkin`、`auto_tuning` |
| `task_run_id` | 一次单任务执行的唯一 ID；单独运行和批量运行都会生成 |
| `batch_run_id` | 一次批量执行的唯一 ID；单独运行的任务为空 |

批量执行先创建 `batch_run_id`，随后每个用户、每个脚本的实际执行分别创建
`task_run_id`，并引用所属的 `batch_run_id`。因此可从批量历史下钻查看该批次的全部单任务，
也可从单任务反查所属批次。

## 3. 持久化

元信息数据库固定为 `config/session/daily_history.db`，包含：

- `batch_runs`：批量配置、输入行与脚本快照、起止时间、耗时、状态、批量报告路径；
- `task_runs`：用户、任务定义、任务性质、输入参数、起止时间、耗时、状态、执行结果、
  独立日志、错误信息，以及可空的 `batch_run_id`。

每次任务的日志写入 `logs/daily/{用户名}/YYYY-MM/DD/`。日志文件名包含任务定义、时间和
`task_run_id` 的短前缀；日志 sink 按执行线程过滤，避免混入其他后台线程的输出。
任务结果继续写入现有的 `config/session/output/{用户名}/YYYY-MM/DD/`，数据库只记录定位路径。目录日期和文件名时间戳均取任务启动时间，跨午夜运行的日志和结果保持在同一天目录。
批量报告写入 `logs/batch/YYYY-MM/DD/`，按批量启动日期定位。旧文件原地保留，
新旧记录均按数据库保存的实际路径打开；不自动搬迁、删除或压缩。

历史持久化或独立日志创建失败只能告警，不得阻断原任务。进程异常退出时未收尾的记录保留
`running` 状态，便于识别非正常退出。

## 4. 查询与查看

任务历史支持用户多选、任务多选、开始日期、结束日期、执行目标类型和状态组合筛选。
对话框默认高度 660，采用可拖动的左右分栏。关闭窗口（含 Esc）时通过统一页面状态接口
合并保存 `interface.json` 的 `ui_state.task_history`：窗口大小与任务、批量两页各自的左右
分栏尺寸。重新打开时恢复；缺失或非法尺寸使用默认布局，其他页面和同页其他字段保持不变。
左侧第一行放日期，第二行放执行目标、
状态和查询按钮；下方是用户、任务的搜索勾选列表与历史记录列表。
搜索只改变候选可见性，不清除已勾选项；未勾选表示全部，标题显示全部或已选数量。
候选取自历史数据库，已删除的用户和任务仍可筛选；任务名称重名时追加定义 ID 区分，
普通任务仅展示名称，定义 ID 放在提示中。

状态包含进行中、已完成、已中断、失败和跳过；任务与批次查询均在数据库中先按状态
筛选，再应用既有条数上限（任务 2000 条、批次 1000 条）。不改变数据库格式。

单任务列表展示开始时间、用户、任务、状态与耗时；执行目标、性质、方式、结束时间
及记录 ID 移到右侧「记录详情」。左侧候选区与结果列表可拖动调整高度。

右侧默认展示「执行日志」，另有「执行结果」和「记录详情」页签，均为只读内嵌预览。
双击单任务切换到执行结果页签，不启动外部编辑器。有效 JSON 格式化展示，解析失败
保留原文并提示；记录详情保留输入参数、错误、文件路径与完整记录 ID，支持复制。

日志级别默认 INFO，采用与主界面相同的阈值语义：显示所选级别及以上日志。按现有
日志首行的时间与级别分组，多行消息和异常堆栈跟随所属记录过滤；未知格式保留。
过滤只改变显示，不修改源文件；点击「刷新日志」重新读取当前文件，不做定时轮询。
单文件预览最多读取 2 MiB：日志取末尾，结果和批量报告取开头，截取时明确提示。
未记录文件、文件为空、文件缺失或读取失败均在预览区提示，不弹出阻塞窗口。

批量历史同样采用左右分栏及两行筛选，左侧展示开始时间、配置、状态、耗时和任务数，
右侧内嵌展示批量报告原文及记录详情。批次没有独立日志文件，不伪造汇总日志；
可下钻单任务查看各自日志。
选择“查看全部单任务”时，清除用户、任务、目标、状态及候选搜索条件，按批次和子任务
时间适配日期范围，并用该 `batch_run_id` 查询子任务；既有查询条数上限仍适用。
返回全部任务解除批次限制，保留当前页面的日期和其他筛选。

## 5. 界面与辅助状态独立存储

`config/session/interface.json`（格式版本 1）保存 `ui_state`、`profile`、`alert_info`、
`server_config` 和根节点 `alert_history`。其中 `alert_history` 原位于
`session.json` 的 `profile` 内；迁移后与 `alert_info` 并列。

在 GUI 创建任何页面前，启动初始化同步加载运行状态与界面状态，并完成必要迁移。
配置尚未就绪或迁移失败时不得先展示主窗口。手机配置同步后也须先重载状态再交给消费者。

仅在 `interface.json` 不存在时导入旧 `session.json` 的四个节点，随后所有消费者
只读写新文件。迁移顺序固定为：锁住新文件 → 锁住旧文件 → 原子写入新文件及版本化
迁移标记 → 从旧文件删除四个节点并原子落盘 → 清除新文件的迁移标记。
保留旧文件其他所有节点；源文件损坏或写入失败时不得以空默认值覆盖源数据。

若新文件已写入但旧节点清理尚未完成，下次启动按明确的迁移标记继续清理，不再次导入。
新文件已存在且没有待完成标记时，不再回读、重导入或清理旧文件残留的同名节点。
迁移可重试且不会二次迁移；不提供永久兼容回读。

新存储复用文件锁、线程锁和原子替换。页面状态补丁只合并调用方拥有的字段；写入时
读取锁内最新磁盘快照，保留其他页面及其他组件刚写入的字段。
只读实例的活动分组、批量草稿及窗口页签状态继续仅保存在本实例内存，告警与服务器等
原本允许持久化的字段仍正常保存。用户 JSON 中的用户级 `ui_state` 不属于此次拆分范围。

手机离线同步清单增加 `interface.json`，确保总览、告警和界面状态随新配置格式一起下发。
Profile key 重命名的跨文件恢复范围同步切换到新文件，继续更新总览列、告警标识和批量草稿引用。

## 6. 任务业务结果摘要

结果用于回答“做了什么、结果如何、关键数值是多少”，排查过程通过日志查看。
不在结果 JSON 中保存 OCR 原文、卡片/格子位置、重复任务名、空原因、默认 unknown、
刷新图标、动作子对象或状态变迁事件列表。原有游戏操作、识别、导航、等待、return、
批量前置检查和任务历史状态不受结果记录影响。

### 6.1 江湖号令

`jianghu` 只输出整次状态、按稳定任务类型分组的结果、未识别类型的首轮结果及
声望首次/最终采用值。`heying`、`huanzhuang`、`qingjing`、`kanbao`、`yinjiu`、
`juezhanglin` 是任务身份，卡片位置和 OCR 文案不是 key。
每组记录名称，各项只保留 `status`、必要的中文 `reason`、有实际记录的领奖状态。
动作异常之后又观察到完成时，额外保留 `problem`，不能用后续成功掩盖异常。
比如觉障林只显示 `not_implemented` 和“暂未实现”，不输出未执行动作与未领奖的重复解释。
同类型多项仍使用数组，不互相覆盖；补扫只新增此前未记录且允许执行的新类型，
过滤只作用于记录，不改变原有补扫动作。

`completed` 表示已有完成检查；`executed_unverified` 表示执行后未检查。
`claim_attempted` 只表示领取尝试，不确认到账。未知或未检查的奖励不添加占位对象。
未读取类型的首轮结果放在 `unidentified`，不额外识别或猜测身份。
顶层收集共享摘要，运行中更新；停止前保留已写的部分结果，未收尾时整次仍是 `running`。
框架异常沿用既有错误输出，不承诺保存所有中途记录。

### 6.2 自动执行任务

系统每日签到、购买不肝、购买袅袅、购买心法、兑换码、钱袋扫描，以及 local 花蕊织、
百业领奖、好友送礼、战令领奖采用 `subcall/result_records.wf` 的纯记录能力。
结果分别位于 `daily_checkin`、`purchase_bugan`、`purchase_niaoniao`、`purchase_xinfa`、
`redeem_code`、`scan_wallet`、`huaruizhi`、`baiye_rewards`、`friend_gifts`、`zhanling`。
整次保留 `status`；失败或跳过按需添加原因；`items` 保留各业务项结论。
关键采用值放在 `values`，有实际计数时添加 `counts`；不输出空观察数组或零计数模板。
同项阶段事件合并为最终结论；例如兑换码每条只输出一项提交未确认、取消兜底或用户已收口。

| 任务 | 结果保留内容 |
| --- | --- |
| 签到 | 活动名称、领取尝试、未检测到奖励、未找到活动 |
| 不肝购买 | 战斗养成、营生、赛季、袅袅及进度奖励的购买/领取尝试或阻塞；不肝进度和体力采用值 |
| 袅袅购买 | 周已购数、余额、计划量；名称拒绝、未找到或购买尝试，成交量不猜测 |
| 心法购买 | 周进度采用值，开箱/回收/购买尝试次数，循环结束原因；正常收尾仍保留旧返回 -1 |
| 兑换码 | 每码一项最终结论；安卓手动输入内容未知，不增加识别 |
| 钱袋 | 旧值、观察值、容差拒绝或写入调用；通宝/宝钱单位为万 |
| 花蕊织 | 花蕊织和止戈最终周进度采用值，周额度已满或开始匹配尝试；关闭导航明确记进度未读取 |
| 百业领奖 | 分红结论、各商店兑换结论及确认新增购买量，活动领取尝试/确认次数；沿用已有领奖浮层、状态与库存证据 |
| 好友送礼 | 每位已读好友一条结果及两种赠礼的结论，情义满额、空持有数、名称拒绝、补货结论；好友文字是数组数据，不作为字典 key |
| 战令领奖 | 任务奖励和等级奖励分别记录未检测到奖励或领取尝试，弹窗未收口时单列问题 |

OCR 原文和逐步状态记录在原有流程日志及新增 debug 日志中；查看排查细节时可在历史
日志预览降低级别过滤。结果中的采用值可能来自旧值回退，不能当成本次 OCR 确认值或收益。
`processed` 只表示流程处理结束；点击购买、赠礼、领取、匹配都不能单独作为成功依据。
local 工作流依赖主仓库记录子过程，两仓库须一并更新。
打桩、装备扫描及其他未指定任务不新增此类业务摘要。
