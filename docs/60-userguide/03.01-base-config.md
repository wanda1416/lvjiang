# 3.1 通用配置

入口：「通用 → 配置管理」。

修改后点「保存」生效。系统默认值随版本分发，你的修改保存为本地覆盖，
更新版本不会丢失。

---

### 基础配置

基础配置页分为常规设置、字体设置、热键设置三个区块。常规设置内包含界面语言、窗口（PC 投屏）和安卓设置。
输入参数和等待参数合并在「执行参数」页，分别展示在独立区块中。合并页支持滚动。

| 配置项 | 说明 |
|--------|------|
| 界面语言 | 界面文案语言，切换后重启生效 |
| 窗口输入 | `前台输入 (SendInput)`（真实移动光标）或 `后台输入 (PostMessage)`（不移动光标）。仅投屏模式有效 |
| 窗口截图 | `前台截图 (mss)` 或 `后台截图 (WGC，Beta)`。后台截图在游戏窗口被别的窗口盖住时也能取到画面，代价是比 mss 略慢；窗口最小化时两种方式都拿不到画面。它要求输入同时走后台，所以**主界面只有勾选「后台输入」后才会按这里的设置自动勾上「后台截图」**，没勾后台模式时该开关置灰不可用。本次运行内仍可随时改，改动不写回这里 |
| 窗口标题 | 填入窗口标题关键字（如「投屏」），「扫描窗口」时自动匹配并定位，免去每次手选 |
| 安卓输入 | 默认使用 `ADB shell input 指令执行`，无需安装手机 App。选择`端侧执行`后，需在手机安装律匠 App、开启无障碍服务；App 不可达时自动回退 `ADB shell input`（运行日志提示一行）。该选项不改变截图方式，下次连接生效 |
| 安卓截图 | `ADB screencap 单帧截图`（每次请求单独截一帧）或 `Scrcpy 流式截图`（持续从投屏流取帧）。流式更流畅但需要额外依赖，不可用时自动回退 screencap。截图选择与输入选择相互独立 |

### 应用注册

点击顶部「添加应用」会增加一张应用参数卡。一个应用名可同时绑定 Android
与 Windows，运行时根据当前实际连接目标选择对应绑定，不根据工作流环境选择。

| 配置项 | 说明 |
|--------|------|
| 应用名 | 工作流使用的别名，例如 `game` |
| Android | 包名、Activity 和期望方向；连接 ADB 后可自动获取 |
| Windows | 可执行文件与窗口标题；定位窗口后可自动获取 |

应用名不能重复，且至少绑定一端。配置保存后，工作流可以使用
`app stop "game"`、`app start "game"` 控制应用，并通过
`app_is_running("game")` 查询当前目标上的应用状态。Android 端还可以通过
`android_wait_stable_frame("game", 90, 1)` 等待画面恢复稳定。

### 输入参数

控制自动化操作中的拟人化参数，以及坐标算错时的处置方式。每项控件旁有
**「?」** 图标，悬停可查看说明。

| 参数 | 说明 |
|------|------|
| 点击前延迟 | 发出点击命令前的等待时长范围 |
| 点击后延迟 | 发出点击命令后的等待时长范围 |
| 鼠标移动时长 | 从当前位置移动到目标位置的耗时 |
| 坐标随机偏移 | 点击坐标的随机抖动范围（像素），模拟人手操作 |
| 默认点击范围半径 | 未单独标定点击区域时，落点框从区域中心向四边延伸的比例 |

> 以上参数影响自动化的「自然度」。如果操作过快导致游戏来不及响应，
> 可以适当增大延迟范围。

分隔线以下是**失败策略**，不是拟人参数：

| 参数 | 说明 |
|------|------|
| 坐标越界处理 | 勾选「越界坐标自动截断」后，引擎算出的坐标跑到画面外时自动截断到边界并记一条 warning；**默认不勾选**，此时报错并结束本次运行 |

**为什么默认报错而不是自动截断。** 坐标越界通常意味着脚本的拖拽距离与当前
面板几何不匹配（例如面板靠屏幕上缘，却要求向上滚两行）。自动截断会把
「滚两行」悄悄变成「滚一行」——脚本以为滚到位了，日志里也看不出来，后续步骤
在错误的页面上继续执行。报错结束虽然打断了运行，但指明了是哪一条指令、哪个
坐标、画面多大，可以直接去调。

**为什么这个判定在引擎里做。** 同一个越界坐标，三条输入通道反应完全不同：
设备端执行（无障碍手势）是硬拒绝，抛一句
`Path bounds must not be negative`，看不出和脚本哪一行有关；而桌面输入和
`adb shell input` 会静默接受、自行截断——于是位移一直没走够，却从来没人发现。
统一在引擎层判定，三条通道行为才一致。

**越界了该怎么改脚本。** 位移量只由 `up/down/left/right <n>` 决定，起点决定
这段位移有没有地方可走。panel 翻页可以用单维形态把起点挪向拖拽方向的反侧：
`drag [场景].[面板][行] up 2`（取靠下的行）或
`drag [场景].[面板][][列] left 2`（取靠右的列），比缩小 `<n>` 更好——后者改掉了
脚本的本意。

### 等待参数

命名等待参数表，供工作流按 key 引用。

| 操作 | 说明 |
|------|------|
| 新增 | 输入 key 名和等待范围（最小值~最大值，单位毫秒） |
| 编辑 | 双击行内修改值 |
| 删除 | 选中行后点「删除」 |

工作流中通过 key 引用等待参数，例如 `wait "短等待"`。
修改等待参数后，所有引用该 key 的工作流都会使用新值。

### 方案设置

分两块。

**连接方案** — 方案把图库、环境、布局绑成一个具名整体，并声明支持的连接
方式。内置「手游 / 端游 / 端游全屏 / 手游投屏」四个预置方案，完整用法见
[2.4 连接方案](02-main-interface.md#24-连接方案)。

| 操作 | 说明 |
|------|------|
| 新建 | 建一个空方案，默认两种连接方式都支持 |
| 从当前组合新建 | 把主界面当前的图库/环境/布局存成方案 |
| 删除 | 删除选中方案 |

右侧编辑名称、图库、环境、布局、管理员权限和「模式」勾选框。名称不能为空，
模式至少勾一个，否则保存会被拦下。管理员权限仅在 Windows 生效；启用后，
程序会在任务启动前检查自身是否已提升权限，不满足时说明原因并拒绝执行。

自建方案保存在 `config/session/session.json`，是**机器级**配置，不随用户切换；
随安装包分发的预置方案存在 `app.yaml` 里，选中时这六项和「删除」按钮都是灰的。

**系统参数** — 可用目标环境列表。目标环境决定 DSL 中 `env()` 的返回值，
用于区分 PC 游戏与手游的导航策略，指**游戏运行的目标环境，不是本机系统**。

| 操作 | 说明 |
|------|------|
| 添加环境 | 填环境 key（如 `ios`）和显示名称 |
| 删除 | 删掉一行 |

预置 `android`（安卓）和 `desktop`（桌面），保存在 `app.yaml`。新加的环境
要保存后重新打开对话框，才能在方案里选到。

### 字体设置

| 配置项 | 作用范围 |
|--------|----------|
| 用户总览字号 | 用户总览的分组页签、列表内容和列表表头 |
| 用户信息字号 | 用户信息中的便利贴和 Profile 信息分区 |

字号范围为 8~24 pt。点击「保存」后立即生效，无需重启。
两个页面顶部的刷新/用户切换工具栏保持原字号；用户总览底部的
「数据模型」按钮也不受影响。

### 热键设置

自定义四个系统级全局热键的按键位（限 F7~F12）：

| 动作 | 默认键 | 含义 |
|------|--------|------|
| 开始执行 | F9 | 启动当前 Tab 的自动化任务 |
| 暂停 / 恢复 | F11 | 暂停或继续正在执行的任务 |
| 停止 / 结束 | F10 | 结束任务（等待中也能立即打断） |
| 脚本录制 | F12 | 仅在「工具 → 脚本编辑」工作台打开期间临时注册 |

保存后立即生效，不需要重启；改动记在会话设置里。菜单项自带的 F2~F6 是固定
快捷键（用户管理、场景管理、图库管理、游戏配置、调律配置），不在这里改；
「燕云 → 属性配置」没有热键，也不占用上面的槽位。

### 功能激活

- **本机序列号**：只读，可一键复制。它由主板标识算出、每次启动现算、不存盘，
  也不包含任何可还原的硬件信息；需要绑定本机的激活码时把这串发给作者。
  非 Windows 平台读不到硬件标识，这里会直接写明。
- **激活码**：粘贴后点「激活」换取授权，换行和空格会被自动忽略。
- **清除激活**：移除本机授权。

这一页是即时动作，不走对话框底部的「保存」——激活要么当场验过写盘，要么当场
告诉你为什么不行。

### 网络与隐私

- **完全离线模式（暂停全部联网功能）**：勾选后下面几项一并停用。
- **启动时检查公告**：拉取作者的公告，在主界面显示。
- **启动时检查新版本**：按当前平台检查是否有新版本。
- **接收在线配置更新**：只下发识别所需的配置（场景与布局坐标、插件规则），
  用于不发新版就修复识别问题；你自己改过的配置始终优先，不会被覆盖。
  拉取到的配置下次启动生效。
- **参与匿名数据收集，帮助改进内置规则**：收集范围与用途见
  [隐私政策](../../PRIVACY.md)。

### AI 设置

在「通用 → 配置管理 → AI 设置」填写支持 OpenAI 兼容 Chat Completions 的接口根地址
（通常以 `/v1` 结尾，不带 `/chat/completions`）、模型名称、API Key 和超时。
模型名称按服务商提供的名称填写；无需鉴权的本地服务可以留空 Key。

点击「测试连接」会用当前填写内容向所选模型发送一条简短请求，可能产生少量费用。
测试不会保存设置，也不发送游戏数据；可以取消，关闭窗口也会取消。
成功表示模型能返回文本，不代表图片、工具调用等能力已验证。

点击「保存 AI 配置」才保存此页内容。Key 存入系统凭据库，不写入配置文件或手机同步包。
系统凭据库不可用时可以临时测试，保存 Key 前需要启用或解锁系统凭据库。
更改接口地址会清空 Key，需要重新填写。当前只提供连接基础能力，答题与调律 AI 分析尚未开放。
