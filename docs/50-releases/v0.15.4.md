# v0.15.4 — 装备养成承音与传律石估算、多实例并发写与退出稳定性

发布日期 2026-10-24。

## ⚠️ 不兼容变动与升级指引

### 多实例同时修改同一份配置时，可能有一方的改动不生效

- **现象：** 同时开两个客户端，两边几乎同时修改同一份配置（会话参数、界面状态、游戏配置、
  Profile 定义、场景与图库文档）时，可能出现一方看不到另一方的改动，或自己刚保存的那一次
  被对方的写入覆盖。
- **原因：** 第二个实例不再被「只读节点」拦住，任一实例都可落盘；写入用跨进程文件锁串行化
  「读盘 → 合并 → 替换」，语义是「最多丢一次更新」，不保证两边并发修改都保留。
- **如何调整：** 无需操作，重新保存一次即可。想彻底避免，一次只用一个窗口改配置；任务执行
  读的是启动时冻结的快照，运行中改配置只影响下一次任务。

### 第二个实例现在会真的写入配置

- **现象：** 以前在第二个窗口里保存配置会被拒绝（「只读节点」），看起来像保存失败；现在会
  正常落盘。
- **原因：** 主节点限制只保留给整目录替换的操作（更新包安装、离线包导入、历史回传），
  其余配置与运行状态任一实例都可写。
- **如何调整：** 无需操作。如果你以前依赖「第二个窗口改不动」来保护数据，请改为只开一个
  实例，或使用完全离线模式。

### 已承音的装备现在可以继续承音到下一阶

- **现象：** 以前 110 阶已承音装备再也承音不上去，提示「该装备已经承音」；现在可以逐阶承音
  （105 → 110 → 115）。
- **原因：** 不可撤销的只是「已承音」这个状态，不是等级上限；旧规则把两者混为一谈，连等级
  下拉都一起锁死了。
- **如何调整：** 无需操作。仍然只能一阶一阶走，105 直接跳到 115 会被拒绝。

### 承音合并的可选候选会比以前少

- **现象：** 装备「承音合并」里不再出现 96→100、100→105 这类跨赛季作废线的候选；两条都未
  承音、只是等级不同的记录也不再被判为同一件装备的前后版本。
- **原因：** 这两类关系本赛季造不出来，旧规则会把它们当成升阶并删除旧记录、迁移方案引用，
  且删除不可撤销，属于误删。
- **如何调整：** 无需操作。如果你在本版本之前已按旧规则合并过，被删掉的旧记录无法恢复，
  用「装备库 → 重新扫描」补齐当前装备即可。

### 本地覆盖过 `basic.yaml` 的用户拿不到新增的传律石比例

- **现象：** 传律石估算按每条词条满值的 4.5% 计算，这个比例来自系统配置
  `yysls/game_config/basic.yaml` 新增的 `chuanlv_stone_percent`。改过同路径本地文件的用户
  读不到这个字段（估算退化为缺省 4.5%）。
- **原因：** `config/local` 无条件优先于 `config/system`，实体文件是整文件覆盖而不是合并。
- **如何调整：** 在本地那份 `basic.yaml` 里手动补上 `chuanlv_stone_percent: 4.5`，或删除
  本地覆盖改用系统配置。

## ✨ 新增功能

### 装备养成按目标等级估算传律石

- 「词条配置」组底部实时显示「当前装备承音喂满需要 N 个传律石（X 阶承音上限）」，逐条明细
  （当前值 → 承音上限、每石增量）在问号提示里。
- 一次传律提升一条词条，增量是该词条在目标等级普通满值的 4.5%（可在「游戏配置 → 基础配置 →
  装备养成」校正）；五条普通词条各自向上取整后求和。定音是独立槽、不受承音限制，不参与估算。
- 终点读该词条的承音上限配置原值，不按 94% 手算：最大外功 131.2 只占满值 139.6 的 93.98%，
  按 94% 判会以为还能提升，实际已经到头。

### 承音改为直接勾选，等级可按目标等阶选择

- 养成的「承音」不再用单独按钮，直接勾选复选框：勾选会把等级带到承音目标、按升级表给被合并
  的词条改名、把数值截断到新等级承音上限；已承音的装备只读展示并提示可继续承音到哪一阶。
- 真实装备的等级下拉开放，只列这件装备合法能到的等阶，可按任一目标等级估算传律石。

### 装备新增「假设同级承音」开关

- 满承音假设此前只对已承音装备生效，同等级的未承音装备（例如 115 级 83% 的枪）即使开了满承音
  也按原值算。新增的 `assume_chengyin` 字段可以显式声明「这件装备按承音上限计算」，在装备属性
  的「状态」与「引用方案」之间勾选，只对本赛季等级、且尚未承音的装备开放。
- 应用带「同等级承音假设」的最优组合时，会自动为对应装备勾选该开关，不再丢失假设状态。

### 多实例并发写

- 第二个实例（只读节点）不再被拦：session、界面状态、`profile.yaml`、游戏配置、场景与图库
  文档都可保存。

## 🔧 修复

- **退出时崩溃**：每次正常退出都在最后打印 `QThread: Destroyed while thread '' is still running`
  然后进程直接崩掉。启动期网络线程没有协作取消接口，关闭收尾时仍在运行，窗口销毁时 Qt 直接
  中止进程；关闭过程中还会新起线程（公告失败后把链推进到版本检查）。现在关闭开始即置标志，
  启动链不再新起线程，并在关闭链最后统一下线仍在跑的线程。
- **只读实例退出变成半关闭**：关闭时保存脚本参数会抛权限异常，异常从关闭事件冒出去，
  ProfileEngine 停止、录屏转正和设备连接释放全部被跳过。现在每步独立兜底，单步失败只跳过该步。
- **点击装备槽位保存筛选导致客户端退出**：另一个进程正在执行该用户的任务时，界面偏好写入被
  任务租约拦下，异常在 Qt 事件里没人接住。界面偏好与任务数据无关，改用独立跨进程文件锁，
  失败时只提示一次、不再中断点击。
- **已承音装备无法继续承音**：见上文不兼容变动。
- **承音合并误判**：见上文不兼容变动；根因是升阶关系判断缺少「必须已承音」与「不低于本赛季
  作废线」两个前提。
- **江湖号令合影落点错误**：新版游戏拍照前会先弹「画质选择」，不处理会让随后的「拍摄」落在
  弹窗上。现在进入拍照前先取消该弹窗，弹窗没出现时不做任何点击、按键或等待。

## 📦 重构

- **在线配置只按修订号加载增量**：公开与会员各自比较本机记录与远端最新修订，相同不下载，
  不同则从 r0 重建整棵树后叠加该修订，远端回退走同一条路径。移除清单基底比对、整树哈希准入、
  索引快照、双阶段预演与跨实例观察器；`r0` 不再作为发布身份凭据，只在恢复预置时确认。
  会员撤回同时归零会员修订，修复关闭在线更新或授权失效后不再拉取的问题。
- **场景注册表改为插件注册完成后显式初始化**：场景加载此前是模块导入的副作用，会让场景、
  PyQt6 与识别器抢在插件注册之前加载，并把「已加载场景」打印两遍。现在由启动流程在所有插件
  注册完成后显式初始化一次，日志顺序为「插件 → 主窗口 → 场景」。
- **配置锁体系统一**：全仓库加锁顺序固定为「进程内 `configuration_lock` → 跨进程
  `interprocess_lock`」，冲突确认弹窗移到两把锁之外；锁目录不再按 `is_dir()` 分支、缓存键带上
  用途后缀、获取跨进程锁加超时并回收失败时漏关的句柄。
