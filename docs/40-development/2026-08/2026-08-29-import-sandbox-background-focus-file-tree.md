## 一、`import` 路径改为根相对并封闭沙盒（`8ae4dec8`）

`.wf` 会被引擎执行，所以**「import 能指向哪里」等价于「能执行什么」**。原实现有两条越界路径，实测均能把 `workflows` 之外的文件加载进来并拿到其中的过程：

```
import "/abs/path/evil.wf"            绝对路径完全绕过校验
import "../../../../../tmp/evil.wf"   rel.startswith("..") 只是跳过跨层解析，
                                      随后 _base_dir / imp_path 裸拼接，无 containment 校验
```

### 1.1 语义改为根相对

`import` 路径一律相对 workflows 根，经 resolver 跨层解析（local 影子优先 → system）。subcall 内部互相 import 也要写全 `subcall/xxx.wf`。

**这不是新约定而是把既有事实固化**：17 条 import 里 13 条本就这么写，只有 4 条用目录相对，已一并迁移。文档 `07-subworkflows.md` 原本写的是「路径基于当前 wf 所在目录解析」，但它自己给的示例却是根相对——一并更正。

每条 import 独立从根算起、不累积路径，于是 `_resolve_imports` 递归时不再需要保存恢复 `_base_dir`/`_wf_rel_dir`，产生逃逸的那条回退分支也随之删除。

### 1.2 校验两道，且不依赖 `Path.is_absolute()`

```
开头        拒 / \ ~ . 开头，拒含 : 或 \
normpath 后 再拒 ..    挡住 subcall/../../etc/x.wf 这种「以文件名开头、中段逃逸」
```

**不能用 `is_absolute()`**：它的结果随平台变——`C:/evil.wf` 与 `\\server\share\x.wf` 在 Linux 上判定为「非绝对」，而开发与 CI 都在 Linux、用户却在 Windows，这类写法会静默漏过。测试专门覆盖 Windows 形态，负向验证时正是这几条先红。

### 1.3 顺带钉住：`workflows` 不得进在线下发注册表

`scenes`/`layouts`/`tuning_rules` 是数据，下发只改识别与判定；`.wf` 会被执行，**下发它等于远程代码执行**。现状是「碰巧没注册」，新增断言把它变成显式约束。

### 1.4 两个原本假绿的用例

`test_input_trace` 里两条此前靠「resolver 不认识 `tmp_path`」才通过——走的是「根外文件」降级分支，**从未验到真实约束**。新夹具让 resolver 认了这个根后真实规则生效，二者暴露。

## 二、后台模式不再抢焦点（`557197b7`）

后台模式每次点击/移动/滚动/拖拽前都会 `SetForegroundWindow` 把目标窗口拉到前台、自旋等最多 200ms、再把焦点还给原窗口。于是「后台」只剩下「不移动光标」，**副屏挂机边用电脑的场景直接废掉**。

### 2.1 这个默认值的来历

排查「后台投递偶发不落地」时，根因并未查明（当时 TODO 原文「未定根因：可能是 Win32 API 序列、窗口焦点、消息队列竞态」），`activate_before_send=True` 是与 `screen_to_client_logical` 这个 DPI 坐标修正**一起打包塞进去的猜测性改动**。随后问题消失、状态改为「经回归验证可用」，就再没回头区分过谁才是真修复。

从改动内容看，真正的修复是 DPI 坐标转换：投递坐标本就算错了，激活与否并不改变这一点。

### 2.2 改法与取舍

改为默认不激活。属性保留（scrcpy 等 SDL 窗口不在前台确实不处理 PostMessage，这类目标可显式设回 `True`），只是不再默认生效。前台模式（SendInput）保持激活不变——系统级注入本就打给焦点窗口。

> **已知影响（明确决定，勿再改回）**：scrcpy 投屏窗这类 SDL 窗口在后台模式下可能收不到点击。这是可接受的——post 后端存在的意义就是不打扰用户操作。确实需要窗口在前台时，正确做法是用户自己点一下窗口激活、再用热键启动任务。

## 三、江湖号令 PC 端可用

该日常此前只能在手机投屏 / 模拟器上跑，端游因菜单项位置不固定、无法用坐标点击而缺失。

### 3.1 `press` 支持变量按键名（`d756b818`）

`press` 此前只收字符串字面量，导致「扫出菜单项在第几列、就按第几个数字键」这类需求写不出来。

改动只有两处：语法 `STRING` → `(STRING | var_ref)`，parser 对 `VarRef` 直接透传。**执行侧本来就支持**：`_exec_press` 一直是 `_resolve(node.key)`，AST 注释写着 `key: str | VarRef`，连「press: 按键变量未定义」这条只对变量才有意义的报错都在——只是语法口子没开。

取值后统一 `str()` 再 `normalize_key`，所以扫描算出来的 int 列号可以直接按。

### 3.2 导航统一走子过程

端游按 ESC、安卓才点菜单，比无条件点击更正确（`8177bfcc`、`ddc5c6d9`、`77a80b92` 配套更新场景与布局）。

### 3.3 测试跟着改对（`09bc9bc8`）

`test_daily_jianghu_matches_legacy_required_scenes` 只 `parse_file`、不解析 import 链，于是任何「把一句 click 挪进 subcall」的重构都会让它红，**但覆盖其实一点没少**。改为按引擎 `_load_and_validate` 的方式先合并 import 链的 procs 再搜集——断言的才是运行期真正的校验范围。

## 四、工作流文件树模型（`f6bb661e`）

脚本编辑器要展示的是「有哪些脚本」，不是「local 里有哪些、system 里有哪些」。这一层把两层合并成一棵虚拟目录树。

### 4.1 `resolver.enumerate_entity_tree`

现有 `enumerate_entities` 只扫一层且返回裸文件名。新增递归版返回带路径的全集，子目录同样取并集。

实现上**刻意复用 `enumerate_entities` 逐目录调用**而非自己写 glob：合并、遮蔽、墓碑、`_` 前缀跳过这些规则必须与单层版本一致，两套枚举对「哪些文件算数」给出不同答案，会让树显示的东西和引擎实际加载的对不上。

### 4.2 `workflows/file_tree.py`

`WorkflowFile(rel_path, layer, overrides_system)`。三条语义直接取自配置层，不另立一套：

- **同名只出现一个节点**：local 影子整份顶掉 system（不做内容合并）；
- **出厂只读**：`editable` 为 `False`，用户要改先「复制到本地」。复制之后该文件就脱离出厂更新了，这个代价要让用户看得见，所以显式区分 `overrides_system`；
- **不做墓碑**：用户删不掉出厂脚本，要让它不出现走「展示勾选」的暴露机制。

本提交只做模型层，UI 接入是下一个增量。

### 4.3 配置层措辞统一（`9b6864d7`）

「出厂」这个词在界面上又土又不准——它对应的其实就是 `config/system` 这一层。全仓统一成配置层本来的三个名字：**本地(local) / 系统(system) / 远程(remote)**。场景版本控件的来源标签「用户」→「本地」。

脚本树排版补 5px 行内边距、16px 缩进、系统标准目录/文件图标。**只调间距不写颜色**——颜色归全局主题样式表管，在这里硬编码 token 会在切换深浅色时留一块不跟着变的死角。

### 6.1 删掉逐像素比对旧 delegate 的脆弱断言（`2e229d49`）

`test_matches_legacy_delegate_pixel_for_pixel` 在 Windows 开发机上稳定失败（单字节单通道 `0xfe` vs `0xfc`，2/255 的子像素级差异），而 CI 与 Linux 上都绿。

它断言的是「新实现与**旧实现**逐像素一致」。旧实现早已从生产代码移除，只为这条断言在测试文件里复活——**这是一次性的迁移证据，不是需要持续守护的不变量**。而「两条不同渲染路径逐像素相等」本就取决于平台 style 实现。一个在开发者本机常红、CI 常绿的用例，只会训练人忽略红色。

保留的四条都不依赖渲染精确性，其中 `TestHeavyWidgetTeardown` 才是当初换实现的真正原因（反复构造/销毁 `SceneTab` 不再段错误）。

## 七、yysls 修复

### 7.1 端游回收确认改按空格 + 材料 label 去掉 `tr()`（`f8735782`）

**材料 label 过 `tr()` 是活着的 bug，不是隐患**。`STONE_LABEL` / `FOOD_LABELS` 匹配的是参考图库的 label（游戏内材料名，恒为中文），却过了 `tr()`。插件译表里这几个词**是有英文翻译的**，实测英文界面下：

```
STONE_LABEL = 'Major Tuning Stone'
FOOD_LABELS = ('Gold Fodder', 'Purple Fodder', 'Rainbow Fodder')
```

参考图 label 恒为中文，于是永远匹配不上：大律准石库存查不到，狗粮必然走到「材料槽位定位失败，提前结束调律」——**英文界面下自动调律基本残废**。改为裸字符串，并把这 4 条从插件译表移除。

> `models.py` 里还有 49 处同类 `tr()`（部位名、词条名、属性名等数据键）暂未处理。

**小律准石缓存失效：实现保留，开关默认关闭**。原本改成「小律准石在场则缓存按轮失效」，依据是一键添加把它用光导致槽位左移——但这条链的第一环没有证据：一键添加理论上只消耗大律准石。而材料区几乎总有小律准石，打开等于缓存形同虚设。故加 `INVALIDATE_CACHE_ON_SMALL_STONE` 开关并**默认关闭**，默认行为与改动前完全一致，待真实成因查清再定。

## 关键设计决策

1. **import 路径 = 可执行范围**：根相对 + 双重校验 + 不用 `is_absolute()`（跨平台判定不一致）。
2. **`workflows` 永不进在线下发注册表**：下发可执行文件等于远程代码执行。
3. **后台模式不抢焦点**：原默认值是未查明根因时的猜测性改动，真正的修复是 DPI 坐标转换。
4. **文件树复用单层枚举而非另写 glob**：两套枚举会让「树里看到的」和「引擎加载的」对不上。
5. **删掉在本机常红、CI 常绿的脆弱断言**：它只会训练人忽略红色；一次性迁移证据不是不变量。
6. **数据键不过 `tr()`（续 08-27）**：这次是活着的线上 bug，英文界面下自动调律找不到材料。
