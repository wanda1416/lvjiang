# 批量执行单元

## 范围与状态

批量配置组保存执行单元键。默认 `user` 沿用原有 `usernames`、
`selected_usernames` 和生命周期变量；旧配置无需迁移。其他候选键来自用户资料的
非空属性，单元值是该属性的去重结果。属性单元的可见范围和主页面勾选范围按属性键
分别保存，不改写用户模式的原有范围。

配置窗口决定执行单元键、可见范围和初始顺序。主页面「单元」页只二次勾选、临时排序；
切换配置组时按已保存的键重建列表。启动时冻结全部已注册用户的属性、单元成员、
任务参数与生命周期参数。运行中只重新读取业务 Profile，不重新读取用户配置。

## 属性单元执行

一个属性值可对应多名用户。批量层在条目准备前对每名成员执行任务声明的
`batch_check`；至少有一名可执行时，把可执行成员的
`[{username, attributes}, ...]` 交给条目准备工作流。准备工作流成功时必须返回
属于该列表的 `username`。任务、独立参数、Session、历史与条目收尾均绑定此用户名。
选定角色后仅执行该角色 `batch_check` 返回 `success` 的任务；其余任务按检查得到的
`skipped` 或 `failed` 写入进度、报告和任务历史。结果文件或历史写入失败只记录告警，
不改变已完成任务的业务结果。
准备阶段之前锁定本单元全部成员，结束后释放；无法锁定时延期尝试该单元。

生命周期新增 `batch_unit_key`、`batch_unit_value`、`batch_unit_members`，
仅属性单元提供。准备工作流可以返回 `retry_after` 秒数；返回 `skipped` 时该单元
延期而不消耗执行轮数，返回 `success` 时完成本次执行后延期。调度器不解释
Profile key、账号或角色的业务含义。属性单元始终执行生命周期工作流。

## 内置属性准备工作流

`batch/prepare_item_by_attr.wf` 有一个 `profile_key` 参数。它逐个读取候选用户
对应 Profile 的当前值；无记录按 0 参与比较，同值保留原成员顺序。选出的用户交给
已有 `prepare_user` 登录，后者根据用户资料中的 `account`、`tail`、`role` 和
`role_index` 选择游戏角色。发现角色仍在线时，整单元一分钟后重试；登录成功后
按托管对战约二十分钟的周期延期。任务是否已达目标仍由业务工作流的
`batch_check` 决定。
