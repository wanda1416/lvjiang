# 官方配置增量更新需求

> 状态：维护版本号为 0.15.0（跳过 0.14），按摘要归档、索引回退、manifest 删除指令、统一发布树及撤销发布已在开发分支实施，尚未正式发布。Windows 原生更新与手机在线更新仍遵守平台验证边界。

## 目标

作者可以不发布新版应用，提前更新与现有应用兼容的官方配置；用户自己的配置不受影响。

支持拼写修正、场景与区域补全、布局、默认调律配置和已有 WF 更新；在应用维护频率降低后，
仍可持续维护现有代码支持的任务。没有网络时依靠完整预置或此前有效更新正常使用。

此前“维护成本增加后再考虑”的初步草案已由本需求及配套架构方案细化取代。
实现与验证边界见配套架构文档；当前正式用户仍使用旧版客户端协议。

## 业务边界

| 概念 | 目标含义 |
|------|--------------|
| 公开预置 | 随应用提供的完整官方基底，下载不到更新也能使用 |
| 公开增量 | 针对当前三段正式版本的累计修正，不要求逐个安装历史更新 |
| 会员包 | 无随包预置，独立在线发布与授权，不跟随公开增量的版本周期 |
| system | 客户端已应用的官方内容，吸收公开增量和有效会员内容 |
| local | 用户修改，按配置类型语义合并或整体覆盖 system |

会员专属内容不进入普通安装包或公开增量。公开内容来自官方 system 源文件；
用户 local、Session、数据库、凭据和私人截图不作为公开发布来源。

官方 system 源目录内所有文件均可下发，包括 app.yaml、说明文件、未知扩展名和客户端
尚不能识别的内容；不设置配置类型白名单。下发与加载分离：未知文件原样安全安装，
加载器仅消费自身支持的内容，不自动执行未知文件，也不凭安装成功宣称支持了新功能。
路径安全、包完整性、渠道归属和发布内容审查仍然有效，不能写出 system 安装边界。

## 更新规则

1. 公开更新默认适用于 `[x.y.z, x.y.(z+1))`。第四段版本属于同一兼容系列，
   新的三段版本从自己的预置开始；不自动采用更旧或更新系列的包。
2. 每系列在首次应用更新或 PC 同步之前，从可信预置创建一次 r0.zip；安装包不重复提供 r0。
   公开及会员包都归入该版本 updates，按修订与清单摘要区分内容，不增加配置读取层。
3. 下载并校验成功后立即应用、刷新相关界面和内存配置，无须重启。
   正在执行的任务保持原配置快照，后续任务使用新内容。
4. 下载不到则忽略本轮更新，继续使用当前可用内容。不得阻断启动、撤销已安装内容或
   将部分下载生效；明确授权失效与暂时断网分别处理。
5. local 与 system 保留两类规则：聚合配置语义合并，独立实体整体覆盖。
   官方更新不覆盖用户设置或编辑草稿。
6. WF 支持更新已有官方脚本，关联场景、布局和资源必须完整。会被当前消费者读取却
   依赖未发布代码的改动不得作为有效修正发布；未知文件可先行下发留存。
   下一版应用承接已发布的公开修正。
7. 用户可以关闭应用，删除 system 后从对应原始预置备份恢复；系统正确识别恢复状态。
8. 有效 system 从 r0 重建：执行当前公开包累计删除指令，覆盖其完整累计文件，再按登记
   语义合并会员完整包；不叠加历史公开包，不以本地最大编号决定生效包。组合未变不重复写盘。
9. index.json 表示当前发布选择，manifest.json 表示具体包内容与安装指令，版本内 state.json
   表示实际成功安装的组合。下载或索引获取成功不能提前推进安装状态。
10. 成功获取索引但没有适用包，撤下该渠道更新；获取失败保留上次成功组合。允许索引撤销
    后选择较低编号，同编号重发按摘要识别。会员授权要求不因缓存或回退而放宽。
11. 公开 manifest 的 delete_files 只接受安全的相对文件路径，与覆盖文件互斥；不存在时无操作，
    不用墓碑文件、不删除目录或 local。撤回覆盖恢复预置，删除文件移除预置，两者必须明确区分。
    会员完整包遗漏旧文件即不再合并，不允许会员删除公开内容。
12. 缓存清理保留 r0、当前及最近成功组合和未完成事务所需包。r0 丢失后不得用已经更新的
    system 重新创建基底；需要恢复可信预置。PC 同步仍写 system，不能冒充官方 r0。

## 发布与版本职责

新协议使用 site/lvjiang/public 与 member；旧 config、protected 目录仅供旧应用读取，
不再混入新协议索引或修订。开发版本号提前更新为 0.15.0，不代表正式发布完成。

管理控制台采用单个推送页、共用左右分栏，取消公开/会员模式按钮。左侧保留“创建公开推送”、
“创建会员推送”和图标刷新，树下分“公开配置 / 会员配置”，各包含“计划版本 / 在线配置”。
支持异步线上状态查询、文件审核、确认发布和失败重试；切换树项不自动联网。
发布计划默认采用当前维护项目的版本号，也可手动修改；浏览线上版本
不改变本地计划。左右栏分别展示版本目录与计划、所选文件树及属性，会员采用独立包发布机制。
发布修订用于追踪更新，文件摘要用于识别和校验内容。新机制不再以文件内容版本仲裁
system 与在线内容；content_version 在开发分支已统一为 1，不再参与仲裁，字段后续退出。
明确勾选的文件必定发布，不因与预置字节相同被排除。公开新修订保留未撤回的累计覆盖和删除。
撤销最新发布删除其产物并恢复索引：r2 撤销后对外为 r1，下次仍发布 r2；唯一 r1 撤销后移除
系列记录。会员撤销恢复发布前完整索引及区间，需要历史快照。使用正常 Git 提交，不改写历史；
二次确认、站点锁和失败恢复均须保留，依赖被撤销公开内容的会员发布须先处理。

## 验收标准

- 同系列含第四段客户端能更新，下一组三段版本不加载旧包；新装客户端能直接应用最新累计增量。
- system 内所有文件均可下发；发布和安装只检查包级协议、安全、完整性与明确版本依赖，
  不做全量业务自检。资源缺失或单个消费者刷新失败不能阻断整包与其它功能，本地编辑也不阻断安装。
- 组合顺序固定为 r0 → public → member，member 同路径覆盖；共享登记表按 key 合并，不审查引用。
  无法合并时保留后层原文并记录对应文件，不拒绝整个包。文件事务先提交，消费者刷新失败不回滚。
- 场景分组暂不可用时不在模块导入阶段抛异常，不能让单个配置问题阻断下一次程序启动。
- local 不被发布或同步覆盖；断网、撤回、关闭在线更新时仍有可用的随包基底。
- 更新完成立即刷新有效配置和界面，当前任务不混用新旧 WF 或识别资源。
- 应用升级后重新验证缓存适配；下载、校验、应用中断均不会生效半套内容。
- 公开与会员更新互不丢失有效内容；会员授权遵守原协议，普通网络失败不影响可用公开功能。
- 人工恢复原始预置后，更新状态与实际内容一致。
- 普通安装包不包含会员专属内容；重复重试不产生新的发布修订。
- 撤销后允许恢复低编号或无更新，同编号重发使用新摘要；不能按编号永久拒绝回退。
- 删除指令和撤回覆盖分别产生预期结果，累计包能独立从 r0 安装，local 不受影响。
- r0 自动创建及缓存清理不误存已更新内容、不删除在用或唯一恢复基底。
- 统一树切换不改草稿，两个渠道刷新独立报状态；撤销准确恢复索引、区间及依赖组合。
