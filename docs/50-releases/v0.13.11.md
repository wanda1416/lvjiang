# v0.13.11 — 多目标并发、出装搭配与工作流编辑增强

> 本文以 v0.13.10 正式版（提交 `c41607c8`）为基线。

本版本在多执行目标连接的基础上正式开放并发运行：Lv1 用户可以让窗口与 Android 设备、
或多台 Android 设备同时执行不同任务。主界面按当前选中的目标切换运行状态、实时日志与
控制动作，每项任务拥有独立运行实例；调律管理也能同时展示多项调律任务。

燕云侧新增“出装搭配”模拟计算器，可配置词条数量和约束，查看八件装备分布、毕业率与
实时战斗属性。工作流编辑、拖拽语法、下拉框展示和系统任务也在本轮得到补强。

## ⚠️ 不兼容变动与升级指引

### 1. 任务控制与热键改为作用于当前选中的执行目标

- **现象：** 多个目标连接或运行时，开始、停止、暂停、恢复以及 F9/F10 等任务热键只控制
  当前在执行目标列表中选中的目标；不会再把“全局唯一任务”当作隐含对象。
- **原因：** 本版本允许不同目标各自持有运行实例，控制动作必须有明确归属，避免停止或
  恢复错误的设备任务。
- **如何调整：** 操作前先在执行目标列表选择对应窗口或设备，并核对该行显示的任务状态。
  未激活 Lv1 的用户仍可正常运行一个任务；只有同时启动第二个目标任务时才会要求 Lv1。

### 2. 越界点击、移动与拖拽默认改为明确报错

- **现象：** 自定义工作流若计算出的点击或拖拽坐标超出当前画面，会停止本次任务并指出
  DSL 行号和越界坐标；旧版部分后端可能静默接受或截断，造成实际位移不足。
- **原因：** 自动截断会把“滚动两行”悄悄变成更短距离，并且 Android 设备端执行会直接
  拒绝负坐标，因此统一在工作流引擎层校验。
- **如何调整：** 优先修正拖拽距离或起点；面板拖拽可用 `[行]` 或 `[][列]` 把起点移向
  拖拽方向的反侧。确认截断符合预期时，可在“配置管理 → 输入参数”启用
  “越界坐标自动截断”。随包系统工作流已按新规则调整。

### 3. 系统聊天场景、工作流和调律规则有更新

- **现象：** PC 好友赠礼现在会先退出赠礼弹窗和私聊页；系统调律规则以“本属攻击”统一
  表达武器无相与非武器流派属攻。若用户保存过同名 `config/local` 覆盖，系统修正可能不会
  生效，仍会沿用本地旧内容。
- **原因：** `config/local` 的优先级始终高于随包 `config/system`，发布不会覆盖用户自定义。
- **如何调整：** 未自定义相关内容无需操作。自定义过聊天布局、聊天场景、好友赠礼工作流
  或调律规则的用户，请手动合并新版区域与规则；不再需要覆盖时可删除对应 local 文件，
  重新使用系统版本。Windows 便携版请解压到新目录，再复制 `config/local` 和
  `config/session`，不要在旧目录上直接覆盖。

任务历史数据库会自动升级并补充执行目标字段，已有历史无需手工迁移。

## ✨ 新增功能

### Lv1 多目标并发执行

- 一个 Windows 窗口可与多台 Android 设备同时运行任务；每个目标同一时间仍只允许一个任务。
- 同一用户继续受跨进程执行锁保护，不能在两个目标重复运行；批量任务会标明因占用而跳过。
- 每个目标保存独立运行草稿和冻结快照，切换观察目标不会改变正在运行任务的用户、参数、
  环境、布局或方案。
- 主界面可在“全部任务”和当前目标日志间切换；输出文件加入任务运行 ID，避免并发同名任务
  互相覆盖。
- Android 设备按稳定身份归并 USB 与无线连接，scrcpy 和设备代理使用独立端口；断线重连
  与 Windows 窗口重新定位不改变原任务身份。
- 应用退出会统一停止并等待全部运行实例，不再只处理当前选中的任务。

### 调律管理支持多运行实例

- 历史记录固定在首页，每次自动调律按任务运行 ID 新建独立页面。
- 多个设备或窗口的调律进度、结果和状态互不覆盖；完成、失败或中断后页面保留到本次会话结束。
- 任务历史和调律历史记录执行目标类型与名称，可按窗口/设备区分来源。

### 出装搭配与模拟计算器

- 备战方案新增“模拟计算器”，可选择装备等级、承音数值、普通数值、弓玦和装备套装。
- 通过增减词条数量与强制/最佳/推荐约束，生成合法的八件装备词条分布。
- 同屏展示毕业率变化与完整战斗属性；旧单体/群体奇术增伤统一折算到“全奇术增伤”。
- 出装搭配可以保存、另存和在玩法配置中维护；保存的是搭配目标，不会改写真实装备。
- 新增 PVE 公共要求配置，默认要求两条“对首领单位增伤”。

### 工作流与编辑工具增强

- `drag` 新增面板行级 `[行]` 和列级 `[][列]` 起点语法，充分利用可滚动区域。
- VS Code 工作流扩展补齐静态编辑、语义校验与缺失运行环境下的降级处理。
- 工作流过程注释和参数文案统一，批量、签到、扫描、购买等随包脚本更易维护。
- 全局下拉框采用统一的自动宽度策略，常用长文本不再被强制压缩成中间省略号。

## 🔧 修复

- PC 周常好友赠礼完成后会明确退出赠礼弹窗与私聊页，再交给批量收尾流程，不再因私聊页
  误判为主页而导致退出失败。
- PC 前台输入会在发送按键或鼠标前确认目标窗口已激活；激活失败时明确中止，避免输入落到
  其他窗口。
- Android 命令输出统一按 UTF-8 解码，不再受系统 locale 影响；设备端手势失败会显示具体
  原因。
- “购买补耕”修正第二段商品面板的滚动区域。
- 最优组合候选列表按十行封顶，避免大量候选把对话框撑出屏幕。
- 战斗属性在全屏与半屏模式统一展示“全奇术增伤”，旧词条折算口径一致。
- 下拉框补齐箭头、边距与弹出列表宽度，修复玩法、装备等级、弓玦等常用内容显示不全。

## ⚠️ 已知限制

- 多目标并发是 Lv1 高级能力；未激活用户可以连接并切换多个目标，但同一时间只能运行一个任务。
- Windows 只支持一个逻辑执行目标。SendInput 是系统级前台输入资源，不能用多个 hwnd 安全隔离；
  Windows 任务可以与 Android 任务并发。
- 多台真实 Android 设备并发已完成自动化回归，仍需要更多不同设备组合的实机覆盖。
- 出装搭配分配器保证位置合法并尽量保留原位置，不负责自动搜索毕业率最高的词条组合。
