# 3.2 场景管理（F3）

入口：「通用 → 场景管理」或按 **F3**。

场景编辑器用于定义游戏画面中的坐标区域。内置场景坐标按分辨率自适应缩放，正常情况无需校准。

### 何时需要校准

- 游戏版本更新导致界面布局变化
- 使用了与内置布局差异较大的分辨率/窗口比例

### 界面结构

```
┌──────────────────────────────────────────────┐
│  布局选择 编辑/新建/另存为/删除 │ 保存/放弃 │ 刷新截图 │
├──────────────┬───────────────────────────────┤
│  场景分组     │  画布（截图底图 + 区域框）     │
│  · 背包       │  · 框选区域                   │
│  · 调律       │  · 拖拽/缩放区域              │
│  · ...        │  · 吸附对齐参考线             │
│              │                               │
├──────────────┴───────────────────────────────┤
│  区域列表：名称 / Key / 类型 / 含文本 / 可点击  │
│  [＋ 创建区域] [删除区域]                      │
└──────────────────────────────────────────────┘
```

### 基本操作

| 操作 | 说明 |
|------|------|
| 截图 | 从当前连接的设备/窗口截取画面作为底图（需先完成定位/连接） |
| 创建区域 | 在画布上框选矩形区域，填写名称、Key、类型 |
| 编辑区域 | 双击区域列表中的行，或拖拽画布上的区域框 |
| 删除区域 | 选中区域后点「删除区域」 |
| 刷新截图 | 从当前连接的设备/窗口截取画面并覆盖当前活动截图；右侧 `+` 追加为新截图 |
| 识别全部字段 | 对当前画面做 OCR，逐个区域列出识别结果，验证区域坐标与识别效果 |

### 布局信息与画布尺寸

顶部「编辑」按钮编辑当前布局的清单信息（布局 key 创建后不可修改）：

| 字段 | 说明 |
|------|------|
| 布局名称 | 下拉框里显示的名字 |
| 描述 | 显示在主界面布局下拉旁，写一句话，过长会放不下 |
| 画布尺寸 | 画布裁剪后应有的宽高比，写 `20:9` 或 `2.22`；留空表示不校验 |
| 允许误差 | 相对误差，默认 0.5% |

**画布尺寸是启动门禁。** 声明之后，每次启动任务前都会用「目标窗口/设备的画布裁剪
后尺寸」对一遍，不符合就拒绝执行并提示「当前布局画布区域尺寸不符合预定义要求，
请修改布局后重试」。

它拦的是**画面形态错配**——端游全屏选了「桌面布局」、窗口模式选了「桌面全屏」、
设备不是 20:9。这类错配不会报任何错，只会让所有坐标整体偏移，现象是「脚本点了
没反应」，几乎不可能自己定位到布局选错。

随包布局的声明：

| 布局 | 画布 | 画布尺寸 | 允许误差 |
|------|------|---------|---------|
| 安卓布局 | 整张截图 | 20:9 | 0.5% |
| 桌面全屏 | 整张截图 | 16:9 | 0.5% |
| 桌面布局 | 裁掉边框 | 16:9 | 2% |
| 投屏布局 | 裁掉边框 | 不校验 | — |

**误差按画布类型定：整张截图的布局用 0.5%，需要裁边框的放宽到 2%。** 两者都可以在
「编辑」里改。

差别的来源是：画布是**比例**，而窗口边框是**固定像素**（左右各 8px、顶部标题栏
31px、底部 8px）。画布覆盖整张截图时没有边框参与，任何同比例分辨率都精确命中；
而裁边框的布局只有在标定用的那个分辨率上才裁得准，换分辨率就会漂——桌面布局在
2560×1440 下画布算成 2554.7×1427.5，而真实客户区是 2560×1440。

注意**漂的是画布，不是屏幕**：2560×1440 和 1920×1080 都是精确的 16:9，是我们的画布
在非标定分辨率上算偏了，靠边和靠底的区域也会跟着偏几像素到二十几像素。2% 放得下
1280×720 到 4K 这一段，同时仍拦得住形态错配（窗口模式配「桌面全屏」偏约 2.7%）。
投屏布局的边框因模拟器而异，刻意不声明尺寸。

> 在 YAML 里手写 `aspect` 时**必须加引号**（`aspect: "20:9"`）。YAML 会把不加引号的
> `20:9` 当成六十进制数字读成 1209；加载时会直接报错拦住，不会静默生效。

### 区域类型

| 类型 | 说明 |
|------|------|
| text | 文本识别区域（OCR 读取文字） |
| click | 可点击区域（点击操作的目标） |
| 其他 | 由工作流定义的特殊用途区域 |

### 区域属性

| 属性 | 说明 |
|------|------|
| 名称 | 中文显示名 |
| Key | 英文标识符（不可与同场景下其他区域/点/面板重复） |
| 含文本 | 勾选后该区域参与 OCR 识别 |
| 可点击 | 勾选后该区域可作为点击目标 |

### 视图管理

同一页面可能有多个滚动态（如背包的不同页），场景编辑器支持**多视图**：

- 视图用于把同一页面的多个滚动态分屏排布，避免坐标叠在一起
- 入口：场景编辑器内的「视图管理」按钮
- 选定视图时只展示该视图自身的定义，选「全部」才展示所有视图
- **同层视图**与基底视图处于同一个图层，只是滚动或翻页后的另一处取景；它没有入口、
  但仍可声明跳转。取消“同层视图”表示这是独立页面，此时需要声明入口
- 在「视图管理」中设置关联视图时，依次选择分组、场景、视图，再保存关系；
  选择「无关联视图」可清除关联

### 多张截图与子场景

场景和子场景都可以在画布上方切换截图，点击「管理」可以预览、排序、删除截图，
或指定当前展示的截图。多张截图共用同一套坐标定义；切换截图只改变编辑时的
底图，不会为每张截图创建一份独立区域。普通场景可再按视图组织定义，
**子场景没有视图选择器**。

新抓取的场景截图默认以 WebP 保存，减少本地占用和同步体积。若当前视图的文字
或图标识别受压缩影响，可打开截图旁的「管理」，把「当前视图新截图格式」改为
PNG，再点击「刷新截图」重新抓取。该选择只作用于当前布局、场景和视图之后
刷新或追加的截图；已有截图不会批量转换。截图与参考图库分开存储，参考图格式
不受此设置影响。

需要在多张任务卡片里复用相同按钮时，可在「场景管理」中把一个普通场景设为
「可作为引用子场景」，再到父场景的「引用」列表绑定实例。子场景先用「裁剪画布」
框住组件的实际内容，随后在这块裁剪画布里标注区域、坐标和模板。父场景中的
实例可以移动、缩放；子场景内部标注要回到子场景编辑。

给子场景区域截取模板时，先切到符合当前图标状态的截图，再选择「截取模版」
或「部分截取」，查看编辑器中的匹配得分，最后点击**「保存布局」**。
模板记录的宽高来自子场景的裁剪画布；运行时按父场景中各引用实例的尺寸
缩放。若图标周围有黑边、不同状态会反色，应核对裁剪边界与模板内容；
深浅反色可使用「兼容反色图标」。修改截图、裁剪画布或模板后，应在实际
画面上重新测试匹配，不要只凭编辑器里看到的截图判断。

### 跨场景引用

同一块屏幕区域有时会在多个场景里出现（如调律页里嵌入的通用确认按钮），无需重复标注：

- 区域面板和坐标面板都提供「+ 引用区域」/「+ 引用坐标」按钮，从其他一级场景（非子场景）
  中选一个已有的区域或坐标接入当前场景
- 引用行在列表中**整行置灰**，与本场景原生定义一眼区分；「来源」列显示来源场景名称，
  「跳转」列显示该实体在源场景配置的页面跳转
- 引用项**只读**：坐标、名称都跟随源场景实时同步，双击不会弹出编辑框，改坐标要去源场景改
- 选中引用行后点「移除引用」即可解除，不影响源场景的定义

### 尺寸信息栏

编辑器底部显示当前截图尺寸/比例和画布相对截图的坐标尺寸/比例，
方便确认缩放关系。

## 自助排查：装备词条解析失败

装备扫描后出现「状态异常」、装备名后带 **!**，或日志里出现
`词条宫(affix_gong) 无法解析: '处功防御'` 这类行，说明某个字段的 OCR 结果没能解析成
有效词条。**这不是崩溃，而是程序在如实告诉你它读错了**——但到底错在哪一层，只看
日志看不出来。场景编辑器就是用来定位这件事的：它能用**你自己机器上的画面**跑一遍
和工作流完全相同的 OCR，把「区域框没套住文字」「截图本身不对」「个别字被认错」
这三种原因分开。

> 请先做这一节的排查再反馈。绝大多数情况在这里就能看出是分辨率/布局问题还是识别
> 误读，反馈时也能给出开发者真正需要的那两行信息（实际识别结果 + 预期文字）。

### 第一步：准备现场

1. 游戏停在**出问题的那件装备的详情页**，端游窗口模式需窗口完整可见无遮挡；
2. 回主界面先完成「扫描窗口」定位或设备连接——编辑器的截图来自这条连接；
3. 确认主界面顶部的**当前布局**与实际目标一致——端游窗口模式是「桌面布局」，
   全屏是「桌面全屏」，选反了坐标整体偏移且不报错（见
   [1.4 布局适配](01-quick-start.md#14-运行前检查布局适配)）；
4. 按 **F3** 打开场景管理，顶部布局选择要与上一步同一个布局。

### 第二步：找到对应场景与视图

装备详情的字段定义在「培养」分组下：

| 场景 | 用途 | 视图 |
|------|------|------|
| 武器 | 武器详情的词条、基础属性、定音 | 基底 / 冷却 |
| 防具 | 防具详情的词条、基础属性、定音 | 基底 / 冷却 |
| 调律详情 | 调律页内读取的词条 | — |

词条区域按五音命名：**词条宫 / 词条商 / 词条角 / 词条徵 / 词条羽**，日志里的
`affix_gong` 等 Key 与它们一一对应——日志报哪个 Key，就看画布上对应的那个框。

### 第三步：用自己的画面截图

点顶部 **「刷新截图」**（右侧 **+** 是追加一张而不覆盖）。

这一步是整套排查的关键：不点它，你看到的是随包附带的作者机器截图，**区域框当然
是对齐的**，看不出你这台机器上的偏差。截图会按当前布局、场景和视图保存。

### 第四步：看区域框有没有套住文字

放大画布，逐个检查日志报错的那个区域：

- 框要**完整包住**整行词条文字，上下左右留一点余量，不要贴着字边缘切；
- 不要框进**相邻行**的文字，否则两行会被读成一行；
- 区域矩形的范围**就是 OCR 范围**。区域内的落点框（可点击区域）必须是它的子集，
  不要为了点击方便把区域拉大。

如果所有框整体偏移或整体错位，那是分辨率/布局/画布层面的问题，不要逐个去拖——
回到 [1.4 布局适配](01-quick-start.md#14-运行前检查布局适配) 或本章的坐标校准处理。
底部尺寸信息栏可以核对截图尺寸与画布比例是否符合预期。

### 第五步：跑「识别全部字段」

点底部左侧的 **「识别全部字段」**，结果区会按场景定义顺序逐行列出
`区域名: 识别到的文本`，读不到的显示 `(未识别到)`。

两个配套开关值得用上：

| 控件 | 用途 |
|------|------|
| **使用实时图像** | 勾选后直接对设备/窗口的实时画面识别，不落盘。适合反复调整游戏画面后连续验证 |
| **OCR 清洗组** | 选「装备词条」= 与工作流实际一致的口径；选「默认规则（全局）」只跑全局规范化、不叠业务组。两者对比能看出误读是否已被现有规则纠正。注意全局规范化对所有 OCR 都生效，没有「完全不清洗」的选项 |

### 第六步：按结果判读

| 识别结果 | 说明 | 怎么办 |
|----------|------|--------|
| `(未识别到)`，或文字串行、读到相邻行内容 | 区域框没套住文字 | 分辨率/布局/画布问题，见第四步 |
| 读到了文字，但个别字认错（`处功防御` ← `外功防御`） | OCR 误读 | 稳定复现的误读可以靠清洗规则纠正，见下 |
| 选「装备词条」后文字已正确，但工作流仍报解析失败 | 清洗口径与解析器不一致 | 这才可能是程序问题，按 [1.6 反馈](01-quick-start.md#16-遇到问题怎么反馈) 提交 |
| 文字发虚、笔画粘连 | 截图压缩影响识别 | 截图旁「管理」→「当前视图新截图格式」改 **PNG（无损）**→「刷新截图」再试 |

### 关于稳定误读的修正

个别字被固定认错（同一个字每次都错成同一个字）属于可修正的清洗问题：
「工具 → 图像识别 → 清洗规则」里的**装备词条**组就是做这件事的，随包已经收录了
`猜准率 → 精准率`、`经甲 → 胫甲` 这类修正。

你可以在本地补一条替换先跑起来，同时把 **OCR 实际读到的原文** 和 **正确文字**
一并反馈，收进随包规则后所有人都不用再配。只给一句「词条识别失败」是无法据此
加规则的——必须知道它究竟读成了什么。

### 不要做的事

- **不要直接修改识别错的真实装备数据。** 装备指纹由词条内容生成，手改会产生一件
  对不上的数据对象；临时评估请复制为模拟装备再改（见
  [5.2 装备数据如何产生](05.02-equipment-data-acquisition.md)）。
- **不要为了让某一次识别通过而拖大区域框。** 框大了会吃进相邻行，换一件装备就错。
- **不要跳过第三步。** 拿随包截图判断自己机器的问题，结论一定是错的。

## 布局继承机制

布局在界面中使用中文名称展示，内部则使用创建时确定的布局 key
保存目录和引用。新建和另存为时都需填写两者；key 创建后不再变更，
且 key 与布局名称都不允许重复。另存为不会覆盖任何已有布局。

### 画布中间层

场景编辑器在「截图」和「区域」之间引入了**画布（Canvas）**中间层：

```
截图（含边框） → 画布（裁掉边框，只留游戏内容区） → 区域（坐标相对于画布）
```

普通场景使用**布局级别**的画布；引用子场景另外保存自己的裁剪画布。
调整布局画布后，普通场景的区域坐标会自动适配；子场景模板的录制尺寸
仍以它的裁剪画布为准，不能填写父布局的整张画布尺寸。

### 根布局与继承布局

| 类型 | 说明 |
|------|------|
| **根布局** | 拥有完整的场景定义（所有区域的坐标数据） |
| **继承布局** | 场景定义全部复用根布局，仅画布（Canvas）独立 |

继承布局不产生任何场景文件，所有区域数据实时从根布局读取。修改根布局的区域后，所有继承它的布局自动同步。

### 设计用意

这个机制解决的核心问题是：**不同投屏环境的边框不同，但游戏内容区域相同**。

例如：

- 「安卓布局」是根布局，画布覆盖整个窗口（无边框）
- 「投屏布局」继承自「安卓布局」，画布缩小以裁掉投屏窗口的边框

两个布局共享同一套场景区域定义，区别仅在于画布在截图中的位置。当你切换布局时，所有场景的区域会自动跟随画布调整，无需重新校准。

### 何时创建继承布局

- 你的投屏窗口有边框/黑边，需要裁剪画布
- 不同投屏软件的边框大小不同，需要多套画布方案
- 不想重新校准所有场景，只想调整画布范围

> 如果你的屏幕比例与基准不同（非 20:9），仅调整画布不够，还需要新建根布局并重新校准场景区域。见 [1.4 布局适配](01-quick-start.md#14-运行前检查布局适配)。
