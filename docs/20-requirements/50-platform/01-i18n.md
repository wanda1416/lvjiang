# 国际化需求与验收

> 状态：部分实现（2026-11-09，基线 v0.15.11）。

## 目标与范围

面向用户的界面、错误消息和配置显示名走翻译通道。缺失译文显示中文原文，不显示空白；开发者日志和源码文档不要求翻译。

随包 12 种语言（`zh_CN`、`en_US`、`zh_TW`、`ja_JP`、`ko_KR`、`de_DE`、`fr_FR`、`es_ES`、`pt_BR`、`ru_RU`、`th_TH`、`vi_VN`），按来源分三档：

- **权威**：`zh_CN`（原文）、`en_US`（人工全译）；
- **同源生成**：`zh_TW` 由简体经 OpenCC `s2twp` + 区域校订生成；`ja_JP` 的**游戏术语**由中文经 `s2t` + 日本新字体 + 词组修正生成，其余文案仍英文回退；
- **英文回退**：`ko_KR`、`de_DE`、`fr_FR`、`es_ES`、`pt_BR`、`ru_RU`、`th_TH`、`vi_VN` 与 `en_US` 逐字相同——对这些语言，完成度指英文回退覆盖率而非本地化程度。

生成档词表可读但不是官方措辞，质量低于 `en_US`；各档完成度与生成方式见
[多语言词表现状](../../10-game/20-translation/08-i18n-language-status.md)。

## 用户行为

在设置选择语言，重启后生效；用户的语言偏好与模型、游戏截图文字和业务身份分离。游戏 OCR 文本匹配使用游戏原文，不能跟随 UI 翻译改变。

## 验收

默认中文、切换英文后重启、缺失翻译回退和切回中文均符合预期。新增翻译不能覆盖已有不同译法，内容检查应暴露遗漏或冲突。

代码里每句 `tr("字面量")` 都必须在每个随包语言查到译文（硬门槛为 0 缺口），新增文案与词表条目必须同批提交；词表值必须是字符串且不带冒号，见 [国际化架构](../../30-architecture/38-platform/08-i18n.md)。

实现见 [国际化架构](../../30-architecture/38-platform/08-i18n.md)，改造记录见 [过程归档](../../40-development/2026-10/2026-10-09-i18n-adoption.md)。
