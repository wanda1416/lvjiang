# v0.13.0 — 模拟转律、毕业率分析与自动化基础升级

## 律匠 v0.13.0

> **发布状态：预发布草案。目标发布日期待定。** 本文于 2026-09-19 根据
> `master..dev` 整理，以 v0.12.2 正式版为基线。预发布验证完成前，功能、迁移
> 方式、版本号和统计数字仍可能调整；当前源码与 Android 工程尚未切换到 0.13.0。

本版本扩展了模拟转律和统一毕业率分析，同时重构输入 DSL、战斗/移动场景和游戏
配置目录。地图管理、场景多截图、锁定装备保护、批量执行重排以及新的商店工作流也在
本次预发布范围内。

### ⚠️ 不兼容变动与升级指引

#### 1. 最低直接升级基线调整为 v0.12.0

- **现象：** v0.13.0 只承诺从 v0.12.0 及更高版本直接升级时，受支持的持久化
  数据不会因格式变化而丢失。从 v0.11.x 或更早版本直接升级不再提供完整的数据
  无损保证。大部分独立数据库、装备快照和仍沿用当前结构的数据通常可以继续使用，
  但旧版的界面选择、脚本偏好、插件 Session、用户文件布局等可能被忽略。
- **原因：** 项目已删除仅服务于 v0.12.0 以前版本的长期兼容代码，包括旧顶层
  `active_*`、独立 `yysls.json`、`local/workflows.yaml`、扁平 `ui_state`、旧用户
  文件布局与旧锁文件位置。Profile 数据库（`profile.db`）的 schema 仍保留
  v1～v5 逐级升级，不受本项影响。
- **如何调整：** 当前版本低于 v0.12.0 时，请先升级并运行 v0.12.2，正常打开相关
  页面、保存仍需保留的配置并退出程序，再备份整个 `config/session` 后升级到
  v0.13.0。已经使用 v0.12.0～v0.12.2 的用户无需为本项手工迁移。

#### 2. 桌面版最低 Python 版本提升到 3.11

- **现象：** 桌面源码环境现在要求 Python `>=3.11,<3.13`，Python 3.10 不再属于
  支持范围。
- **原因：** Windows 精确计时链路使用 3.11 起提供的高精度 `time.sleep`，鸣金虹
  木桩测伤等时序敏感任务依赖该能力。
- **如何调整：** 源码运行或二次开发请安装 Python 3.11/3.12，并重建虚拟环境。
  Android APK 内部仍由 Chaquopy 使用 Python 3.10，这属于项目自身的打包实现，
  Android 用户无需处理。

#### 3. 燕云游戏配置由单文件拆为七个领域文件

- **现象：** `config/*/yysls/game_config.yaml` 不再参与加载，配置改放在
  `config/*/yysls/game_config/` 下的七个同级文件：

  | 文件 | 顶层配置段 |
  |------|------------|
  | `basic.yaml` | `basic_config` |
  | `seasons.yaml` | `level_configs`、`season_configs` |
  | `affixes.yaml` | `affix_caps`、`affix_categories`、`affix_aliases`、`affix_parts` |
  | `equipment.yaml` | `base_attrs`、`equipment_name_series`、`weapon_types` |
  | `martial_arts.yaml` | `martial_arts` |
  | `schools.yaml` | `schools` |
  | `playstyles.yaml` | `playstyles` |

- **影响：** 如果你在 `config/local/yysls/game_config.yaml` 中保存过自定义赛季、
  等级、词条、流派或玩法，旧单文件不会自动拆分，新版会直接使用新的系统配置。
- **如何调整：** 升级前备份旧文件。启动新版后，优先对照备份通过“游戏设置”重新
  录入并保存需要的自定义内容；也可以按上表把旧文件的顶层段分别迁入对应的 local 文件。不要把
  整份旧 `game_config.yaml` 改名成某一个新文件。
- 开发过程曾使用的 `game_config/levels_and_seasons.yaml` 会在首次加载时自动改名为
  `seasons.yaml`；这项自动改名不适用于 v0.12.2 的单体 `game_config.yaml`。

#### 4. `drag` 和原始鼠标输入语法调整

- 点对拖拽必须显式写 `to`，时长必须显式写 `duration`：

  ```wf
  # 旧写法
  drag (0.2, 0.7) (0.3, 0.5) 0.4

  # 新写法
  drag (0.2, 0.7) to (0.3, 0.5) duration 0.4
  ```

- Arrow 拖拽同样把裸时长改为 `duration`，并新增 `scale`、`exact` 和终点
  `hold`。修饰子句可换序，但每种最多出现一次。
- 原 `mouse left/right/... down|up` 统一并入 `press`：

  ```wf
  press "MOUSE_LEFT" down
  press "MOUSE_LEFT" up
  press "MOUSE_RIGHT" hold 0.2
  ```

- **如何调整：** 自定义 `.wf` 不会自动改写。请搜索 `drag` 的点对/裸时长形式和
  `mouse ... down/up`，按新语法修改后再运行静态检查。系统预置工作流已全部更新。

#### 5. 战斗与移动实体从 `general_control` 拆出

- 战斗实体迁入 `general_combat`，包括 `switch`、`wuxueji`、`qishu`、`xuli`、
  `qingji`、`shanbi`、`bow` 等。
- 移动实体迁入 `general_move`，并统一使用 `move_center`、`move_forward`、
  `move_backward`、`move_left/right` 与 `look_*` 命名。
- **如何调整：** 自定义工作流中类似 `[general_control].[xuli]` 的引用应改成
  `[general_combat].[xuli]`；旧 `origin/forward/backward/turn_*` 应按用途改成
  `general_move` 下的新 key。自定义布局也应在两个新场景中重新标定。

#### 6. 调律规则和基础规则组改为目录驱动

- `tune_config.yaml` 不再用 `tuning_rules` / `base_rules` 登记存在性和顺序。
  规则是否存在由 `yysls/tuning_rules/*.yaml`、`yysls/base_groups/*.yaml` 决定，
  `order` 决定顺序，`disabled` 决定停用。
- 旧的启停声明会在首次加载时自动迁移：未修改的系统规则使用轻量 local 停用桩，
  已有本地影子继续保留正文；随后旧登记段会从 `tune_config.yaml` 移除。
- **如何调整：** 正常通过界面管理的用户无需手工操作，但升级前仍建议备份
  `config/local/yysls`。自行生成配置的工具需要改为读写规则文件本身。

#### 7. 部分界面偏好改换存储位置

- 装备卡片字号、卡片高度和网格列数回到本机 `session.json` 的
  `settings.equip_display`，不再属于可远程分层的游戏规则。
- 战斗属性页的满等级/满承音/满定音/模拟转律开关与黄字显示偏好改存每个用户的
  `loadouts.json`。旧 session 中的战斗属性偏好不会迁移，升级后请按用户重新选择。

#### 8. 材料处理狗粮规则改用统一条件结构

- **现象：** `materials.food_rules` 不再接受 `min_expect`、`min_quality`；规则改用
  `parts`、`max_quality`、`judge_scope`、`judge_rules`、`ratings`、`pct_op` 和
  `pct`。其中 `pct_op` 仅允许 `ge`。旧字段仍存在时配置会明确报错，不会静默套用。
- **原因：** 材料处理现在与扫描处理、调律处理共用部位、品阶、判定语义和判定结果
  口径，并区分“继续调律”和“顺延下一规则”。此前 `continue` 的界面含义是继续调律，
  实际却会继续匹配下一规则，无法可靠表达“不加狗粮直接调律”。
- **如何调整：** 通过“装备调律规则 → 材料处理”重新保存自定义规则；需要在彩狗粮
  不足时尝试金狗粮的规则，把 `on_insufficient` 设为 `next`。`continue` 现在表示
  不添加狗粮并立即继续本轮调律，`skip` 仍表示跳过当前装备。内置默认与激进规则组
  已改为彩狗粮不足后顺延金狗粮。

#### 9. 扫描处理与调律处理不再提供阶段级停用开关

- **现象：** 扫描处理和调律处理规则表现在始终参与决策，界面不再显示“启用处置表”
  或“启用行为表”。自定义基础规则组中残留 `scan.enabled` 或 `tune.enabled` 会被视为
  无效配置；单条规则的 `enabled` 开关不受影响。
- **原因：** 自动调律必须经过这两个处理阶段，阶段级开关只会把完整状态机退化为隐式
  默认行为，已经没有独立业务意义。
- **如何调整：** 删除自定义 `base_groups/*.yaml` 中的 `scan.enabled` 和
  `tune.enabled`。若需要某条规则暂时不参与匹配，可继续在规则行右键停用该条规则；
  空规则表会使用该阶段已有的无命中默认行为。

### ✨ 模拟转律与毕业率分析

- 每个流派新增有序的转律词条库，配置页使用统一的选择/排序对话框；候选范围会随
  可用词条库收窄，避免配置实际不能转入的词条。
- 新增转律建议：对八件装备逐件评估第 2～5 条中的合法转律目标，每件最多改一条，
  在预算内搜索整套毕业率最优方案，并按边际收益给出执行顺序。
- “应用”只给装备保存模拟目标，不改变真实词条、指纹、冷却或锁定状态，也不会代替
  玩家在游戏内执行转律。装备重新扫描时目标保留；真实养成导致词条变化后自动作废。
- 备战方案新增“模拟转律”假设。开启后，战斗属性、毕业率、最优组合与培养分析会
  使用已保存的目标词条计算。
- 最优组合、转律建议、培养建议、词条收益率合并为“毕业率分析”对话框，共享一份
  临时计算假设；关闭即丢弃，不会反写备战方案。各页按需计算并标记过期结果。
- 最优组合结果会直接标出相对当前方案需要更换的部位，新增组合详情和
  “战斗属性 (#N)”预览；取消后台搜索不再显示或缓存半截结果。
- 毕业率计算统一使用同一评分内核和方案上下文。词条的部位合法性、无相穿透折算、
  同名词条累加/取最大值等口径在备战方案、最优组合、培养/转律建议之间保持一致。
- 承音上限改为读取词组等级配置中的实际值，不再在计算时固定按普通上限的 94%
  推算；游戏设置中可直接编辑承音列。

### ✨ 装备保护与管理

- 调律门槛默认只看首词条胚子的潜力；进入调律后再用完整实际词条做首次调律决策。
  原“结束处理”统一为“调律处理”，可在进入调律页前直接跳过或回收。
- 装备扫描会识别游戏内锁定状态，卡片显示紧凑的锁定、冷却和转律目标标记。
- 自动调律默认保护锁定装备：不会回收、重置或误点解锁；本次实际调律过且符合结束
  条件的满词条装备可自动锁定。
- 冷却装备管理器新增用户多选过滤，默认显示全部用户，并显示当前结果数/总数。
- 装备卡片的词条、定音、承音和上限显示收敛为穿戴槽与背包卡片的同一实现；定音值
  统一按百分比展示。
- “创建基础属性”现在只扣除真实穿戴装备，不再误扣满等级、满承音、满定音或模拟
  转律等面板假设，修复开启假设时反推基础属性严重偏低的问题。

### ✨ 输入、场景与工作流

- 输入系统统一“可按压对象”：`press` 可操作键盘键和桌面鼠标按钮，`click hold`
  会遵循布局 `activation_key`，桌面按绑定键、Android 执行触屏长按。
- `drag` 的 Arrow、点对和归一化坐标形式共用同一执行链路，支持缩放向量、关闭
  抖动、到达终点后保持；停止时会尽快释放桌面输入，Android 超时不会重试成双击。
- Android `ESC` 统一映射系统返回；`keyevent` 只发送一次。输入与截图后端能力矩阵
  已文档化，明确 PC 前台/后台、Agent 无障碍、Shizuku 与 ADB 的差异。
- 模板定位改为按已知画布分辨率精确缩放，仅在取整误差导致容不下模板时扩展最多
  2px 搜索余量，修复 1:1 模板被跳过后以低分缩放匹配的问题。
- 脚本录制器可把无移动轨迹的鼠标按下/抬起折叠为 `click` 或 `drag`，写入完成前
  保留录制结果；脚本编辑和录制工作区的模态链与布局也得到修正。
- 新增“购买袅袅之音·绑”工作流：按周配额和长鸣玉余额预检，通过列表与详情双重
  “绑”标识校验后一次买满周库存，避免误买付费版本。
- 购买心法心得工作流会在循环购买前后读取每周剩余库存，并换算、同步本周已购买数量，
  供 Profile 与批量任务使用。
- 系统工作流会集中声明自己依赖的 Profile 数据模型；扫描钱袋、商店购买、江湖号令和
  花蕊织等任务首次运行时会自动补齐缺失定义，不再要求用户预先建立同名 key。
- 不肝商店与心法工作流名称统一去掉“自动”前缀；鸣金虹木桩测伤更新场景引用与
  Android 后退移动手势。

### ✨ 地图与场景编辑

- 新增地图定义和地图管理器，可创建/删除地图、导入底图、标注 POI、绑定 HUD 场景
  与实体，并从截图测试小地图朝向识别参数。
- 随包新增中原地图定义、地图场景分组和基础 HUD 场景；地图文件写入采用校验、备份
  与原子替换，避免编辑中断损坏配置。
- 场景编辑器支持同一“场景 + 视图”保存多张截图，可预览、排序、删除并选择活动
  截图；旧的单张截图文件继续作为第 1 张使用，无需迁移。
- 装备详情场景和布局重新整合，新增通用锁定/解锁模板；场景列表会显示各实体类型
  的数量，便于核对标定完整性。

### ✨ 批量执行与配置体验

- 主页面批量脚本和用户列表支持拖拽调整实际执行顺序，右键可恢复配置组初始顺序或
  随机打乱；批量配置中的列表只负责可见性和初始顺序，二者不再互相覆盖。
- 批量配置窗口切换编辑组不再改变主页面默认执行组；新建、重命名和删除仍会安全
  处理实际不存在的默认组。
- 编辑日常脚本参数时会清理已经不存在的脚本配置，但按完整脚本发现结果判断，不会
  误删专用或当前正在编辑的配置。
