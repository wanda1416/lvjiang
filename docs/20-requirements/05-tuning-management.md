# 调律管理与历史记录需求

## 1. 目标

将右侧“调律进度”升级为“调律管理”，在不干预自动调律决策与操作流程的
前提下，同时提供当前任务进度、全部装备处理结果、历史运行列表和单次历史
详情。

## 2. 功能范围

### 2.1 当前任务

- 完整保留现有调律进度能力。
- 可随时打开当前任务详情，关闭详情不影响工作流。
- 展示所有已开始处理并形成终态的装备，包括调律、回收、调律后回收、
  跳过和重置未执行。
- 装备获得本轮稳定的处理顺序 ID；槽位、结果和搜索筛选只能稳定过滤，
  不得改变处理顺序。

### 2.2 历史记录

- 每次自动调律启动后立即创建运行记录。
- 每件装备处理结束后增量持久化，不能等整轮完成才一次性保存。
- 成功重置是结构化历史的生命周期边界：重置前记录以“已重置”结束，
  重置后的首词条状态作为一件新装备建立下一条记录。实时进度可以保持
  连续展示，但历史详情和匿名统计必须是两次独立调律事件。
- 重置后再次无法继续时，终态必须明确区分“冷却期等待”和
  “次数耗尽转回收”，不得因已经执行过调律轮次而归类成普通“已调律”。
- 历史列表展示开始时间、状态、用户、部位、处理数量、异常数量、总轮次和规则。
- 历史总体统计包括运行次数，以及装备处理、调律、回收、跳过、重置和异常数量。
- 选择一次历史记录后，复用当前任务的详情视图展示历史详情。
- 可删除选中的整次调律任务；删除前必须二次确认，并级联删除任务装备和
  本地上报状态。删除本地历史不代表撤回已经成功上传的匿名数据。
- 历史详情固定按 `sequence_id` 升序，筛选后仍保持该顺序。
- 每次狗粮决策都必须本地记录轮次、选择的狗粮、决策理由、当时库存及
  是否实际执行调律；历史装备详情必须能逐轮查看。因库存策略在准备阶段
  停止的轮次也要保留，但不能计入已完成调律轮数。

### 2.3 识别异常

自动化过程中"这一步没看清楚"必须与"业务上就是这个结果"分开记录，否则事后
无法区分规则生效和 OCR 失灵。

- 识别异常是独立的终态，不能混进普通处理结果。当前只有一种：
  **无法识别重置次数**（`count_unreadable`，见
  [自动调律 §6.5](01-auto-tuning.md#65-重置处理reset-动作的执行)）。
- 异常必须逐件记录，并在装备卡片上与普通重置结果**视觉区分**
  （标红、前缀「异常：」而非「重置结果：」）。
- 历史列表必须能在运行这一层看到异常件数，无需逐条打开详情去找；为零时留空。
- 异常件数按装备行实时聚合，不依赖运行收尾时写入的聚合计数——崩在半路的
  运行恰恰最需要看到异常，而那种运行的聚合计数恒为 0。
- 新增异常态只应扩展 `tuning_history.models.RESET_ANOMALIES`，卡片、列表和
  统计自动跟随。

### 2.4 运行状态

一次运行至少区分：

- `running`
- `completed`
- `interrupted`
- `material_exhausted`
- `failed`

### 2.5 Markdown 报告

- Markdown 继续作为人类可读的调律说明。
- 结构化历史以 SQLite 为唯一持久化真源。
- 不再向 Markdown 尾部写入隐藏的 `TUNING_DATA_JSON`。

## 3. 匿名统计补传

- 本地历史与统计开关无关，关闭统计不能删除用户历史。
- 用户开启统计即授权补传最近 7×24 小时内尚未上报的调律数据。
- 超过窗口仍未上报的数据标记为 `expired`，以后不再上传。
- 每件可上报装备必须记录稳定 `event_id`、尝试时间、尝试次数、事件 Schema
  版本和成功上报时间。
- 已成功上报的数据不得因关闭、重新开启或重置匿名标识而重复上传。
- 本地完整历史不得直接发送；上传必须经过匿名白名单投影和事件 Schema 校验。
- 投影包含未知词条或不合法序列时，整件标记为 `rejected`，不得上传部分轮次。

“网络与隐私”必须明确告知用户：开启后会补传最近 7 天内尚未上报的历史，
关闭期间的调律记录仍保存在本地。

## 4. 非功能要求

- 历史、Markdown 和匿名统计必须来自同一套运行期领域记录。
- 历史保存、统计投影或上报异常不得中断自动调律。
- 数据库使用独立文件、WAL、短连接、busy timeout 和显式迁移版本。
- 数据库 Schema 版本、历史领域模型版本和服务器事件 Schema 版本分别演进。
- 新增统计来源应通过数据源接口注册，通用统计模块不能依赖燕云领域类型。

## 5. 验收标准

- 新一轮开始时旧的实时列表被清空，但旧记录仍可在历史页面打开。
- 一轮中断后，已形成终态的装备可从历史详情查看。
- 历史筛选不会改变装备 ID 顺序。
- 关闭统计产生数据、7 天内重新开启后可补传；8 天前数据不会进入发送批次。
- 网络成功后数据库写入 `reported_at`；失败后保留为未上报并可重试。
- Markdown 中不再出现 `TUNING_DATA_JSON` 标记。
