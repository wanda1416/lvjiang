# 备战方案管理
> 状态：已实现（2026-10-06，基线 v0.13.11）。

## 范围与状态归属

备战方案按用户分别保存在 `{user}.loadouts.json`。主页面的方案下拉框只负责
切换当前用户的活动方案；旁边保留「新建」「管理」。流派、主武学、副武学、玩法
在主页面只读展示。管理窗口左侧选择编辑用户，右侧按持久化顺序展示该用户的方案；
切换用户、选中方案或排序都不得改变主页面的活动用户和该用户的活动方案。

## 管理操作

- 右侧提供新建、删除、上移、下移和方案列表；双击方案整体编辑名称、流派、
  主武学、副武学、玩法。编辑以方案 ID 定位，单次原子保存，不覆盖装备池。
- 选择明确流派时，两门武学由流派填入并锁定；切换到「自定义」才可手动修改。
  「自定义」只是编辑模式，不是第二份流派数据。保存后仍由两门武学的无序组合
  解析流派。玩法按武学无序组合过滤，明确流派时再限于该流派。
- 管理窗口新建方案不自动切换活动方案；主页面直接新建仍切换到新方案。
  删除至少保留一个方案；删除活动方案时由相邻剩余方案接替，公共装备池不删除。
- `plan_order` 保存方案 ID 顺序。旧数据没有该字段时按现有 `plans` 顺序展示，
  普通读取不写盘；上移、下移仅修改顺序，不改变方案 ID 或活动方案。

## 装备扫描时间与清理

- 真实装备分别记录内容更新时间与扫描时间。扫描时间只在游戏画面实际识别到该装备时
  刷新；锁定、冷却、定音切换和手工养成等本地编辑不能刷新它。模拟装备不记录、也不受
  扫描时间筛选影响。
- 历史装备没有独立扫描时间时，以更新时间作为扫描时间；两者都没有时，在任意“超过
  N 小时/天”条件下视为过期。这样无需数据迁移，重新扫描后自然写入独立扫描时间。
- 装备页可按超过 1 小时、1/3/7/14/30 天未扫描到进行筛选，再使用现有批量删除确认。
  超过 1 小时适合在完成一次全部装备扫描后检查未再见到的旧装备。扫描时
  已识别但因词条条件未写入的已有装备仍须刷新扫描时间。删除落盘前重新核验最新扫描
  时间、方案引用和锁定状态，避免确认期间重新扫到的装备被旧结果删除。
- 未扫描到不等于已确认回收，因此扫描任务不得在结束时自动删除旧记录；删除始终由用户
  明确触发，并默认保留备战引用和已锁定装备。

## 全部方案扫描

- 游戏内「方案管理」是独立场景 `training_plan`：`base` 为方案列表与详情，`fill`
  为智能填充弹窗，`confirm` 为切换确认弹窗。培养场景 `training_main` 仅保留进入
  方案管理的入口；方案页返回后再经培养页、菜单回到主页。
- 扫描任务先进入游戏的「主页 → 菜单 → 培养 → 功法 → 方案管理」，按游戏列表顺序
  扫描当前可见的 `plan_list` 网格。格内文本去空白后长度大于零即为已有方案；空格
  跳过。第一版仅处理网格行数内的方案，不滚动、不去重，超出可见网格的方案暂不支持。
  确认有方案后，直接在当前页面选择第一套；扫描并返回主页后，才为下一套重新进入。
  每套均按发现的名称定位、读取方案标题和两张武学卡片，点击「使用方案」。
  缺装备弹窗点击「智能填充」，未保存搭配弹窗点击「切换」。单套方案识别或切换
  失败但仍在可操作的方案列表时记录原因，直接选择下一套；若弹窗未处理完或列表
  状态不确定则停止，避免误点。扫描成功的方案返回主页读取装备后才重新进入列表。
  全部方案均未完成装备扫描时，任务最终返回失败，不把空结果记为成功。
  不根据本地方案清单猜测游戏里有哪些方案。
- 游戏方案只有名称和两门武学。本地有同名方案时，无序核验武学后直接使用，不改动
  其玩法；同名但武学不符或重名时跳过写入。没有同名方案时创建一套本地方案：流派由
  武学无序组合解析，玩法只在匹配这组武学的候选中选择；方案名称包含某个玩法名称时
  使用该玩法，否则使用系统配置声明顺序中的第一个候选。没有候选玩法时允许创建，
  但本轮只扫描装备，不静默写入基础属性。创建和切换游戏方案均不改变主页面活动方案。
- 成功切换后才把本次 WF 的装备写入目标绑定到同名本地方案；此绑定不改变主页面
  活动方案。每次扫描八件装备均成功后，继续读取角色面板。基础属性按现有口径
  由面板减去**该方案实际扫描的装备**及该方案弓玦反推，保存为流派下的
  `用户名_备战方案名`，并将该基础属性名称关联回该方案。同一玩法的不同方案分别
  保存各自的基础属性，不要求反推数值一致。未配置玩法、装备未扫全或基础外功区间
  识别不可靠时禁止静默覆盖。
- 弓玦类型与生效等级都属于备战方案。扫描仅在详情中唯一识别出套装类型及
  `二件套[生效等级:N]` 后原子写入，无法确定等级时跳过本方案基础属性反推。
  方案页面允许输入 113 等中间等级；未设置时沿用赛季默认等级。
- 原「扫描基础属性」任务默认继续弹出确认表单；显式选择静默写入时，按主页面
  当前活动方案保存，并返回主页。全部方案扫描始终走静默路径，逐方案回到主页
  后再切换下一套。
- 「扫描备战装备」「扫描基础属性」两个直接运行入口均可传入方案名称及主副武学；
  留空时仅由入口读取当前活动方案作为参数。真实扫描分别封装为
  `scan_equipped_plan(name, main_art, sub_art)` 与
  `scan_role_base_attr_for_plan(name, main_art, sub_art, silent_write, scroll_count)`。
  `import` 只注册这两个子过程，不执行被导入任务的顶层指令。全部方案扫描把目标
  方案名称和武学直接传入子过程；写入按名称定位本地方案，不切换主页面活动方案。
- 全部方案扫描可选择跳过任务开始时本地已经存在的同名方案；判断在切换游戏方案前
  完成，默认不跳过。单套方案的装备或属性识别/写入失败应拒绝本套写入并安全回主页，
  再扫描下一套；只有无法确认已回到主页等导航不安全情况才停止整批。

## 装备套装

游戏里八件装备分成两组，套装身份彼此独立：

- **攻具**：主武器、副武器、环、佩。两件同名套装即提供一条输出属性；
- **防具**：冠胄、胸甲、胫甲、腕甲。当前只记录和展示，不计入毕业率；
- 左右名称只是流派推荐搭配，例如玉斗推荐搭配易相，但它们不是一个套装，持久化
  分别使用 `yudou`、`yixiang` 等稳定 key；飞隼使用 `feisun`；
- `2A + 2B` 的攻具混搭同时获得 A、B 两项两件套属性；四件套额外效果暂不计算。

### 生效数值

两件套数值由**全部攻具**的精确平均等级决定。先在词组配置已经登记的等级中寻找
相邻两档：

- 平均等级恰好等于某档，取该档完整普通词条上限；
- 平均等级严格位于两档之间，取两档上限的算术中点；
- 不先把平均等级取整。例如 `105、105、105、115` 的平均是 `107.5`，位于 105 与
  110 之间，结果为 `105 档 + (110 档 - 105 档) / 2`；
- `110、110、110、115` 同理取 110 与 115 两档的中点；四件均为 115 才取完整
  115 档数值。

套装配置只登记属性名，不复制词条数值；数值、单位和战斗属性映射继续以词组配置为
唯一来源。计算假设先投影装备等级，再用投影后的四件等级计算套装属性。

### 装备状态与方案状态

游戏允许低成本自由切换全部同侧套装，不维护“历史已解锁套装”列表：

- 装备记录自身原始/默认套装；该字段不参与装备指纹；
- 备战方案按槽位记录当前套装，左右八槽互不绑定；
- 方案装备槽优先展示方案套装，缺失时回退装备原始套装；背包卡片只展示原始套装；
- 首次扫描入库可以同时建立装备原始套装和方案套装；已存在装备的备战方案扫描只更新
  方案套装，不覆盖装备原始套装；非备战方案扫描可以更新原始套装；
- 从装备槽打开属性编辑时修改方案套装，从背包打开时修改装备原始套装。候选为该侧全部
  已登记套装，不检查解锁历史。属性页以“装备套装：名称”展示当前值，通过同行语义的
  “切换套装”按钮选择新套装，不把持久化字段直接暴露成编辑框。

切换备战方案只对内存副本叠加该方案的套装选择并刷新装备槽卡片，不改装备池、不更新
时间戳。换装或卸下时必须清除旧槽位留下的方案套装选择。

## 定音属性互换

装备属性窗口在“普通定音”和“止戈定音”两行分别提供“互换定音”按钮，按钮层级与
“切换套装”一致。普通定音入口加载当前用户公共装备池中所有**同部位**且具有普通定音
的其他装备；武器不区分主副槽或剑、枪等具体武器种类，统一属于“武器”，环、佩、冠胄、
胸甲、胫甲、腕甲则各自独立。候选包含真实装备和模拟装备，并明确展示来源。

用户选择一件候选后，仓储在一次原子写入中互换两件装备完整的 `dingyin` 数据槽。
装备指纹、`dingyin_type`、止戈定音槽以及各备战方案按槽位保存的定音类别均不得改变；
因此任何方案继续引用原装备，并按原类别自然展示互换后的具体普通定音。写入前必须重新
核验两件装备仍然存在、部位相同且都有普通定音，避免对话框打开期间的数据变化造成错换。

当前配置没有止戈定音具体类型，止戈定音行仍展示同名入口，但必须置灰并说明原因；仓储
同样拒绝止戈互换，不能把固定的“止戈定音”占位内容当作可交换的具体类型。

### OCR 与旧数据边界

套装名称从 `[equip_detail].[equip_detail]` 完整文字中按配置白名单提取。左右候选由装备
部位决定；只保存名称，不保存画面上的 `1/4`、`4/4`、生效等级或加成数值。无法唯一
识别时保留旧值，不能丢弃整件装备。

旧数据没有套装信息时不迁移、不猜测。只有四个攻具槽位都能解析出有效套装时才计算
任意套装加成；否则视为旧基础属性已经包含套装数值，不再额外累计。用户重新扫描完整
备战方案及基础属性后自然切换到新口径。防具是否完整不影响攻具计算。

### 统一计算边界

套装属于组合级装备贡献，必须进入公共装备属性聚合：基础属性反推从角色面板扣除套装
贡献，战斗属性、毕业率、智能调律和假设视图再统一加回。最优组合的向量内环必须按每个
组合另外加入套装向量。

最优组合不把每件候选当前套装作为搜索维度：计算设置在弓玦套装之前提供一个攻具
“装备套装”单选项，调用方按流派推荐套装给出默认值，用户可以临时覆盖。搜索时四件
攻具候选统一投影为该套装，结果预览和应用同样携带该选择；应用组合时写入方案的四个
左侧槽位，不覆盖装备原始套装。备战方案静态评分不增加这项假设，直接按方案已经保存的
逐槽套装计算。
