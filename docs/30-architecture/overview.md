# 律匠主流程开放文档

本文档记录当前 GUI 主流程与状态规则。后续新增 OCR、坐标校准、批量筛选、精调工作流时，应先更新这里，再让代码状态与文档保持一致。

## 当前范围

当前版本只覆盖启动阶段的主流程：

- 扫描可见窗口
- 选择目标投屏窗口
- 定位目标窗口并绘制边框
- F9 / 运行按钮开始执行
- F10 / 运行按钮停止执行

装备扫描、OCR 识别、规则决策和自动点击仍是后续阶段功能。

## 状态定义

| 状态 | 含义 | 关键数据 |
| --- | --- | --- |
| 未定位 | 没有可用于执行任务的目标窗口 | `_target_window is None` |
| 已扫描待定位 | 已刷新窗口列表，但用户还没有确认目标窗口 | `_scanned_windows` 有候选，`_target_window is None` |
| 已定位 | 用户已从当前扫描结果中定位目标窗口 | `_target_window` 保存窗口信息，边框为红色 |
| 运行中 | 任务已启动 | `_running is True`，边框为绿色 |

## 主流程

1. 启动程序。
   - 初始状态为“未定位”。
   - 不允许直接开始执行。

2. 点击“扫描窗口”。
   - 仅在非运行中允许。
   - 每次扫描都会刷新候选窗口列表。
   - 如果之前已经定位过窗口，旧定位必须立刻失效。
   - 旧边框必须隐藏，`_target_window` 必须清空。

3. 在窗口列表中选择一个候选窗口。
   - 只启用“定位”按钮。
   - 此时仍然不能开始执行，因为尚未确认定位。

4. 点击“定位”。
   - 将所选窗口写入 `_target_window`。
   - 用 Win32 透明置顶边框标记目标窗口。
   - 边框颜色为红色，表示“已定位但未运行”。

5. 点击“开始执行”或按 F9。
   - “开始执行”和“停止”在界面上是同一个运行按钮。
   - 非运行状态下，运行按钮显示“开始执行 (F9)”。
   - 如果 `_target_window is None`，必须阻止启动，并通过运行日志和状态栏提示用户先扫描并定位窗口。
   - 未定位提示不使用弹窗，避免打断操作流。
   - 如果已经定位，则进入运行中状态。
   - 边框改为绿色。

6. 点击运行按钮或按 F10 停止。
   - 运行状态下，运行按钮显示“停止 (F10)”。
   - 退出运行中状态。
   - 保留当前定位窗口，允许用户再次开始执行。
   - 边框改回红色。

7. 停止后再次点击“扫描窗口”。
   - 旧定位失效。
   - 回到“已扫描待定位”或“未定位”状态。
   - 用户必须重新选择并定位窗口后才能开始执行。

## 状态转移规则

```text
启动
  -> 未定位

未定位
  --扫描窗口成功--> 已扫描待定位
  --F9/开始执行--> 阻止并提示

已扫描待定位
  --选择候选窗口--> 已扫描待定位
  --点击定位--> 已定位
  --F9/开始执行--> 阻止并提示
  --重新扫描窗口--> 已扫描待定位 / 未定位

已定位
  --F9/开始执行--> 运行中
  --重新扫描窗口--> 已扫描待定位 / 未定位，旧定位失效

运行中
  --F10/停止--> 已定位
  --扫描窗口--> 阻止并提示先停止任务
```

## UI 反馈约定

| 场景 | 日志 | 状态栏 | 边框 |
| --- | --- | --- | --- |
| 重新扫描导致旧定位失效 | `[状态] 重新扫描窗口，旧定位已失效` | 正在扫描 / 等待重新定位 | 隐藏 |
| 扫描成功 | 找到窗口数量，提示选择目标窗口 | 已扫描窗口，等待定位 | 隐藏 |
| 定位成功 | 输出窗口标题、位置、大小、DPI | 已定位信息 | 红色 |
| 未定位时点击运行按钮或 F9 | 提示先扫描并定位窗口，不弹窗 | 未定位窗口 | 无 |
| 开始执行 | 输出流派和模式，按钮切换为停止 | 执行中 | 绿色 |
| 停止执行 | 输出停止，按钮切换为开始执行 | 已停止 | 红色 |

## 后续开放问题

- 是否需要在目标窗口关闭、最小化或尺寸变化时自动判定定位失效。
- 是否需要在运行中周期性刷新目标窗口矩形，让边框跟随窗口移动。
- 是否需要将状态定义抽成显式枚举，避免后续工作流变复杂后状态分散。
