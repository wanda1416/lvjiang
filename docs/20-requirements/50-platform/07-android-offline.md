# Android 离线任务执行

> 状态：部分实现（2026-10-06，基线 v0.13.12）。第一阶段已实现，真机运行管线已验收；游戏业务逐项验收尚未完成，尚未正式发布。

## 第一阶段边界

PC「移动设备」提供离线任务控制页：一键同步现有脚本、配置、布局、模板、用户数据和
一致性 Profile DB 快照，手机选择执行用户/任务和启动、暂停、继续、结束。
手机任务参数设置采用独立全屏列表/详情页，边界见 [任务参数设置](08-android-task-settings.md)。
同步是单向覆盖，不回写 PC；覆盖前提示手机离线结果将被替换。运行或暂停中拒绝同步。
PC 同步区仅选择布局，始终下发全部用户资料、全部任务配置和完整 DB；只保留该布局
与必要的继承依赖。同步初始用户取 PC 活动用户，不受远程执行区的临时选择影响。
远程执行区从手机读取用户/任务候选，启动时一次性绑定所选用户；浏览或刷新候选不改变
PC 或手机活动用户。仅手机选择用户或明确远程启动会改变手机活动用户。

PC 向手机下发配置属于 Lv1 用户能力。未授权时保留同步按钮但禁用并说明激活路径；
操作入口、后台打包前及传输入口均校验 Lv1。刷新状态、环境检查、暂停/结束和手机
已有配置的离线执行不增加授权限制；不把 PC 绑定激活码下发给手机。

APK 首页采用顶部应用栏，首屏突出悬浮图标启停，下面仅展示最近同步与只读执行用户/
布局及必要的权限提示。右上角菜单进入任务设置、权限设置、高级功能、自检与诊断；二级页面支持
返回首页，不把自检、复制报告或高级授权堆在首页。页面切换不启动任务、不更改配置；
既有 ADB 自检入口与报告回读保留。
悬浮主面板使用紧凑宽高，顺序为顶部启动/安全控制、“用户”、“任务”、下一行
“选择任务”、状态与
INFO 及以上日志、底部固定“收起”。任务全集仅在二级选择面板滚动，选择后返回
主面板，不自动启动；保留任务选择。第四行并排选择用户/任务，用户仅从已同步的有效
资料中选择，手机活动用户持久化但不回写 PC，下次同步覆盖。仅切换执行资料，不自动
切换游戏角色；运行、暂停和结束中禁止切换。运行控制左侧停止、右侧暂停/继续，等宽。
日志按序号增量追加，悬浮窗仅保留最近 100 行，
更多日志通过 PC 设备状态读取（最近 200 条记录）。向上浏览时暂停跟随，点击
“回到最新”恢复跟随；警告、错误使用不同颜色。启动成功自动收起，失败保留面板。
悬浮面板空闲时选任务并启动，运行时暂停/结束，暂停时继续/结束。收起不改变执行状态。
同步连接不隐藏悬浮球；PC 代理注入控制与本地执行互斥。断开 PC 不停止本地任务。
外部直接 ADB 输入不受 APK 管控，不能与手机任务并行执行。

手机任务入口包含作者明确开放的专用任务（目前为自动调律），不改变 PC 日常列表，
不公开其他内部专用任务；共享的显式启停、排序和改名偏好仍生效。自动调律启动时
冻结执行用户的独立调律配置，不读取旧共享配置。手机可选择下发的规则、玩法和部位，
不编写规则定义；修改不回写电脑，下一次同步覆盖。

## 数据与执行边界

- APK 仅携带 Python 执行代码、OCR 模型和原生依赖，不携带业务配置。脚本、场景、布局、
  参照图及用户数据统一由 PC 下发；首次同步前可查看权限/代理状态，但不能运行任务。
  APK 升级不覆盖手机已同步的配置，不再以 versionCode 作为配置解压标记。
- 同步不包含 Git 元数据、诊断归档、输出日志或锁文件，不同步 Python 源码或桌面原生库。
- 同步包完整校验后才替换配置，失败保留原配置；应用后清除旧配置/引擎缓存。
- 本地执行绑定启动时的用户、布局、任务参数与 Session，复用公共引擎及 Profile 管线。
- 无障碍主通道无需 PC。需要 Shizuku 的应用启停能力必须在执行前提示或明确失败。
- 人工异常暂停在手机可见，绝不因缺少 Qt 回退为无提示继续；第一阶段未支持的输入交互
  必须明确失败。任务结束、失败或服务被杀不能显示为仍在正常运行。
- 不修改正式版本号、versionCode、content_version，不启用发布标签或默认 Beta 通道。

## Android OCR 内存与观测边界

### 原生 OCR 优化

手机工作流、场景区域、清洗组、装备解析及 Profile 写入仍使用公共 Python 能力。
设备端 OCR 后端改为 C++ 完成检测、方向分类、文字识别和后处理，只跨语言返回
文字、置信度及四角坐标。继续使用同一套模型，不引入第二套业务配置或自动回退。
第一阶段保持 BGR 图像输入及 from last 契约，不迁移整个 DSL，也不改 PC OCR 后端。
原生内存与图像必须按请求释放，模型会话可复用；任务终态释放截图引用。截图回调
交付/超时后不再持有像素，稳定检测遇到尺寸变化重新建立基准。
手机资源预算从 `ocr.yaml` 的 `recognition.device_ocr` 读取：默认 2 个推理线程、
最终检测输入最多 2,000,000 像素；区域拼图按高度和像素面积分批，PC 默认参数不变。
裁剪、分类和识别逐条处理，检测输入/输出在进入文字识别前释放，不保留最大输入池。
真实任务与同图识别对比通过前，不把构建成功描述为内存优化已全面验收。

本轮正式签名真机验证：运行环境和实际 OCR 推理通过，3 次 2800×1260 游戏截图
识别通过，Java 堆采样约 28～38 MiB，识别后 RSS 约 313～346 MiB，进程峰值约
574 MiB。随后江湖号令进入原生识别并在缺少菜单页时按原有流程暂停，游戏仍存活；
该进程累计峰值约 624 MiB，不能称为完整任务通过，也不能保证所有场景不会低内存。
全量 Python 回归 3304 项通过；逐字段同图对比、调律完整业务及长时间运行尚待复验。

真实游戏任务暴露了低内存杀游戏和 OCR 分配失败；小图自检通过不能代表游戏场景可用。
优化必须对齐 PC 的 CPU arena 关闭策略，减少 Java 输出副本，复用单会话输入缓冲，并在
配置重载时明确关闭旧 OCR 会话。Android 识别/方向分类使用单条批次，PC 默认行为不变。
内存耗尽必须终止本次任务，不得作为普通“没识别到文字”继续点击或反复重试。

记录模型创建/关闭、每次推理的输入输出形状/字节数/耗时和原生/Java 内存，以及任务
启动/终态与配置重载。日志有固定轮换上限，位于手机私有 data/diagnostics 目录，不随
配置同步覆盖；只读 ADB 回读继续限制 shell/root/本应用身份。不记录截图或 OCR 原文。
截图失败原因（服务、权限、节流、回调超时、转换异常）同时进入任务日志和有界
诊断日志。装备详情扫描有限重试，成功后整轮字段复用同一新帧；连续失败立即
停止调律，不复用上一件装备的帧，也不继续执行锁定、回收或调律操作。
必须用正式包名、保留现有数据，在真实截图连续推理和游戏并行条件下测量，不再仅以
hello/import 或小图推理作为内存验收。上述优化状态随实测结果更新。

## 验收

必须验证实际 APK 的插件加载、引擎装配、OCR 初始化和同步后任务执行；只有入口 import
成功或 APK 构建成功不算验收。用隔离测试配置完成启动、暂停、继续、结束与断开 PC 后
执行结束。模拟器不代替游戏真机验收：设备限制与未验证游戏任务必须如实记录。

### 本轮实测

- 真机正式签名 release APK：完整依赖、Profile 管线、游戏插件、工作流引擎、任务发现
  和实际 OCR 推理通过；正式应用保留数据覆盖升级，未同步合成用户数据。
- 独立应用数据目录的同源 APK：配置/DB 同步、共享参数与用户覆盖、DB 初始值和增量写入
  通过；任务暂停/继续、暂停后结束、DSL 人工暂停通过。
- 全部 PC 连接断开后仍完成任务；暂停中拒绝再次启动、同步和代理输入。
- 悬浮面板实际点击启动、继续、结束通过；任务列表滚动，启动按钮保持可见。
- 软件模拟器实际 OCR 推理也通过；不能以这些合成任务结果代替游戏任务实测。

### 内存修复复验

正式签名、正式包名保留现有数据覆盖安装；实际 APK 已检查不包含 assets/config。
在游戏运行时累计连续识别真实截图通过，原生已分配内存约 53～64 MiB，采样 RSS 为
约 245～327 MiB（全屏推理瞬时 RSS 峰值仍可接近 780 MiB，不能把稳态当峰值）。
游戏进程保持存活，未再出现本轮原生堆长期占用 3 GiB 的情况；自检后日志确认 det/cls/
rec 会话依次关闭，活跃会话计数归零。上述仅为本轮画面和次数范围，不代表全部游戏
任务或无限时长均已验收。

此前触发内存问题的每日自动签到也在正式应用中实跑约 36 秒后正常结束，游戏保持
存活，未出现 OCR 分配失败。任务终态原生已分配约 75 MiB、RSS 约 289 MiB；当次
未发现可领取按钮，不把流程结束描述成首次领奖验收。
