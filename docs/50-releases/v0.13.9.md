本轮主线是**批量的状态边界**：原来「批量配置」窗口和主页面批量页都在直接改同一个
扁平对象，于是主页面的一次临时勾选、拖拽、轮数调整全都写回配置组，而决定可见性的
调度单元反倒长在主页面——配置窗口里会出现一个灰着、勾着、在本窗口里找不到任何
理由的勾选框。现在拆成「配置组定义 / 本次运行草稿 / 执行快照」三层，入口与层一一
对应。

另外两件事：**无人值守批量**（没人看守时撞上弹窗不再卡死整批），以及**账号列表按
到边判定翻动**（账号一多就「翻几下说找不到」的那个问题）。

**用过批量功能的用户请先看不兼容变动第 1 条**：本次勾选、执行顺序、轮数不再保存在
`batch.json` 里。**改过批量配置的用户请看第 2 条**：几个控件换了位置。

## ⚠️ 不兼容变动与升级指引

### 1. 批量的「本次执行选择」不再保存在 `batch.json`

- **现象：** 升级后首次打开批量页，任务与用户的勾选按配置组的「默认执行」列重建，
  上一次运行时的临时勾选、拖拽顺序和轮数不会带过来。此后这些选择按配置组记在本机
  的会话状态里，切换配置组会各自载入自己的选择。
- **原因：** 旧版把主页面的临时选择写回配置组，同一个字段既是「上次运行勾了哪些」
  又是「下次打开的初始值」，于是「恢复默认」说不清该恢复到哪；任务页的拖拽顺序落盘
  而用户页的不落盘，同一个窗口里两种语义。现在定义层只回答「这个配置组是什么」，
  本次执行的选择属于页面状态。`batch.json` 随之升到 version 2，配置组改用稳定 ID
  索引（重命名不再影响任何关联）。
- **如何调整：** 配置组本身（可见任务、可见用户、顺序、生命周期工作流及其参数）
  **全部保留**，无需重建。旧的 `selected_*` 被读成新的「默认执行」勾选，所以首次
  打开看到的就是你上次保存的那一组；只需确认一次勾选和顺序即可开始。想固定某些
  任务默认不跑，到「批量配置」把它的「默认执行」列取消勾选。

### 2. 批量配置窗口重新分区，几个控件换了位置

- **现象：**
  - 「调度单元」和「指定排序」从主页面「参数」页移到了**批量配置**窗口；
  - 生命周期工作流的参数也从主页面移到了批量配置窗口，紧跟它所属的工作流；
  - 任务与用户列表各多了一列：**可见** / **默认执行**；
  - 五个工作流槽位的标签从「批次准备 wf」改成「批次准备工作流」等；
  - 主页面「参数」页现在只读展示调度单元、指定排序和五个工作流，并新增
    「无人值守」勾选项。
- **原因：** 调度单元决定主页面候选列表的内容、生命周期契约和条目准备工作流的
  合法性，是配置组定义级的决定，不是「本次启动」的选择。它留在主页面时，依赖它的
  「单个执行单元时跳过生命周期」勾选框在配置窗口里就成了一个没有理由的灰色控件。
  工作流在一个窗口选、参数却要去另一个窗口填，也是同一个问题。
- **如何调整：** 不需要操作，配置值全部保留。改调度单元、排序键或生命周期参数请到
  「工具 → 批量配置」。

### 3. 「最大滚动次数」改名为「单轮最大滚动次数」，默认 8 → 50

- **现象：** 批量参数里该项的标签变了，默认值从 8 改为 50，上限从 20 提到 50。
  已经手动设过值的配置保持原值不变。
- **原因：** 它原来是「预期要翻几次」，账号一多默认 8 次就悄悄不够，表现成「翻了
  几下说找不到账号」。现在到底/到顶由列表自己是否还在动来判定，这个数字退化为单轮
  的保险上限，正常情况下远早于它结束。
- **如何调整：** 不需要操作。保持原值（哪怕是 8）仍然有效，只是会在翻到第 8 步时
  收手；想让它完整翻到底，把值调大即可。

## ✨ 新增功能

### 无人值守批量

长时间无人看守时，可以在主页面批量「参数」页勾选**无人值守**。此时任务弹出的
**暂停**或**确认**框不再等人：当前任务按失败记录、**不重试**，随后执行配置组的
**异常恢复工作流**把游戏收回登录主页，再继续下一个任务。自动关闭的通知照旧显示并
写入告警面板，不会中断执行。只有确实撞上弹窗才会触发恢复——任务因识别失败之类的
原因报错时画面通常还可用，不会顺手重启客户端。

**必须先配置「异常恢复工作流」**，否则勾选项不可用：缺了它，撞上弹窗之后没人把游戏
收回初始页，后面的任务只会在错误页面上接连失败。

随包的 `batch/recover_to_login.wf` 分两个阶段：

| 情形 | 行为 |
|---|---|
| 当前用户的任务已全部跑完 | 只回到登录主页，等调度器切换下一个用户 |
| 当前用户还有未执行的任务 | 回到登录主页后，再点「当前角色」重新登录到游戏主页 |

收口按代价从低到高：已在登录主页就什么都不做、在启动页点一次返回、两处都不在才
重启客户端。重新登录必然遇到「角色在线」提示，恢复流程会点确定把角色顶下线——这与
正常流程里点取消改走「跳过」的处置相反，无人值守下没有「稍后再来」这个选项。

需要人工介入才能完成的批量（例如「输入兑换码」要人在游戏里粘贴）不要勾选无人值守。

### 账号列表按到边判定翻动，失败后回顶再查一轮

切换账号时，账号列表的翻动不再依赖预设次数：**到底/到顶由列表自己是否还在动来
判定**。一轮翻到底没找到就记一次失败、回到顶部再完整翻一轮。

这修的是一个隐蔽的现场：进入账号列表时它停在哪里是未知的，账号多的时候常常停在
中间，而只向下翻**永远看不到上面的账号**。

### 场景画布 Ctrl 多选与整组平移

战斗、移动这类定义里几个区域和坐标之间的相对位置必须严格相等，而原来只能一个个挪
——吸附只能把单个实体贴到别人的边上，表达不了「一组实体相对位置保持不变地整体
平移」，逐个挪必然在小数位上散掉，散掉之后也没有任何地方会报错。

- `Ctrl` + 空白处拖拽框选，`Ctrl` + 单击实体加入/移出选区；之后**直接拖拽**任一
  成员即整组平移，不需要一直按着 `Ctrl`。单击选区外的实体或空白处、按 `Esc` 取消。
- 可混选**区域、坐标、网格**三类。跨场景引用外框与方向箭头不参与：前者的内部实体
  跟随外框整体变换，后者跟随两端的坐标点，进组会被位移两次。
- 撞到画布边界时**整组一起停下**，不会一部分贴边、另一部分继续走而把队形拉变形。
- 整组平移期间不吸附——成员互相吸附会当场破坏组内相对位置。因此 `Shift` 在整组
  平移时没有作用；代价是整组无法对齐到别的实体，需要时先单独挪一个成员对齐。
- 选中数量与类型显示在底部状态栏（画布多选在右侧列表里没有对应高亮）。多选状态下
  `Delete` 不删除，只提示先取消多选。

顺带把一直存在但从未写进文档的 **`Shift` 取消吸附**补进了用户手册：拖动或缩放
区域、网格、引用外框，以及移动坐标点时按住 `Shift`，吸附与参考线立即关闭。

## 🔧 修复

- **未加载对应插件时，一条看不懂的 Profile 定义会让整个 Profile 不可用。** Profile
  的周期可以由插件注册，核心单独运行时算不出它的周期边界——旧版在加载阶段直接判定
  整个 `profile.yaml` 无效，于是毕业率、配额、总览列、排序键全部一起瘫掉，而问题
  只在一条定义上。现在这类定义被**忽略**（不进任何列表，也不参与后台周期结算），
  文件里**原样保留**。
- **定义编辑器保存会静默删掉看不懂的定义。** 编辑器从自己的草稿重建配置后保存，
  旧版会把它看不见的那些定义、以及插件自带的整段配置一起写没了；定义上的陌生字段
  同样会在保存时消失。现在保存时一字不改地带回，包括周期、字段和在文件中的位置。
  编辑器里新造一个核心不认识的周期仍然会被拒绝保存。
- 场景编辑器「坐标」「方向」「引用」三个 Tab 的删除按钮在没有选中任何行时仍是亮着
  的红色，点下去只会无声无息或弹一个「请先选择」。现在和「区域」「网格」一致：没有
  选中项就禁用。
- 「升序/降序」与主页面「日志级别」两个下拉框弹出后文字被截断（`WARNING` 这类长项
  显示不全），现在弹出列表按最长项放宽，关着的宽度不变。
- **九剑 / 走地玉 自动保留单体奇术增的绑定丢了 8 个版本。** 0.10.0 把「绑定开关」从
  玩法定义搬到调律规则时（要求是换归属：玩法不该决定怎么调律），连随包的两条绑定
  数据一起清空了，并用测试把「没有任何规则声明绑定」固化成契约——搬迁只做了一半。
  现在随包规则重新声明：通用会意 → 九剑、玉玉大王 → 走地玉。
  - **依据**：这两个流派的竞速毕业表把单体奇术增算进了基线（鸣金·影
    `single_qs_bonus` 110 级 0.2678 / 115 级 0.1338，牵丝·玉 0.2678 / 0.2677），
    而全奇术基线全为零。标准构筑本来就带这条词条，不绑等于按一个到不了的目标判垃圾。
  - **为什么不能靠全局开关代替**：`keep_danti` 是全局的，勾上会连
    `qishu_requirement: 不需要` 的玩法（无名、飞天玉）一起影响。「只给某个玩法保留」
    只能靠玩法级绑定表达。
  - **你需要做什么**：如果你在「调律配置 → 规则管理 → 绑定开关」列里自己补过这两条
    绑定，可以保留（重复声明不冲突），也可以删掉改用随包默认。其他玩法的判定不变。

## ⚠️ 已知限制

- **批量配置窗口的两列编辑器、三级选择与生命周期参数面板只有自动化覆盖，尚未在
  Windows 上实机点过。** 自动化断言的是结构与对齐机制（同一个表单、标签列左对齐、
  弹出列表宽度），字体与 DPI 不同时的实际观感需要实机确认。
- **无人值守的恢复流程未经实机验证。** 阶段二（点「当前角色」→ 顶下线 →
  登录落地主页）只有用例覆盖；真机上「角色在线」提示的出现时机与文案需要确认——
  判定依据是文案包含「在线」，不含该字样会漏判。
- 时间线在真机上的双路并发效果仍未纳入门禁，与 0.13.8 相同。
- 后台截图仍是实验性能力，很多脚本暂时无法在该模式下跑通，该模式下的功能不可用
  问题暂不受理。
- `uv.lock` 中记录的项目版本自 0.13.5 起未同步；本轮依赖未变化，不影响构建。
