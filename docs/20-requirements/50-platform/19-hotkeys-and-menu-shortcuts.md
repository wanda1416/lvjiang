# 键位分区：菜单快捷键与全局热键

> 状态：已实现（2026-11-17，待随下一版本发布）。

## 1. 问题

键位原先只有"全局热键（F7~F12，可带修饰）+ 少量写死的菜单键（F2/F3/F4/F5/F6）"两块，
没有任何归属约束。后果：

- 「最小化 / 恢复」默认 `Alt+F8`，而 F8 本身空着；用户想改成裸 `F8` 得靠手工编辑配置，
  设置页只给一个合成长字符串的下拉；
- 菜单键写死在 `menu_ops` 与插件菜单里，无法改绑，也没人检查它们会不会和全局热键
  抢同一个裸键；
- 系统热键（`RegisterHotKey`）先于窗口拿到按键，一旦菜单误占 F8~F12，那项菜单就
  永远"按了没反应"，事后极难定位。

## 2. 键位分区

| 区段 | 归属 | 机制 |
|---|---|---|
| `F1–F4` / `Alt+F1–F4` | 通用菜单 | 窗口内 `QAction` |
| `F5–F7` / `Alt+F5–F7` | 插件菜单 | 窗口内 `QAction` |
| `F8–F12` + `无/Alt/Ctrl/Shift` | 系统级全局热键 | `RegisterHotKey` |
| `Alt+字母` | 通用 / 工具 / 插件菜单共用 | 窗口内 `QAction`，跨来源查重 |

`Alt+A`（截图）、`Alt+F4`（关窗）、`Alt+Tab/Esc/Space/Enter/PrintScreen` 与
`Win+*` 一律禁止绑定。字母取英文首字母：拼音会撞车（"参数""配置"都是 P）。

## 4. 数据归属与校验

- 通用 / 工具菜单键位：`session.json` 的 `settings.menu_shortcuts`，`{稳定 action id: 键位}`，
  只存用户改过的项（默认值不落盘，"（不绑定）"显式落 `""`）。
- 插件菜单键位：插件自己的配置（燕云写 `basic_config.hotkeys`），core 不认识插件菜单有几项。
- 校验集中在 `core/config/menu_shortcuts.py`：`normalize_menu_shortcut` 负责写法与区间，
  `validate_menu_shortcuts` 查同来源重复，`cross_source_conflicts` 查跨来源撞键；
  设置页保存前跑一次，菜单构建期再按同一规则报错。
- 全局热键（`HotkeyConfig`）主键收窄到 `F8~F12`，`normalize_hotkey` 对越界值按动作
  回退默认；五个动作仍不允许重复，重复时整组回退。

## 5. 运行时

- 五个全局热键**全部**走 Windows 的系统热键（`RegisterHotKey`），pynput 只作非 Windows
  兜底。原因：允许修饰键之后，pynput 的"按下集合恰好等于目标集合"判定会被系统菜单
  模式吞掉 Alt 的 release，表现为第一次能触发、之后永久无响应。
- 系统热键注册失败时整组退回 pynput，并在日志里指出是哪一条被占用。
- 窗口内兜底（`keyPressEvent`）只在全局通道不可用时接管，且按 `event.modifiers()`
  比对——否则 `Ctrl+F9` 这类配置在降级路径永远不触发。
- 菜单快捷键改绑后直接写回已存在的 `QAction`，不需要重启。

## 6. 不做的部分

- 「最小化 / 恢复」默认仍是 `Alt+F8`（带修饰键，不与游戏/输入法的裸 F 键抢），
  它落在全局热键区间内；菜单键位被限制在 `F1–F7` 与 `Alt+字母`，不会碰到它。
- **不迁移旧键位**：`Alt+F8` 收窄后依然是合法值，老配置原样保留；想换成裸 `F8`
  或其他组合，在「热键设置」里改一次即可。
- **不让用户改"是否显示键位"**：只读实例沿用既有策略，不在界面暴露键位。
