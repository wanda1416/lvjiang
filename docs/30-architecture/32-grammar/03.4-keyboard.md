## 一、press — 模拟按键

模拟键盘按键。支持四种模式：完整按键、长按、按下、释放。

**语法**：

```
press "KEY"                # 完整按键（down + up）
press "KEY" hold <秒数>    # 按住指定时长后释放
press "KEY" down           # 按下保持（不释放）
press "KEY" up             # 释放此前按下的键
```

**示例**：

```
press "M"                  # 按 M 键（完整按键）
press "escape"             # 按 ESC（别名自动标准化）
press "W" hold 2.0         # 按住 W 键 2 秒
press "SHIFT" down         # 按住 SHIFT
press "C"                  # 按 C（SHIFT 仍按住）
press "SHIFT" up           # 释放 SHIFT
press "F5"                 # 按 F5 刷新
press "ENTER"              # 按回车
```

**说明**：

- 键名不区分大小写：`"m"` / `"M"` / `"Shift"` / `"SHIFT"` 均可
- 支持别名：`"Escape"` → `"ESC"`、`"Control"` → `"CTRL"` 等
- 键名必须是已知键（字母 A-Z、数字 0-9、功能键 F1-F12、特殊键、修饰键、方向键），否则报错
- `press "KEY"` 是 `down + up` 的原子操作，中间无等待
- `press "KEY" hold N` 的 `N` 必须 > 0，受停止信号（F10）中断保护

## 二、四种模式

| 模式 | 语法 | 时序 | 状态变化 |
|------|------|------|---------|
| **PRESS** | `press "K"` | down → up | 无残留 |
| **HOLD** | `press "K" hold N` | down → sleep(N) → up | 无残留 |
| **DOWN** | `press "K" down` | down | 键留在 registry |
| **UP** | `press "K" up` | up | 键从 registry 移除 |

**PRESS vs HOLD**：
- `press "W"` — 瞬间完成，适合单次按键（确认、选择）
- `press "W" hold 0.5` — 持续按住，适合需要长按的场景（蓄力、持续移动）

**DOWN/UP 的用途**：
- 仅在构造组合键时需要（如 CTRL+C）
- 普通按键永远用 PRESS 模式，不要手动 down + up

## 三、后缀等待子句

press 支持 `before` / `after` / `around` 后缀等待子句，与 click/drag 语法一致：

```
press "KEY" before wait <延迟>    # 按键前等待
press "KEY" after wait <延迟>     # 按键后等待
press "KEY" around wait <延迟>    # 按键前后各等待一次（同一参数）
press "KEY" before wait X after wait Y  # 组合使用
```

**示例**：

```
press "A" after wait 0.5          # 按 A 后等待 0.5 秒
press "ENTER" before wait @step_interval  # 等待命名延迟后按回车
press "W" hold 2.0 around wait 0.3  # 等 0.3 秒 → 按住 W 2 秒 → 再等 0.3 秒
press "SHIFT" down before wait 0.2  # 等 0.2 秒后按住 SHIFT
```

**说明**：

- 参数形式与 `wait` 指令完全相同：固定秒数、命名延迟 `@name`、变量 `$var`、随机范围 `(min, max)`
- 也支持 `wait stable` 后缀：`press "A" after wait stable 5`
- `around` 是语法糖，等价于同时指定 `before` 和 `after`（同一参数）
- press 没有默认延迟，因此不需要像 click/drag 那样用显式 wait_clause 抑制默认延迟

## 四、KeyStateRegistry 状态管理

press 指令通过 **KeyStateRegistry** 跟踪「按下未释放」的键集合。它是 DSL 层面唯一的按键状态来源，Backend 不管状态。

**设计原则**：

| 原则 | 说明 |
|------|------|
| 状态唯一来源 | DSL 的 KeyStateRegistry，不是 Backend |
| 严格校验 | 重复 down 或未 down 就 up → 报错（DSL 作者错误） |
| 幂等清理 | `release_all` 单键失败不阻塞其他键，最终清空集合 |
| 懒初始化 | 首次 press 时按当前 Backend 创建 |

**生命周期**：

```
execute() 开始
  └─ try:
       └─ press "SHIFT" down    → registry: {SHIFT}
       └─ press "CTRL" down     → registry: {SHIFT, CTRL}
       └─ ... 执行工作流 ...
  └─ finally:
       └─ release_all()         → backend.key_up("SHIFT") + backend.key_up("CTRL")
                                  registry: {}
```

所有退出路径（正常结束 / 异常 / 取消 / 超时）都经过 `finally`，确保按键不会「粘住」。

## 五、组合键

通过 down/up 显式时序构造任意组合键：

```
# CTRL+C
press "CTRL" down
press "C"
press "CTRL" up

# CTRL+SHIFT+S
press "CTRL" down
press "SHIFT" down
press "S"
press "SHIFT" up
press "CTRL" up

# ALT+TAB（切换窗口）
press "ALT" down
press "TAB"
press "ALT" up
```

**注意事项**：

- 修饰键（SHIFT/CTRL/ALT）用 `down`/`up` 包裹
- 实际按键用普通 `press`（自带 down + up）
- 释放顺序建议与按下相反（先放内层修饰键），但不强制
- 忘记 `up` 不会报错（`release_all` 兆底），但显式释放是好习惯

## 六、键名与别名

键名不区分大小写，引擎先标准化再查 VK 映射表。

### 字母与数字

| 键名 | VK | 键名 | VK |
|------|-----|------|-----|
| `A` ~ `Z` | 0x41 ~ 0x5A | `0` ~ `9` | 0x30 ~ 0x39 |

### 功能键

| 键名 | VK |
|------|-----|
| `F1` ~ `F12` | 0x70 ~ 0x8B |

### 特殊键

| 键名 | VK | 说明 |
|------|-----|------|
| `ESC` | 0x1B | 退格/取消 |
| `ENTER` | 0x0D | 回车/确认 |

| `TAB` | 0x09 | Tab |
| `BACKSPACE` | 0x08 | 退格 |
| `DELETE` | 0x2E | 删除 |

| `PAGEUP` | 0x21 | 上翻页 |
| `PAGEDOWN` | 0x22 | 下翻页 |

## 七、后端实现

press 通过 `InputBackend` 抽象层注入，三个桌面/移动后端各自实现：

| 后端 | 机制 | 说明 |
|------|------|------|
| **SendInput** | Win32 `SendInput` + 扫描码模式 | 全局注入，需窗口在前台 |
| **PostMessage** | Win32 `PostMessageW` (WM_KEYDOWN/UP) | 后台注入，不移动光标 |
| **ADB** | `adb shell input keyevent` | Android 设备，不区分 down/up |

**扫描码模式**：SendInput 使用 `KEYEVENTF_SCANCODE`（wVk=0, 用扫描码），确保 DirectInput 游戏响应。扫描码通过 `MapVirtualKeyW(vk, 0)` 计算。

**扩展键标志**：方向键、修饰键（L/R SHIFT/CTRL/ALT）、HOME/END/PGUP/PGDN/INS/DEL 等需要 `KEYEVENTF_EXTENDEDKEY` 标志，引擎自动处理。

**ADB 特殊行为**：Android 的 `input keyevent` 不区分 down/up，发一次即完成。`key_down` 和 `key_up` 行为相同。

## 八、失败语义

**配置错误 → 抛错终止**：

| 情况 | 报错时机 |
|------|---------|
| 键名不在 VK 映射表中 | `press` 执行时 |
| 重复 `down` 同一键 | `press "K" down` 时 |
| `up` 未 `down` 的键 | `press "K" up` 时 |
| `hold` 时长 ≤ 0 | `press "K" hold N` 时 |

抛出的错误可以被 `try` / `catch` 捕获。

**与 click/drag 的区别**：press 不依赖场景布局配置，没有静态检查阶段（不涉及 scene/region/panel 引用）。所有校验在运行时执行。
