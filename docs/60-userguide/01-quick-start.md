# 1. 快速开始

## 1.1 环境要求

律匠支持直接操作游戏 PC 端窗口，也支持通过 **直连手机/手机投屏** 或 **Android 模拟器** 运行游戏。不同运行环境需要选择对应的目标环境和布局。

- **游戏运行环境**：安装《燕云十六声》，并满足以下任一连接方式：
  - **窗口模式**：捕捉 PC 上任意可截屏的窗口，包括手机投屏窗口、Android 模拟器窗口、游戏窗口化模式。
  - **ADB 模式**：手机开启开发者选项中的「USB 调试」（或无线调试），或模拟器开启 ADB 调试

> **⚠️ Windows 端游用户必读**
>
> 预置「端游」连接方案要求以管理员身份启动律匠；未满足要求时，
> 任务会在启动前被拒绝，并说明原因。自定义连接方案可以自行决定是否
> 勾选「管理员权限」。如果游戏进程以管理员身份运行，Windows 会阻止
> 低权限的律匠向它发送输入；此时应提升律匠的权限。
>
> 方法：右键 `lvjiang.exe`（或快捷方式）→ 「以管理员身份运行」。

电脑端要求因安装方式不同而有差异，见下方 1.2。

## 1.2 安装与启动

律匠提供两种安装方式，按需选择：

| | 发行版 | 源码版 |
|---|---|---|
| **适用系统** | **仅 Windows 64 位** | Windows / macOS / Linux |
| **需要 Python** | 不需要（已内置） | 需要 Python 3.10+ |
| **获取方式** | GitHub Releases 下载 | git clone 仓库 |
| **更新方式** | 安装版直接覆盖安装；免安装版解压到新目录 | git pull + pip install |

> macOS / Linux 桌面目前无发行版，只能使用源码版运行。

### 发行版（推荐 Windows 用户）

1. 前往 [GitHub Releases](https://github.com/wanda1416/lvjiang/releases) 下载最新版本
2. 两种格式任选其一：
   - **`lvjiang-vX.X.X-win64-setup.exe`** — 安装程序，双击安装后从开始菜单或桌面启动
   - **`lvjiang-vX.X.X-win64.zip`** — 免安装版，解压后运行 `lvjiang.exe`
3. 启动后进入主窗口，默认已加载燕云调律插件

> **升级到新版本时**：安装程序会自动清理旧版文件，直接装到原目录即可。
> **免安装版请解压到新目录**，再把旧目录里的 `config/local`（你自己的配置）和
> `config/session`（账号、装备库、历史记录）拷到新目录——就地覆盖解压不会删除旧版
> 遗留的文件，可能出现重复的脚本或已经下架的场景。

> **使用预置「端游」方案的 Windows 用户**：请右键 `lvjiang.exe` → 「以管理员身份运行」。详见 [1.1 环境要求](#11-环境要求)。

> 使用安装程序时建议选择「仅为当前用户安装」，不建议「为所有用户安装」，否则可能被安全软件拦截。

### 源码版（macOS / Linux / 需要最新功能的用户）

```bash
# 1. 克隆仓库
git clone git@github.com:wanda1416/lvjiang.git
cd lvjiang

# 2. 创建虚拟环境并安装依赖
python -m venv .venv

# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

pip install -e ".[dev]"

# 3. 启动（加载燕云调律插件）
python -m lvjiang -reg yysls

# 或使用快捷脚本（自动处理 PYTHONPATH）
# Windows:
.\dev.bat
# macOS / Linux:
./dev.sh
```

启动后进入主窗口「律匠 - 燕云十六声装备调律工具」。

### 日志与崩溃反馈

- 当天日志写入 `logs/lvjiang_日期.log`；最近 7 天内更早的日期在下次启动时归入
  `logs/logs/年月/lvjiang_日期.log`，再早的日志会删除
- 崩溃现场写入 `logs/crashes/`
- 反馈问题时可附带以上文件帮助定位

## 1.3 连接设备

两种模式二选一，点哪个扫描按钮就切到哪个模式。

> **目标环境交给方案就行**
>
> 「环境」指游戏运行的目标环境（非本机系统），决定用哪种输入方式：
> - **桌面（desktop）**：PC 游戏窗口，使用窗口投屏 + 鼠标点击
> - **安卓（android）**：手机或模拟器，使用 ADB 截图 + 触摸输入
>
> **PC 端使用模拟器（如 MuMu、雷电）必须选择「安卓」**，否则导航流程会因输入方式不匹配而失败——
> 这也是最容易踩的坑。选中[步骤 3](#步骤-3选择连接方案) 里的预置方案后环境会自动定好，
> 不必手动操心；只有切到 `- 自定义 -` 时才需要自己选。

### 窗口模式

捕捉 PC 上任意可截屏的窗口，适用于手机投屏窗口、Android 模拟器、游戏窗口化模式等。

> **预置「端游」方案在 Windows 上要求管理员权限**。自定义方案是否要求提升权限，
> 取决于方案设置和目标游戏进程的实际权限，详见 [连接方案](02-main-interface.md#24-连接方案)。

> **⚠️ 游戏窗口必须完整可见**
>
> 使用端游或窗口模式时，游戏运行的窗口必须在屏幕区域内**完整可见**（或至少核心操作区域可见），且**不能被任何其他窗口遮挡**。
>
> 原因：窗口模式截图时，如果被其他窗口（如浏览器、聊天工具、任务栏等）遮挡，截图只会捕获到最顶层的窗口内容，导致游戏画面被截断或完全截到其他应用，进而引发识别失败、点击偏移等问题。
>
> 建议：运行律匠时，将游戏窗口置于显眼位置，避免被其他应用覆盖。可以使用 Windows 的「分屏」功能（Win + 方向键）将游戏和律匠并排显示。

1. 确认目标窗口可见（投屏窗口、模拟器窗口或游戏窗口）。
2. 主窗口点 **「扫描窗口」**，下拉列出所有可见窗口（格式「标题 (宽x高)」）。
3. 选中目标窗口，点 **「定位」**。成功后窗口信息变绿字，目标窗口四周显示
   红色边框 1 秒后自动消失。需要持续显示时，勾选 **「红框标定」**；该勾选
   仅在本次运行期间有效，下次启动默认不勾选。
4. **「后台模式」** 复选框：勾选 = 后台输入（点击不移动你的鼠标光标，
   窗口可被遮挡）；取消 = 前台输入（会真实移动光标）。

> **提示**：在「通用 → 配置管理 → 基础配置 → 窗口标题」填入窗口标题
> 关键字（如「投屏」「模拟器」）后，以后点「扫描窗口」会自动匹配并定位，无需手选。

### ADB 模式（USB / 无线 / 模拟器）

#### 手机 USB 连接

1. 手机开启「开发者选项 → USB 调试」，用数据线连接电脑，手机上允许调试授权。
2. 主窗口点 **「扫描设备」**，下拉列出已授权设备（格式「serial (型号)」）。
3. 选中设备，点 **「连接」**。成功后显示绿字「已连接: 序列号 | 分辨率 | 截图方式」。
4. **「流式截图」** 复选框：勾选 = scrcpy 视频流截图（流畅、预览为实时画面）；
   取消 = screencap 静态截图。持久默认值在「配置管理 → 基础配置 →
   ADB 截图方式」设置。scrcpy 不可用时会自动回退 screencap 并在日志提示。

> 想拔掉数据线改无线连接：运行 `python scripts/adb_wireless.py`，脚本会把
> USB 设备切到无线模式并自动连接（要求手机与电脑在同一局域网）。连好后
> 回到主窗口重新「扫描设备」即可。纯 USB 使用不需要这个脚本。

#### 模拟器 ADB 连接

如果使用 Android 模拟器，建议开启模拟器的 ADB 调试并用 ADB 模式连接，而非窗口模式。ADB 模式截图更快、输入更稳定。

**步骤：**

1. **开启模拟器 ADB 调试**：在模拟器设置中找到「开发者选项」或「ADB 调试」并启用。不同模拟器入口不同：
   - 雷电模拟器：设置 → 其他设置 → 开启 ADB 调试
   - 夜神模拟器：设置 → 开发者选项 → USB 调试
   - MuMu 模拟器：设置 → 其他 → 开启 ADB 调试

2. **用 ADB 连接模拟器**：模拟器通常监听本地端口，用以下命令连接：
   ```bash
   # 项目自带 adb，位于 data/adb/adb.exe
   .\data\adb\adb.exe connect 127.0.0.1:端口号
   ```
   常见模拟器默认端口：
   | 模拟器 | 端口 |
   |---------|------|
   | 雷电 | 5555 |
   | 夜神 | 62001 |
   | MuMu | 7555 |
   | 逍遥 | 21503 |

   连接成功会显示 `connected to 127.0.0.1:端口号`。

3. **在律匠中连接**：回到主窗口，点「扫描设备」，选中模拟器设备，点「连接」即可。

> 如果不确定端口，可以用 `.\data\adb\adb.exe devices` 查看已连接设备列表。

### 验证连接

定位/连接成功后会自动截取一帧画面。点 **「显示预览」** 展开预览区，能看到
游戏画面即连接正常。看到「截屏失败」则检查窗口是否被关闭 / 设备是否掉线。

## 1.4 运行前检查：布局适配

律匠通过预置的场景布局坐标来定位游戏界面元素。**运行前请确认布局是否适配你的屏幕**，否则可能出现点击偏移、识别失败等问题。

> 正常情况下你不需要手动选布局——[步骤 3](#步骤-3选择连接方案) 里选好方案，
> 布局就已经跟着定了。这一节是给「选了方案但点击还是偏」的情况准备的。

### 预置布局

| 布局 | 说明 | 画布尺寸要求 | 对应方案 |
|------|------|-------------|---------|
| **安卓布局** | 根布局，完美适配 20:9 屏幕比，画布覆盖整个窗口区域 | 20:9 | 手游 |
| **投屏布局** | 继承自安卓布局，画布已预裁上下边框，适用于模拟器等有边框的场景 | 不校验 | 手游投屏 |
| **桌面布局** | 根布局，用于 PC 端游窗口模式（1920×1080），画布只取窗口内的游戏画面，已裁掉标题栏与不可见边框 | 16:9 | 端游 |
| **桌面全屏** | 继承自桌面布局，画布覆盖整张截图——全屏没有标题栏和边框，无需裁 | 16:9 | 端游全屏 |

如果你的设备屏幕比为 20:9（高/宽 ≈ 2.22）且无投屏边框，使用「安卓布局」即可**无缝适配**，无需额外调整。

> **画布尺寸要求是启动门禁。** 上表声明了尺寸的布局，启动任务前会校验目标窗口/设备
> 的画布尺寸；对不上会拒绝执行并提示「当前布局画布区域尺寸不符合预定义要求，请修改
> 布局后重试」。它拦的正是「全屏用了窗口布局」这类不会报错、只会让坐标整体偏移的
> 错配。误差按画布类型定：画布覆盖整张截图的布局（安卓布局、桌面全屏）用 0.5%，
> 需要裁掉窗口边框的（桌面布局）放宽到 2%，两者都可在场景管理「编辑」里改。

> **模拟器用户**：如果目标模拟器没有 20:9 的画面比例预设，可采用自定义设置 **2000:900**（等效 20:9）。

如果投屏窗口有边框/黑边（如模拟器），改用「**手游投屏**」方案——它绑的就是「投屏布局」。该布局的画布已预裁了常见模拟器的上下边框，所有场景区域会自动跟随画布偏移，无需逐个场景重新校准。

### 需要调整的情况

以下情况预置布局无法直接适配，需要手动调整：

- 设备宽高比不是 20:9（如 16:9、19.5:9 等）
- 投屏软件的边框尺寸与预裁值不匹配

### 调整方法

**方法一：在场景编辑器中调整画布**

适用于仅画布偏移的情况（如投屏有边框）：

1. 打开场景管理器 (F3)
2. 顶部「当前布局」切换到「投屏布局」
3. 点击顶部按钮栏的「编辑画布」按钮，进入画布编辑模式
4. 画布显示为黄色虚线边框，带 8 个缩放手柄
5. 拖拽手柄或内部拖动，将画布框对齐到游戏内容区域（排除边框/黑边）
6. 底部信息栏实时显示画布坐标比例，方便确认
7. 调整后切回区域编辑模式，所有场景区域自动跟随画布适配

**方法二：另存为新布局方案**

如果宽高比差异较大，仅调画布不够，需要新建根布局并重新校准场景区域：

1. 顶部「当前布局」下拉框，将「安卓布局」**另存为**新方案；
   填写唯一的布局 key（如 `my_android`）和布局名称（如「我的布局」）
2. 打开场景管理器 (F3)，切换到新布局
3. 对每个关键场景截图，通过**截图对比**调整区域绑定关系
4. 重点检查以下场景：背包装备页、调律页、江湖号令页、菜单页

> 调好之后，把图库/环境/布局三项配齐，用「从当前组合新建」存成你自己的
> 方案，以后一次选中即可——预置方案不能改，但你可以在它旁边建自己的。

> 详见 [3.2 场景管理](03.02-scene-management.md) 中的布局继承机制与坐标校准说明。

## 1.5 第一次运行：从零到跑通

以下步骤帮你完成第一次完整运行。以「扫描备战装备」工作流为例——它无需额外配置，开箱即用。

### 步骤 1：启动程序

- 发行版：双击 `lvjiang.exe`
- 源码版：运行 `.\dev.bat`（Windows）或 `./dev.sh`（macOS/Linux）

启动后看到主窗口「律匠 - 燕云十六声装备调律工具」。

### 步骤 2：连接设备

1. 手机打开游戏，停在**游戏首页**
2. 主窗口点「扫描窗口」或「扫描设备」
3. 选中目标窗口/设备，点「定位」或「连接」
4. 看到绿字 + 预览区出现游戏画面 = 连接成功

### 步骤 3：选择连接方案

主窗口顶部「方案」下拉框，**按你实际怎么跑游戏选一个**：

| 你的情况 | 选这个方案 |
|---------|-----------|
| 手机或模拟器，用「扫描设备」走 ADB 连接 | **手游** |
| PC 端游**窗口模式**，用「扫描窗口」定位 | **端游** |
| PC 端游**全屏**，用「扫描窗口」定位 | **端游全屏** |
| 手机投屏窗口 / 模拟器窗口，用「扫描窗口」截图 | **手游投屏** |

选完就可以直接跑了——不需要再动图库、环境、布局这三个下拉框。

<details>
<summary>这三个预置方案分别绑定了什么（点开查看）</summary>

| 方案 | 图库 | 环境 | 布局 | 连接方式 |
|------|------|------|------|---------|
| 手游 | 手游 | 安卓 | 安卓布局 | ADB 模式 |
| 端游 | 端游 | 桌面 | 桌面布局 | 窗口模式 |
| 端游全屏 | 端游 | 桌面 | 桌面全屏 | 窗口模式 |
| 手游投屏 | 手游 | 安卓 | 投屏布局 | 窗口模式 |

图库存放参考图供 OCR 和图像匹配使用，参考图与游戏画面风格一致时识别更准确；
环境决定输入方式（安卓走触摸、桌面走鼠标）；布局决定各界面元素的坐标。

三者必须配套，**选错任意一项都会导致识别失败或点击整体偏移，而且不会报错**
——方案存在的意义就是把这三项绑成一个整体，让你不可能选错。

「手游」和「手游投屏」的区别只在布局：模拟器/投屏窗口通常有上下黑边，
「投屏布局」已预裁了这部分边框；走 ADB 直接取原始画面则不需要裁。

「端游」和「端游全屏」同理，区别也只在布局：窗口模式截到的图含标题栏和窗口边框，
「桌面布局」把它们裁掉；全屏没有这些东西，「桌面全屏」直接用整张截图。选错会让所有
坐标整体偏几十像素。

</details>

选中方案后，图库、环境、布局三个下拉框会自动填好并**变灰锁定**（点一下会提示
怎么解开）。连接方式和方案不匹配时——比如选了「端游」却去点「扫描设备」——
「开始执行」会变灰显示「方案不支持」，直接把你拦下来。

> **预置方案是随安装包下发的，不能改也不能删。**
> 如果你的设备需要不同的组合（比如自定义布局），把「方案」下拉框切回
> `- 自定义 -`，这时三个下拉框会解锁，手动选好后到
> 「通用 → 配置管理 → 方案设置」点「从当前组合新建」存成你自己的方案，
> 它会和预置方案并列显示在下拉框里。详见
> [2.4 连接方案](02-main-interface.md#24-连接方案)。

如果点击位置明显偏移，说明预置布局不适配你的屏幕，参考
[1.4 布局适配](#14-运行前检查布局适配) 调整。

### 步骤 4：选择工作流

1. 左侧切到「日常」Tab
2. 脚本下拉框选择「扫描备战装备」
3. 该脚本没有参数面板，无需额外设置

### 步骤 5：执行

1. 点绿色「开始执行 (F9)」
2. 观察运行日志：应看到依次扫描各槽位（主武器、副武器、戒指…）的输出
3. 完成后按钮恢复为「开始执行」

> **💡 最小化到系统托盘**
>
> 如果不想让主窗口占用屏幕空间，可以点击窗口最小化按钮将律匠最小化到系统托盘（通知区域）。最小化后，托盘图标会随工作流运行状态变化。
>
> **操作方式**：最小化后，可以通过全局热键控制律匠：
> - **F9**：开始/停止执行当前工作流
> - **其他热键**：详见 [主界面与用户管理](02-main-interface.md) 中的热键说明
>
> 这样可以在不遮挡游戏窗口的情况下运行律匠，特别适合使用端游或窗口模式的用户。

### 步骤 6：确认结果

- 运行日志中应显示各槽位的装备词条信息
- 右侧切到「备战方案」Tab，装备面板中可看到各槽位数据已更新

> 恭喜！你已经跑通了第一个工作流。接下来可以探索调律 Tab（F6 配置规则）或其他日常脚本。

### 关于「扫描钱袋货币」

你可能注意到日常脚本里还有一个「扫描钱袋货币」。首次运行时，工作流会自动声明所需的
Profile 数据模型，无需提前手工建立 key：

**自动声明的 key（共 5 个）：**

| Key | 模型类型 | 说明 |
|-----|---------|------|
| `tongbao` | 库存 | 通宝（万） |
| `bugan` | 库存 | 么玉（个） |
| `baoqian` | 库存 | 宝钱（万） |
| `changmingyu` | 库存 | 长鸣玉（个） |
| `bugan_of_week` | 配额 | 么玉本周消耗 |

工作流只创建缺失定义，不会覆盖用户已经存在的同类型定义及其自定义字段。如果同名 key
已经被定义成另一种模型类型，工作流会明确报错并停止，避免把数据写入错误模型。仍可在
「用户总览」页底部的「数据模型」对话框中查看或调整这些定义。

## 1.6 遇到问题怎么反馈

**先自查，再提问；提问一次性把信息给全。** 下面这套流程不是门槛，是因为律匠做的是
「截图 → 识别 → 点击」，同一个现象（识别失败、点错位置）可能来自分辨率、布局、
窗口遮挡、游戏版本更新里的任何一环。缺了其中任何一项信息，开发者只能靠猜，
一来一回问三轮还定位不了。

> 只发一句「不能用」「识别失败」外加一张截掉上下文的截图，然后等着被追问，
> 这样的反馈**会被直接忽略**。完整规范见[8. 问题反馈规范](08-feedback-and-issues.md)。

### 第一步：自己先排查这几项

多数问题在这一步就能解决，顺序照着来：

| 检查 | 怎么做 |
|------|--------|
| **方案与画面形态**对得上吗 | 端游窗口模式选「端游」，全屏选「端游全屏」。两者的画布口径不同（窗口模式的截图含标题栏与边框，全屏没有），选反了所有坐标整体偏几十像素，而且不报错 |
| 游戏窗口**完整可见、无遮挡**吗 | 见 [1.3 窗口模式](#窗口模式)。被浏览器、聊天工具、任务栏盖住时截到的是那些窗口的内容 |
| **布局选对**了吗 | 顶部「当前布局」要与实际目标一致，见 [1.4 布局适配](#14-运行前检查布局适配)。布局配错时坐标整体偏移且**不报错** |
| **分辨率**对得上吗 | 端游窗口 1920×1080、手机按实际分辨率；换了手机或改过分辨率要重新做屏幕标定 |
| **截图正常**吗 | 看主界面预览区：画面是否完整、是否是游戏本身 |
| **OCR 读到了什么** | 「工具 → 图像识别」对着出问题的区域跑一次，看实际识别结果与预期差在哪 |
| 装备**词条解析失败**吗 | 按 [3.2 自助排查：装备词条解析失败](03.02-scene-management.md#自助排查装备词条解析失败) 走一遍：用自己机器的画面截图、看区域框、跑「识别全部字段」。这类问题绝大多数在这一步就能定位 |
| 查过**常见问题**了吗 | [7. 常见问题](07-faq.md) 已收录识别不准、点击偏移、布局选错等高频项 |

顺带一个常被误解的点：装备扫描后提示「状态异常」、装备名后带「!」，是程序在**如实
告诉你某个词条读错了**，请手工校正——它是提醒，不是崩溃，也不代表程序坏了。日志里
形如「词条宫(affix_gong) 无法解析: '处功防御'」的行就是对应的 OCR 误读（正确应为
「外功防御」），日志报的 Key 对应场景编辑器里同名的那个区域框。

### 第二步：一次性提供这些信息

自查后仍复现，**在一条消息里**给全下面这些，不要分多次挤牙膏：

1. **律匠版本号**（「帮助 → 关于」），以及是发行版还是源码版；
2. **目标与环境**：端游窗口 / 投屏窗口 / 模拟器窗口 / ADB 连手机；当前布局名称；
   是否改过 `config/system` 下的场景、布局或工作流；
3. **分辨率与缩放**：游戏窗口或设备分辨率、Windows 显示缩放比例；
4. **完整截图**：游戏画面截图（出问题的区域要完整可见，**不要裁**）；
5. **自查结果**：词条/识别类问题请附上「识别全部字段」的输出——哪个区域读成了什么、
   正确应该是什么。这两行往往直接决定问题归属；
6. **日志文件**：先看 `logs/lvjiang_日期.log`（当天）；最近 7 天内更早的日期
   归入 `logs/logs/年月/`，再早的日志不会保留。取从本次任务 `[开始]` 之前到异常之后的连续
   内容。**发文件或完整文本，不要发日志区的截图**——截图必然截断上下文，而上下文
   往往才是原因所在；崩溃再附 `logs/crashes/` 里的现场文件；
7. **复现过程**：开始前游戏停在哪一页、执行的工作流与全部参数、每一步操作、
   预期结果与实际结果、是每次必现还是偶发。

提交前请按 [8.7 隐私与脱敏](08-feedback-and-issues.md#87-隐私与脱敏) 遮盖账号、角色名、
设备序列号等信息，但**不要删掉日志时间、级别、调用顺序和错误栈**。

主窗口「帮助 → 反馈」里有这份清单的精简版和可直接复制的 Bug 模板。

### 哪些不在受理范围

一对一教学与远程配置、没有版本/环境/步骤/日志的笼统反馈、未做上面基础排查的已知
误操作、第三方修改包导致且无法在干净版本复现的问题，都不作为 Bug 排查；标注
Beta 的功能只接受测试反馈，不承诺按正式功能处理。完整清单见
[8.9 不在受理范围的内容](08-feedback-and-issues.md#89-不在受理范围的内容)。
