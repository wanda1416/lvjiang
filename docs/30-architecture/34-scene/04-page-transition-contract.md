# 页面切换契约

> **状态**：声明与校验已实现，管理视图已展示。**不驱动执行**——现有 `.wf` 与
> Python 编排一行未改。

## 1. 为什么要有

跳转逻辑此前散在三处、两种语言：

| 位置 | 内容 | 语言 |
|---|---|---|
| `TuningRouteStrategy` | 14 个方法 + Android/Desktop 子类覆写 | Python |
| `navigation.wf` | 8 个 `nav_*` | DSL |
| `page_detection.wf` | 5 个 `is_in_*_page` | DSL |

平台差异被表达了两遍且形式不同（子类覆写 vs 内联 `if env("desktop")`）。而
`view` 字段虽然已在 29 个场景、114 处定义上标注，**运行期完全是惰性的**——除了
`key_validation` 按视图去重激活键，没有任何执行逻辑读它。

惰性元数据会烂：`equip_tune_detail` 的视图 key 一度拼成 `reset_confrim`（少个
`r`），活了很久才被发现——因为运行期没有任何东西引用视图 key，拼错也不会有人
报错。契约把视图 key 变成被引用、被校验的东西之后，这类问题才会当场暴露。

契约的目的不是取代这些代码，而是**把「点这个按钮会去哪」从散落的实现变成可校验、
可展示的声明**。即使一行执行代码都不改，也在逐步建立完整的页面切换关系，后续
读代码的人和 AI 能直接看懂转移逻辑。

## 2. 多视图归属

entity 的归属视图从单值改为列表。同一个按钮出现在多个视图是常态——
`close_btn` 在调律结果视图和狗粮返还视图都在。

**坐标只有一份、跟布局走，不跟视图走**：布局侧的 `Region` 从来没有 `view` 字段，
所以多归属完全不碰布局 JSON。

```yaml
- key: close_btn
  name: 关闭
  type: func
  views: [result, return_good]
```

单归属仍写 `view:`，既有文件不产生无谓 diff；读取侧两种都认。

`is_view_visible` 接受单值或列表，**命中其一即可见**。

## 3. 转移声明

```yaml
- key: tune_btn
  name: 调律
  to: /result              # 停留本场景，切到 result 视图
- key: enter_tune
  to: equip_tune_detail    # 进入该场景基底视图
- key: goto_result
  to: equip_tune_detail/result
```

**声明放在场景定义（游戏语义，不随布局变），可用性放在布局**
（`Region.disabled` 表达「这个布局上没有这条边」）。

这个分工解决了拓扑差异：`nav_main_to_bag` 在桌面端按 `B` 一步直达、安卓端要
`主页 → 菜单 → 背包`。用「桌面布局启用 `game_main_page.bag`、默认布局 disabled」
表达即可，`to:` 本身不需要带 environment 条件。

## 4. 同层视图

非基底视图有一个属性 `same_layer`，**默认为真**。

同层视图与基底处于**同一图层**，只是滚动/翻页后的另一个取景，不是另一个页面。
菜单的 `page_1` / `page_2` 就是典型。

> **同层视图没有入口，只有跳转。** 没有任何按钮“进入”它——你只是把同一页滚过去
> 了；但它上面的按钮照样可以跳到别处。

```yaml
views:
- key: base
  name: 基底
- key: page_2
  name: 第二屏          # 默认同层，无需声明
- key: result
  name: 调律结果
  same_layer: false     # 独立页面，需要声明入口
```

默认为真是有意的：新建视图多半是滚动态，这个默认值**不会制造假警报**；确实是独立
页面时再取消勾选，那时才要求它有入口。

这条属性直接解决了「视图」这个概念承载的两种含义——它最初的用途就是「把同一页面
的多个滚动态分屏排布」，与「页面切换的目标」不是一回事。没有它，死视图检测在当前
配置上会报 37 个假警报（全部非基底视图）；有了它是 0 个。

## 5. 校验与查询

`core/scene_transitions.py`：

| 函数 | 用途 |
|------|------|
| `collect_transitions` | 收集所有边；多视图按钮每个视图各算一条 |
| `validate_transitions` | 目标场景/视图必须存在；格式必须合法 |
| `find_unreachable_views` | 没有任何入口的非基底、**非同层**视图 = **死视图** |
| `entries_of_view` / `exits_of_view` | 管理视图展示用 |

基底视图是场景入口，不需要场景内的按钮指向它，因此永不判为死视图。

校验是**只读**的，不阻断加载——契约逐步补全，不完整是常态。

## 6. 编辑器

- 区域/坐标点的编辑弹窗：视图从单选下拉改为**多选清单**，新增「跳转」选择器
- 「跳转」是**三级级联**：分组 → 场景 → 视图。不平铺全部组合——29 个场景已经能
  凑出上百个，平铺后选不动，而且场景只会越加越多。选定场景后视图默认基底
- 取值做规范化：跨场景指向基底时省掉 `/base`，与不带视图的写法归一。否则没动过
  转移的 area 一经编辑就会把 `to: bag_detail` 改写成 `to: bag_detail/base`，
  制造纯噪声 diff。**本场景**回基底仍写 `/base`——空串是「不跳转」，两者不能混
- 区域面板表格新增「跳转」列
- **管理视图**在选中视图时展示：

  ```
  入口：bag/base [tune]
  跳转：[close_btn] → tune/base
  ```

  非基底、非同层视图没有任何入口时直说「无入口（死视图：补 to: 声明，或改标为
  同层视图）」；同层视图则显示「同层视图与基底处于同一图层，无入口」。列表项上带「· 同层」
  标记，选中后可用勾选框切换。
