# 05 · 调优与失败模式手册

> Layer: L3 · 按症状索引 · 排查顺序按"最可能原因"降序

## 使用方法

先按下表定位症状行，逐条排查。找不到对应症状就查 [02](02-color-ops-internals.md) / [03](03-template-matching.md) / [04](04-coordinate-system.md) 三篇的算法描述。

## 症状索引

### 模板匹配类

#### T1 · 明明图上就是它，score 上不去

| 排查项 | 判据 | 修复 |
|---|---|---|
| 分辨率不匹配 | `record_w ≠ 当前 canvas_w` 且差 > 20% | 用当前布局重录模板 |
| `record_w = 0` | 布局 JSON 里 `template.record_w` 缺失 | 编辑器打开模板绑定重保存；手写就补上 |
| 光照/对比度差异 | 截图整体亮度不同 | `TM_CCOEFF_NORMED` 已经抗这个；多半不是这个 |
| 帧不是同一时刻 | 目标元素有动画 | 用 `wait` + 稳定条件；或降低阈值 |
| Region 位置不准 | 归一化 Region 与实际像素位置差 > 10 px | 编辑器重画 Region |

#### T2 · 桌面能命中，投屏不命中

`by image` 的**跨分辨率适配靠 `resolution_scale` 线性缩放**。桌面 1920 录 → 投屏 1280：`scale = 1280/1920 ≈ 0.667`。

如果缩放后模板像素与投屏上真实像素**不是** 0.667 关系（游戏渲染在小分辨率下笔画可能整像素对齐变了，UI 元素按不同规则重排），单尺度就救不了。

**修复**：
1. 首选：**投屏布局独立录一份模板**。每个布局下 `template.name` 会走各自的目录（`desktop/` vs `android/`）。
2. 次选：把该 Region 从 `by image` 换成图色判据（`color_ratio` 主导色），不依赖像素形状。
3. 应急：降低阈值到 0.6。memory `Layout config restoration: min_score 0.6→0.8` 提醒过这是**临时降级**，找到根因后要恢复。

#### T3 · 相邻图标串扰（scan by image 命中邻居）

`search_box` 在 Region 装不下"模板 + 每边 `SEARCH_SLACK_PX=2`" 时会**对称外扩**。外扩后可能把邻居 Region 的一部分纳进搜索区，导致邻居的图形被识别成当前模板。

**判据**：日志里 `scan by image 命中` 的 region 与实际画面不符。
**修复**：
- 编辑器把 Region 画得比模板大至少 4 px（每边 2 px slack），触发原样使用不外扩
- 或收紧模板尺寸（截取时只截核心图案，不带外边距）
- 或加 `where confidence >= 0.9` 拉高门槛

#### T4 · 同形状红/蓝按钮互相误命中

`by image` 输入是灰度，颜色信息**完全丢失**。

**修复路径**：
- 走 OCR：如果按钮有 label，`scan` 读文字最准
- 走图色：`find_icons(channel, margin)` 判主导色
- 让模板更独特：截带颜色的完整按钮（虽然匹配时仍灰度，但灰度轮廓可能已经不同）

#### T5 · scale=1.0 被跳过（历史 bug）

**症状**：桌面 1920 录的模板放桌面 1920 用，理论 scale 应该正好 1.0，但只能靠 0.99/1.01 匹配，分数掉 5–10 点。
**根因**：编辑器 `int(round(right))` 与运行时 `int(right) - 1` 差 2 px，触发 `tw > rw` 判据。
**已修**：`int(right) + 1`（memory `模板搜索区域边界取整修复`）。
**如果又出现**：查 `template_locator.py` L305-306 是不是被改回 `- 1`。

#### T6 · 编辑器 ✓ 运行时 ✗

按 [03-template-matching.md](03-template-matching.md) §"与编辑器预览匹配的一致性"排查清单逐条走。最常见的是**帧不同**：编辑器用的是你**录截图时那一帧**，运行时是**实时截屏**，两者相差几秒到几小时。

**修复**：用截图工具截**当下运行时**的那一帧，喂给 `scripts/diagnostics/scan_tpl_bound.py`（若存在）离线诊断。

### 图色函数类

#### C1 · color_ratio 分数飘

| 原因 | 处理 |
|---|---|
| 区域选太大，混进背景 | 收紧 Region 到纯色元素内部，留 5% 内边距 |
| `tol` 太紧 | 从 40 起调；抗亮度差异一般要 30–60 |
| 用了绝对 RGB 但元素半透明 | 换 `find_icons` 或 `color_vec` 走"主导通道 margin" |
| 元素有动画（呼吸/闪光） | 采样多次取中位；或降阈值 |

#### C2 · bright_segs 计数不对

**已知陷阱**：一直到行尾仍未退出的亮段**不计**（对齐 Kotlin）。如果页签最右侧一段贴到画布右边界，会被吞。

**修复**：把扫描线的 `x2` 往右挪 20–30 px（留暗背景余量）；或者让布局里 Region 右边界外扩一点。

**迟滞带太窄**：`on_min - off_max < 100` 时抗噪差，笔画中间一小段可能被算两次。放宽两个阈值的差。

#### C3 · find_icons 一堆碎小命中

**判据**：日志里 `n` 很大，`area` 都小。
**根因**：`min_area` 阈值太低。
**修复**：按目标图标的实际面积 ×0.5 设。1080p 下小图标 ≈ 120 px²，归一化 `120 / 1080² ≈ 0.000103`。

#### C4 · find_icons 找不到目标

反过来，`min_area` 太高，或 `margin1` 太严导致掩膜不覆盖。

**判据**：手动跑一次掩膜，看命中像素总数。

**修复**：
- 降低 `margin1`（比如 35 → 20）
- 降低 `c_min`（目标通道本身的下界）
- 检查 `channel` 是不是选错了（该是绿主导选了红主导）

#### C5 · color_vec 返回 -1

`count == 0` = 掩膜内没有任何像素落在 `[min_r, max_r]` 环带。

**判据**：
- 环带设太窄
- 掩膜全空（改判据 `margin` / `c_min` / `c_hi`）
- 中心点 `(cx, cy)` 不在 Region 里

**修复**：先只算掩膜（把 `min_r=0, max_r=inf`），确认有命中；再逐步收紧环带。

#### C6 · color_vec 方向反了

`atan2(sum_x, -sum_y)` 是**屏幕上方 0°、顺时针**。屏幕 y 轴向下，`-sum_y` 已经把 y 翻转。

如果实测方向差 180°，多半是中心点选错：小地图的"路线朝北"是像素上从中心往上（`dy < 0`），如果中心点在地图之外，向量方向全反。

**判据**：中心点坐标是否落在地图 Region 内。

#### C7 · find_multi_color 偏移在跨分辨率下不命中

`dx/dy` 归一化按**画布宽**。录制的偏移基于录制时画布，运行时按 `canvas_w` 反归一化。

**如果**：录制 1920 上 dx=10，运行时投屏 1280 上应该按 `10 / 1920 * 1280 ≈ 6.67` 换算。若 DSL 层没做这步，就会挂。

**检查**：`builtins/vision.py` 里 `find_multi_color` 是否用了 `dx * canvas_w` 归一化。

### 坐标系类

#### X1 · Region 越界报错

`layout_models.py` 里 `x_ratio + w_ratio > 1 + _RECT_EPS` 抛错。

**原因**：编辑器里拖拽后浮点末位飘（`1.0000000000000002`）。
**修复**：`_RECT_EPS = 1e-6` 会容忍这种误差；若还挂说明确实越界，改回 `≤ 1`。

#### X2 · 点击位置偏 1–2 px

`int()` vs `round()` 差异。**这是设计上的**：`round` 与编辑器一致，`int` 会左偏。

如果实际点击中心总是偏左上 1 px，多半是某处用了 `int(...)` 而不是 `round(...)`。搜代码：`int(.*x_ratio.*canvas` 或 `int(.*canvas.*x_ratio`。

#### X3 · 布局改分辨率后所有 by image 挂

改分辨率意味着 `canvas_w` 变了，`resolution_scale` 结果变了。若模板 `record_w` 未同步更新，缩放会算错。

**修复**：
- 分辨率变了就**重录**模板（编辑器打开布局 → 重存所有模板 → 自动记新 `record_w`）
- 或者把 `record_w = 0`，让运行时按 scale=1.0 原样匹配（此时**必须同分辨率**）

#### X4 · `find ... by image [scene].[B]` 抛错 "模板不存在"

**原因**：`TemplateBinding.name` 指向的 PNG 文件在 `config/system/templates/` 下不存在。

**判据**：`binding.name` 会被规范（去 `.png`、拆 POSIX 路径），实际查找路径 = `config/system/templates/<binding.name>.png`。

**修复**：
- 检查文件是否真存在
- 布局目录（`desktop/` vs `android/`）是否写对
- 从旧布局导入的 Region 是否遗留了别的布局的模板路径

## 通用调参流程

### 加新 by image 判据

1. 在编辑器打开目标布局 + 场景
2. 画 Region 框住目标元素（不要留边距，紧贴边缘）
3. **录模板**（编辑器保存 → 自动填 `record_w/record_h`）
4. 编辑器点"预览匹配"，看 ✓ + score
5. 若 score < 0.9：多半是 Region 内混进了动态背景；缩 Region
6. 阈值默认 0.8 起；跨分辨率不稳就 0.75

### 加新图色判据

1. **先离线**：截一张代表性帧（真机或桌面截图工具），存到 `fixtures/`
2. Python REPL 里跑 `color_ops` 函数，调阈值看输出
3. 定下阈值后写进 wf 或 `game_config.yaml` 的常量表
4. 设备端跑一遍验证

**不要**在真机上在线调参，一次 3 秒 × 几十轮 = 半小时。

### 加新 find_icons 判据

1. 目标图标颜色必须能靠**主导通道**表达（"绿 >> 红/蓝"），不能靠绝对 RGB
2. 面积/bbox 门槛按**最小可接受尺寸**设；宁可漏不要误命中
3. 先用 `find_icons(..., min_area=0)` 拿全部候选，肉眼判断分界；再定阈值
4. 归一化换算参考 memory 里 `yysls game_config.yaml 装备命名结构与 affix 上限值规范`（同思路）

## 常见误用一览

| 误用 | 正确做法 |
|---|---|
| 用 `pixel(x, y)` 判单点色 | 用 `color_ratio` 面积投票，抗噪 |
| 用 `by image` 找一堆相同图标 | 用 `find_icons` |
| 用 `by image` 区分红蓝同形按钮 | 用 `find_icons` 通道 margin 或 OCR 文字 |
| 用 OCR 判状态（有颜色可用） | 用 `color_ratio` 或 `bright_segs`，快 100× |
| 一个 scan 里塞 10 个候选 | 拆两次 scan（前 5 + 后 5），日志更清晰 |
| 每帧都重跑 `find_icons` | 缓存 `FoundRegion`；同一画面里位置不变 |
| 阈值调到 0.5 求过 | 找根因（多半是 T1/T2/C4）；0.5 意味着 30% 相关性都没到，就是没对上 |
