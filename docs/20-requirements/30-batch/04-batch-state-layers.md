# 批量的状态分层

> 状态：已实现（2026-10-08，基线 v0.13.14）。
>
> 数据归属、协调算法、`batch.json` v2 迁移与落点见
> [39-runtime/06-batch-state-layers.md](../../30-architecture/39-runtime/06-batch-state-layers.md)。

## 1. 问题

批量原来只有一个扁平的配置项，「批量配置」窗口和主页面批量页都直接改它，划分依据
是哪个界面方便，而不是语义。后果：

- 主页面的一次临时勾选、拖拽、轮数调整**全都写回配置组**，于是"上次运行的勾选"
  和"下次打开的初始值"是同一份数据，说不清"恢复默认"该恢复到哪；
- 任务页的拖拽顺序落盘，用户页的拖拽顺序不落盘——同一个窗口里两种语义；
- 决定可见性与生命周期契约的**定义级设置长在主页面**，而依赖它的「单用户直通」
  勾选框长在配置窗口，于是出现一个"灰着、勾着、在本窗口里找不到任何理由"的控件；
- 配置窗口保存前要把主页面拥有的字段读盘搬回来，这段反向合并代码的存在本身就是
  所有权没划清的证据；
- 启动时活动组来自磁盘，而用户名与脚本来自页面控件——执行快照由两个可能不一致的
  源头拼出来。

## 2. 四种状态

| 状态 | 回答的问题 | 谁能改 |
|---|---|---|
| 配置组定义 | 这批任务长期包含哪些任务与用户、用什么调度单元与生命周期 | 只有「批量配置」窗口 |
| 配置编辑器草稿 | 本次编辑尚未保存的内容 | 对话框自己，点保存才落盘 |
| 本次运行草稿 | 这一次跑哪些、按什么顺序、跑几轮、是否无人值守、生命周期参数怎么填 | 只有主页面批量页 |
| 执行快照 | 已经开跑的这批到底包含什么 | 点「开始」时冻结，之后不可变 |

两阶段的用户流程因此成立：**先定义配置组，再准备本次执行，点开始后冻结为不可变
计划。**

## 3. 用户可感知的状态边界

字段名、存放位置、协调算法（`BatchSelection.reconcile`）与执行快照的构造在
[39-runtime/06-batch-state-layers.md](../../30-architecture/39-runtime/06-batch-state-layers.md)；
本节只写需求层的三条硬约束：

1. **本次与长期分开**：本次勾选、执行顺序、轮数、是否无人值守只在本次运行生效，
   不得写回配置组；配置组只放可见项、初始顺序、默认勾选、调度单元与生命周期配置。
2. **保存配置组不重置本次顺序**：仍在候选里的条目保留草稿中的勾选与位置，新候选按
   定义层顺序追加并取默认勾选，只有用户点「恢复默认」才完整重建；切换配置组只换对应
   草稿。顺序与勾选必须分开存——合在一起的话取消勾选就丢位置。
3. **点「开始」后冻结**：运行期改配置、改用户资料、在主页面重新勾选，都不影响正在跑的
   这一批。调度器只认执行快照，不再读配置组或页面控件。wf 脚本文件本身不缓存，运行中
   修改脚本仍会作用于后续阶段。
4. **生命周期参数属于本次执行**：条目准备、批次准备等阶段声明的参数在「批量 - 参数」
   里随时调整，写运行草稿而不是配置组；「批量配置」只决定用哪个 wf 文件。参数定义仍按
   wf 文件头实时读取，换工作流后草稿里不再声明的旧值不会生效。旧版固化在配置组里的
   参数不再读取，也不做自动迁移；下次保存该配置组时字段自然消失，参数回落到 wf 默认值。

两条容易被误当成本次设置的语义：调度单元属于**定义**（决定候选列表、生命周期契约与
能否跳过），Profile 排序键定义的是**能力**而不是已经排过的顺序。

## 4. 不兼容切换

用户感知到的变化是：**本次勾选、执行顺序、轮数、无人值守不再跨配置保存在配置组
文件里，而是按配置组记在本机会话状态里；首次打开按配置组的"默认执行"列勾选。**
旧格式一次性转换，不保留常驻兼容层；读取规则见
[实现契约](../../30-architecture/39-runtime/06-batch-state-layers.md#batchjson-v2-迁移)。


## 5. 配置窗口与参数页

配置窗口的固定设置按双列编排：调度单元／指定排序、批次准备／批次收尾、条目准备／
条目收尾、异常恢复工作流／单个执行单元时跳过生命周期（复选框在右侧）。空间不足时
回到单列，字段标签共用宽度，不截断关键内容来挤出双列。任务用户列表与设置表单同处
一个纵向分隔条，高度分配可拖动调整，保存和取消固定在底部。

生命周期参数不在配置窗口编辑，而是主页面「批量 - 参数」按当前 wf 文件头的参数声明
生成控件，改动写本次运行草稿；切换配置组或开始批量前会先落盘未提交的改动。

布局不拥有配置值：require 仅控制整个字段的显隐，隐藏或重新排布不删除控件、不重置值。
调度单元切换保留既有跳过选项，恢复用户单元时按原值展示；编辑组切换仍不改活动组。
