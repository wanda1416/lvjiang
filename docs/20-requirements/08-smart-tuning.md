# 智能调律 — 基于备战方案毕业率的二次调律处理

> **状态**：第一版已实现；公共能力默认启用，用户级二次开关默认关闭
> **依赖**：[自动调律](01-auto-tuning.md)、[毕业率分析](02-player-profile/01-graduation-rate.md)、
> 备战方案与装备库、培养建议中的理论敏感度、调律历史

## 1. 背景

现有自动调律以流派规则判断装备的最大可能评级，再由基础规则组中的三个行为点
编排流程：

1. 扫描处理决定是否进入调律；
2. 材料处理决定本轮使用何种材料；
3. 调律处理在装备通过准入后以及每轮调律后决定继续、重置、回收或保留。

这套流程能够判断装备是否符合某类词条规则，但不知道该装备对当前用户的真实
备战方案是否还有毕业率收益。因而会出现以下浪费：

- 某部位已经有足够好的装备，仍继续遍历并调律该部位；
- 一件装备虽然能达到规则要求，但放入用户任一目标备战方案都不能提高毕业率；
- 装备在某轮产生新词条后已失去提升可能，仍继续投入律准石和狗粮。

智能调律的目标是在不改变现有三大处理方式的前提下，引入一层结合备战方案毕业率
的复杂调律处理，在确定装备无法带来收益时及时停止投入。

## 2. 产品定位

智能调律不是新的扫描处理，也不替代基础调律处理。它位于调律处理之后：

```text
调律初始状态或一轮调律完成
        ↓
调律处理
        ├─ 跳过 / 回收：直接结束
        ├─ 调满后回收：进入专用模式
        └─ 最终结果为继续
                ↓
          智能调律判断
                ├─ 仍可能提升：继续下一轮
                └─ 无法提升：执行智能处理动作
```

这样可以保证垃圾装备优先由现有廉价规则处理，只有原流程确实准备继续投入时，
才运行成本更高的毕业率计算。

### 2.1 核心原则

- 公共智能配置不得保存用户名、备战方案 ID 或任何用户装备数据；
- 运行时依据 `run_username` 读取执行用户数据并建立只读快照；
- 只使用本次配置范围内的备战方案；
- 原装备、装备库和备战方案在推演过程中不得被修改；
- 无法可靠得出结论时必须放行，不能误跳过或误回收；
- 智能调律不自动应用装备，也不修改用户的备战方案。

## 3. 范围

### 3.1 第一版范围

- 公共“智能调律”配置页；
- 按“传入玩法/全部玩法”过滤当前执行用户的备战方案；
- 装备通过准入且首次调律处理返回继续时，在首次实际调律前执行智能判定；
- 每轮调律后，在调律处理返回继续时再次判断；
- 按当前装备状态推演剩余普通词条；
- 将推演结果逐一替换进参与方案，把替换前后的整套装备统一按满等级、
  满承音、满定音计算极限毕业率；
- 支持 `>` 和 `>=` 两种比较语义；
- 无法提升时执行独立的智能结束动作；
- 完整日志、调律历史和观察模式；
- 使用真实用户数据进行性能基准测试。

### 3.2 第一版不包含

- 自动修改或应用备战方案；
- 自动将调律结果写入用户装备库；
- 同等级承音分支或彩色狗粮 100% 数值；
- 每个判断点重新搜索八个部位的全局最优组合；
- 给不同用户或具体备战方案保存独立智能配置；
- 按方案设置权重或材料预算；
- 改写现有调律处理的匹配顺序和规则含义。

## 4. 配置归属与界面

### 4.1 导航位置

“调律配置”左侧一级导航调整为：

```text
基础配置
扫描处理
材料处理
调律处理
智能调律
────────
流派规则
各调律规则……
```

智能调律紧接在“调律处理”之后，两者之间不使用分割线，表达其属于扩展调律
处理；智能调律之后使用分割线，与流派规则区分。

智能调律页：

- 不属于任何基础规则组；
- 不显示“当前规则”下拉框；
- 切换基础规则组时不刷新；
- 使用 `TuneConfigManager` 读写公共配置；
- 与调律配置对话框共用保存、撤销和版本来源展示。

导航实现不得继续依赖分割线数量推算页面索引。每个有效导航项应显式保存对应的
栈页面索引，分割线不绑定页面。

### 4.2 配置存储

配置写入公共 `yysls/tune_config.yaml`，不写入 `base_groups/*.yaml`，也不写入
`users/{username}.json`。

建议结构：

```yaml
smart_tuning:
  enabled: true
  plan_scope: incoming       # incoming / all
  evaluation:
    enabled: true
    operator: gt             # gt / gte
    precision: 0.001         # 1% / 0.1% / 0.01% 对应 0.01 / 0.001 / 0.0001
  failure_action:
    enabled: true
    action: skip             # continue/reset/recycle/skip/tune_full_recycle
    keep_min_rating: excellent  # 调满后回收专用：junk/normal/excellent/top
```

配置缺失时公共能力等价于 `enabled: true`，不编写自动迁移逻辑。

公共配置只是能力总开关。每个用户的 `workflow_params.auto_tuning` 还必须保存
`smart_tuning_enabled: bool` 作为二次确认，默认 `false`；只有两级开关同时开启
才初始化智能评估器。

### 4.3 页面结构

#### 智能调律

- `[] 启用智能调律`
- 固定说明：运行时读取当前执行用户的备战方案，公共配置不保存用户信息。

#### 备战方案范围

- `传入玩法（推荐）`
- `全部玩法`

#### 智能收益判断

- `[] 启用装备最大可能毕业率判断`
- `装备最大可能毕业率必须 [大于/大于等于] 当前方案三满极限`
- `毕业率精度 [1%/0.1%/0.01%]`，默认 `0.1%`；比较双方先按精度
  向下取整，再执行所选比较。例如 `94.59%` 在 `0.1%` 精度下按
  `94.5%` 判断，在 `1%` 精度下按 `94%` 判断。

界面必须使用“毕业率”，不得简称“评级”，避免与垃圾、一般、优秀、顶级四档
装备评级混淆。

#### 无法提升后的智能调律处理

- `[] 启用无法提升后的处理`
- 动作：继续调律、重置、回收、跳过、调满后回收。
- 仅当动作选择“调满后回收”时，显示附属项
  `强制保留 [顶级/优秀/一般/垃圾] 及以上装备`，默认“优秀”。装备调满后
  使用本次传入的当前调律规则重新判定；评级达到门槛时跳过回收并保留装备。
  此门槛只属于智能调律失败动作，不改变基础规则表中“调满后回收”的原有语义。

收益判断和失败动作分别带启用开关，允许先观察计算结果而不改变实际流程：

- 只启用收益判断：计算并记录，失败仍放行；
- 两者都启用：失败时执行所选动作；
- 只启用失败动作：因没有失败事件，不生效，界面应给出提示。

## 5. 备战方案范围

### 5.1 传入玩法

初始化时必须保留「规则 key / 规则显示名 / 玩法」三元关系，不能只压平成玩法集合。
每一项分别检查匹配备战方案、毕业率方案和八件穿戴装备，并记录明确日志：

- 没有备战方案或毕业率方案时，该规则玩法不参与智能调律；
- 备战方案未穿满八件装备时直接忽略，提示用户先扫描已穿戴装备；
- 部分规则玩法无效不得影响其他有效项；全部无效时按 UNKNOWN 放行。

“传入玩法”取本次自动调律实际启用的 `(rule_key, playstyle_name)` 集合：

- 规则明确勾选部分玩法时，只包含勾选项；
- 规则没有单独声明玩法选择时，包含该规则声明的全部玩法；
- 当前用户的备战方案仅在 `plan.playstyle` 命中传入玩法时参与；
- 方案武学组合必须仍与公共玩法注册信息一致；
- 同一玩法被多条传入规则引用时，方案只加入一次，判定保留完整规则上下文。

用户本次没有勾选的玩法不得参与智能判断。若没有任何有效方案匹配，应记录警告并
退化为普通自动调律，禁止偷偷扩大为全部玩法。

### 5.2 全部玩法

“全部玩法”使用当前用户中由未禁用公共调律规则覆盖的全部有效备战方案：

- `disabled: true` 的调律规则不得被重新启用；
- 没有任何启用规则承接的玩法不参与；
- 使用对应公共规则的默认配置进行玩法上下文解析。

### 5.3 有效方案

参与毕业率计算的方案至少应能够解析：

- 流派；
- 玩法；
- 基础属性；
- 弓玦套装；
- 毕业方案；
- 当前装备集合。

单个方案异常只排除该方案并记录原因；全部方案异常时关闭本件装备的智能判断，
继续执行原自动调律流程。

## 6. 毕业率比较基准

对每个参与方案建立运行期只读快照：

- 基准装备为备战方案当前配置的八件装备；
- 基准毕业率按方案自己的流派、基础属性、弓玦和毕业方案计算；
- 判断当前部位候选时，另外七件装备保持方案快照不变；
- 当前部位替换为正在调律的真实装备或其虚拟推演结果；
- **武器按类型定位**：自动调律把全部武器放在主武器槽遍历，但方案里主/副
  武器类型不同——候选武器与方案主武器同类型时替换主武器，与副武器同类型
  时替换副武器，两者都不匹配则该方案对这件装备**不适用**，既不算通过也不
  算失败，不参与聚合；全部方案不适用时按未知放行；
- 游戏角色此刻物理穿戴的装备不作为毕业率基准；
- 运行中修改备战方案不影响已经开始的任务。

第一版不因为找到一件较好装备就修改备战方案基准。是否维护“本轮已发现最佳装备”
作为影子基准，待真实数据验证后再决定。

## 7. 智能判断点

### 7.1 首次判断

装备通过扫描准入后，基础调律处理会先用完整实际词条得出首次决策：

```text
首次调律处理
    ├─ skip/recycle：结束，不运行智能判断
    ├─ tune_full_recycle：进入专用模式，不运行智能判断
    └─ continue：运行智能判断
```

调律处理是必经步骤，不再有可选的 `initial_check` 开关。其执行重置并
最终返回继续时，智能判断应面对重置后的实际首词条状态。

### 7.2 每轮判断

每次实际调律完成后都是一个打断点：

1. OCR 新词条并更新 `EquipmentData`；
2. 刷新现有潜力评级；
3. 执行调律处理；
4. 只有调律处理最终返回继续，才执行智能判断；
5. 智能判断通过后进入下一轮；
6. 智能判断失败且启用失败动作时，执行智能处理动作。

调满后回收模式具有独立的材料回收目标，不执行毕业率智能判断。

### 7.3 重置后的判断

调律处理或智能处理动作执行重置成功后：

1. 当前装备恢复为实际首词条状态；
2. 词条数更新为 1；
3. 重新执行智能判断；
4. 仍失败且失败动作也是重置时，不对相同首词条再次
   执行无意义重置，直接转当前基础规则组的“重置耗尽处置”。

重置必须沿用现有最大次数、次数 OCR 和耗尽动作约束，禁止形成无限循环。

## 8. 剩余词条推演

### 8.1 输入状态

每次判断以当前真实状态为起点：

- 装备类型、等级、品阶和基础属性保持不变；
- 第 0 分支保留已经产生的普通词条；转律分支只在虚拟副本中移除一条
  已出现的第 2～4 词条；
- 第一词条不得替换；
- 为尚未出现或转律后空出的普通词条位置生成虚拟词条；
- 不直接修改 `EquipmentData`，所有推演基于深拷贝或不可变状态。

### 8.2 候选词条

候选必须同时满足游戏物理规则和当前调律规则的可用词条库：

1. 按装备类型和部位筛出游戏中可以出现的词条；
2. 与当前“规则-玩法”的 `affix_pool` 取交集；
3. 动态本属、外属词条按当前备战方案的流派属性展开后参与交集；
4. 排除与当前组合重复或冲突的词条；
5. 每次加入后使用全局装备合法性判定器校验；
6. 专属武学词条必须与装备类型匹配。

词条池只决定候选范围，不再沿用其人工价值顺序；候选之间的顺序由毕业率理论
敏感度实时决定。玩法明确声明的武学增伤、全武学增效、奇术增伤或单位增伤属于
当前部位必需词条，有空位且尚未出现时先固定填入，不参与收益竞争。

### 8.3 数值口径

智能调律默认不投入彩色狗粮，因此虚拟新增词条使用当前等级配置中的
`caps["chengyin"]`：

```text
虚拟新增词条值 = 当前等级该词条的承音上限
```

不得统一写为 `cap * 0.94`，必须使用配置中的已取整结果。当前真实词条使用 OCR
数值作为分支输入，不直接改写原始数据。最终比较的是双方统一执行满等级、满承音、
满定音后的虚拟副本；当前赛季原生装备也必须纳入同等级承音假设，不能让原方案与
候选方案使用两套不同口径。

现有培养建议“理论敏感度”继续展示 100% 理论上限；智能调律通过参数化公共内核
选择承音上限，不能改变原界面的解释口径。

### 8.4 一次转律分支

智能调律必须考虑尚未执行的一次词条转律，否则中途出现一条垃圾词条就会过早终结
实际仍可挽救的装备。分支规则如下：

1. 第 0 分支不改动任何词条，保留原有直接补全路径；
2. 只有当前词条数为 2～4 时建立转律分支；五词条已是终局判定，不再执行智能毕业率
   推演；
3. 检查已经出现的第 2～4 词条。若存在不属于当前规则可用词条库的词条，只对第一条
   池外词条建立转律分支；
4. 若这些词条全部属于可用词条库，则分别尝试转出每一条；每个分支只改一条；
5. **转入词条必须是游戏里真能转出来的**：取各流派转律词条库（`schools.yaml`
   `transmute_pool`）的并集，再与规则词条库、部位可出现词条取交集，去掉装备第 2～5
   条已有的名字与被转出的名字。每个合法转入词条各建一个分支，形如“第 i 条「X」转为
   「Y」”，转入词条落回原槽、按承音上限取值；尚未出现的空槽仍由调律补全，不受转律
   库限制（例如规则池里的神力词条只能调出来，不能转出来）。没有配置任何转律词条库
   时不建立转律分支；
6. 各分支使用同一套候选合法性、理论敏感度贪心和三率临界交换算法补满空槽，所有分支
   取最高毕业率；
7. 增伤词条不享有特殊的“禁止转出”待遇，但玩法最终必需的增伤词条仍须在补全结果中
   存在；
8. 能进入自动调律的装备不会已经带有转律结果，第一版不设计重复转律状态机。

转律仅存在于计算副本中，不修改扫描装备、不修改背包数据，也不代表程序会自动替用户
执行词条转律。备战方案侧的转律建议与已保存目标见 [模拟转律](09-transmute-simulation.md)。

### 8.5 理论敏感度贪心路径

快速路径按以下方式逐条填充：

```text
当前方案另外七件装备 + 当前候选装备
    ↓
分别试加所有合法候选词条
    ↓
计算每个词条的毕业率边际收益
    ↓
加入收益最高的一条
    ↓
重新计算理论敏感度
    ↓
补满后对整套装备统一应用满等级、满承音、满定音
    ↓
重复直到五词条
```

补满后的最高结果再执行 `>` 或 `>=` 判定；中间未补满状态不得作为最高毕业率。

### 8.6 正确性保护：贪心为主，三率临界交换兜底

游戏装备词条只影响伤害数值和判定三率。同一侧的词条彼此可加，逐条取最大边际
不会走错；唯一的例外是 **势** 和 **敏**——各给"半条会意率/会心率 + 攻击"：

- 会意流派：整条会意率与"外攻 + 半条会意"的势；
- 会心流派：整条会心率与"外攻 + 半条会心"的敏。

当会意率或会心率正处在黄字判定临界点（40% / 80%）时，"半条率 + 攻击"与
"整条率刚好跨过临界"谁更优取决于最终组合，单条边际看不出来。

真实数据对拍（2026-09-16，5 位用户、486 个"装备 × 方案"案例，纯贪心 vs 穷举）：

- 贪心 484 次与穷举最优一致，仅 2 次次优，差 6×10⁻⁵；
- 2 次反例都是同一件 佩（用户C/无名PVE/通用会意）：贪心第一步选 势（单条
  +0.015092，略高于会意率的 +0.014951），最优解把 势 换成会意率，会意率
  **恰好顶到 40.00%**。没有出现任何其他类型的反例。

反例说明触发条件不能是"贪心准备加入整条率且截断前黄字严格溢出"：真实反例里
贪心选中的是 势（半条率），且整条率只是刚好达到上限而非超过。因此采用**贪心
补满后的双向交换验证**：对贪心结果中出现的 势/会意率、敏/会心率，把 势 换成
会意率、或把会意率换成 势（会心同理），每对至多 2 个变体、总计至多 4 次额外
求值，取最高者与贪心结果比较。交换后的策略在全部 486 个案例上与穷举一致。

一次方案计算最多 `候选数 × 缺位数 + 4` 次求值，不进行通用词条组合穷举；
穷举只作为开发期离线对拍（scratch 脚本），不进入代码库。搜索取消、超时、候选
不合法或无法补满时返回未知并放行。

对拍结论只对"三率 + 伤害数值"这一结构成立。若将来毕业率模型引入新的非单调
结构（例如按词条种类计数的套装效果），须重新做真实数据对拍后再决定是否更换
默认策略——这正是策略层存在的原因（8.7）。

### 8.7 搜索策略层

补全搜索抽成独立策略（`core/graduation/smart_search.py`），评估器只负责方案
快照、部位定位、属性聚合与缓存：

```text
SearchProblem(装备, 候选词条, 缺几条, 基准, 比较符, 精度,
              complete(), rate(), 预算)
    → SearchStrategy.search()
    → SearchOutcome(improves | no_improvement | unknown, 最高毕业率, 求值次数, 中选词条)
```

- 策略只看到"补词条"和"打分"两个回调，不知道备战方案、不碰缓存；
- 按名注册（`register_strategy` / `get_strategy`），未知名字回退默认策略；
- 默认策略 `greedy_swap`：逐条重算理论敏感度补满（只在补满后比较）→ 对结果
  中的 势↔会意率、敏↔会心率 做双向交换验证，至多 4 次额外求值；
- 预算 `SearchBudget`：墙钟上限 + 停止检查，**停止检查内阻塞的时间（暂停）不
  计入预算**，暂停恢复后继续计算而不是判超时；
- 将来的算法调整只替换策略，不动评估器和自动调律流程。

## 9. 多方案聚合

每个参与方案独立执行剩余词条推演和毕业率比较。例如：

```text
纯奶方案：基准 91.34%，推演最高 91.34%，失败
纯唐方案：基准 88.72%，推演最高 88.81%，通过
```

聚合语义为“任一通过”：

```text
任意可靠方案满足比较条件 → 继续调律
所有可靠方案确定失败       → 产生无法提升事件
不存在可靠计算结果           → 未知，放行继续
```

不得对多个方案的收益求和、平均或加权。

## 10. 比较语义

### 10.1 严格大于（`gt`）

```text
candidate_max_rate > plan_max_rate + epsilon
```

只有确定提高毕业率才继续，建议作为默认值。

### 10.2 大于等于（`gte`）

```text
candidate_max_rate + epsilon >= plan_max_rate
```

允许毕业率持平的装备继续调律，适合用户希望保留同等水平替代品的场景。

比较必须使用计算器原始值和统一浮点容差，不能先格式化为界面显示百分比再比较。

## 11. 智能处理动作

智能判断确定失败且启用了失败动作后，支持与现有调律处理一致的动作：

| 动作 | 语义 |
|------|------|
| `continue` | 忽略失败结论，继续下一轮，主要用于观察或保守策略 |
| `reset` | 使用现有重置执行器；成功后重新运行智能判断 |
| `recycle` | 退出调律页后回收当前装备 |
| `skip` | 结束并保留当前装备 |
| `tune_full_recycle` | 进入调满后回收模式，后续不再运行智能判断；调满后若当前规则评级达到附属保留门槛则保留，否则回收 |

智能调律处理只复用动作执行能力，不改变现有调律处理规则，也不归属于基础规则组。
`reset` 的次数限制和耗尽处置沿用当前运行所选基础规则组。

## 12. 部位级跳过

最初目标还包括“当前部位已经无需提升时直接跳过整个部位”。这与本需求主体的
二次调律处理不同：没有看到背包候选前，无法通过候选推演证明整个部位不存在提升。

第一版核心范围暂不把毕业率意义上的部位封顶作为硬阻断。后续可增加独立快速策略：

- 仅当参与方案在该部位都有装备；
- 且按各自玩法规则均达到顶级；
- 才允许跳过整个部位。

该策略只代表四档规则评级上的“已顶级”，不代表毕业率数学上绝对无法提升，必须在
界面和日志中明确区分。

## 13. 性能要求

### 13.1 计算规模

剩余四个位置时，贪心填充不是四次毕业率计算，而是最多四轮敏感度分析。若某部位
有约 20 个候选词条，单方案初始判断约需：

```text
20 + 19 + 18 + 17 ≈ 74 次毕业率计算
```

同一装备还可能在后续三轮再次判断。每个转律分支内部仍只有一条贪心路径；没有池外
词条时，分支数为“不转律 + 第 2、3、4 条各转成每个合法转入词条”（转入词条来自转律库
并集 ∩ 规则池 ∩ 部位，通常每槽 3～6 个）。有池外词条时只对第一条池外词条建立
转律分支。所有分支共享同一个单方案预算，不允许把每个分支都
扩张为独立 5 秒预算。三率临界交换仍只在各自贪心结果上做有限验证，不执行通用组合
穷举。

### 13.2 必须缓存

- 每个方案的毕业率计算器；
- 基础属性、弓玦和另外七件装备的聚合属性；
- 装备类型对应的合法候选词条；
- `(装备等级, 词条名)` 对应的承音上限；
- 虚拟词条组合的合法性结果；
- 已计算组合的毕业率；
- 每个判断点中不随候选词条变化的属性向量。

不得为每个候选词条反复深拷贝并重新聚合全部八件装备。计算层应支持当前部位属性
增量替换。

### 13.3 响应与取消

- 方案之间、候选求值之间必须检查停止请求；
- 用户暂停时不得继续长时间占用计算线程；
- 未得出可靠失败结论前被取消，应按未知处理；
- 计算发生在自动调律工作线程，不阻塞主 UI；
- 进度区应显示“正在计算智能调律收益”，避免用户误以为卡死。

### 13.4 真实数据基准

使用 `session` 中具备丰富装备数据的真实用户（下称用户A、用户B……）测试：

- 参与方案数量；
- 各部位候选词条数；
- 贪心路径通过率；
- 三率临界交换改变结果的比例；
- 单判断点 p50/p95/p99；
- 单件装备累计计算耗时；
- 缓存命中率；
- 停止和暂停响应时间。

性能目标需以真实数据基准确定。若设置搜索预算，预算耗尽只能返回未知并放行，不能
把“未搜索到”解释为“确定无法提升”。

第一版算法验证（2026-09-16，开发机）：

- 毕业率模型（编译后的 Excel DAG）单次求值约 43ms，是全部耗时的来源；各部位
  去重后候选词条 15–22 条；
- 使用用户A～用户E 五位真实用户的装备，对 486 个
  “装备 × 方案”案例离线对照穷举：纯贪心 2 例次优（见 8.6），贪心 + 三率临界
  交换 0 例次优；
- 穷举只作为开发期回归验证，不进入生产执行路径。单方案保留 5s 安全预算，
  超时、暂停、结束均返回未知并放行。

## 14. 日志、进度与历史

### 14.1 启动日志

至少记录：

- 智能调律是否启用；
- 方案范围为传入玩法还是全部玩法；
- 本次传入的规则与玩法；
- 参与和被排除的备战方案及原因；
- 比较操作符；
- 失败动作是否启用及具体动作。

### 14.2 判断日志

每个判断点记录：

- 装备名称、部位、当前词条数；
- 判断阶段：初始/第 N 轮后/重置后；
- 每个方案的基准毕业率、贪心结果、三率临界交换是否改变结果和最大增量；
- 选择的虚拟词条及其承音上限数值；
- 最终结论：通过、确定失败或未知；
- 原调律处理结论和智能处理动作。

正常日志不输出逐条求值，详细过程仅进入调试日志。

### 14.3 调律历史

调律历史需保存公共智能配置快照和每件装备的结构化智能判断结果，以支持：

- 复核某件装备为何继续或停止；
- 对比观察模式与实际阻断结果；
- 统计计算耗时和触发率；
- 后续调整算法后进行离线回放。

## 15. 异常与降级

以下情况均不得触发破坏性智能动作：

- 没有匹配的有效备战方案；
- 装备 OCR 缺失关键字段；
- 备战方案或毕业配置无法解析；
- 词条上限数据缺失；
- 装备合法性无法确定；
- 毕业率计算异常；
- 搜索超时、取消或未完成；
- 规则词条库同时包含会意与会心两组完整五维候选。

统一降级语义：记录警告，返回“未知”，继续现有自动调律流程。
