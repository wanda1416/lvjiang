# 武学 / 流派 / 玩法

三层配置，依赖顺序即游戏配置里的 tab 顺序：**武学 → 流派 → 玩法**。

## 1. 职责切分

| | 决定什么 | 谁引用它 |
|---|---|---|
| **武学** | 武器、属性 | 流派、玩法 |
| **流派** | **毕业率计算** | 毕业率表 |
| **玩法** | **调律方向**：要什么增伤、定什么音 | 调律规则、备战方案 |

这一刀解决了混搭：**混搭是「有玩法、无流派」**——能调律，算不了毕业率。降级是
自然的而不是异常，因为混搭本来就没有人做毕业率表格。旧结构里玩法藏在规则里、
规则又和流派耦合，混搭玩家要么被硬塞一个流派，要么什么都用不了。

## 2. 武学：武器和属性的唯一真源

```yaml
martial_arts:
- name: 无名剑法
  weapon: 剑
  attr: 鸣金
```

拆分之前 `weapon` 和 `martial_art` 是流派里两个**独立录入、互不校验**的字段。
写成「武器=枪 + 武学=无名剑法」也存得下来，然后毕业率按枪算、词条按剑法找，
全程没有任何地方会喊。

现在武器是**派生值**：流派配置面板里武学是下拉，武器只读。配置文件格式不变
（仍写 `weapon`），但它恒等于派生值，不再是一个能和武学矛盾的字段。
`check_school_weapon_consistency()` 把随包配置的一致性钉在测试里。

## 3. 玩法：主副只是顺序标签

```yaml
playstyles:
- name: 纯唐
  school: 裂石·钧
  attr: 裂石
  arts: [斩雪刀法, 十方破阵]
  main_damage: 横刀武学增伤
  output_dingyin: 外功穿透
  defense_dingyin: 无名剑法蓄力技增伤
```

玩法可以绑定正式流派，也可以选择“自定义”：

- 绑定流派时，属性、主武学、副武学由流派配置自动填充并锁定；派生武器也必须
  与流派一致。玩法差异通过主/副增伤要求表达，不再通过交换武学顺序表达。
- 自定义时，属性和两门武学都可自由选择，适合混搭玩法。
- 备战方案按武学查玩法仍使用无序集合匹配——纯唐和双切可以绑定同一流派，
  再由用户明确选择玩法。

混搭因此仍是“有玩法、无流派”：可以调律，但没有正式流派的毕业率方案。

### 定音要求

| | 词条类别 | 前缀 | 适用部位 |
|---|---|---|---|
| 输出装备 | 外功增益 + 属攻增益 | — | 非防具 |
| 防御装备 | 指定技能增效 | **流派分组** | 冠胄/胸甲/胫甲/腕甲 |

输出/防御的划分**沿用词条类别自己的 `_parts`**，不另建分组——`指定技能增效`
的 `_parts` 就是防具四件，粒度比全局二分更准，加部位时只改配置。

绑定流派时，防御定音直接读取“指定技能增效”中同名的流派分组；自定义玩法展示
该类别的全部词条。不能按武学名前缀过滤：`破竹·樽` 包含
`悬身断水·浓醺技能增伤`、`断水双诀·轻击增伤` 等合法词条，它们不一定以
`悬身拳法`或`断水双诀`这两个武学名开头。

内置输出玩法的两门武学是否需要增伤，以 `data/excel` 毕业率表转换出的
基础方案满值属性为准：对应武器增伤值大于 0 才要求该词条。防御定音也从
同一份满值属性的流派「指定技能增效」中取大于 0 的词条。`纯奶`、`纯唐`、
`飞天玉` 不追求对应流派的最大化伤害，是明确的人工配置例外，不从毕业率表覆盖。

玩法还保存三项受限枚举的说明元数据：全武学增伤是否需要；奇术增伤选不需要、群体或单体；
对单位增伤选不需要、首领或玩家。它们目前**只用于配置和展示**，不进入评级、自动调律或毕业率
计算；评级中的对应取舍仍由调律规则与独立开关决定。

## 4. 规则只引用玩法

```yaml
# tuning_rules/huiyi_general.yaml
playstyles: [无名, 九剑]
```

**规则不能再自定义玩法**——以前同一个「纯唐」在多个规则文件里各写一遍（实测
14 个玩法、跨文件零差异的重复），玩法因此没有唯一归属：用户是纯唐还是双切
只能从「他勾了哪条规则的哪个玩法」反推。

可选的 `switch` 留在规则里：开关控制的是判定口径，属于规则的事。同一个玩法在
不同规则下可以绑不同开关，甚至不绑。当前内置玩法不再自动绑定“保留单体奇术增”，
是否保留完全服从用户选择的独立开关。

规则页的玩法表因此是这样：**只列本规则已引用的玩法**（不把全部铺出来勾选——规则
一多就分不清哪些是真正在用的），定义列只读，唯一可编辑的是「绑定开关」列。增删
引用用「新增玩法 / 删除玩法」，新增时只列尚未引用的。

## 5. 满定音 = 按玩法配齐

`apply_hypothetical_caps(full_dingyin=True, playstyle=...)` 的语义从
「当前定音顶满」改成「换成玩法要求的定音再取上限」：

| | 旧 | 新 |
|---|---|---|
| 输出装备带了无相穿透 | 顶到上限、计入 | **归零**（不是目标定音） |
| 四件防具各定各的音 | 四行各自顶满 | **收敛成一行**同名同值 |

这两个问题不同：旧的答「我的定音满了会怎样」，新的答「我按这个玩法配齐了会
怎样」。后者才是调律方向该对齐的目标。

**没绑玩法时退回旧行为**——方案没绑玩法是正常状态（武学没登记进任何玩法），
不该因此算不出数。

> **已知**：勾选后数字会变（某些归零、某些合并）。这不是算错，是口径从「实然」
> 换成了「应然」。

## 6. 备战方案绑玩法

`LoadoutPlan.playstyle`。候选由两个武学无序匹配得出；武学没登记进任何玩法时
留空——那只是算不出定音目标，方案照常可用，不该硬塞一个玩法给用户
（那等于替他决定怎么打）。
