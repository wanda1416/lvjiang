# v0.11.2 — 应用注册、配置编辑与最优组合增强

## 律匠 v0.11.2

> **发布状态：正式发布。发布日期：2026-09-13。** 本文以 v0.11.1
> 发布完成后的代码树为基线。

本版本继续完善 0.11 系列，不包含架构升级。重点增强 Windows/Android 应用注册、
配置编辑安全性、全部用户参数查看和最优装备组合计算。

### ⚠️ 不兼容变动与升级指引

#### 1. 工作流应用运行状态函数更名

- **现象：** 自定义工作流继续调用 `android_app_running("应用名")` 会提示函数不存在。
- **原因：** 应用控制已统一支持 Android 与 Windows，运行状态查询改为内置函数
  `app_is_running("应用名")`，并根据当前实际连接目标选择平台，不再根据工作流环境判断。
- **如何调整：** 将自定义工作流中的 `android_app_running(...)` 替换为
  `app_is_running(...)`。`app start`、`app stop` 指令名称不变。

#### 2. 应用注册配置升级为双平台结构

- **现象：** 「安卓设置」改为「应用注册」；同一应用现在分别展示 Android 与 Windows
  两组绑定参数。
- **原因：** 一个应用名可以同时绑定 Android 包信息和 Windows 窗口/可执行文件信息，
  工作流按当前实际连接目标调度。
- **如何调整：** 旧 `android_apps` 配置会自动合并读取，无需人工迁移。需要控制 Windows
  应用时，先以窗口模式连接目标窗口，再在应用注册中使用「获得信息」并保存。

#### 3. 游戏、调律与图像识别配置改为显式保存

- **现象：** 修改控件后不再立即写盘；对话框中的「保存」和「撤销」按钮会变为可用，
  直接关闭存在未保存改动时会要求确认。
- **原因：** 旧的逐控件写盘会造成连续 YAML 写入和界面卡顿，也无法可靠撤销一组修改。
- **如何调整：** 完成编辑后点击「保存」。不想保留本次改动时点击「撤销」；无改动时
  两个按钮保持禁用。

#### 4. 用户锁文件集中到独立目录

- **现象：** 新产生的用户数据锁位于 `users/.lock/`，删除用户只从列表和批量配置中移除，
  不再删除该用户的 JSON 数据。
- **原因：** 锁文件集中存放可避免用户目录散落多个 `.lock`；保留数据允许误删后恢复。
- **如何调整：** 无需操作。重新添加同名用户即可恢复保留的数据；旧的相邻 `.lock`
  文件不会再被使用，可在确认程序未运行后自行清理。

### ✨ 新增功能

- 应用注册支持同一应用分别绑定 Android 和 Windows；窗口模式与 ADB 连接会自动记录
  当前应用信息，工作流新增 `app_is_running()` 统一查询函数。
- Windows 应用支持停止、启动和尽力恢复窗口位置；启动通过 Explorer Shell 调度，
  与律匠进程脱离。
- 日常任务增加「全部用户参数」对话框，可按任务与用户快速查看全局/独立参数来源，
  并提供相邻任务切换。
- 最优组合搜索拆分筛选设置与计算设置，支持多选弓玦套装，并新增本赛季原生装备的
  同等级承音假设分支。
- `press ... hold` 支持 `(下限, 上限)` 区间字面量和二元 tuple 变量，每次执行在区间内
  随机取值。

### 🔧 修复

- 修复场景管理直接运行编辑器脚本时不再写入 `_editor_run.wf`，导致运行内容与编辑区
  不一致的问题。
- 配置编辑使用隔离会话，保存前不再污染运行时单例；游戏配置、调律配置、调律规则
  和图像识别统一支持保存与撤销。
- 修复远端配置版本高于系统版本时，调律规则编辑器仍加载或标注旧系统版本的问题；
  游戏配置和调律配置也统一展示本地、系统、远端版本及实际生效来源。
- 最优组合中的假设装备始终关联背包原始装备，组合详情和应用组合不会写入虚拟装备；
  仅在实际执行假设时标注满承音、满定音、满等级或同等级承音。
- 修正鸣金虹打桩工作流的枪 Q 切换与卸势时序，并收拢重复连招为子过程。

### 📦 重构

- Android 与 Windows 应用生命周期统一由应用注册控制器调度，平台选择依据当前实际连接
  目标，而非工作流 `env`。
- 游戏与调律配置编辑改为临时会话提交；普通保存保留系统内容版本，只有显式提升版本
  才能反超正在生效的远端配置。
- 用户数据文件锁集中到 `users/.lock/`，删除用户改为保留可恢复数据。
- 最优组合计算统一使用关联原始装备的虚拟候选，隔离所有属性假设，避免改写背包数据。

### ⚠️ 已知限制

- Windows 目标应用若以高于律匠的权限运行，或拒绝窗口关闭消息，`app stop` 的强制终止
  可能因权限不足而超时。需要控制管理员权限应用时，请以相同或更高权限运行律匠。
- Windows 窗口位置恢复属于尽力而为：只在能重新识别目标顶层窗口且本次运行已记录位置
  时恢复；应用自身的启动布局、跨显示器变化或窗口创建时序仍可能覆盖该位置。

以上两项不影响 Android 应用控制、配置编辑、装备计算及其他主流程，本版本不因此延后。
