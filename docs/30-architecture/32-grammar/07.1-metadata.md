# `.wf` 文件头元数据

`.wf` 文件可以通过文件头部的 `#%` YAML 元数据声明显示信息、运行环境和外部
参数。元数据供脚本发现层和 UI 使用；DSL 引擎仍将这些行视为注释。

## 一、解析边界

元数据必须从文件第一行开始，并且每一行都必须带 `#%` 前缀。解析器遇到
第一行不以 `#%` 开头的内容便结束读取；空行、普通注释和 DSL 语句都会结束
元数据区块，后文再次出现的 `#%` 只是一条普通 DSL 注释。

```text
#% name: 示例脚本
#% env: [android, desktop]
#% note: |-
#%   运行前请确认已经进入目标页面。
#%   确认无弹窗后再开始执行。

# 从这个空行开始均为 DSL 正文，不再解析元数据
log "开始执行"
```

`#%` 后的内容拼接起来必须是一个 YAML 键值映射。前缀前允许缩进，但建议
始终顶格书写。未知字段、YAML 错误、未知参数类型及不合法的字段组合都会抛出
`WorkflowMetadataError`，不会再被静默忽略。

## 二、顶层字段

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `name` | 非空字符串 | 文件 id | UI 显示名 |
| `note` | 字符串 | `""` | UI 中显示的运行说明；可用 YAML 块文本 |
| `env` | 字符串列表 | `[]` | 可运行环境，例如 `android`、`desktop`；空列表表示不限制 |
| `parameters` | 参数列表 | `[]` | UI 控件及注入变量定义，见下文 |
| `scope` | `daily` / `dedicated` | `daily` | 日常脚本或专用脚本 |
| `hidden` | 布尔值 | `false` | 是否默认从日常入口隐藏 |
| `required_scenes` | 字符串列表 | `[]` | 仅兼容临时加载接口；自动发现的脚本由 AST 检查场景依赖，新脚本不要使用 |

顶层不接受表格之外的字段。

## 三、参数公共字段

`parameters` 是参数映射列表。每个参数必须有唯一的 `name`，其命名规则与 DSL
变量一致：以字母、下划线或汉字开头，后续可以包含数字。脚本通过 `$name`
引用该参数。

| 字段 | 要求 | 说明 |
|---|---|---|
| `name` | 必填 | 参数名及注入后的 DSL 变量名 |
| `label` | 可选字符串 | UI 标签；缺省使用 `name` |
| `type` | 可选 | `select`、`number`、`bool`、`checkgroup`；缺省为 `select` |
| `default` | 可选 | 默认值，具体结构取决于 `type` |

参数只允许使用公共字段和其类型专属字段。例如 `number` 中写入 `options` 会
直接报错，以便在加载脚本时发现拼写错误。

## 四、参数类型

### 4.1 `number`

整数输入框。可使用 `min`、`max`，默认分别为 `0`、`999999`；`default`、
`min`、`max` 必须是整数，且默认值必须在范围内。执行时 UI 将值以数字字符串
注入 DSL。

```text
#% parameters:
#%   - name: execute_times
#%     label: 执行次数
#%     type: number
#%     default: 10
#%     min: 1
#%     max: 999
```

### 4.2 `select`

单选下拉框。必须提供非空 `options`；选项可以是字符串，也可以是同时包含
`value`、`label` 的映射。两种形式的值均为字符串。若声明 `default`，它必须
是 `options` 中已有的值。

```text
#% parameters:
#%   - name: target_material
#%     label: 目标材料
#%     type: select
#%     default: purple
#%     options:
#%       - { value: "", label: 不添加 }
#%       - { value: purple, label: 紫色材料 }
#%       - gold
```

执行时注入选中项的 `value`；字符串选项的显示文本和值相同。

### 4.3 `bool`

单个复选框。推荐用 YAML 布尔值 `true` / `false` 作为 `default`；为兼容已有
配置，也接受明确的布尔字符串 `true/false`、`1/0`、`yes/no`、`on/off`。
执行时注入布尔值。

```text
#% parameters:
#%   - name: claim_reward
#%     label: 领取奖励
#%     type: bool
#%     default: false
```

### 4.4 `checkgroup`

一组复选框。必须提供非空 `options`，格式与 `select` 相同；映射选项的
`label` 可省略。`default` 必须是 `{选项值: 布尔值}` 映射，且不能包含
`options` 之外的键。未在 `default` 中列出的选项默认勾选。

```text
#% parameters:
#%   - name: buy_keywords
#%     label: 购买项
#%     type: checkgroup
#%     default: { 心法: true, 武学: false }
#%     options:
#%       - { value: 心法, label: 心法 }
#%       - { value: 武学, label: 武学 }
```

执行时注入 `{选项值: 是否勾选}` 字典，而不是列表：

```text
for kw in keys($buy_keywords)
    if not $buy_keywords.$kw
        continue
    end
    # 处理勾选项
end
```

## 五、在工作流中使用

UI 根据 `parameters` 生成控件，运行时把控件值作为初始变量注入。工作流直接
使用 `$name` 即可。建议同时用 `default` 语句提供无 UI 注入时的兜底值；它
不会覆盖已经注入的变量。

```text
default $execute_times = 10
default $buy_keywords = {"心法": true, "武学": false}

loop $execute_times
    # ...
end
```

动态 Area 同样可以引用参数：

```text
click [bag_equip_detail].$bag_slot
```

数据流如下：

```text
.wf 文件头 #% parameters
       ↓
UI 动态参数面板
       ↓
运行入口收集 params 字典
       ↓
BaseWorkflow.run_file(..., initial_variables=params)
       ↓
WorkflowEngine.variables
       ↓
.wf 中的 $name 引用
```
