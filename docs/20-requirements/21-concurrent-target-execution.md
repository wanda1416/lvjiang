# 多执行目标并发任务

> 状态：需求已确认，尚未实现。
>
> 前置能力：[连接目标与执行目标分离](20-execution-targets.md)。技术设计见
> [多目标并发执行架构](../30-architecture/11-concurrent-execution.md)。

## 1. 目标

律匠已经可以同时保留一个 Windows 窗口和多台 Android 设备，但 0.13.10 仍然只有
一份全局运行状态，一次只能执行一个任务。本需求在不改变既有连接能力的前提下，使不同
执行目标可以同时运行任务。

并发执行是首个 **Lv1 高级能力**。未激活用户继续拥有完整的多目标连接、切换和单任务
执行能力；只有在已有任务运行时，向另一个目标启动额外任务才需要 Lv1。

## 2. 身份与术语

系统只公开两种运行身份：

| 身份 | 含义 | 生命周期 |
|------|------|----------|
| `target_id` | 一个可执行目标的稳定身份 | 目标登记后持续存在；临时断线、重连、窗口移动不改变 |
| `task_run_id` | 一次具体任务运行的唯一身份 | 从任务启动到历史收尾 |

不引入持久化或业务可见的 `connection_id`。连接是 `target_id` 当前绑定的一组截图、输入、
窗口或设备资源；这些资源可以因为断线恢复、设备重启或重新定位而替换，但不会因此产生
新的目标或任务。

- Windows 本机窗口只有一个逻辑目标，固定使用 `target_id=window`。这是输入后端约束：
  SendInput 是系统级前台输入资源，无法按 hwnd 隔离；即使轮流激活窗口，也不能保证两个
  SendInput 任务的鼠标和键盘序列不串扰。PostMessage 理论上可以按窗口隔离，但本需求
  不开放多 Windows 目标。
- Android 可以同时存在多个逻辑目标，每台设备使用不同且稳定的 `target_id`。
- ADB serial、无线调试地址、hwnd 和窗口坐标都是可变连接信息，不得代替稳定目标身份。
- 页面、日志和历史以 `task_run_id` 区分不同运行；`target_id` 只说明任务在哪个执行端运行。

## 3. 并发与互斥规则

1. 一个目标同一时间最多运行一个任务。Lv1 不能绕过目标互斥。
2. 不同目标可以并行运行任务；最大并发数由已连接目标数量决定。
3. Windows 目标只有一个，因此最多贡献一个并发任务；每台 Android 设备各自贡献一个。
   一个 Windows 任务可以与多个 Android 任务并发。
4. 现有跨进程用户执行锁继续生效：同一用户不能同时在两个目标上进入任务。单任务冲突时
   拒绝启动；批量任务沿用逐条目取锁、冲突条目跳过并继续的语义，但必须展示占用原因，
   不能把它混同为“无需执行”。属性单元继续按整组成员加锁。
5. 任务启动时冻结用户、工作流、参数、环境、布局、方案和业务配置；切换主界面观察目标
   不得改变正在运行的任务。
6. 扫描、连接和查看其他目标不因某个任务运行而被全局禁止，只限制会破坏对应运行目标的
   操作。
7. 单任务、专用任务和批量任务最终都必须经过同一套目标占用与运行实例管理，不允许保留
   绕过门禁的第二套全局运行状态。

## 4. Lv1 授权边界

授权判断使用现有等级能力 `has_feature("lv1")`：

- 当前没有任何运行任务时，未激活用户可在任意就绪目标启动第一个任务。
- 已有任务运行时，在另一个目标启动任务需要 Lv1。
- 未激活用户仍可连接多个目标、切换观察目标、预览画面以及停止已有任务。
- UI 入口和实际启动入口必须同时检查，不能只靠禁用按钮防止绕过。
- 激活状态应在每次启动时读取；用户完成激活后无需重启应用。
- 任务启动后授权过期或被清除，不强制中断已有任务，只拒绝后续新增的并发任务。
- 未授权提示应说明“并发执行需要 Lv1”，并提供前往“功能激活”的可行动入口；不能把
  目标误报为未连接或把第一个任务也锁住。

## 5. 主页面交互

### 5.1 目标选择是控制视角

执行目标列表不再代表“全局唯一运行目标”，而是当前正在查看和控制的目标。切换目标：

- 不重建连接；
- 不停止、暂停或修改任何任务；
- 更新左侧执行区、预览、实时日志和控制按钮，使其指向选中的目标；
- 允许在其他目标运行期间选中一个空闲目标并启动新任务。

每个目标行至少展示连接状态和任务状态，例如：空闲、运行中、暂停中、等待重连、结束中。
多个目标运行时，主窗口还应显示总运行数量，不能只用一个全局“运行中”掩盖具体归属。
状态投影应覆盖启动中、暂停中、已暂停、等待重连、结束中、已完成、已中断和失败等过渡或
终态，不能把尚未完成的停止动作提前显示为空闲。

### 5.2 每目标运行草稿

每个目标在本次连接会话中保留独立的待运行草稿，包括用户、工作流、环境、布局、方案和
参数。切换目标时恢复对应草稿；它属于 UI 编辑态，不得覆盖持久化默认配置，也不得反写
已经冻结的运行快照。

目标已经运行时，执行区以只读状态展示其冻结快照和运行状态；空闲目标展示可编辑草稿。
第一阶段不在同一区域混入“下次运行”的可编辑参数，避免用户误认为修改会影响当前任务。

### 5.3 控制动作

- 开始、停止、暂停和恢复只作用于当前选中的目标。
- F9、F10 和暂停热键与主按钮保持同一语义，作用于当前选中目标。
- 切换控制目标后，按钮文字、颜色、提示和状态栏必须同步变化，并明确显示目标名称。
- 本需求不新增“停止全部”热键；如后续增加，应作为独立且需确认的高风险动作。
- 托盘停止动作若保留，必须让用户选择具体任务，或明确标为“停止全部任务”；不能无声
  停止当前主界面未展示的任务。

## 6. 断线、重连与重新定位

临时连接故障不能改变 `target_id` 或 `task_run_id`。

### 6.1 Android

设备异常断连或重启后：

1. 目标保留在列表中并进入“等待重连”；
2. 对应任务停止继续输入，等待目标恢复；
3. 重新连接同一目标时替换其截图、输入、Agent 等底层资源；
4. 原任务从原运行上下文继续，不创建新任务历史；
5. 其他目标及其任务不受影响。

设备的传输地址发生变化时仍应能重绑定原目标。设备发现层必须取得跨 USB/无线连接一致的
稳定设备身份；无线 ADB `IP:端口` 只能作为当前 transport。同一物理设备经 USB 和无线
同时出现时必须归并成一个目标，不能借此绕过目标互斥。无法自动取得稳定身份时，应要求
用户确认重绑定关系，不能猜测为同一设备，也不能静默创建可同时执行的重复目标。

### 6.2 Windows

窗口移动、DPI 或坐标变化通过“刷新位置”更新同一目标的几何信息；任务无需重启。
窗口句柄失效时可以暂停任务并重新定位到窗口目标，成功后继续原任务。
窗口几何是可恢复的 I/O 状态，不属于业务配置快照；每个输入动作开始时读取一份当前几何，
同一动作执行期间保持该份几何不变，避免一次动作前后使用不同原点。

### 6.3 主动断开

运行目标的主动断开属于破坏性操作，必须阻止或明确确认停止该任务。普通网络/ADB 中断属于
可恢复故障，不能自动删除目标或销毁任务页面。

用户暂停和连接等待是两个独立状态：设备恢复后，如果用户此前主动暂停，任务仍保持暂停。
等待重连期间任务仍处于运行生命周期，继续占用目标、用户执行锁和并发名额。用户必须能够
明确停止该任务；不能通过释放占用让仍可能恢复的任务与新任务并行操作同一资源。

## 7. 实时日志

每条任务日志必须携带结构化运行上下文：

- `task_run_id`
- `target_id`
- 目标展示名称快照
- 日志级别、时间和正文

主页面提供：

1. **全部任务**：按时间合并，清楚标注执行目标和任务短 ID；
2. **当前目标/任务**：只显示当前控制视角对应的运行日志。

系统级日志没有 `task_run_id`，仍进入全部视角。不得通过解析正文前缀判断日志归属。
每个任务的独立日志文件继续保留，并按 `task_run_id` 路由，不能只按线程 ID 过滤，因为
工作流将来可能派生自己的后台线程。

## 8. 调律管理

调律管理调整为：

```text
调律管理
├─ 历史记录                 固定第一页
├─ 设备 A · 用户 · 运行中   一次 task_run_id
├─ 窗口 · 用户 · 已完成     一次 task_run_id
└─ 设备 B · 用户 · 已中断   一次 task_run_id
```

- 每次自动调律启动都按 `task_run_id` 新建当前任务页。
- 页面独占进度事件、结果 Store 和界面状态，不能通过“重连到最新 Hub”覆盖旧任务。
- 同一目标连续运行两次调律也必须保留两个页面。
- 任务结束、失败、连接中断或目标关闭后不自动销毁页面。
- 已完成、已中断和失败页面允许用户手动关闭；关闭只销毁当前会话页面，不删除历史记录。
- 当前任务页只保留到本次应用会话结束；跨应用启动的持久结果统一从历史记录读取。
- 任一调律任务形成持久结果后都刷新历史首页，但不得重置其他任务页。

## 9. 任务历史与执行结果

单任务历史增加执行端快照：

- `target_id`
- `target_kind`（`windows` / `adb`）
- `target_label`
- 必要的环境、布局与输入方式快照

历史列表增加“执行端”展示和类型筛选。不得以 hwnd、无线地址或完整设备 serial 作为主要
展示身份。批量任务的子任务记录同样带执行端；批次本身也记录其绑定目标，不能仅靠当前
主界面选择反推。

调律领域历史同步记录 `target_id`、类型和名称快照，便于从调律历史区分不同执行端，但
业务历史仍以调律 `run_id` 为主键。

## 10. 共享资源与交互隔离

- 每个任务拥有独立 WorkflowEngine、停止/暂停状态、OCR 调用上下文和 UI 交互上下文。
- 目标的 capture/input 只能被占用该目标的任务使用。
- 图库、布局和配置等可共享只读数据，但运行中不得重新读取活动 UI 配置替换快照。
- 多个任务请求用户确认时，提示必须标注目标和任务，不能让一个任务关闭另一个任务的
  对话框，也不能阻塞其他目标的停止操作。
- 应用退出时对全部运行实例发出停止请求，分别等待安全收尾；不能只等待当前选中任务。
- 退出等待超时时必须列出未结束任务，并让用户选择继续等待或明确强制退出；不得在没有
  用户确认的情况下销毁仍运行的 QThread 或提前释放其目标资源。

## 11. 分阶段交付

1. 完成稳定设备身份、Android 端口隔离、历史库迁移和安全退出等前置能力。
2. 引入多运行实例与按目标互斥，迁移单任务、专用任务和批量任务，但保持产品入口最多运行
   一个任务。
3. 接入每目标草稿、目标视角控制、结构化日志和任务历史执行端字段。
4. 调律管理改为历史首页和多任务页，完成批量锁冲突展示与跨目标交互隔离。
5. 完成断线恢复、应用退出和所有入口的等价回归后，最后接入 Lv1 并开放第二个并发任务。

在任一阶段中，尚未迁移的运行入口都必须明确保持单任务限制，不能无提示地与新运行管理器
并存并争抢同一目标。

## 12. 验收标准

- 未激活用户可以连接多个目标并正常运行一个任务；启动第二个任务时收到 Lv1 提示。
- Lv1 用户可以让窗口和设备、或两台设备同时运行不同用户的任务。
- 同一目标的第二个任务始终被拒绝；同一用户的并发任务仍被用户执行锁拒绝。
- 切换目标只改变观察和控制视角，不改变任何运行快照。
- 单独暂停、恢复或停止一个目标，不影响其他目标。
- Android 断连重连、设备重启恢复和 Windows 重新定位不改变原 `task_run_id`。
- 同一 Android 设备通过 USB 和无线连接时只产生一个目标；两台同型号设备的展示名称仍可
  明确区分。
- 两台 Android 设备同时使用 scrcpy 和 Agent 时，本地端口与 forward 规则互不覆盖。
- 旧资源产生的延迟帧或断线回调不会污染重连后的目标。
- 全部日志可按任务区分，独立日志和执行结果归属正确。
- 两个自动调律任务同时运行时各有独立页面，结束后页面仍保留，历史均可查询。
- 任务历史能区分执行端，且不依赖当前 UI 选择。
- 同时生成的单任务结果和批量报告使用各自运行 ID 命名，不会互相覆盖。
- 退出应用能停止并收尾全部任务，不遗留仍在运行的 QThread。
