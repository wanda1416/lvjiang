# 任务入口反馈边界

`ui.execution_feedback` 只提供共同的空闲按钮展示和局部提示控件。连接、方案和
启动权限从主窗口既有检查取得；运行状态仍由运行管理器与宿主信号投影。
各任务页面独立负责空选择、执行用户、路线和平台限制，不把本页条件广播为
其他页面的不可执行状态。刷新反馈不读取截图、OCR 或启动预检所需的重型数据。

启动失败按 `execution_scope` 找到页面的 `execution_feedback` 控件；不能按
当前选中的 Tab 归属，以免程序化启动或切换观察页面时提示错页。日常的提示
由主窗口持有。用户租约和既有启动校验照常执行，不因为按钮允许点击解释
原因而放宽启动授权。

提示控件区分可执行性原因和本次启动失败。普通状态刷新不会抹去启动失败；
改变相关选择、切换目标、再次启动或进入运行状态才清除。运行提示不修改
配置、临时运行顺序或已经冻结的执行快照。
