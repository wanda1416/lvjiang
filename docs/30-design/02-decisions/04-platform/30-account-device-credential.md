# 设备 ID 作为重置密码的凭据

> 状态：已实现（2026-11-19，基线 v0.15.18）。

## 1. 问题

账号体系没有自助找回：忘记密码只能由作者手动重置。可作者拿到手的只有「某人报了一个
账号名」——账号名是公开信息，证明不了来者就是这个账号的主人；而重置会立刻踢掉该账号
的全部会话，等于把账号交出去。此前的 admin「重置密码」只要求填新密码，这个环节实际上
没有任何身份确认。

## 2. 凭据选型

用 `devices.id`（客户端 `config/session/instance.id`，32 位十六进制、首次生成后不变），
也就是账号设备列表里那串标识。理由：

- 只有真正用那台设备登录过的人才拿得到，抓不到、猜不到（随机 16 字节）；
- 不需要密码、不需要网络、不随登录态变化——忘了密码的人正是登录不了的人；
- 服务端本来就有这张表，重置与核对都只是查一行，不需要新的存储或流程。

两端的展示位置（同一串标识，不能各编一套）：

| 端 | 位置 |
|----|------|
| PC | 「账户管理」**未登录**时顶部第一行（带复制与「不要泄露」提示）；登录后在「设备管理」每行「操作」列的「复制ID」 |
| Android | 设置页「账户」卡顶部「设备 ID」区块（复制图标按钮 + 等宽整行值 + 换行提示）；登录后「在线设备」明细每台也可逐一复制 |
| 网页 | 设备列表条目的 tooltip 已带设备标识（既有行为，未改） |

## 3. 服务端做法

- `/admin/accounts/reset_password` **必带** `instance_id`：缺失或形态不符 → 400
  `device_required`；查不到这台设备 → 404 `device_unknown`；设备属于别的账号 → 403
  `device_mismatch`。三种都**不写密码**。
- 已 `revoked` 的历史设备行仍算数：被踢下线的人往往正是来求重置的人；回执里如实标
  `revoked`，让管理员心里有数。
- 预检 `/admin/devices/verify`（**只查不改**）：返回设备名 / 平台 / 最近活跃 / 是否被踢，
  与控制台「校验」按钮配合，管理员在填新密码之前就知道这串 ID 对不对。
- 判定只有一处实现（`deviceCredential()`），重置与预检同源，避免两套口径漂移。

## 4. 被否决的方案

| 方案 | 否决原因 |
|------|----------|
| 只在控制台做界面校验 | 界面不是安全边界：直接调接口即可绕过，而重置是最危险的动作 |
| 新增「列出某账号设备 ID」的管理接口 | 管理员本就有 `ADMIN_TOKEN`（能直接改库），多一个接口只扩大暴露面；查 `devices` 表即可 |
| 邮件 / 短信验证码 | 账号体系刻意不引入邮件服务；一次性登录码适合「临时进入」，不适合「证明是谁」 |
| 让用户报「最近登录时间」这类软信息 | 可猜、熟人可知，强度远低于随机 32 位标识 |

## 5. 边界

- 设备 ID 是**证明身份**的凭据，不是密码：泄露它不能直接登入账号，但足以冒名求重置。
  因此两端都提示不要外泄，Android 复制时把剪贴板内容标为敏感（系统浮层不预览原文）。
- 同一台机器可能有多个实例（源码版 / 安装版），各有各的 `instance.id`；用户要报的是
  **他正在用的那个实例**的 ID。
- 账号注销后设备行随之删除，该 ID 失效——这是预期行为，不是 bug。
- 重置后全部会话失效，用户在新的任一端用新密码登录即可；同 `instance_id` 重新登录会
  就地复活设备行（既有逻辑，不复用旧的已撤销会话）。

## 6. 回归点

- `server/test/worker.test.mjs`：缺 ID / 不存在 / 别人的设备 / 历史 `revoked` 设备四种情形，
  预检与重置同码。
- `admin/tests/accounts/`：请求必须带 `instance_id`；拒绝原因翻成可执行中文；对话框未校验
  不能提交、校验失败红字说明、改 ID 作废上一次结论、形态不符不发请求；服务端未部署时
  404 不得译成「账号不存在」。
- `tests/ui/test_account_device_id.py`：PC 未登录顶部行可见可复制、登录后隐藏、设备管理
  行内「复制ID」复制的是该行设备。
- `tests/core/account/test_devices.py`、`tests/core/ondevice/test_ondevice_account_status.py`：
  在线窗口口径（心跳 10 分钟、窗口 20 分钟）、`instance_id` 恒在状态里、设备列表的本机与
  在线标记、「首次出现」缺失时不编造。
