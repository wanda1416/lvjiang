## 一、装备处理

### to_equipment — 装备解析

将 OCR 原始扫描结果解析为标准装备字典，支持链式字段访问。纯基于 OCR 文字分析，不依赖场景信息。

```
scan [equip_weapon_detail] as $scan_result
eval $main_weapon = to_equipment($scan_result)
collect $main_weapon
```

返回字典字段：`type`、`level`、`quality`、`base_attr`（嵌套 dict）、`affix_1`~`affix_5`（嵌套 dict）等。支持链式访问：

```
if $main_weapon.affix_1.value > 100
    log "首词条数值超过 100"
end
```

### make_fingerprint — 装备指纹

基于 type + level + quality + chengyin + 全部词条(name:value) 生成 MD5 前 8 位 hex 指纹。空数据返回空字符串。

```
eval $equip = to_equipment($scan)
eval $fp = make_fingerprint($equip)
```

### affix_cap / chengyin_cap — 词条上限查询

根据词条名和装备等级查询数值上限。`affix_cap` 返回上限值，`chengyin_cap` 返回承音值（上限的 94%）。自动映射词条名（如 "最大外功攻击" → "外功攻击"），找不到返回 0。

```
eval $equip = to_equipment($result)
eval $cap = affix_cap($equip.affix_1.name, $equip.level)
if $equip.affix_1.value > $cap
    log concat($equip.affix_1.name, " 超标")
end
```

### is_good_equip — 装备初筛

基于 OCR 扫描结果中的词条文本，检查是否包含 ≥ 2 条高价值词条（大外攻、会心、会意、三率、劲、敏、势、武学增效、首领增伤）。

```
scan [equip_weapon_detail] as $result
if is_good_equip($result)
    collect $result
end
```

### evaluate — 装备评估

使用当前流派规则（`config/system/rules/` 下第一个 .yaml）进行完整评估，返回评级结果字典。

```
eval $equip = to_equipment($scan)
eval $result = evaluate($equip)
if $result.rating equals "heirloom"
    log "传家宝！"
end
```

返回字段：`rating`（评级）、`disqualified`（是否取消资格）、`details`（详情列表）等。

## 二、背包遍历

用于 grid 滚动遍历场景的指纹管理三件套，配合 `check_scroll` → 处理 → `notify_scroll` → `scroll_advance` 流程使用。

### check_scroll — 滚动校验

比对 grid[1][1] 指纹与滚动管理器预期，返回偏移量：
- `"0"` — 正常
- `"1"` — 没有滚动
- `"-1"` — 滚动过头

```
eval $offset = check_scroll($fp)
```

### notify_scroll — 记录指纹

记录已处理装备的指纹。每行第一列（col=1）的指纹自动记录为行指纹。

```
eval notify_scroll($col, $row, $fp)
```

### scroll_advance — 推进状态

校验通过后调用，移除已滚出的行指纹。

```
eval scroll_advance()
```

## 三、玩家档案函数

访问 ProfileDB（玩家档案数据库）的内置函数，支持 quota / regen / stock / note 四模型，
可读可写。函数清单与详细说明见 [09-data-channels.md](09-data-channels.md#八profile--玩家档案独立数据源)
与 [06.2-system-interaction.md](06.2-system-interaction.md#三玩家档案函数)。

```dsl
# 读取配额
eval $remain = profile_get("niaoniao_of_week")

# 消耗体力（realtime regen，自动处理时间锚点）
eval $tili = profile_inc("tili", -900)

# 查询模型类型
eval $model = profile_model("tili")    # "regen"

# 批量获取
eval $all = profile_all()
```

## 四、综合示例

### 装备扫描 → 解析 → 评估 → 收集

```
scan [equip_weapon_detail] as $scan
eval $equip = to_equipment($scan)
eval $fp = make_fingerprint($equip)

# 指纹去重
if $fingerprints.$slot equals $fp
    log "重复装备，跳过"
else
    eval append($fingerprints, $slot, $fp)
end

# 评估
eval $result = evaluate($equip)
eval $total = count_nonempty($result)
log concat("评级: ", $result.rating, " 详情数: ", $total)
```

### 字典变量聚合

```
eval $summary = {}
eval $summary.total_affixes = count_nonempty($scan_result)
eval $summary.status = "done"
collect $summary
```

## 五、背包扫描游标与装备入库

这一组函数服务于「滚动遍历背包并入库」的完整流程，与前面的滚动三件套互补：
三件套判断「滚动是否正常」，游标三件套判断「这一行有没有看过」，入库函数负责落库。

### bag_cursor_* — 背包扫描游标

游标状态保存在 `context._bag_cursor`，因此天然跨子过程共享
（见 [09-data-channels.md](09-data-channels.md#二context--运行时共享)）。

| 函数 | 签名 | 说明 |
|------|------|------|
| `bag_cursor_init` | `() -> ""` | 初始化游标（`seen` / `window` / `new_count` / `idle` / `rounds`）；重复调用会清空既有游标 |
| `bag_cursor_visit` | `(fingerprint) -> str` | 登记行首锚点指纹，返回 `"new"`（新行，需逐列读取）/ `"skip"`（整行已扫过）/ `"end"`（未初始化或指纹为空） |
| `bag_cursor_finish_window` | `(visible_rows, expected_rows) -> str` | 提交一个完整窗口，返回 `"scroll"`（继续滚动）或 `"end"`（到底） |

`bag_cursor_finish_window` 判定「到底」的规则：空窗口、非满窗且零新增、满窗连续 2 轮零新增、
滚动轮数超过 200 轮，任一成立即返回 `"end"`。

```text
eval bag_cursor_init()
scan [bag_item_detail].[bag_grid] as $grid
for r in [1...3]
    eval $fp = $grid.$r.[1]
    if bag_cursor_visit($fp) equals "new"
        # 逐列处理这一行……
    end
end
eval $next = bag_cursor_finish_window(3, 3)
if $next equals "end"
    log "已到背包底部"
end
```

### write_bag_item / write_equipped — 装备入库

| 函数 | 签名 | 说明 |
|------|------|------|
| `write_bag_item` | `(group_key, dict) -> str` | 把背包装备写入用户装备库，返回写库指纹；参数必须是字典，且 `type` 与 `group_key` 不一致时抛 `ValueError` |
| `write_equipped` | `(slot_key, dict) -> str` | 把装备写入「当前生效方案」的指定槽位，返回指纹；生效方案 ID 缓存在 `context._bound_loadout_plan_id` |

两者写库后都会广播「装备变更」事件，UI 侧无需轮询。

```text
eval $fp = write_bag_item("weapon", to_equipment($scan))
log concat("已入库: ", $fp)
```

### to_role_base_attrs / open_base_attr_form — 角色基础属性

| 函数 | 签名 | 说明 |
|------|------|------|
| `to_role_base_attrs` | `(dict) -> dict` | 解析角色详情页滚动识别的 OCR 原始数据（`left_*` / `right_*` 键）为基础属性字典；输入为空或解析失败返回 `{}` |
| `open_base_attr_form` | `(dict) -> null` | 触发 UI 弹出「创建基础属性」面板并预填数值，不等待确认、不阻塞工作流；无 UI 回调时静默返回 |

```text
scan [role_detail].[left_1, right_attack] as $raw
eval $attrs = to_role_base_attrs($raw)
if not $attrs is_empty
    eval open_base_attr_form($attrs)
end
```
