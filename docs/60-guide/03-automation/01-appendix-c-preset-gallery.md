# 附录 C · 预置图库内容（端游 / 手游）

这份附录回答一个问题：**系统随包带了哪些参考图——端游和手游各有什么，哪些是两边共用的。**

改图、加图、调分组请见 [3.3 图库管理](../04-desktop/03.03-gallery-management.md)；参考图匹配算法与
命中失败的含义见 [37-vision/01-perception-channels.md](../../30-design/01-architecture/08-vision/01-perception-channels.md)。

数据来源：`config/system/references/{desktop,android}.yaml` 与同名图片目录（本文用界面上的中文名「端游 / 手游」称呼对应 key `desktop` / `android`）。图片按分组分目录
存放（`{空间}/{分组}/{文件名}.png`，目录名即分组名），文件名来自内容哈希，**不代表语义**；
分组归属只以 YAML 的 `group` 字段为准。用户层可单张覆盖：`config/local/references/{空间}/{分组}/同名文件`。

---

## 一、两个空间共有的规格

| 项目 | 端游 | 手游 | 说明 |
|------|------|------|------|
| 条目结构 | `file` / `label` / `meta` / `source` / `notes` | 同左 | 一致 |
| `meta_schema` | `level`（input，number，降序）、`level_text` / `count_text`（output，OCR） | 同左 | 字段、类型、排序与裁剪区域完全一致 |
| 输出字段裁剪 | `level_text` 取上部 `y=0~0.5`，`count_text` 取下部 `y=0.5~1` | 同左 | 一致，见「图像识别」输出 |
| 分组（目录） | 调律材料 / 定音转律 / 装备培养 / 货币资产 / 普通道具 / 增益道具 | 同左 | 同名同义，界面按此展示 |
| 匹配阈值 | 0.35（YAML 显式写出） | 未写（用默认 0.35） | 生效值相同 |
| 匹配方式 | ORB 特征（`recognize`），非模板定位 | 同左 | 与 `by image` 的模板匹配是两套东西 |
| 图片目录组织 | `{空间}/{分组}/*.png` | 同左 | 写入时图片跟随第一个分组 |

两条对使用者有实际影响的共同约定：

- 分组是**筛选维度**：脚本里 `recognize ... on group "调律材料"` 只会在该分组的参考图里比对，
  与图片所在目录无关；
- 等级（`level`）是**输入元数据**，用于区分同一物品的不同阶外观，不参与匹配计算。

两边的收图策略不同，这决定了「共同 / 差异」怎么来的：

  五个等级各存一张同 label 的图（同名多条目），因为不同阶的材料图标有细微差别；

- **货币资产方向相反**：手游把大量代币、票券类图标都归到货币资产（25 张），端游只收了
  8 种主要货币。

## 四、工作流与自动调律实际用到的 label

**改 label 前先看这一节。** label 是识别结果里的字符串键，脚本和自动调律用它做等值比较；
改了名字却没同步改引用，表现是「静默不命中」——识别照常跑，只是永远匹配不上，不报错。

引用强度分三档：

| 档 | 含义 | 改名的后果 |
|---|---|---|
| 精确绑定 | 脚本/代码写死 label 字符串做等值比较 | **必须同步改引用**，否则该功能静默失效 |
| 整组候选 | 只写了 `on group "分组"`，组内所有 label 都进候选集，label 本身不再被比对 | 改名安全，只是识别结果里的 label 值跟着变 |
| 未点名 | 随包分发，当前没有 wf / 自动调律按名字依赖它 | 只影响 F4 的手动识别与用户自写脚本 |

### 4.1 工作流（`config/system/workflows/*.wf`）

| 引用点 | 分组 | 写法 | 精确绑定的 label |
|---|---|---|---|
| `daily_jianghu.wf` 战斗饮酒 | 增益道具 | `recognize … by equals "黄泉酿" on group ["增益道具"]` | **黄泉酿** |
| `purchase_xinfa.wf` 打开心法心得箱 | 普通道具 | `recognize … by equals "心法心得" on group "普通道具"` | **心法心得** |
| `scan_wallet.wf` 钱袋取值 | 货币资产 | `recognize … as rich on group "货币资产"`，随后 `$cell.label == "<名>"` | **么玉、宝钱、长鸣玉** |
| `scan_wallet.wf` 通宝区域累加 | 货币资产 | 对 `money_1`（1×4 格）里**任何**命中 label 的数量直接求和 | —（不比名字，注释写明该区域应是宋元通宝/月华通宝/周元通宝/墨筹） |

> 提醒：`money_1` 的累加不按 label 过滤，它假设该 1×4 区域只会出现四种通宝。
> 如果换到货币 label 更多的空间（手游比端游多 17 种），而该区域出现了别的货币，
> 会被误计入「通宝(万)」。要收紧就得在 `money_1` 的累加处加 label 白名单。

### 4.2 自动调律（yysls，Python 工作流）

自动调律只用 **`调律材料`** 一个分组：材料区一次识别后按 label 精确取用。

| 常量 / 配置 | label | 用途 |
|---|---|---|
| `STONE_LABEL` | **大律准石** | 材料数量基准（1 枚按 10 单位记，对应 0.1 枚账本） |
| `SMALL_STONE_LABEL` | **小律准石** | 在场时材料区槽位易失，缓存只用一轮 |
| `FOOD_LABELS` | **金狗粮、紫狗粮、彩狗粮** | 狗粮规则表 `food:` 的合法取值（超出即报错），添加时按 label 取库存 |
| `base_groups/*.yaml` 的 `food:` | 彩狗粮 / 金狗粮 / 紫狗粮 | 预置规则组实际喂的狗粮，取值受上一行约束 |

代码位置：常量在 `apps/yysls/core/tuning_rules/models.py`；分组名在
`workflows/implementations/auto_tuning.py`（`MATERIAL_GROUP = "调律材料"`）；
识别与取用在 `workflows/implementations/tuning/executor.py`。

### 4.3 只作为候选、没有 label 判定

- **货币资产全组**（端游 8 / 手游 25）：全部进候选集，除 4.1 点名的三个外，代码不按名字依赖任何一项；

## 七、怎么维护

- **加图 / 换图**：F4「图库管理 → 新增参考图」，导入或截图后填 label 与分组；图片会自动落进
  该分组目录。
- **改分组**：在图库管理里改「分组」字段，图片会跟着移动到新分组目录。
- **不要改文件名**：文件名是内容哈希，`file` 字段与图片一一对应；要替换图请覆盖同一 label
  的记录，而不是在磁盘上换名。
- **用户层覆盖**：只想换掉某一张而不动系统内容，把同名文件放到
  `config/local/references/{空间}/{分组}/` 下。
- 目录名和分组名必须一致，且分组名不能是保留目录 `default`（未分组参考图的存放位置）。
- **等级等 `number` 字段写数字**：界面里按文本提交也会在写入时自动转成数字；
  手工改 YAML 时不要写成 `'110'` 这种带引号文本，否则按等级筛选会失配。
