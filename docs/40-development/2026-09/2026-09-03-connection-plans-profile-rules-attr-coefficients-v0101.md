## 一、机器级连接方案（plans）

方案把**图库、环境、布局和连接模式**绑成一个具名整体。它描述「这台机器怎么连游戏」，与用户无关，所以存 `session.json` 的 `plans` 节点、选中项存 `actives.plan`。

### 1.1 存储层（`34276086`）

顺带两处修正：

- `actives` 的 kind 校验从 `_ACTIVE_LEGACY_KEYS` 拆成独立的 `_ACTIVE_KINDS`——plan 没有旧顶层键，不必伪造一个 `active_plan`；
- `save_env` 改走 `update_node` 浅合并；原先 `load_settings` + `set_node` 会把**读盘到写盘之间别人写进 `settings` 的键整体覆盖掉**。

### 1.2 顶部选择器与锁定（`bc4fb8ee`、`1ba9a2a6`）

单个 `_batch_locked` 布尔改成**按原因计数的锁**：批量结束时的无条件解锁会把方案锁一起解掉。同时把图库选择器升级成可锁类型——方案要锁的正是图库、环境、布局这三个。批量锁的范围保持不变。

方案下拉默认「- 自定义 -」，选中已存方案后自动填充并锁定三者，切回自定义则解锁并**还原进入方案前的组合**。启动按 `actives.plan` 恢复；方案被删或引用的图库/环境/布局已不存在时降级回自定义，并在日志里说明是哪一项，不静默吞掉。

批量锁顺带覆盖方案下拉——切方案会连带改环境和布局，等于绕过那把锁。

### 1.3 连接模式不匹配时阻止执行（`f84e6764`）

「开始执行」加第四态：已连接但当前方案不声明这种连接模式时按钮变灰、文案「方案不支持」。

**灰是样式不是 `setEnabled(False)`**——禁用的控件收不到鼠标事件，点了不会有任何反馈；现在点击会在左下角状态栏说明是哪个方案不支持哪种模式。

灰按钮只挡主界面点击，另外三个入口一并堵上：F9 和托盘「开始」走 `_on_start`，插件 Tab 的按钮走各自订阅的状态。**三个 `automation_state_changed` 订阅方原本都用 `else` 兜底，新状态会被当成「就绪」**——托盘的开始还亮着，调律 Tab 的 `else` 分支还会 `mark_done()` 误报完成。

### 1.4 方案设置 Tab（`a3d833b7`）与表单回写 bug（`2511eb4c`）

「系统参数」Tab 改名「方案设置」，上半新增方案管理，下半保留原系统参数（可用环境列表）。「从当前组合新建」直接取主界面手上那套组合，是存量用户迁移成本最低的一条路。

**`2511eb4c` 修的是个典型的「表单显示与对象内容脱节」**：新建方案时表单显示「手游/安卓/默认布局」，方案对象里三项却是空串——表单是在 `blockSignals` 里填的，编辑回调压根没触发，而 `max(idx, 0)` 又会把空值静默显示成第一项。保存后主界面选中该方案，`_apply_plan_context` 因为值为空全部跳过，表现就是「切换方案，三个框没跟着变」。改为**填完表单后回写方案，所见即所存**。

## 二、五维换算系数修正（`8b71bb15`，数据正确性事故）

劲/势/敏 → 战斗属性的换算系数是早期自行拟合的，**敏被高估约 11%**（1.0 小外攻，正确值 0.9）。

**判据**：一条满值五维词条产出的各项，按各自词条满值归一后应相加为 1。错误系数下敏为 1.044，超过一整条词条，不可能成立。修正值同时得到国服实测与 where-builds-meet 国际服数据的印证——两个不同服、不同等级给出同一组数，证实系数与等级无关。

### 2.1 为什么一直没被发现

影响经装备聚合扩散到词条边际收益、最优组合与战斗属性展示；更要紧的是**反推路径**——基础属性由「面板 − 装备」得出，装备侧算多了，存下的基础属性就等量偏低。**用同一套装备算毕业率时两处误差相抵**，所以数字看着正常，一换装备才暴露。

### 2.2 处置

已存的基础属性无法自动补偿：创建时只保存了反推结果，没有面板值与装备快照。所以需要用户重填一次。

> `429f30e0` 随后**移除了版本标记**：最初加了版本号字段 + UI 过期提示，权衡后判定这类一次性标记会长期留在数据里且没有清理路径，改为只在发布说明与用户手册里讲清楚影响范围（排序类结论仍然正确，受影响的是毕业率绝对值）。

补齐了五维转换的测试：**归一不变量把系数与 `affix_caps` 绑在一起**，任一侧漂移都会红灯——此前这组系数零覆盖，改动不会触发任何失败。

## 三、Profile 快捷规则可视化（`0182b2e4`、`fb29094c`、`5da643b4`、`ee6560b6`、`ab0c6f56`）

原来的「增减幅度」是一段自由文本，靠中英文逗号、冒号分隔解析，混用就炸。改为结构化变动规则：

- 可直接选择「用途（减少）」或「来源（增加）」，并为同一来源/用途录入多个快捷数量；
- 来源、用途和快捷数量改为**按 Enter 创建的可删除标签**，绕开分隔符解析；
- 变动规则与同步目标之间可纵向拉伸；标签超出一行时提供横向滚动；
- 快捷菜单按「快捷用途 → 快捷来源 → 增加/减少/覆写 → 历史记录」分组，仅在非空分组之间加分隔线。

**继续使用既有 `sources`、`uses` 和 `steps` 数据结构**，保存时自动合并回兼容形态，旧 Profile 定义无需迁移。

`9d5b0d3f` 给标签 chip 里的「×」登记样式豁免：它由 `QFrame#profileTagChip QPushButton` 规则统一着色，本身就是 chip 视觉的一部分；套通用按钮样式会在 18px 的 chip 里塞进一个带底色和内边距的独立控件。静态扫描看不到容器样式表，与 `alert_panel` 的关闭按钮属于同一类。

## 五、i18n：领域值与翻译解耦（`87de07e1`）

延续 08-27 与 08-29 的同一条线。流派、部位、武器和装备词条等**领域值**不再随界面翻译后写入或参与规则校验——此前切换英文后，基础规则组会因为「全部」等值无法识别而**加载失败**。

至此这条线上已经修过三轮：`parse_number` 的「万」（08-27）、材料 label（08-29）、领域值（本轮）。共同判据是：**凡是要与 OCR 文本、参考图 label、配置枚举比对的字符串，都是数据键，不是界面文案。**

## 关键设计决策

1. **方案是机器级配置，不随用户切换**：所以存 `session.json` 而非用户档案。
2. **锁改为按原因计数**：单布尔在两个来源（批量 / 方案）同时锁定时必然互相解掉对方。
3. **不可用状态用样式变灰而非 `setEnabled(False)`**：禁用控件收不到点击，用户得不到任何解释。
4. **新增状态必须逐个订阅方检查，不能靠 `else` 兜底**：三个订阅方都会把未知状态误认为「就绪」。
5. **表单所见即所存**：`blockSignals` 填表 + `max(idx, 0)` 兜底会让显示值与对象值静默脱节。
6. **系数类常量必须有不变量测试**：归一相加为 1 把系数与词条上限绑在一起，任一侧漂移即红灯。
7. **不给数据加一次性版本标记**：没有清理路径的标记会永久留在用户数据里；影响范围写进发布说明即可。
8. **数据键不过 `tr()`（第三轮）**：领域值参与规则校验，翻译它会让英文界面下规则加载失败。
