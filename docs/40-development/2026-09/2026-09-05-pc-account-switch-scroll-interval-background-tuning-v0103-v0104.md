## 一、批量 PC 端账号切换

此前批量任务只能在安卓端切号，端游走不通。

### 1.1 PC 分支与登录页布局校准（`8685fdf7`）

`prepare_item.wf` 的 `switch_account` 按 desktop / android 分支：PC 端先登出再触发选择账号，安卓端直接切换。桌面登录页的 enter / 确认 / 返回登录补充 `activation_key`（SPACE / F）。

同一提交把登录页的 `users_icon` 改名为 `user_icon`——登录页只有一个用户图标，复数 key 是笔误。这条进了 v0.10.3 的不兼容变动第 1 条：**`config/local` 无条件优先于 system，系统这份修正到不了改过登录页布局的用户**，他们会看到「区域未绑定坐标: user_icon」。

### 1.2 角色判据与在线校验（`923008b1`、`5d58cee4`、`76a9bc1e`）

三处修正，前两处两端同时中招：

1. **`select_role` 的「当前角色已就位」快捷判据是测试时硬编码写入的角色名**。同账号多角色批量时，上一条跑完留在登录页的角色名会让下一条误认已就位，直接点进上一个角色，还把 `batch_state.role` 记成目标角色——**静默跑错角色且状态污染**。判据改回 `$role`。
2. 点 `current_role` 同样会弹「其他角色在线」二次确认，而该快捷路径**绕过了原有的在线校验**。把校验抽成 `handle_role_online()`，两条路径共用。
3. `switch_account` 按 env 分了 desktop / android 两支**且无兜底**，环境取到其他值（含 UI 未选中时的空串）会让两支同时落空，表现为切号步骤静默不执行。入口加 `check_env(["android", "desktop"])` 直接卡死。

`5d58cee4` 进一步把在线判定从「扫 `confirm` 弹窗判『其他角色』」改为**登录页自己的 `online_label` 区域**——原来靠弹窗文案判断，文案一变就误判。`76a9bc1e` 给 PC 端登出识别补兜底判据：`scan switch_user` 判「登出」失败时回退 `scan login` 判「进入游戏」，两者都识别不到则判定尚未登出，避免登出按钮 OCR 太浅漏识别导致切号卡住。

### 1.3 登录页改为跨场景引用（`7e2fa9d4`）

`cancel` / `confirm` 改为引用 `general_control`，两套布局里同名的残留坐标一并清掉；不再使用的 `user_2` / `user_3` 移除。这是 08-30 引用场景机制的第一次实战收益。

## 二、布局加载期丢弃孤儿坐标（`e71c0ee1`）

删除区域定义只改场景 YAML，**布局 JSON 里的坐标不会跟着走**；保存路径又只过滤带 `source_scene` 的引用项，残留记录于是永久留存。

它在编辑器列表中根本不显示（列表按场景定义遍历），运行期却照常参与查表，还会**把同名跨场景引用的展开顶掉**——引用从此指向一份再也不会同步的陈旧坐标，而且完全静默。

改为加载期在内存中丢弃并打日志：

```
布局中 <场景> 有 N 条坐标已无场景定义，已丢弃: <key 列表>
```

**不改写用户的布局文件**。若日志点名的 key 仍在使用，在场景管理中把区域定义补回来，坐标会重新生效。

## 三、DSL 补完

### 3.1 `scroll` 新增 `interval` 参数（`2ea9d8ed`、`6aa7671d`）

`scroll [target] up|down N interval S`：指定后逐格之间用固定间隔取代默认 20~50ms 随机间隔；**仅对逐格发送事件的桌面后端（SendInput / PostMessage）生效**，ADB / 设备端忽略。

`6aa7671d` 把非法值改为降级而非中断：`interval` 只影响逐格滚动的节奏、不影响滚动是否发生，为它抛 `WorkflowUserError` 中止整条批量任务不划算。非数值和负数（负数原本能过解析，落到 `time.sleep` 会抛未包装的 `ValueError`）现在统一记 error 后回退默认间隔。

### 3.2 实参位支持容器与常量字面量（`c1075128`）

grammar 的 `arg`（内置函数实参）与 `call_arg`（过程实参）原本各写各的分支，只认字符串 / 数字 / 变量 / 字段访问。后果是 `check_env(["android"])` 这种**连 builtin 自身 docstring 都在示范**的调用在实参位解析不过，只能先 `eval` 到变量再中转。

现在两处对齐到同一套分支，都支持 `[]` / `{}`（可嵌套）/ `null` / `true` / `false` / `(x,y)` / `(x,y,w,h)` 元组。**引擎侧无需改动**：`_resolve` 早有 dict/list 递归分支，缺的只是语法入口。

顺带修掉 `list_literal` 的**空列表 bug**：只滤了 `_MISSING`，没滤 lark 为可选组填的占位 `None`，导致 `[]` 求值成 `[None]` 这个长度 1 的**真值**列表——`eval $x = []` 之后 `if $x` 由假变真、`for i in []` 由不循环变成循环一次。

## 四、PC 后台调律与角色扫描（v0.10.4）

### 4.1 后台兼容滚轮策略（`c9b91ba8`）

自动调律新增「PC 端兼容后台模式」。启用后背包翻页使用 `scroll [bag_equip_detail].[bag_grid] down 1` 等价能力代替拖拽，使 PostMessage 后台输入可用；关闭时继续使用更精准的拖拽。Android 始终使用原有拖拽流程。

背包移动拆分为 `DragBagScroll` 与 `WheelBagScroll` 两个策略，**自动调律只选择并调用策略，不在业务流程中散布环境判断**；通用 `scroll` 能力下沉到基础工作流 action，DSL 引擎与 Python 业务工作流共享同一实现。

> **已知限制（写进发布说明）**：PC 后台滚轮不要与非默认的 `positional` 遍历策略同时启用——`positional` 的位置校正依赖四分之一行的精准拖拽，而后台滚轮一次只能移动一个刻度。

调律配置由「规则 / 部位 / 更多」整理为「规则 / 参数」两页，并新增「启用位置校验遍历策略」复选框（默认不勾选，使用 `dedup`）。

### 4.2 角色属性扫描改滚轮（`7f0373ec`）

PC PostMessage 模式下角色基础属性扫描依赖拖拽、无法在后台稳定执行，改为滚轮逐格滚动；Android 流程不变。这条同样会被 `config/local` 的工作流覆盖遮蔽。

## 六、诊断能力：`scan by` 未命中时记录实际 OCR 文本（`585872e4`）

原来只有命中那条打印 text，未命中只记 key 列表。于是三种完全不同的成因在日志里长得一模一样，只能靠猜：

1. 框标歪了读到别的字；
2. OCR 把标签拆成多个检测框、被 `' | '` 分隔导致 `contains` 落空；
3. 整个框一个字也没检出。

改成未命中时一并打印 target 和每个区域实际读到的文本，成因当场可辨。纯诊断改动，匹配逻辑、返回值、控制流均未变动。

## 关键设计决策

1. **判据取最直接的那个信号**：角色是否就位用 `$role` 而非缓存的角色名，是否在线用 `online_label` 而非弹窗文案。
2. **按 env 分支必须有兜底**：两支都不命中会表现为「静默不执行」，入口 `check_env` 直接卡死比后面出怪事强。
3. **孤儿数据在加载期丢弃、不改写用户文件**：它会静默顶掉跨场景引用，但清理用户文件不是加载器的职责。
4. **只影响节奏的参数，非法值降级而非中断**：为它中止整条批量任务不划算。
5. **环境差异走策略对象，不散落在业务流程里**：`DragBagScroll` / `WheelBagScroll` 让自动调律只管选策略。
6. **不要用与 Qt 内建信号同名的自定义信号**：`finished` 遮蔽后 `deleteLater` 会挂错时机，主线程销毁运行中的线程直接崩。
7. **诊断日志要能区分成因**：只记「未命中」的日志等于没有日志。
