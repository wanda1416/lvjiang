# v0.12.0 — 布局体系升级

## 律匠 v0.12.0

> **发布状态：预发布。发布日期：待定。** 本文以 v0.11.2 正式版为基线，
> 内容会随发布准备继续更新。

### ⚠️ 不兼容变动与升级指引

#### 1. 布局清单直接切换为 schema v2

- **现象：** `layouts.yaml` 现在必须声明 `schema_version: 2`；布局使用稳定
  key 保存，中文名称只用于展示。系统预置 key 为 `android`、`android_cast`
  和 `desktop`，原「默认布局」改名「安卓布局」，原「继承布局」改名「投屏布局」。
- **原因：** 展示名不再兼任目录名和持久化引用，后续可以调整界面文案而不
  改变数据身份。新建/另存为会同时要求唯一 key 和唯一名称，另存为不再
  允许覆盖已有 key。
- **如何调整：** 本次不提供自动升级。升级前备份 `config/local`，删除旧的
  `config/local/layouts.yaml`，不要把它整份覆盖回新版。如需保留预置布局的
  本地标定，请手动将 `layouts/默认布局/` 和 `templates/默认布局/` 的内容复制到
  对应的 `android/` 目录，将「桌面布局」目录的内容复制到 `desktop/`。自定义
  布局请先在新版界面中使用新 key 创建，再将原场景 JSON 和模板按 key 复制到
  新目录。如需保留场景编辑器底图，同样将
  `config/session/screenshots/默认布局/` 和「桌面布局」目录分别复制为
  `android/` 和 `desktop/`；升级后重新选择一次连接方案。

#### 2. 自定义 WF 脚本需声明运行属性

- **现象：** 脚本发现改为递归扫描 `workflows/` 后，不再根据顶层或
  `standalone/` 目录判断脚本是否可运行。未声明属性的 `.wf` 不会出现在
  日常任务和批量任务列表中。
- **如何调整：** 如果曾自行编写 `.wf` 脚本，请手动在文件开头连续的
  `#%` 元数据区加入 `#% runnable: true`。如需允许进入批量任务，再加入
  `#% batchable: true`。`batchable: true` 本身也隐含可独立运行。如果声明
  `id`，允许使用以 Unicode 字母开头的字母/数字/下划线标识符（包括中文）。
- **升级策略：** 本次不自动扫描或改写用户脚本，也不提供兼容迁移。

### 📦 重构

- 布局的持久化身份与显示名称分离，内部引用、布局目录、模板目录和截图目录统一使用
  不随展示文案变化的布局 key。
- 系统预置布局与模板目录统一为 `android`、`android_cast` 和 `desktop`；布局选择器
  继续向用户展示中文名称。
- 在线配置允许快速下发新的实验性 `.wf` 脚本。远程脚本只能新增，不能覆盖同路径
  系统脚本，也不能按原文件名更新；所有脚本列表会强制标记 `[远程]`，日常页会显示
  红色来源警告，脚本编辑器中则保持只读。

### 🔧 修复

- 修复升级后会话仍记录旧布局名称时，首次打开场景编辑器只显示布局名称、却不加载
  截图和场景定义的问题；失效的活动布局现在会回退到清单中的首个有效布局。
- 恢复批量配置中误删的“单用户执行时跳过生命周期工作流”选项；默认开启，且同一
  用户执行多轮时仍会跳过 `batch_setup`、`prepare_item`、`finish_item` 和
  `batch_teardown`。
- 修复 Windows 脚本录制遗漏或混淆小键盘输入的问题；小键盘数字和运算键现在按
  独立虚拟键码录制为 `NUMPAD*`，不会再被丢弃或误记为主键盘数字。
- 低精度脚本录制会在停止时无损压缩键盘时间线：没有其他动作插入的
  `down → wait → up → wait` 合并为一条 `press ... hold ... after wait ...`；
  存在交叠输入时仍保留必要的 down/up，不牺牲执行时序。
- WF 的 `env` 现在同时是展示与启动契约：不支持当前环境的脚本不再
  出现于日常、全部用户参数和批量候选列表，批量启动时会再校验一次。
- 单个 WF 元数据解析失败时只记录 error 并忽略该文件，不再拖垮整个
  脚本列表；脚本编辑器会在编辑区上方显示醒目的元数据错误。
- 暂停和结束操作现在会立即显示“暂停中”或“结束中”；暂停按钮只在
  工作流真正到达可暂停检查点后才切换为“恢复”，避免长操作期间让用户误以为点击
  没有生效。

### ⚠️ 已知限制

- 本次 schema 升级不兼容旧版用户布局，不提供自动迁移；升级前必须按上述指引备份并
  手动复制需要保留的布局、模板和截图。
