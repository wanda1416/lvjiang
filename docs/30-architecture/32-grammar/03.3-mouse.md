## 一、click — 激活

激活屏幕上的 Area（Region 或 Point），或点击 Panel / 动态坐标目标。

**语义**：对具名 Region / Point，`click` 表示执行当前布局为该实体绑定的
“激活动作”。默认动作是鼠标左键点击实体中心；若布局实例设置了
`activation_key`，则改为按下该键。这样同一份 DSL 可以在手游布局点击按钮，
在桌面布局按 `SPACE` / `ESC` / `R`。

Panel、Panel 格子、坐标字面量、`CoordRef` / `find` 结果以及子场景三段引用仍是
明确的物理坐标点击，不读取实体按键绑定。显式写出 `right` / `middle` / `x1` /
`x2` 时同样强制执行鼠标操作，不会被 `activation_key` 替换。

**语法**：

```
click [name].[name]            # 配置引用（场景.区域）
click [scene].[panel][r][c]    # Panel 三级索引（点击格子中心）
click [scene].[panel]          # 点击 Panel 中心（无 row/col）
click $var                     # 点击 CoordRef / find 产出的文字区域
```

**示例**：

```
click [scene].[region]         # 常量.常量
click [scene].[reference].[region]  # 子场景引用中的实体
click [scene].$reference.[region]   # 动态子场景引用 key
click [scene].$var             # 常量.变量
click $scene.[region]          # 变量.常量
click $scene.$var              # 变量.变量
click (0.52, 0.38)             # 画布归一化坐标（录制产物）

# 点击 find 指令找到的文字位置
find as $found by contains "调律"
click $found                   # 直接点击找到的文字

# Panel 三级索引
click [bag_equip_detail].[bag_grid][1][1]     # 点击第 1 行第 1 列的格子中心
click [scene].[panel][$row][$col]             # 动态行列（变量指定）

# 点击 Panel 中心
click [general_action].[actions]              # 点击面板中心（用于点击空白处）
```

**说明**：

- `[scene].[area]`：从布局中查找 Area 并激活（Region 优先，未命中回退 Point，再回退 Panel；Panel 始终点击中心）
- `[scene].[reference].[entity]`：先按引用外框变换子场景局部坐标，再点击内部 Region、Point 或 Panel；引用 key 和实体 key 均可使用变量
- `[scene].$var`：Area 名在运行时由变量值决定。引擎会先从 `_coord_meta` 查找该 key 对应的 Region（由 scan/recognize 自动存入），找到则直接点击其屏幕坐标；找不到则回退到场景配置中查找同名 Area
- `click (rx, ry)`：**画布归一化坐标模式**。`rx`/`ry ∈ [0,1]`，表示画布内容区域内相对位置。回放时按「窗口偏移 + 画布原点 + 比例 × 画布尺寸」动态反算屏幕坐标，窗口缩放/移动后仍准确。这是脚本录制对话框生成的坐标字面量，可直接剪切复用，与 `scene.area` 引用形式混用
- `[name]` 表示配置引用，`$var` 表示变量引用。`"text"` 始终表示字符串数据，不用于配置引用
- `[scene].[panel][r][c]`：**Panel 三级索引模式**。`r`/`c` 从 1 开始计数。首次执行时自动触发图像自对齐（`align`），缓存格子中心坐标；后续点击直接查缓存。详见 [03.2-interaction.md — align](03.2-interaction.md#一align--面板自对齐)

> **重要区分**：`scene`/`panel` 是配置引用（用 `[name]` 或 `$var`），而 `row`/`col` 是面板索引（用 `[INT]` 或 `[$var]`）。row/col 不是 area 引用，不支持字符串，`["a"]` 语法不合法。正确示例：`[scene].$panel_ref[$row][5]`，错误示例：`[scene].$panel_ref["a"]["b"]`。
- `[scene].[panel]`：**Panel 中心点击模式**。点击面板中心点，用于点击空白处或重置面板状态
- `click $var`：**CoordRef / find 结果点击模式**。`$var` 可以是：
  - `CoordRef` 类型（包括 `RectCoordRef` / `CircleCoordRef`）：点击其中心点（+ 抖动）
  - `find` 指令产出的 `FoundRegion`：点击文字中心坐标
  - 变量未定义或不是可点击类型时报错。详见 [04.3-find.md](04.3-find.md)

**隐藏延迟**：

每次 `click` 底层执行时，会自动插入两段随机延迟（模拟人类操作节奏）。
无论实体最终执行坐标点击还是按键激活，等待语义一致：

```
[before_click_wait] → 点击 → [after_click_wait]
```

默认值（`app.yaml` 配置）：

| 参数 | 默认范围 | 说明 |
|------|----------|------|
| `before_click_wait` | 0.05 ~ 0.2s | 点击前随机延迟 |
| `after_click_wait` | 0.05 ~ 0.2s | 点击后随机延迟 |
| `click_random_offset` | ±5px | 坐标随机偏移（模拟手指抖动） |
| `region_jitter_ratio` | 0.25 | 区域中心抖动比例 |

**默认延迟等价于 `around`**：如果不写任何后缀等待子句，每次 click 实际耗时 **100~400ms** 的隐藏等待。

**显式 wait_clause 抑制默认延迟**：一旦指定了 `before`/`after`/`around` 任一子句，默认 `before_click_wait` 和 `after_click_wait` 全部废弃（置为 0）。例如：

| 语法 | 执行时序 |
|------|----------|
| `click [s].[r]` | `[默认 before] → activate → [默认 after]` |
| `click [s].[r] after wait 1.0` | `activate → wait 1.0`（无默认延迟） |
| `click [s].[r] before wait 0.5` | `wait 0.5 → activate`（无默认延迟） |
| `click [s].[r] around wait 0.3` | `wait 0.3 → activate → wait 0.3`（替换默认） |

- 如果写 `click ... wait 1.0 click ...`（中间是独立 wait 语句而非后缀子句），两条 click 各自仍有默认延迟，wait 是额外叠加的
- 详见 [后缀等待子句](#五后缀等待子句beforeafteraround)

**鼠标键**：

紧跟目标之后可选写鼠标键，省略时默认 `left`：

```
click [scene].[region]              # 默认左键
click [scene].[region] right        # 右键
click [scene].[region] middle       # 中键
click [scene].[region] x1           # 侧键一
click [scene].[region] x2           # 侧键二
click [scene].[region] back         # x1 的别名，更直观
click [scene].[region] forward      # x2 的别名，更直观
click (0.52, 0.38) right            # 坐标形式同样支持
```

非 `left` 值表示调用方明确要求物理鼠标键，因此会忽略布局中的
`activation_key`。默认 `left` 才具有“按布局激活”的语义。

可选值：`left` / `right` / `middle` / `x1` / `x2` / `back`（= `x1`）/ `forward`（= `x2`），大小写不敏感。`back`/`forward` 只是更好记的别名，解析后一律规范化为 `x1`/`x2`。

> Windows 默认把侧键一映射到"后退"、侧键二映射到"前进"，但鼠标驱动可自定义，不是绝对规则，写脚本时按实测行为选。

**平台支持**：仅桌面 SendInput 后端完整支持全部五种键；PostMessage 后端支持后台投递，但非左键会降级为左键并记警告；ADB / 设备端触屏后端没有鼠标键概念，非 `left` 会被忽略（仍执行普通点击）并记警告。

`drag` 目前不支持指定鼠标键（固定左键拖拽）。

### 鼠标键原始事件

需要保留多个输入交叠的准确时间线时，不使用会自动完成 down/up 的
`click`，而是分别记录鼠标键的按下和松开：

```wf
place (0.52, 0.38)
mouse left down
wait 0.12
mouse left up
```

语法为 `mouse <button> down|up`，`button` 支持 `left`、`right`、
`middle`、`x1`、`x2`，以及 `back`/`forward` 别名。该指令不移动光标、
不加入点击随机延迟；录制器会在事件前生成 `place` 或 `move` 来还原位置。
原始鼠标键仅由桌面 SendInput 后端执行。工作流正常结束、停止或异常退出时，
引擎会兜底释放仍处于按下状态的鼠标键。

## 二、move — 鼠标移动

产生鼠标移动输入，不点击。`move` 必须明确写出 `to` 或 `by`，
不再支持旧的 `move <目标>` 写法。

**语法**：

```text
move [(x1, y1)] to <目标> [duration <秒数|$var>]
move [(x1, y1)] by (dx, dy) [duration <秒数|$var>]
```

- `move to`：移动到目标。坐标目标是画布内的归一化位置，常用范围为
  `0..1`；也可使用与 `click` 相同的场景、Panel 和变量目标。
- `move by`：从当前位置移动一段长度。`dx` 乘画布宽度，`dy` 乘画布高度；
  分量范围为 `[-1,1]`，例如 `(-0.2, 0)` 表示向左移动画布宽度的 20%。
- `duration` 为移动总时长（秒）；省略时使用输入模拟配置的默认随机时长。
- 可选的起点 `(x1, y1)` 表示执行移动前先将光标放到该画布坐标。

```
move to (0.8, 0.5) duration 0.3
move to [inventory].[slot3]
move to [scene].[panel][1][2] duration $move_time
move by (-0.2, 0) duration 0.4
```

### 起点与 place 辅助指令

`place (x, y)` 直接设置光标位置，不产生移动过程。它是附属于 `move`
的辅助原语，只接受画布归一化坐标。带起点的 `move` 是它的语法糖：

```
# 下面两段完全等价
move (0.5, 0.5) by (0.2, 0) duration 0.3

place (0.5, 0.5)
move by (0.2, 0) duration 0.3
```

**各后端行为**：

| 后端 | `place` | `move to` | `move by` |
|------|---------|-----------|-----------|
| **SendInput** | `SetCursorPos` 直接放置 | 从当前光标位置计算差值并注入相对移动 | 直接注入相对移动 |
| **PostMessage** | 投递绝对 `WM_MOUSEMOVE` | 投递绝对 `WM_MOUSEMOVE` | 不支持，警告后忽略 |
| **ADB / 设备端** | 不支持 | 不支持 | 不支持 |

**与 click 的区别**：

- `move` 和 `place` **没有**默认 before/after 延迟（click 有隐藏延迟）
- `move` 支持 `before`/`after`/`around` wait_clause，但不抑制默认延迟（因为没有默认延迟）
- 仅 `move to` 的目标解析与 `click` 一致；`move by` 只接受坐标形式的位移量

### Raw Input 录制

Windows 脚本录制使用 Win32 `WM_INPUT` 直接读取鼠标 HID 相对位移，
不依赖系统光标绝对位置，因此游戏锁定光标的动作模式也能录制。
只有已扫描的目标窗口处于前台时才记录 Raw Input。

录制对话框提供两种模式：

- **低精度**：连续 Raw Input 包以 100ms 空闲间隔划分移动段，每段合并为
  一条 `move by`；键盘与鼠标键不做点击/长按推断，而是按统一时间线生成
  独立的 `down`、`wait`、`up`。所有正数事件间隔都会输出，因而可以表达
  键盘键与鼠标键同时处于按下状态的交叠操作。部分驱动会把一次物理滚轮
  动作拆成多个短脉冲；同方向且相邻不足 80ms 的脉冲会合并为一次滚动，
  避免回放时连续切换武器。鼠标移动仍可通过界面开关过滤。
- **高精度**：不生成海量 `move by`。原始鼠标整数增量、鼠标键、滚轮和
  键盘 down/up 按统一时间线保存到 `.lvtrace`，WF 只保留一条引用：

```wf
replay input_trace "lvtrace/7f02c8c43d7a.lvtrace"
```

高精度保存仍只选择一次 `.wf` 文件。程序先把按内容哈希命名的不可变轨迹
写入当前配置层的 `workflows/lvtrace/`，最后原子替换 WF；因此保存中断最多
留下无引用轨迹，不会生成指向缺失文件的新 WF。`standalone/` 下的 WF 使用
`../lvtrace/...` 相对引用，工作流发现层不会扫描 `.lvtrace`。

轨迹头保存源画布宽高，移动事件保存原始有符号整数。回放时按
`dx/source_width`、`dy/source_height` 换算到当前画布，并通过累计误差分配
保持归一化路径与总位移。专用回放器只激活一次窗口，使用绝对截止时间调度，
并为相对移动设置 `MOUSEEVENTF_MOVE_NOCOALESCE`；不会逐事件进入 DSL 调度。
轨迹缺失、损坏或版本不兼容会在执行任何动作前报错。

## 三、scroll — 鼠标滚轮

在指定位置滚动鼠标滚轮。通常与 `move` 配套使用：先移动光标到目标区域，再执行滚动。

**语义**：`scroll` 将目标解析为屏幕坐标，先移动光标到该位置，然后发送滚轮事件。未指定目标时在画布中心滚动。

**语法**：

目标（如果有）紧跟指令关键字，方向紧随目标之后，数量收尾——与 `drag` 的
`drag [target] up|down|left|right [n]` 语法形状保持一致（`click`/`move` 也是
目标紧跟指令关键字），旧版本把方向放在目标前面是本指令独有的风格不一致，已
统一为下列形式：

```
scroll up|down                       # 在画布中心滚动 1 格
scroll up|down N                     # 在画布中心滚动 N 格
scroll [scene].[region] up|down      # 移动到目标位置后滚动 1 格
scroll [scene].[region] up|down N    # 移动到目标位置后滚动 N 格
scroll $var up|down                  # 移动到变量指向的位置滚动
scroll [scene].[panel][r][c] up|down # 移动到格子中心后滚动
scroll (rx, ry) up|down              # 移动到坐标位置后滚动
scroll [target] up|down $n           # 滚动数量由变量控制
scroll [target] up|down N interval S # 逐格之间固定间隔 S 秒
```

**示例**：

```
# 配合 move 使用：先悬停到列表区域，再滚动
move to [inventory].[list]
scroll down 3

# 直接指定目标位置滚动（内部自动先移动再滚动）
scroll [inventory].[list] down
scroll [inventory].[list] up 5

# 逐格固定间隔 100ms（默认是 20~50ms 随机间隔）
scroll [inventory].[list] up 5 interval 0.1

# 动态数量
scroll [bag_equip_detail].[bag_grid] down $scroll_amount

# 坐标模式
scroll (0.5, 0.6) down
```

**参数说明**：

| 参数 | 语法 | 说明 |
|------|------|------|
| 目标 | 与 click 相同的目标语法 | 可选。指定后先移动光标到目标位置再滚动。省略则在画布中心滚动 |
| 方向 | `up` / `down` | 滚动方向。`up` = 向上滚（看上面内容），`down` = 向下滚（看下面内容） |
| 数量 | 数字 或 `$var` | 可选。滚动格数，默认 1。支持变量动态指定 |
| 间隔 | `interval <秒数>` | 可选。逐格滚动之间的固定间隔（秒），如 `interval 0.1` 即每格间隔 100ms。省略时用后端默认随机间隔（桌面 20~50ms）。仅对逐格发送事件的桌面后端生效，ADB / 设备端忽略 |

**各后端行为**：

| 后端 | 实际行为 | 说明 |
|------|----------|------|
| **SendInput** | `SetCursorPos` + N 次独立 `MOUSEEVENTF_WHEEL` | ✅ 移动系统光标 + 逐格发送滚轮事件（数量 N 时发 N 条独立消息，而非把 N 折算进单条消息的 delta——很多游戏 UI 只按"是否收到过消息"响应一次，不按 delta 数值等比例滚动）。逐格间隔默认 20~50ms 随机，`interval` 指定时改用该固定值 |
| **PostMessage** | 坐标转换 + N 次独立 `WM_MOUSEWHEEL` | ⚠️ 向目标窗口逐格投递滚轮消息，同上原因。`interval` 语义同 SendInput |
| **ADB** | `input swipe` 短距离滑动 | ⚠️ 用触摸滑动模拟滚轮，每格 100px（单次连续手势覆盖全部格数，天然按距离等比例，无逐格间隔概念，故 `interval` 被忽略） |
| **设备端** | 空操作 | ❌ 不支持 |

**与 move + drag 的关系**：

- `scroll` 是**滚轮**操作，`drag` 是**拖拽**操作
- 桌面端用 `scroll` 更自然（直接发滚轮事件），移动端/ADB 用 `drag` 更可靠（模拟手指滑动）
- `scroll` 往往需要先 `move` 到正确位置，因为滚轮事件作用于光标下方的控件
- 指定了目标的 `scroll [target]` 内部已包含移动逻辑，无需额外写 `move`

## 四、drag — 拖拽

执行拖拽动作。支持 Arrow 拖拽、Panel/Region 翻页、Point 点对拖拽。

**语义**：`drag` 将目标解析为 Entity：
- **Arrow** → 直接执行其定义的拖拽（起点 → 终点）
- **Region / Panel** → 隐式转为单向 Arrow（利用 w/h 计算终点）
- **Point** → 不允许单独 drag（无 w/h 无法计算终点），必须使用两点模式

**语法**：

```
# Arrow 拖拽（基于 Layout Action 定义）
drag literal.literal                            # literal 可以是 [] 或 $var
drag literal.literal 0.5                        # 指定时长 0.5s
drag literal.literal [0.3, 0.8]                 # 随机时长范围 0.3~0.8s
drag literal.literal 0.5 hold 0.2               # 拖拽后按住 0.2s

# Panel/Region 拖拽（翻页）
drag [scene].[panel][r][c] up [n]              # 上翻 n 行（默认 1）
drag [scene].[panel][r][c] down [n]            # 下翻 n 行（默认 1）
drag [scene].[panel][r][c] left [n]            # 左翻 n 列（默认 1）
drag [scene].[panel][r][c] right [n]           # 右翻 n 列（默认 1）
drag [scene].[panel][r][c] up $var             # 上翻 $var 行（动态）
drag [scene].[panel][r][c] down $var           # 下翻 $var 行（动态）

# Panel/Region 中心拖拽（无 row/col）
drag [scene].[panel] up [n]                    # 从面板中心上翻
drag [scene].[region] up [n]                   # 从区域中心上翻（使用区域高度作为步长）
drag [scene].[region]                          # 从区域中心默认向上拖拽

# 点对拖拽
drag [scene1].[point1] [scene2].[point2]       # 两点之间拖拽
```

**示例**：

```
# Arrow 拖拽
drag [scene].[arrow]                            # 常量.常量
drag [scene]."arrow"                            # 常量.字符串
drag [scene].$var                               # 常量.变量
drag $scene.[arrow]                             # 变量.常量
drag [scene].[arrow] 0.5                        # 指定时长
drag [scene].[arrow] 0.5 hold 0.2               # 拖拽后按住
drag (0.52, 0.45) (0.52, 0.22)                  # 画布归一化坐标（录制产物）
drag (0.52, 0.45) (0.52, 0.22) 0.4              # 坐标模式 + 指定时长

# Panel 拖拽（翻页）
drag [bag_equip_detail].[bag_grid][1][1] down   # 下翻 1 行
drag [bag_equip_detail].[bag_grid][1][1] up $n  # 上翻 $n 行（动态）
drag [bag_equip_detail].[bag_grid][1][1] right 2 # 右翻 2 列

# Panel/Region 中心拖拽
drag [general_action].[actions] down            # 从面板中心下翻
drag [scene].[scroll_area] up 2                 # 从区域中心上翻 2 次

# 点对拖拽
drag [scene].[point_a] [scene].[point_b]        # 两点之间拖拽
```

**参数说明**：

| 参数 | 语法 | 说明 |
|---|---|---|
| 时长 | 数字 或 `[min, max]` | 拖拽持续时间。省略则使用默认值；`[min, max]` 在范围内随机取值 |
| hold | `hold <秒数>` | 可选。到达目标位置后按住不放的时长 |
| 方向 | `up` / `down` / `left` / `right` | Panel/Region 拖拽方向。`up`/`down` 按行计算，`left`/`right` 按列计算 |
| 距离 | 数字 或 `$var` | Panel/Region 拖拽距离。`up`/`down` 为行数，`left`/`right` 为列数。省略默认为 1 |

**坐标模式**：`drag (rx1, ry1) (rx2, ry2) [时长]` 直接给出起点/终点的画布归一化坐标（与 `click (rx, ry)` 同源），无需引用 Arrow。这是脚本录制对话框生成的形式，可直接剪切复用。

**Panel/Region 拖拽语义**：

- `up` = 手指从下往上划 = 内容向下滚动 = 看上面的内容（类似 PageUp）
- `down` = 手指从上往下划 = 内容向上滚动 = 看下面的内容（类似 PageDown）
- `left` / `right` 类推
- 拖拽起点为指定格子/区域中心
- Panel 垂直拖拽距离 = 行数 × 单行高度（panel 高度 / 行数）
- Panel 水平拖拽距离 = 列数 × 单列宽度（panel 宽度 / 列数）
- Region 拖拽距离 = 区域高度/宽度 × 距离参数

**查找顺序**：

- `drag [scene].[key]`：先查 arrow，未命中再查 region，最后查 point
- `drag [scene].[key] direction`：先查 panel，未命中再查 region
- `drag [scene].[point]`（单独）：**不允许**，Point 无 w/h 无法计算终点，请使用两点模式 `drag [scene].[point1] [scene].[point2]`

**隐藏延迟**：

`drag` 与 `click` 类似，底层执行时也会插入 `before_click_wait` / `after_click_wait` 随机延迟。显式指定 `before`/`after`/`around` 子句时同样会抑制默认延迟（与 click 一致）。此外还有：

| 参数 | 默认范围 | 说明 |
|------|----------|------|
| `mouse_move_duration` | 0.4 ~ 0.6s | 鼠标/手指移动到起点的时长 |
| `duration`（拖拽时长） | 视模式而定 | Arrow/坐标模式默认 0.3~0.5s；Panel/Region 翻页默认 0.3~0.6s |

`drag` 同样支持 `before`/`after`/`around` 后缀等待子句，详见 [后缀等待子句](#五后缀等待子句beforeafteraround)。

## 五、后缀等待子句（before/after/around）

`click` 和 `drag` 支持后缀等待子句，语法糖展开为多条语句。`wait` 的两种形式（定时/稳定）均可用于后缀子句。

`before` 和 `after` 可以同时出现，顺序不限；`around` 是语法糖，等价于同时指定 `before` 和 `after`（同一参数）。

```
# 单独使用
click [scene].[btn] after wait 1.0        # → click; wait 1.0
click [scene].[btn] before wait 0.5       # → wait 0.5; click
click [scene].[btn] around wait 0.3       # → wait 0.3; click; wait 0.3（等价于 before wait 0.3 after wait 0.3）

# before + after 组合（顺序无关，语义始终：before 在操作前，after 在操作后）
click [scene].[btn] before wait 0.5 after wait 1.0   # → wait 0.5; click; wait 1.0
click [scene].[btn] after wait 1.0 before wait 0.5   # → wait 0.5; click; wait 1.0（同上）

# 稳定等待组合
click [scene].[btn] before wait stable 3 after wait stable 5  # → wait stable 3; click; wait stable 5
click [scene].[btn] around wait stable 8 least 0.5  # → wait stable 8 least 0.5; click; wait stable 8 least 0.5

# drag 同样支持
drag [scene].[arrow] after wait 1.0       # → drag; wait 1.0
drag [scene].[arrow] before wait 0.3 after wait 0.8  # → wait 0.3; drag; wait 0.8
```

**展开规则**：

| 子句 | 展开顺序 |
|------|----------|
| `before wait X` | `Wait(X) → 操作` |
| `after wait Y` | `操作 → Wait(Y)` |
| `before wait X after wait Y` | `Wait(X) → 操作 → Wait(Y)` |
| `after wait Y before wait X` | `Wait(X) → 操作 → Wait(Y)`（与上一行等价） |
| `around wait Z` | `Wait(Z) → 操作 → Wait(Z)`（等价于 `before wait Z after wait Z`） |

## 六、失败语义

鼠标操作的失败按原因分两类：

**配置错误 → 抛错终止**（脚本或布局配错，继续执行只会在错误的页面上乱点）：

| 情况 | 指令 |
|------|------|
| Region / Point / Panel 未绑定坐标 | click / scroll |
| Arrow / Region / Point 未绑定坐标 | drag |
| Point 单独作为 drag 目标（无 w/h 无法计算终点） | drag |
| Arrow 的起点或吸附态终点 Point 丢失 | drag |
| `$var` 未定义或取到空值 | click / scroll / drag |
| Panel 未在布局中定义 | click / scroll / drag |
| Panel 行列索引不是数值、拖拽距离不是数值 | click / drag |
| 滚动数量 / 间隔不是数值 | scroll |

**运行时状态 → 记日志后跳过**：

- Panel 索引越界：脚本遍历网格时用越界作为终止条件

抛出的错误可以被 `try` / `catch` 捕获，需要容错的片段自行包裹即可。

配置错误在**执行前**就会被静态检查拦下：引擎解析完 `.wf` 先把全部静态引用与当前布局比一遍，一次性列出所有问题（含文件名与行号），不等执行到那一行。详见 [33-engine/02-static-check.md](../33-engine/02-static-check.md)。
